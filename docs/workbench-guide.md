# 本机工作台使用说明

更新日期：2026-10-02。适用于当前 API Key 本机桌面源码。需要包含同版本前端与 Python 执行器的桌面客户端；普通浏览器预览不提供本机执行能力。

## 配置模型与开始使用

首页“就绪清单”显示模型配置与项目目录两个必需项，完成后自动收起。模型验证是可选项，不会因为尚未验证而阻止使用。点击缺项进入相应设置，返回工作区会重新读取配置。

模型设置支持“从服务获取”和“手动填写模型 ID”。服务不提供模型列表时可以手动添加，不根据名称猜测容量和能力。上下文容量未知时允许保存，发送前会要求填写，并定位到对应模型。手动模型不在列表中仅表示“无法通过列表确认”。

“配置已保存”“模型列表检查通过”与“生成／工具能力已验证”分别显示；列表请求成功不证明模型能生成或调用工具。真实能力验证须由用户单独触发，可能产生模型服务费用。

切换供应商、设置栏目、返回工作区或正常退出应用时，未保存的模型配置提供“保存并继续／放弃更改／留在此处”。托盘退出使用同一保护；隐藏到托盘保留输入。部分保存失败会说明完成的步骤并保留草稿。点击保存后，API Key 持久化到系统凭据库，重启时加载到本机执行器；保存采用“准备配置 → 保存所需凭据 → 应用配置”的持久记录；更新密钥使用独立凭据槽位，全部就绪前保留原活动配置。中断后在模型设置的“配置保存与恢复”中手动继续或放弃，不会自动调用模型。“检查并清理旧凭据”先核对引用，仅清理没有活动配置或待保存记录引用的已知条目。Windows 上，尚未提交的模型 ID、地址、参数及密钥草稿统一由当前系统用户的 DPAPI 加密保存，候选包与正式包隔离，不写入浏览器存储或明文配置。显示“密钥草稿已加密保存”后，即使强制结束进程，再次打开模型设置也能恢复输入；恢复不会自动启用配置或调用模型。保存成功或选择放弃更改后清除恢复草稿。正在写入且尚未确认落盘的最后一次输入仍可能丢失；加密存储不可用时会明确提示。此草稿恢复目前仅支持 Windows。“默认启用知识库”控件已移除，旧字段和值保留。

旧凭据清理在确认清单后按每批最多 64 项串行处理，每批依次登记、删除系统凭据、确认结果，再进入下一批。只有执行器已确认的删除才计入完成数；任何一步失败或本机会话变化都会停止，并提示累计完成数量。再次点击“检查并清理旧凭据”会重新读取剩余条目并要求确认，不自动重试。

## 查找与组织任务

点击侧栏放大镜或按 `Ctrl/Cmd+K`，默认搜索项目、任务标题和消息正文。可按项目、最近运行状态、时间过滤；“已归档”切换为归档范围。点击消息结果定位原消息，归档结果明确显示“恢复并打开”。导航命令放在独立页签。

搜索完整持久化正文，包括存入内容仓库的长消息。每页最多扫描 2500 条记录，默认返回 40 条命中；可继续搜索更早记录。顺序按记录创建 ID 倒序，时间过滤使用更新时间，不提供语义排序。独立子任务不混入用户任务历史。

任务菜单提供归档，归档保留消息与运行记录；删除仍需确认且不可撤销。运行、暂停、进程清理或工作区租约未完成时不能删除。删除父任务一并清理其内部子任务；未关联任务和项目磁盘文件保留。

侧栏标题增大、次要操作收进带文字的更多菜单。侧栏和审阅面板可拖动调整宽度，也可聚焦分隔条后使用方向键、Home、End；宽度仅存本机。键盘焦点使用可见的主题强调色轮廓；壁纸主题继续保留正文与状态色的对比度保护。窄窗口使用侧栏抽屉和完整宽度的审阅区。

## 运行控制与草稿

回答、工具执行与模型请求的耗时统一四舍五入为整数秒（不足半秒显示 0 秒），不再显示毫秒或小数秒；底层时间戳及协议中的 `latency_ms` 保留原精度，以维持历史和事件兼容。

主输入框在运行中仍可编辑和保存草稿，但不再提供“补充当前任务”“排队下一条”及发送方式选择。运行或暂停期间不会通过 Enter 提交新消息，当前运行结束后可发送保留的草稿。

输入框右下角的暂停图标暂停当前任务；已暂停时显示“继续任务”。任务顶部的“停止”用于结束当前运行。输入框上方不再重复显示运行提示及暂停按钮。活动输出状态显示“正在思考”，暂停后隐藏。

控制操作携带请求 ID 与状态版本；暂停接收后等待执行边界生效，期间不可重复提交。连接中断导致结果未知时，“重试上次请求”复用原 ID。暂停和继续不会清空草稿。

本机执行器退出后，首页的“重试连接”会重新启动或复用执行器，绑定本机身份、同步当前项目，再刷新数据。任务页手动重连在健康检查失败时执行相同流程，仍在原任务时才继续读取输出。重连保留仍有效的项目、工作区和任务选择及草稿；失败后可再次点击。普通刷新和自动续流保持原有行为，重连不会自动继续任务执行，也不会重放失败的写入请求。

旧版本已经保存的后续输入仍可查看及撤回，原有持久化协议保持兼容。已启动的旧队列任务需停止对应运行。

草稿正文、项目引用、附件引用和请求标识按项目、工作区和会话保存到本机 SQLite，WebView 仅作为编辑缓存。旧浏览器草稿首次进入时迁移；清空浏览器草稿缓存仍可恢复后端已确认的版本。显示“草稿已保存在本机”后才表示完成持久写入；最后一段尚在写入的输入不能保证跨强制退出恢复。版本冲突时可“核对已保存草稿”，明确选择当前输入或本机版本，不自动覆盖。收到任务创建确认后才清空已发送的正文和附件；失败时保留。响应丢失时先按原请求标识查询结果，手动重试沿用该标识。等待期间新增的草稿不会被旧回执清空。

任务需要处理时，可从输入区上方直接“查看审批”“继续任务”“查看恢复详情”或“查看验证结果”。这些入口复用现有审批、恢复和验证状态，不自动重放失败操作。

## 对话附件与项目文件引用

首页与会话页的“从本机添加文件”将所选文件存为应用数据目录中的独立副本。选择、预览和移除附件不会写入项目目录；项目内的 `@文件引用` 与对话附件分开显示。原始文件随后移动、修改或删除不影响已经保存的副本。

支持 UTF-8 文本（含 UTF-8 BOM，单文件 **1 MiB**，允许空文本）、PNG/JPEG/WebP 静态图片及 PDF（单文件 **10 MiB**、PDF **50 页**），每条消息最多 **8 个附件**。图片最大 2000 万像素、单边 16384 像素；动画、损坏文件、需密码的 PDF、链接及凭据文件不接受。PDF 单页最多 50 万、整份最多 200 万提取字符。附件显示名称、字节数与读取状态，点击可预览图片、按页查看 PDF 或分段读取文字；不可读取时提示原因。

PDF 文字优先在本机提取；图片与没有可提取文字的 PDF 页由所选视觉模型理解。请根据服务文档在模型设置中勾选“支持视觉输入”，不根据模型名称推测能力；这不是实测认证。只添加或预览附件不会调用模型。发送后，模型先收到清单，再通过 `read_task_attachment` 按需读取；PDF 的 `page` 从 1 开始，`view=auto` 优先文字、无文字页提供图片，图表可用 `view=image`。模型接收的图片最长边缩放至 1536 像素、JPEG 最大 2 MiB，原件仍完整保存。识别准确度取决于模型和材料质量，密集文字或细小图表可拆分成清晰图片再提交。

图片内容不会当作项目指令或额外授权；未发送附件不向模型开放。模型请求临时包含图片数据，运行日志、上下文事件只保留附件引用。纯文字 PDF 可使用文本模型；若附件含图片或无文字页，发送前会定位视觉模型配置。显式导入图片/PDF 会创建原始文件，重名必须改名。

附件与未发送草稿一起恢复，不按时间自动删除。移除草稿附件只解除此草稿的引用；没有草稿或消息引用时清理应用副本。已发送材料随消息与会话保留，取消任务不会删除，删除会话时清理对应引用。旧版已复制到项目中的文件不自动搬移或删除。

预览中的“导入项目…”是独立操作。先填写目标相对路径，再确认创建文件；重名须改名，不覆盖现有文件。导入后对话附件仍保留。

模型先收到附件清单，通过只读工具 `read_task_attachment` 按 ID 分段读取当前会话已提交的材料。未发送附件和其他会话材料不可读取；附件正文不作为项目说明、额外指令或额外授权。

## 改动、验证与工作区交接

任务右上角“环境与变更”打开固定审阅面板：

- **变更**：最近一轮、整个任务、当前工作区。任务范围显示操作记录及验证结果；工作区范围显示当前目录全部 Git 差异，包含其他任务或手动编辑。整个任务范围最多支持 200 次运行，超过时明确提示改用最近一轮或拆分任务。
- **行级反馈**：点击 diff 行号，输入问题后添加到任务输入。保留现有草稿，附文件、修改前/后行号和审阅版本；用户发送后才继续修改。
- **验证**：区分已回答、已验证、验证失败和待核实项，显示已记录 Token、工具调用、服务返回费用、浏览器证据及子任务结果。供应商未返回费用时显示未知，不推算账单。
- **进程、上下文**：继续使用现有执行会话及上下文查看能力。观察诊断和恢复详情放在任务更多菜单。

在项目菜单的“编辑项目 → 独立 worktree”选择起始分支并显式创建。成功后选中新工作区，可用于新会话；输入区不再放置 worktree 创建开关。不会复制根目录中未提交的改动。结束后在“环境”选择“预览交接到本地”。预览检查共同起点、源目录身份和根目录冲突，确认后逐文件应用并将任务后续运行切换到项目根目录。源 worktree 保留。

新会话中央提供“读懂项目”“修复问题”“审查改动”三个快捷入口，点击后填入草稿，由用户发送。

输入区的模型控件从左到右为：上下文圆环、模型 ID、模型强度。模型名称只使用配置的 `model_name`，例如 `deepseek-flash`、`qwen-3.8-flash`；单行紧凑显示，不拼接供应商或其他属性。超长 ID 在窄空间省略显示，悬停名称可查看完整值，实际请求仍使用配置的模型 ID。

仅询问“你是什么模型”时，模型提示要求简短回答“我是 <模型 ID>。”，不附配置来源、字段名、版本边界或工具能力说明。ID 未知时说明无法确认；不会使用配置项名称冒充模型 ID。

点击强度打开分档滑杆，档位由模型已声明的 `reasoning_efforts` 决定，可使用方向键、Home/End 调整，恢复按钮回到默认。未声明可调档位时展示说明，切换模型后不保留其不支持的强度；Escape 或点击外部关闭浮层。

悬停、点击或键盘聚焦上下文圆环，显示已用比例、已用标记数和总容量，例如“55% 已用 / 已用 142k 标记，共 258k”。估算值明确标注“估算”；新会话显示已知容量及等待用量的提示，数据缺失时说明原因。用量来自当前会话与所选模型的现有计量接口，切换时丢弃旧回执。

交接仅支持应用管理的 worktree，同一项目根目录为目标。一次最多 200 个文件、8 MiB，总共保留最多 100 次交接记录；链接、子模块、目录与文件类型替换会拒绝。两端内容变化会使预览失效。跨文件写入不是一次文件系统事务：中断时保留逐文件落盘记录，不把部分完成标为成功，也不自动删除源目录。可在“交接记录”核对。

## Skills 与 MCP

壁纸入口改为“设置 → 外观”。“插件”集中提供 Skills 和 MCP；设置中的 MCP 也提供相同服务管理，原有公开文档服务保留为单独展开区域。

### Skills

提供“项目说明、代码审查、测试建议”三类可编辑模板。填入模板只改变表单，保存创建技能文件，检查与启用仍分别由用户操作。

项目目录为 `.agents/skills/<目录名>/SKILL.md`；用户目录为本机资料目录下的 `skills/<目录名>/SKILL.md`。可在界面新建并粘贴内容，或放置已有技能目录后重新扫描。先检查正文，再允许当前项目使用；启用绑定内容摘要，正文变化后自动要求重新检查。

支持名称、描述和命令依赖的头部子集，例如：

```markdown
---
name: project-review
description: 审查项目修改并核对验证证据
requires: ["git"]
---

先阅读项目规则，再检查差异。报告可复现问题，并附文件和行号。
```

`requires` 是最多 16 个命令名的 JSON 数组；依赖缺失不能启用，不自动安装依赖。目录名限字母、数字、下划线、连字符，最多 64 字符。目录总计最多 200 项；正文与单个参考文件最多 64 KiB，要求普通 UTF-8 文件。

输入 `/skill` 并按回车，或在 `/` 命令菜单选择 `/skill`，按需打开已启用技能列表。选择后插入 `$project:目录名` 或 `$user:目录名`，命令本身不发送给模型；也可直接输入技能引用。模型先发现目录，再按需调用 `load_skill` / `read_skill_reference`。参考文件须位于该技能目录，读取仍受任务路径范围和秘密过滤约束。技能不会扩大权限，也不会因加载正文自动执行脚本。

### 通用 MCP

个人服务库保存连接配置与登录引用，同一服务可绑定到多个项目。每个项目独立选择工具、启用状态和审批策略。流程为“填写配置 → 本地预检 → 登录／连接 → 选择工具 → 启用”；预检只检查本机配置，不联网、不启动程序。连接发现需点击触发。保存失败保留输入和原活动配置；中断的保存记录可继续或放弃。

只读工具可选择“首次同意后允许当前会话”；有写入或未知副作用的工具必须每次审批。修改共享配置前列出受影响项目，修改后各项目需重新验证，原授权失效。解除项目绑定不删除服务；仍有项目引用的服务不能直接删除。旧配置分别迁移为服务与原项目绑定，不按相同 URL 自动合并。

- **HTTPS**：仅公开地址、443 端口。每次连接检查 DNS 并固定解析结果，拒绝内网、环境代理和自动重定向。无认证、OAuth、Bearer、自定义请求头四种模式互斥。OAuth 默认保存到系统凭据库，可选择“仅当前应用进程”；令牌不返回 WebView。刷新按服务串行，持久化失败会提示本次可用、重启后可能需要重新登录。
- **stdio**：用户确认信任后选择现有可执行文件绝对路径，参数逐项编辑并保留高级 JSON 入口，可配置环境变量。直接运行程序，不做 Shell 展开或变量插值，不接受 `.cmd`、`.bat`、`.ps1` 包装脚本。工作目录仍为当前调用项目根目录。进程以当前用户权限运行，不能将工具自报只读等同于操作系统沙箱；禁止启动命令或限定读取范围的任务不能调用该进程。

Bearer、认证头值和显式环境变量值通过桌面私有凭据通道保存，配置仅含引用。系统凭据失败不回退明文，必要凭据缺失时停止连接。非桌面 HTTP 兼容模式只支持会话 OAuth，不支持静态秘密持久化。

个人库最多 128 个服务，每项目最多绑定 32 个服务、每服务最多选择 32 个工具。支持有界、无环的本地 schema 引用；远程引用、递归引用和超限目录继续受限。单个工具不兼容时显示原因，其他兼容工具仍可选择。Resources、Prompts、交互式 elicitation 和自动安装不在本期范围内。

界面区分配置已保存、待登录、连接中、目录已验证、配置变化和连接失败，并显示最近验证时间。“目录已验证”是上一次发现结果，不表示持续在线。缺少凭据时提示重新保存；目标服务返回 401 时提示检查认证或重新登录，403 时提示检查账号与远端权限。外部写入发送后发生断流、超时、取消或无效回执时显示结果未知，需先核对远端结果，不会自动重放。

### 长期记忆

在会话中明确说“记住：……”可保存当前项目记忆；只有明确要求全局适用才保存跨项目偏好。保存、纠正和遗忘均返回实际操作结果，记忆使用关闭时仍可明确保存，但不自动开启使用或后台生成。只读或规划会话不能通过模型持久写入，可在设置的记忆管理页操作。

会话“上下文”面板显示本轮用了哪些记忆、范围、匹配依据和更新时间，也显示因预算或待复核而排除的原因。可查看来源原文、打开来源会话、编辑或遗忘。候选与旧值独立保存；设置页显示当前列表的待复核数量，冲突内容暂停自动召回，复核后采用新值、保留旧值或编辑合并。旧记忆继续使用，历史自动条目有标识，不重新提取旧历史。

遗忘清除条目及修订正文，保留防止重复生成的去重标记。会话原文独立保留；已经导出的备份和已经发送的模型请求不会被删除或撤回。开关、后台额度和生成模型保持原设置，详见[记忆设计](memory-design.md)。

## 网页与浏览器证据

`read_web_page` 经审批读取公开 HTTPS 页面的正文和来源链接，不执行脚本。搜索引擎检索由用户配置的 MCP 搜索工具提供，不内置搜索账号或密钥。

先通过现有执行会话启动项目预览，再要求 Agent 使用 `verify_local_preview`。该工具使用已安装 Edge/Chrome/Chromium 的全新临时配置，在独立浏览器中检查已经启动的本机 HTTP 地址（回环地址、端口至少 1024）。一轮支持最多 8 个单一 CSS 选择器动作：点击、填写普通输入、检查文本。

浏览器代理仅允许同来源 GET/HEAD，阻止写请求、跨来源资源、WebSocket 和授权头。含登录、跨域 API、HMR 或写接口的流程可能不适用。此网络限制不把网页或本机 GET 接口变为完整的安全沙箱；不要用它操作含写入副作用的 GET 接口。

结果包含 DOM 摘要、逐项断言和本机 PNG 截图引用。页面成功打开或截图生成不等于视觉验收通过；模型获得文本与截图标识，用户可在验证面板查看图片并反馈。截图不上传，每轮最多 20 张、单张 8 MiB、总计 512 MiB，删除相关任务历史时清理孤立截图。

## 模型与执行边界

“设置 → 模型 → 能力记录”查看已存探测结果；再次探测需用户点击并确认可能产生费用。连接测试、工具能力探测和实际任务验证是不同结论。

本轮实际选用的模型 ID 会进入系统上下文，询问当前模型时按该 ID 回答。ID 来自本机路由配置，不证明供应商背后的不可变模型版本；未知 ID 不用 Profile ID 或助手角色替代。

对话入口移除 Token 预算、美元费用上限及独立只读子任务选项，不再提交对应参数。`run_readonly_agents` 不再注册或执行，旧的 `allow_subagents=true` 请求会被拒绝，任务恢复和后续队列均不恢复此许可。旧子任务历史仍可查询和清理。上下文容量、请求次数、运行时间限制以及已有预算核算继续作为运行时内部保护，不扩大权限。

## 关于与更新

“设置 → 关于与更新”读取实际客户端版本。已有内置更新源时可直接检查；未配置时展开“更新源设置”，填写发布方为此客户端提供的 HTTPS JSON 清单地址。有效地址按更新目标保存在当前客户端，下次打开继续使用；地址不允许携带凭据、查询参数或片段。

检查与安装使用同一更新源，修改地址会清除旧的安装入口。下载安装前再次核对版本，下载验签完成后才停止本机执行器并安装。统一客户端使用 `unified-windows-x86_64`，旧联网客户端使用 `remote-windows-x86_64`；清单必须在 `platforms` 中明确列出对应安装目标，不接受无目标的动态清单，候选版不能切换为正式更新通道。签名公钥固定在客户端，填写地址不能绕过签名校验。

2026-09-21 用户确认当前更新源尚未部署。因此这里只交付客户端配置、检查与安装链路；缺少清单或签名安装包时不能完成真实在线升级，也不能宣称已是最新版本。发布方需后续部署与客户端目标、公钥匹配的正式更新产物。

## 首页布局与可读性

“设置 → 外观 → 首页布局”提供标准和紧凑两种模式。默认标准布局保留插画与现有底部输入位置；紧凑模式收为简短标题区，继续保留项目入口、任务示例与底部输入。偏好仅保存在本机。

文件正文基准为 13px、行高至少 1.5，辅助信息至少 12px；文件面板常用图标的点击区域至少 32px。新增弹窗沿用设计组件的初始焦点、Tab 循环、Esc 关闭与焦点返回；提交期间按操作状态禁用重复触发。

## 模型选择的作用范围

输入区模型按钮显示实际生效来源。点击后可保存全局默认、当前项目或当前会话的选择；优先级为会话、项目、全局，项目和会话可选择“继承上级设置”。这里只保存已有模型的引用，不能修改供应商地址、密钥或执行权限。选择影响后续发送，已启动的任务使用原模型。被引用模型删除或禁用时明确阻止发送，不静默切换到其他模型。

恢复备份后，模型来源缺失、身份冲突或模型不可用时显示“待确认”。当前生效范围待确认时禁止发送，也不会回落到上级模型；直接 API 传入模型 ID 和内部队列同样受此限制。打开原有模型选择器，核对供应商、协议、接口格式、地址和模型后明确保存。只清除本次保存范围的标记；选择“继承上级设置”后，上级仍待确认则继续阻止发送。重启或再次备份不会消除待确认状态。

## 备份、恢复与材料管理

“设置 → 备份与恢复”区分三种操作：

- 历史导入导出：沿用 v1/v2/v3 兼容接口，保存会话和已发送附件。
- 普通配置导出：保存供应商、模型 ID、请求地址、显式能力、参数和首页标准/紧凑偏好。API Key、密钥引用和加密设置草稿不导出。
- 应用数据备份：在普通配置之外保存本机历史、持久草稿、项目引用、未发送附件以及项目/会话模型选择。新导出使用 `privateagent.backup.v2`，附带模型来源身份、继承来源和待确认状态；继续读取合法 v1 包。包与附件分别校验摘要，上限 64 MiB，超限不生成缺项文件。桌面下载保存后端原始字节，避免小数被重新序列化导致摘要失效。

这份应用数据包覆盖上述工作台记录，不是系统磁盘镜像。项目文件、长期记忆、用户 Skills、MCP 设置和头像/壁纸资源需要另行保管，凭据需要在目标电脑重新输入。备份不加密，包含对话和材料，应保存到可信位置。

应用数据包不包含此前导入后只读保留的历史归档正文；需要保留这些旧归档时，应在对应导入记录中单独导出历史归档。

导入前先预览创建时间、格式版本、文件大小、实际覆盖范围和模型身份差异。普通配置和工作台数据分步确认，分别报告导入、跳过和待确认数量；供应商 ID 冲突时保留本机配置，新供应商导入后保持禁用，启用与能力验证仍需用户触发。普通参数只在本机尚无供应商时恢复；首页模式会按确认后的备份值替换。

数据恢复会核对显式项目/会话选择，以及原来继承的全局默认模型。只有供应商 ID、协议、接口格式、规范化地址和模型 ID 一致且本机模型可用时才自动恢复，不修改目标电脑的全局默认模型。其余情况先恢复历史、草稿和附件，再提示确认模型；无需先填写凭据。v1 从包内配置推导身份，无法确认的来源也进入待确认。

旧客户端不支持 v2，恢复前应升级到支持该格式的版本。摘要失败的旧包和被修改的包会拒绝导入，程序不会自动修改或重算摘要。请保留原包；原数据仍在时使用修复后的版本重新导出。

数据导入为每个项目、工作区重新选择本机目录，不复制项目文件、不覆盖现有记录。旧 Git 工作树对应已映射的普通目录，不自动重建 Git 工作树；旧运行转为历史，不恢复审批和进程。待发送草稿使用新的草稿标识并清除旧发送标识，需用户核对后发送。只有附件引用而没有正文记录的材料会进入“恢复的附件草稿”会话。整个数据部分在同一 SQLite 事务内导入，失败回滚新记录和附件副本；同一备份重复导入返回原结果。

恢复结果显示重复导入状态、草稿与附件数量、待确认模型及导入记录 ID；成功后立即刷新材料和迁移记录，可进入“核对并回滚”。新记录注明来源是应用备份还是历史归档，并保存实际导入计数；旧记录缺失的信息显示“未知”，不按当前数据猜测补写。历史回滚只撤销数据导入，不撤销独立完成的配置导入。

导入记录中的“导出历史归档”只导出该次导入的历史子集，不包含配置、持久草稿、未发送附件或模型选择，不能替代原备份。本轮不保存完整原应用包副本，应自行保管原包。

新导入记录使用第 2 版回滚指纹，覆盖 MCP 服务库及待提交的 MCP 配置记录。导入后新增、修改这些数据会阻止历史回滚；仅在指纹一致、没有活动任务且备份校验通过时允许恢复。缺少指纹版本或版本不受支持的旧导入记录不能自动回滚，即使看起来没有后续修改；应保留导入记录和备份并人工核对。旧记录仍可查看、导出，同一备份重复导入仍返回原结果，不会补写新的回滚基线。

“附件与存储”列出名称、大小、项目、草稿/会话引用、读取状态和预览入口。移除前会显示受影响草稿、其他引用和预计释放空间；预览后引用发生变化会拒绝清理并要求重新核对。移除保留正文和历史材料，且不改变用户源文件。已发送材料随会话保留，只能通过会话管理解除该会话的引用。目前 PDF 页面和图片按需解码，没有持久化解析缓存，因此不会把原件当成缓存清除。

## 存储与验证边界

队列、技能启用、交接日志和子任务关联继续复用原有字段。附件沿用 SQLite v8 表与应用附件目录；v9 增加持久草稿与首条会话请求去重索引，当前 v10 增加个人 MCP 服务库和配置保存记录，项目保留独立绑定。旧库增量升级前先备份，事务失败回滚；更高版本库拒绝写入。消息和附件引用仍在同一事务中提交，正文独立存放并校验 SHA-256。供应商凭据库、本机身份、命令沙箱和原有补丁审批保持原有边界。

历史交换格式 v3 包含已发送的文本、图片与 PDF，二进制正文采用 Base64 并校验 SHA-256；继续读取 v1/v2；历史导出不包含未发送草稿；要迁移草稿请使用应用数据备份。总量仍限制为 64 MiB，损坏或超限明确报错，不静默丢弃材料。导入重新映射附件标识，回滚同步处理副本；不会恢复旧授权或重放旧任务。

功能使用同一版本的前后端。当前完成的是源码、隔离协议和浏览器验证；未以真实供应商账号、第三方 OAuth 账号或重新安装后的原生客户端验收。此前的工作台交付见[历史交付记录](solutions/2026-09-21-workbench-upgrade.md)，此前的入口、模型身份与更新修复见[修复记录](solutions/2026-09-21-conversation-controls.md)。这些历史记录不代替本轮附件与体验调整的验收结果。
