## 1. 交付内容

### 1.1 可信完成条件（`agents/verification.py` + `routes_agent_runs.py`）

- `WorkflowCompletionOutputVerifier`（OutputVerifier 实现）：基于 **durable
  executions 事实**求值完成条件——`must_succeed_tools`（必须存在 succeeded
  执行）、`max_failed_tools`（失败工具数上限，默认 0）、`require_verified`
  （succeeded 且显式 verified=False 的工具拒绝，缺失字段不检查）；
  条件不满足 → run 以 `output_validation_failed` 失败关闭，模型不能通过
  自由填写"完成"宣称完成；
- `AgentRunCreateRequest.completion_conditions`（字段白名单校验）+ additive
  迁移 0026 `agent_runs.completion_conditions_json`——持久化后审批恢复/
  sidecar 重启续跑路径与创建路径使用同一组条件；
- 创建与 approve 路径统一走 `_build_output_verifier_factory`（RAG 引用验证器
  与完成条件验证器可组合）。

### 1.2 unknown execution 人工处置（`executions.py` + API）

- `ToolExecutionRepository.resolve_unknown`：仅 `unknown` 状态可处置；
  `succeeded` 必须提供用户确认的输出事实（限长/脱敏/审计），`failed` 标记
  失败终态；处置写入 `error_message`（`[人工处置] <decision>：<note>`）；
- `POST /agent-runs/{run_id}/executions/{execution_id}/resolve`：不自动猜测
  成功或重跑，处置后同 call 重试按既有 claim 语义处理（succeeded → 缓存
  人工输出；failed → 不再重放）。

### 1.3 首批端到端场景（`tests/test_workflow_e2e.py`）

| 场景 | 验证 |
|---|---|
| 1. propose→apply→command 多工具链 | 逐步审批续跑 → completed；文件写入 + 回读验证；完成条件基于事实满足 |
| 2. 完成条件不满足 | 必需工具失败 → `output_validation_failed`，run 不进入 completed（失败步骤不被包装成"已完成"） |
| 5. 审批等待 → 重启 → 续跑 | pending 审批 → approve + reissue（模拟 token 丢失）→ 新 runner 续跑 → completed；副作用只发生一次（单一 succeeded execution） |
| 4. 取消/进程树 | 既有 B2 测试覆盖（run cancel + Job Object 清理） |
| 四类工具同注册 | 独立 flag 组合，无总开关 |

`{filesystem.read, database.query}` 收紧为 `{filesystem.read}`（与 B0 冻结
契约一致）。
