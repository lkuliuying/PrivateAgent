## 2. 关键决策

1. **新壳复用 AppShell 而非另建壳组件**（W1 任务 1「改造 AppShell 的 Coding 模式」）：
   rail 槽换 CodingSidebar、coding 视图关顶栏，旧视图（设置/诊断/自动化/扩展）在
   同一壳内原样渲染——满足 W0 §5「次级入口指向既有页面」且零重复壳代码。
2. **store 单例 + props 注入**：`useCodingWorkspace()` 单例（对齐 stores/health.ts
   惯例），组件以可选 `store` prop 默认取单例——测试/预览传夹具 store，生产零配置。
   生产 API 只发生在 `features/coding/api/*` 与 store，组件不自取（计划 §5.4）。
3. **`apiFetch` 不自动拼 base**：沿用 api.ts 惯例 `fetch(\`${await ensureApiBase()}…\`)`，
   领域层统一经 `codingFetch()` 拼装（e2e 首轮失败教训：相对路径会打到 vite origin）。
4. **W1 输入语义**：首页主输入 Enter 提交 → `POST /sessions`（kind/project/workspace
   成对）创建 coding 线程并进入任务页；首轮消息与 run 流是 W2（useRunStream/runProjector
   迁移），`CodingComposer`（@上下文、/ 命令、权限/模型/推理）是 W3。任务页 W1 为
   占位形态：ThreadHeader 摘要（标题/项目/分支/更新时间）+ W2 交付说明，不虚构
   run 状态（零容忍 §10「UI 根据文案猜计划/状态」）。
5. **homeState 派生优先级**（codingWorkspaceStore）：
   `sidecar-unavailable > loading > load-error > no-projects > no-workspace >
   provider-unconfigured > workspace-invalid > ready`；sidecar 探测（/health 可达性）
   先于一切，避免后端不可达时闪现「无项目」空态。provider-unconfigured =
   模型 profile 409 `coding_mode_disabled` **或**启用列表为空。
6. **抽屉模式自包含**：<1280px 由侧栏组件内 matchMedia 驱动（Teleport 覆盖层 +
   浮标 + 遮罩，监听器随卸载清理），App.vue 仅按 viewportWidth 传 `railHidden`；
   与 W0 §2.2 冻结的「240px（折叠 72px；<1280 抽屉）」一致。
7. **预览夹具动态 import**：`?coding-preview=<key>` 经 `import()` 加载
   `dev/codingHomePreview.ts`，生产构建不进入 chunk（比 workspace-preview 的静态
   import 更进一步）；六状态夹具直接实现 Fetchers，语义对齐 W0 矩阵第 1–6 项。
8. **敏感字段红线结构性保证**：`CodingProjectSummary` 等契约从类型上不含
   `root_path`；映射函数单测断言剔除，e2e 断言页面不出现路径原文。
