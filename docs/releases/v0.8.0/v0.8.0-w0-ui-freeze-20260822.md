## 1. 参考图 vs 现有 v2 工作台功能对照

现有 v2 工作台（`features/agent` + `App.vue` 编排，design-qa.md 已通过对照）与
v0.8.0 参考图的差距决定了 W1–W3 的改造范围：

| 维度 | 参考图（v0.8.0 目标） | 现有 v2 工作台 | 差距处置 |
|---|---|---|---|
| 左侧栏 | 一级动作（新建任务/搜索/自动化/扩展）+ **Project → Workspace/branch → Thread 树** + 底部用户/本地数据/设置/诊断 | NavRail 图标分组导航（日常/执行/工作/知识/连接/系统），无项目/分支/任务树 | W1 `CodingSidebar` 新建项目树（数据源：projects + workspaces + threads） |
| 首页 | 项目/workspace 选择 + 主任务输入 + 推荐任务 + 空态引导 | Today 视图 + chat 欢迎页（无项目维度首页） | W1 `CodingHome` 新建 |
| 主区 | 文档式会话流：用户请求 → 计划摘要 → 工具卡 → Diff 预览 → 命令输出 → 审批卡 → 完成/失败摘要 | RunTranscript 已有消息/工具卡/审批卡；Diff 只有工具卡文本，无结构化 Diff Artifact | W2/W3 `RunTranscript` 扩展 + `DiffArtifact`（消费 patch_set.* 事件与 Artifact kind） |
| 计划 | 右侧计划区（Step 列表 + 当前进度高亮） | 上下文栏计划片段（`buildAgentPlan()` 启发式） | W2 `RunPlanPopover` 接后端真实 plan（plan.created/item_changed durable 事件），**删除启发式计划**（计划 §7 W2 退出条件） |
| 输入器 | 多行 + `@` 上下文 + `/` 命令 + 权限/模型/推理强度 + 停止 | 单行升级多行已有；无 `@`/`/`、无权限/模型/推理选择 | W3 `CodingComposer`（权限三模式 + 模型 profile + reasoning_effort 均为 v0.7.0 冻结 API） |
| Inspector | Files/Context/Sources/Artifacts 可折叠抽屉 | ContextRail 已有 Files/Context/Artifacts 标签 | W3 `ContextDrawer` 改造（补 Sources） |
| 底部状态 | 本地数据状态 | 状态栏已有 | 沿用 |

**结论**：现有 v2 工作台的可复用资产为三栏骨架、design tokens、`pa-*` primitives、
Phosphor 图标、RunTranscript 消息模型；需要新建的是项目维度的信息层（侧栏树/首页）
与后端事实的消费层（真实计划/Diff Artifact/权限模型输入器）。

## 2. 冻结：信息架构、布局尺寸、排版与视觉方向

**本节冻结后不再变更一级导航和主布局**（W0 退出条件）。

### 2.1 信息架构（一级导航冻结）

```text
CodingWorkbench（v0.8.0 新壳，flag 内部启用）
├── CodingSidebar        项目 → Workspace/branch → Thread 树
│   ├── 一级动作：新建任务 / 搜索 / 自动化 / 扩展
│   └── 底部：用户与本地数据状态 / 设置 / 诊断 / 折叠
├── CodingHome           项目/workspace 选择 + 主输入器 + 推荐任务 + 空态引导
├── CodingThreadWorkspace 任务页
│   ├── ThreadHeader     标题 / branch / HEAD / dirty / 运行状态
│   ├── RunTranscript    用户请求 → 计划 → 工具 → 审批 → Diff → 命令 → 摘要
│   ├── RunPlanPopover   后端真实计划浮层
│   ├── ContextDrawer    Files / Context / Sources / Artifacts
│   └── CodingComposer   多行 + @ 上下文 + / 命令 + 权限/模型/推理
└── 旧壳回退             ?ui=v1 / pa_ui_v2=0（短期保留，见 §5）
```

### 2.2 布局尺寸（冻结）

| 表面 | 冻结值 | 依据 |
|---|---|---|
| 左侧栏宽度 | 240px（折叠 72px；<1280px 抽屉模式） | 参考图比例 + design-qa 通过的 220–248px 区间 |
| 右侧 Inspector | 360px（<1320px 自动隐藏，可手动开合） | 沿用 v2 工作台已验证断点 |
| 主区 | 自适应，独立滚动；输入器常驻底部 | 参考图文档式主区 |
| 断点矩阵 | 1280×720 / 1440×900 / 1920×1080 + 125%/150% 缩放 | 计划 §7 W5 视觉矩阵（基线见 §4） |
| 密度 | 14px 表面间距、12–14px 正文、1px 细边框、克制阴影 | 参考图 + 现有 tokens |

### 2.3 排版与视觉方向（冻结）

- 延续 v0.7.0 design-qa 通过的方向：低饱和中性层级 + 深青导航 + 冷白主区 +
  青色强调；权限/审批/风险一律警告色语义；无装饰渐变、无玻璃拟态。
- 全部使用现有 design tokens、`pa-*` primitives、Phosphor Icons；不引入新图标库、
  不复制参考图品牌/模型名称/装饰资产。
- 工具活动默认摘要折叠，展开才见完整 payload；长列表窗口化，命令输出与 Diff 按需加载。

## 5. 旧页面保留与次级入口策略（冻结）

1. **旧壳短期保留**：`?ui=v1` / `pa_ui_v2=0` 回退入口不删除（计划 §3.2/§9）；
   新 UI 失败时可回旧壳查看相同 session/run 事实。
2. **v0.8.0 新壳 flag 内部启用**：不切正式默认；CodingWorkbench 入口经内部
   flag 开启，旧业务页面（自动化/知识/记忆/备份等）全部保留原入口不动。
3. **次级入口策略**：新建任务不经过独立项目页（W1 退出条件）；项目/诊断/设置
   从侧栏底部进入；扩展/自动化入口在侧栏一级动作区，指向既有页面。
4. **不建立永久 `ui_v3`**：新代码只落在 `features/coding/`，不新增版本开关。

## 7. 早期工程任务登记（源自 v0.7.0 冻结前非阻断项）

以下两项为 v0.7.0 验收/冻结过程记录的非阻断问题，登记为 v0.8.0 **早期任务**
（不阻塞 W0–W1，须在 `0.8.0-beta.1` 前关闭；同步记入开发计划 §7）：

| 编号 | 任务 | 来源与现状 | 验收标准 |
|---|---|---|---|
| **E-1** | 重新校准 50ms E2E 性能预算基线 | v0.7.0 K1（`performance-resource.spec.ts:205`「页面切换无 50ms 级长任务」自 0.4.0 起临界；多轮门禁 p95 实测 51–73ms 围绕预算抖动，本机重负载环境漂移非回归；v0.7.0 生产运行时零变化） | 在真实桌面负载（动态壁纸/IDE/浏览器并存）下采集 ≥3 轮基线，按分布（如 p95 + 环境系数）重定预算并回归该用例；不允许以放宽预算掩盖真实回归——需附改动前后分布对照 |
| **E-2** | 修正取消测试 tasklist 输出的 UTF-8 解码缺陷 | `tests/test_agent_process_cancellation.py:24` `_tasklist_has_pid` 使用 `subprocess.run(text=True)` 未显式 encoding：本机（Python 3.13 + UTF-8 语义）reader 线程对 tasklist 的本地码页输出抛 UnicodeDecodeError → `stdout=None` → TypeError 被 `except Exception` 吞掉 → **恒返回 False（假阴性）**，「取消后子进程仍然存活」断言在本机形同虚设 | 改为字节级匹配（PID 与 CSV 引号均为 ASCII，`capture_output=True` 后在 bytes 中找 `b"\"<pid>\""`）或显式 `encoding="utf-8", errors="replace"`；修复后用「故意不杀进程」的反向用例证明 helper 能返回 True |

> E-2 说明：该缺陷不影响 v0.7.0 冻结结论（进程树清理另有 Job Object 证据链
> `processes_remaining==0` 与 v070 全套 148 用例），但使该文件的存活断言失去
> 独立证据价值，须在 0.8.0 早期恢复。
