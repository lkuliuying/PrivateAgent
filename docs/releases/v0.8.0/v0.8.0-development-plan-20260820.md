## 1. 版本结论

`v0.8.0` 将 `v0.6.0` 和 `v0.7.0` 已冻结的 Coding 契约实现为新的桌面工作台。该版本只消费公开 DTO 和事件，不重写 Runtime、审批或执行器。

版本完成后：

1. 应用首页以项目和任务输入为核心。
2. 左侧栏按 Project → Workspace/branch → Thread 组织。
3. 任务页统一展示用户消息、Agent 结果、工具、审批、Diff、命令和 Artifact。
4. 右侧计划浮层展示后端真实计划。
5. 底部输入器支持项目、上下文、权限、模型和推理强度。
6. 断线、切换、停止和恢复不会产生旧状态覆盖。
7. 旧 UI 保留短期回退，但新代码不建立永久 `ui_v3`。
8. 今日页只保留当日概览、最近活动、加长搜索和上下文信息；移除 Agent 对话框，提醒以紧凑区块放在上下文中心下方，其余个人工作模块继续使用左侧栏独立入口。
9. Agent 执行页按时间顺序展示公开决策摘要、计划步骤、工具调用、实际命令、流式输出、审批、验证与最终结果。
10. Agent 页采用参考图的信息密度与工作台结构：左侧会话记录，右侧为当前会话工作区，底部固定输入器。
11. Agent 输入器显示当前模型、模型配置入口和命令权限模式；选择必须绑定真实公开契约，不得用前端标签伪造权限。
12. 每轮用户消息形成独立的“用户请求 → 公开思考摘要 → 命令/工具轨迹 → 最终回答”分组，最终回答可一键复制。
13. Agent 页顶部显示当前授权工作目录和 Git 分支；无项目、非 Git 目录、分支游离或读取失败时显示真实降级状态，不沿用上一任务的旧值。
14. Agent 页移除顶部模型/上下文按钮和独立“执行计划”大卡片；计划事实仍进入逐轮公开过程，项目上下文由 Runtime 自动选择、压缩和续接。
15. Agent 会话栏收起后完全退出布局和键盘顺序，不保留空白窄栏；主应用左侧的最近任务改为紧接“Agent 执行”入口展示。
16. Agent 输入器底部以“模型/Provider 配置入口 + 权限下拉 + 上下文用量”组成主控制区；移除“知识检索”和“生成记忆”手动按钮，短期摘要与长期记忆候选改为自动生成。
17. 每轮均展示真实公开的分析/决策摘要和本轮命令/工具记录；无命令时明确显示“本轮未执行命令”，不得伪造动作或暴露隐藏推理。

## 2. 设计原则

- 吸收参考 UI 的信息架构、密度和文档式主区，不复制品牌、模型名称或装饰资产。
- 继续使用现有 design tokens、`pa-*` primitives 和 Phosphor Icons。
- 颜色以低饱和中性层级为主；权限、审批和风险使用警告色。
- 减少整页卡片堆叠，工具活动默认摘要折叠。
- 主区可以独立完成任务；Inspector/Context 不是关键操作的唯一入口。
- 不展示模型隐藏推理；用户所需“思考过程”定义为可公开的决策摘要、判断依据、下一步和风险说明，并与公开计划、动作、验证和结果一起展示。
- 所有长任务、流、轮询和监听器在切换 thread 或卸载时清理。

## 4. 目标信息架构

### 4.1 左侧栏

一级动作：

- 新建任务
- 搜索
- 自动化
- 扩展

Agent 执行区：

```text
Agent 执行
  最近任务 1（标题、状态、更新时间）
  最近任务 2
  …
  查看全部
```

- 主页面左侧原有“最近任务”独立区整体迁移到“Agent 执行”入口正下方，并在 DOM、视觉和键盘顺序上与该入口连续。
- 最近任务继续使用原任务数据源、未读/运行/失败状态、排序、打开和恢复逻辑；迁移后删除旧位置的重复渲染，不复制任务数据。
- “最近任务”是跨项目的 Agent 执行任务入口，不等同于 Agent 页内部的 `ConversationList`；选择后进入对应任务/会话，二者通过稳定 id 关联。
- 侧栏折叠时不挤出文字列表，可通过“Agent 执行”的展开层或导航抽屉访问；窄窗口下不得形成第二个永久侧栏。

个人工作区：

- 提醒
- 收件箱
- 长期目标
- 主动简报
- 快速捕获
- 隐私与维护

六个入口打开各自独立主区；可显示待处理数量或异常徽标，但不得把完整模块重新塞回今日页。侧栏折叠时保留可辨识图标、tooltip 和键盘可达名称，窄窗口时进入同一导航抽屉。

项目区：

```text
项目
  项目 A
    main
      任务 1
      任务 2
    feature/x
      任务 3
  项目 B
    main
```

底部：

- 用户与本地数据状态
- 设置
- 诊断
- 折叠侧栏

### 4.2 首页状态

必须覆盖：

- 无项目。
- 有项目但无 workspace。
- Provider 未配置。
- sidecar 未就绪。
- 项目路径缺失或权限失效。
- 正常空任务。
- 最近任务和推荐模板。

布局约束：

- 今日页彻底移除 Agent 对话/快速输入区；发起对话统一进入 Agent 页面，避免两个输入入口产生能力和草稿分叉。
- 顶部搜索入口使用头部剩余空间，桌面宽屏目标宽度为 `360–560px`，可随窗口收缩；保留 `Ctrl/Cmd+K` 提示、键盘焦点和全局搜索/命令入口语义。
- 上下文中心保持右侧紧凑信息栏；其下新增提醒摘要区，显示最近或即将到期的有限条目、到期数量和“查看全部/新建提醒”入口。
- 上下文中心下方的提醒是摘要而非完整 `ReminderPanel`：不在今日页内展开重复提醒表单、长列表或完整编辑流程，点击后进入左侧栏提醒独立页面。
- 今日页可保留只读数字、到期提示或快捷链接；点击后切换到左侧栏对应独立页面，不在当前页展开长面板。
- 迁移仅改变信息架构和路由归属，原有创建、编辑、转换、删除、刷新和错误处理能力必须保真。

### 4.3 任务页状态

必须覆盖：

- 用户请求已提交。
- 正在准备上下文。
- 正在生成计划。
- 正在执行工具。
- 等待审批。
- PatchSet 预览。
- 命令运行和流式输出。
- 验证中。
- 完成、失败、取消、超时和 limit exceeded。
- SSE 断开和恢复。
- sidecar 重启后重新水合。
- workspace 冲突和 Git HEAD 漂移。

执行详情必须在主时间线中可追溯：

- 每一步显示时间、状态、对应计划项和公开的决策摘要/执行依据。
- 工具调用显示工具名、脱敏后的参数、结果摘要、失败原因和重试信息。
- 命令执行显示脱敏后的实际命令、工作目录范围、stdout/stderr 流、退出码、耗时和测试摘要；长输出可以折叠、分段和截断，但不能只显示“已执行”。
- 审批前后、停止、恢复、断线重连和 sidecar 重启不得丢失已经公开的过程记录。
- 不存在公开决策摘要时，只显示真实计划、动作和验证事实，不由前端猜测或生成模型隐藏思维链。

### 4.4 Agent 页面信息架构（第二轮试用反馈基线）

> 本节记录 W6-R2 已实现基线。第三轮反馈以 §4.5 为最终目标；其中顶部模型/上下文入口、独立执行计划卡、会话栏收起行为和输入器控制位置如有冲突，均以 §4.5 为准。逐轮归属、公开过程、命令脱敏和回答复制继续保留。

桌面宽屏采用两区工作台：

```text
Agent
├── ConversationList（左，240–280px）
│   ├── 新建对话
│   ├── 会话搜索/筛选
│   └── 最近会话（标题、更新时间、运行/未读状态）
└── AgentWorkspace（右，minmax(0, 1fr)）
    ├── SessionHeader（标题、当前模型、运行状态、工作区/上下文入口）
    ├── TurnTranscript（逐轮请求、公开过程、命令、回答）
    └── AgentComposer（输入、模型、配置、权限、发送/停止）
```

布局与视觉约束：

- 参考图只作为信息架构、密度、留白、细边框和文档式对话主区的视觉依据，不复制 Codex 品牌、菜单、文案或装饰资产。
- 左侧会话记录独立滚动，选中态清楚；新消息、重命名或删除后不重置右侧工作区的滚动和草稿。
- 右侧工作区占据主要宽度，回答正文使用约 `760–920px` 的可读宽度并居中；工具/命令详情可比正文更宽，但不得形成页面级横向滚动。
- 输入器固定在工作区底部；主时间线独立滚动，输入器高度变化不遮挡最后一条消息。
- `1280px` 以下会话栏可折叠，窄窗口改为抽屉；键盘可以进入会话列表、切换会话、回到输入器。
- 原 Context/Files/Sources/Artifacts 能力保留为按需抽屉或工作区入口，不作为永久第三列挤压对话主区。

逐轮内容结构：

- 每条用户消息创建稳定 turn 分组；同一轮的计划、公开思考摘要、工具/命令、审批、验证和最终回答都归入该分组。
- “思考过程”只显示 Agent 主动输出的公开决策摘要、当前目标、判断依据、下一步和风险提示；不得显示或推断隐藏 chain-of-thought。
- 思考摘要下按发生顺序列出本轮运行的命令和工具，至少包含状态、脱敏命令/参数、开始结束时间、退出码和可展开结果。
- 最终回答与过程区视觉分层；完成后显示“复制回答”按钮，复制该轮完整最终回答正文，保留换行与代码块，不混入按钮文案或隐藏 DOM。

### 4.5 Agent 页面最终信息架构（第三轮试用反馈）

```text
AgentWorkspace
├── AgentHeader
│   ├── 会话标题 / 运行状态
│   ├── 当前授权工作目录
│   └── Git 分支 / detached / 非 Git 状态
├── ConversationList（可展开；收起后完全隐藏）
└── ConversationSurface
    ├── TurnTranscript
    │   └── Turn
    │       ├── 用户请求
    │       ├── 公开分析/决策摘要
    │       ├── 命令与工具轨迹（无命令时显示真实空态）
    │       └── 最终回答 / 复制回答
    └── AgentComposer（固定底部）
        ├── 输入区 / 附件
        └── 权限下拉 / 上下文用量 / 模型与 Provider 配置 / 执行或停止
```

顶部与工作区：

- 标题区紧邻会话标题显示当前授权工作目录和 Git 分支，数据来自当前 workspace/session 的公开事实；切换任务、项目或 workspace 时原子更新，加载期间不得短暂显示上一会话路径。
- 工作目录支持长路径截断与 tooltip/复制；Git 状态至少区分正常分支、detached HEAD、非 Git 目录、目录不可用和读取失败。不得为了显示分支在组件中直接执行 Git 命令。
- 删除右上角独立模型 chip 和“上下文”按钮；模型配置下沉到底部模型/Provider 入口，上下文改为 Runtime 自动装配、压缩并由底部用量模块反馈。
- 删除 transcript 顶部独立“执行计划”大卡片，释放首屏空间。后端 plan、step 和验证事实不删除，按所属 turn 投影成公开阶段/事件，必要时在过程区内折叠查看。
- 会话栏展开时维持独立滚动；点击收起后宽度、边框、占位和可聚焦子项全部消失，主区立即占满可用空间。再次打开沿用显式按钮；窄窗口使用覆盖式抽屉，关闭后焦点回到触发按钮。

逐轮执行可见性：

- 每次用户发送都创建稳定 turn，并在该请求之后依次显示公开分析/决策摘要、实际工具/命令事件和最终回答；不得把过程集中到会话顶部或串入下一轮。
- 公开摘要应尽量说明当前目标、采用的方法、关键判断、执行进度、验证结果和受阻原因；只使用 Runtime 主动提供的公开 summary/plan/event，不读取、存储或推断隐藏 chain-of-thought。
- 命令轨迹显示脱敏命令、授权工作目录范围、状态、开始/结束时间、退出码、stdout/stderr 摘要和可展开详情；未运行命令或工具时显示明确空态，不能省略整个过程区造成“没有记录”的歧义。
- 独立执行计划卡移除后，等待审批、失败、重试、取消、恢复、上下文压缩和验证仍必须在所属 turn 中可追溯。

输入器控制与自动化：

- 输入器左下原“知识检索”位置改为“命令权限”下拉框，提供“总是询问、替我批准、完全访问”三档；真实语义、能力门禁和 run 快照继续遵守 §6.7 的权限表。
- 删除输入器中的“知识检索”和“生成记忆”两个手动按钮及其快捷键、tooltip、焦点位和空占位。移除按钮不等于删除 RAG/记忆能力：知识检索按项目/session 策略自动触发，短期摘要随上下文压缩自动维护，长期记忆自动生成候选。
- 长期记忆候选的自动持久化遵守现有隐私级别、敏感内容过滤、远程 Provider 边界和用户设置；需要确认的类别继续进入候选确认流，不得因去掉按钮而静默写入敏感长期记忆。
- 底部“PrivateAgent · 本地/远程”模型入口显示当前模型或 profile 与运行位置；点击进入现有模型/Provider 配置界面，返回后刷新真实配置。配置未完成、模型不可用或远程 Provider 关闭时给出明确状态。
- 在执行按钮前增加上下文用量模块，显示本轮当前窗口的 `used / limit` 与百分比，并提供正常、接近阈值、已自动压缩和数据不可用状态；数值必须来自公开 usage/capability，不由前端按字符数估算冒充 token 用量。
- 到达阈值时由 Runtime 自动压缩项目/会话上下文，压缩成功后更新用量并在当前 turn 留下公开事件；压缩失败必须可见且可重试，不得静默丢弃用户消息、项目约束或未完成任务状态。

- 组件不得拼 URL、直接 fetch 或直接 invoke。
- 不在单一提交中机械移动所有 API/types。

## 9. 回退

- `v0.8.0` 内部开发完成版仍保留短期旧 UI 入口。
- UI flag 只改变 renderer，不改变后端执行和数据。
- 新 UI 失败时可回旧壳查看相同 session/run 事实。
- 不为回退删除 Artifact、Plan 或 ProjectWorkspace 数据。
- 旧 UI 不理解的新数据应安全忽略。

## 10. 零容忍问题

- UI 根据文案猜计划、审批或完成状态。
- thread 切换后旧 token/事件写入新任务。
- 停止后流继续修改当前消息。
- 关键审批只能在 Inspector 中操作。
- 本地路径、完整命令或敏感正文进入 toast。
- 1280/150% 下无法完成主链。
- 重复切换导致 SSE、定时器或监听器泄漏。
- 新 UI 开启时仍调用旧 planner。
- 前端根据状态或文案猜测、补写 Agent 的“思考过程”。
- 命令、输出、路径或环境变量未经脱敏直接展示凭据和敏感信息。
- 模型或权限选择只改变界面文案，实际请求仍静默使用其他模型/模式。
- 把 `workspace` 权限伪装成不受限制的“完全访问”，或在 capability 不支持时仍允许选择。
- turn 切换或会话切换后，把上一轮的思考、命令或最终回答归入当前轮。
- 复制回答时混入隐藏 DOM、工具输出、敏感字段或其他轮内容。
- 主侧栏旧位置和“Agent 执行”下方同时渲染两份最近任务，或点击最近任务打开错误 execution/session。
- 切换项目/session 后仍显示上一任务的工作目录、Git 分支、上下文用量、模型或权限快照。
- 会话栏视觉收起但仍占宽度、拦截点击、保留 Tab 焦点或被读屏读取。
- 顶部模型/上下文控件、独立执行计划卡、知识检索按钮或生成记忆按钮仍以隐藏 DOM、快捷键或空白占位残留。
- 删除独立计划卡后丢失 plan/step/approval/verification 事实，或任一用户 turn 缺少真实公开过程与命令空态。
- 前端用字符数、消息数或常量伪造上下文 token 用量、百分比、压缩完成或记忆生成成功。
- 自动压缩静默丢失项目约束、未完成步骤或最新消息，或压缩失败没有可见状态和恢复路径。
- 自动检索/记忆跨会话串写、重复生成，或绕过敏感内容、远程 Provider、长期记忆确认和隐私设置。

8. 今日页六个工作台模块已迁入左侧栏独立入口，今日主区不再因这些模块形成超长页面。
9. Agent 执行页可追溯公开决策摘要、工具、脱敏命令、输出、审批、验证和终态，且不暴露隐藏推理。
10. 今日页已移除 Agent 对话框，搜索入口加长，提醒摘要位于上下文中心下方且不重复完整管理页。
11. Agent 页完成左会话/右工作区重构，模型配置和权限选择绑定真实能力与请求快照。
12. 每个 turn 均可追溯真实公开过程和命令，最终回答可完整、准确、安全地复制。

16. Agent 底部已完成权限下拉、模型/Provider 配置入口和上下文用量模块重排；知识检索和生成记忆手动按钮已删除。
17. 项目上下文自动装配与压缩、自动知识检索、短期摘要和长期记忆候选使用真实公开契约，并通过隐私、隔离、失败恢复和反向测试。
18. W6-R3 的组件、E2E、视觉/a11y、资源、生产构建和安装版覆盖安装门禁重新通过，执行记录与安装包哈希已回填。

W6-R3 已完成前端布局、状态与安装包门禁；第 16–17 项在 `v0.8.0` 的完成口径仅包括“消费真实能力或诚实显示不可用”，不代表后端已经提供“替我批准”“完全访问”、准确上下文用量、自动压缩或自动记忆。上述真实能力不得在 `v0.8.0` 发布说明中宣称可用，统一按 §12 的第四轮反馈移交 `v0.9.0`。

### 12.1 第四轮试用反馈移交（2026-08-22）

本轮不再重开 `v0.8.0` RC。以下内容作为 `v0.8.0` 已知缺口冻结，并由 `v0.9.0` 开发计划完整承接：

| 反馈项 | v0.8.0 当前状态 | v0.9.0 目标 |
|---|---|---|
| 新建项目与新建对话拆分 | 尚未形成独立产品动作 | “新建任务”改为“新建项目”；项目创建时选择/授权工作目录；新建对话必须绑定项目/workspace |
| 未指定项目的对话 | 当前可出现未关联项目状态 | 使用“当前用户目录”作为显式默认项目候选，但不自动扩大 trusted path 或写入权限 |
| 工作目录与 Git 分支 | W6-R3 仅消费已有 workspace facts | 工作目录在项目创建时冻结；Git 分支由后端固定 Git 检查从该目录实时读取，非 Git/detached/失效状态明确 |
| 会话时间 | 当前显示受运行环境/数据影响 | 数据库存 UTC 时刻作为事实源，产品时区固定 `Asia/Shanghai`，API 序列化带时区，列表统一按上海时间显示 |
| 输入器模型控件 | 仍可能同时显示模型 chip 与 Agent profile | 删除独立 `test-model/未配置` 模块；当前模型与 Provider 信息合并到 `PrivateAgent` 入口 |
| 上下文用量 | UI 可显示“上下文用量不可用” | 接入真实 token 窗口、保留输出预算、百分比和压缩状态；改为 `PrivateAgent` 旁的小圆环，hover/focus 展示详情 |
| 替我批准 | UI 标签存在，真实后端能力缺失或不完整 | 实现 workspace 内安全操作自动批准、高风险/越界继续询问或拒绝，并形成审计与 run 快照 |
| 完全访问 | 明确禁用，不用 `workspace` 冒充 | 新增独立 capability、逐会话显式授权、有效期/撤销/审计和硬安全边界；不等于管理员提权 |
| 开始执行后的详情 | W6-R3 已有逐轮事实，但空态到执行态边界仍不完整 | 点击“执行”后进入具体 execution 视图，完整呈现公开决策链、计划、工具、命令、审批、输出、验证和最终回答 |

“模型的全思路链路”在交接中定义为**可公开执行链**，不包括模型隐藏 chain-of-thought。`v0.9.0` 必须通过结构化公开摘要、计划/步骤、证据、工具与命令事件达到可理解、可审计的效果，不读取、保存或展示隐藏推理。
