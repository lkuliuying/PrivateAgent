# PrivateAgent v0.8.0 开发计划书

> 制定日期：2026-08-20
> 实施基线：`v0.7.0` 内部开发完成版
> 版本主题：Coding Workbench
> 内部交付目标：`0.8.0-alpha.1 → 0.8.0-alpha.2 → 0.8.0-beta.1 → 0.8.0-rc.1 → 0.8.0`
> 观察策略：本版本只执行即时门禁；唯一自然日观察顺延至 `v1.0.0-rc.1`
> 策略依据：[观察期顺延决策](../observation-policy-20260820.md)
> 前置计划：[v0.7.0 开发计划](../v0.7.0/v0.7.0-development-plan-20260820.md)

## 1. 版本结论

`v0.8.0` 将 `v0.6.0` 和 `v0.7.0` 已冻结的 Coding 契约实现为新的桌面工作台。该版本只消费公开 DTO 和事件，不重写 Runtime、审批或执行器。

版本完成后：

1. 应用首页以项目和任务输入为核心。
2. 左侧栏按 Project → Workspace/branch → Thread 组织。
3. 任务页统一展示用户消息、Agent 结果、工具、审批、Diff、命令和 Artifact。
4. 右侧计划浮层展示后端真实计划。
5. 底部输入器支持项目、上下文、权限、模型和推理强度。
6. 断线、切换、停止和恢复不会产生旧状态覆盖。
7. 旧 UI 保留短期回退，但新代码不建立永久 `ui_v3`。

## 2. 设计原则

- 吸收参考 UI 的信息架构、密度和文档式主区，不复制品牌、模型名称或装饰资产。
- 继续使用现有 design tokens、`pa-*` primitives 和 Phosphor Icons。
- 颜色以低饱和中性层级为主；权限、审批和风险使用警告色。
- 减少整页卡片堆叠，工具活动默认摘要折叠。
- 主区可以独立完成任务；Inspector/Context 不是关键操作的唯一入口。
- 不展示模型隐藏推理，只展示公开计划、动作、验证和结果。
- 所有长任务、流、轮询和监听器在切换 thread 或卸载时清理。

## 3. 版本范围

### 3.1 必须交付

| 领域 | v0.8.0 交付 |
|---|---|
| 应用壳 | Coding 主导航、返回/前进、项目/任务侧栏、状态栏 |
| 首页 | 项目/workspace 选择、主输入器、推荐任务、未配置引导 |
| 任务页 | ThreadHeader、RunTranscript、真实计划、工具/审批/Artifact |
| 输入器 | `@` 上下文、`/` 命令、权限、模型、推理、停止/继续 |
| Context | Files、Context、Sources、Artifacts 可折叠抽屉 |
| 前端状态 | run projector、SSE composable、thread store、恢复与竞态处理 |
| 工程收敛 | 拆分 `api.ts`/`types.ts`、收敛 `App.vue`、组件化 coding feature |
| 质量 | UI Lab/fixture、视觉、a11y、性能、资源清理、安装版验证 |

### 3.2 明确不做

- 自动 Git worktree 创建。
- 新 UI 默认对所有用户开启。
- 删除旧壳、旧 planner 或旧业务页面。
- 自动化和插件市场全面重做。
- 深色主题正式交付。
- 完整终端、编辑器或 IDE 布局。
- 修改后端安全契约来迁就 UI。

## 4. 目标信息架构

### 4.1 左侧栏

一级动作：

- 新建任务
- 搜索
- 自动化
- 扩展

项目区：

```text
项目
  项目 A
    main
      任务 1
      任务 2
    feature/x
      任务 3
  项目 B
    main
```

底部：

- 用户与本地数据状态
- 设置
- 诊断
- 折叠侧栏

### 4.2 首页状态

必须覆盖：

- 无项目。
- 有项目但无 workspace。
- Provider 未配置。
- sidecar 未就绪。
- 项目路径缺失或权限失效。
- 正常空任务。
- 最近任务和推荐模板。

### 4.3 任务页状态

必须覆盖：

- 用户请求已提交。
- 正在准备上下文。
- 正在生成计划。
- 正在执行工具。
- 等待审批。
- PatchSet 预览。
- 命令运行和流式输出。
- 验证中。
- 完成、失败、取消、超时和 limit exceeded。
- SSE 断开和恢复。
- sidecar 重启后重新水合。
- workspace 冲突和 Git HEAD 漂移。

## 5. 前端架构

### 5.1 目录

```text
apps/desktop/src/features/coding/
├── api/
│   ├── projects.ts
│   ├── threads.ts
│   ├── runs.ts
│   └── modelProfiles.ts
├── model/
│   ├── contracts.ts
│   ├── runProjector.ts
│   └── codingWorkspaceStore.ts
├── composables/
│   ├── useRunStream.ts
│   ├── useThreadSelection.ts
│   └── useComposer.ts
└── components/
    ├── CodingHome.vue
    ├── CodingSidebar.vue
    ├── CodingThreadWorkspace.vue
    ├── ThreadHeader.vue
    ├── RunTranscript.vue
    ├── RunPlanPopover.vue
    ├── ToolEventCard.vue
    ├── DiffArtifact.vue
    └── CodingComposer.vue
```

### 5.2 App.vue

最终仅保留：

- boot/config/sidecar 状态。
- 当前 view/thread 选择。
- AppShell 挂载。
- 全局快捷键。
- Toast、Confirm、Notification、CommandPalette、GlobalSearch。

迁出：

- planner 判定。
- 消息和 token 拼接。
- 审批后续跑。
- run 事件解析。
- 项目和活动轮询。
- tool result 二次提交。

### 5.3 Run Projector

- 以 `(run_id, sequence)` 幂等消费 durable event。
- 临时 token delta 不改变 durable cursor。
- 重连后用 run snapshot 修正临时文本。
- thread 切换时终止旧流并拒绝迟到回调。
- 按 id 更新 plan/tool/artifact，不整页重置。
- 后端未知事件记录诊断并安全忽略，不推测含义。

### 5.4 API 和类型

- 新 Coding API 只放在领域模块。
- `api.ts` 保留兼容 re-export，调用方迁完后再删除对应段。
- `types.ts` 保留旧类型，新契约进入 `features/coding/model/contracts.ts` 或共享 contracts。
- 组件不得拼 URL、直接 fetch 或直接 invoke。
- 不在单一提交中机械移动所有 API/types。

## 6. 核心组件

### 6.1 CodingSidebar

功能：

- 项目/workspace/thread 树。
- 当前运行、等待审批、失败和未读状态。
- 项目授权、刷新、折叠、搜索和归档入口。
- 最近任务和更新时间。
- 侧栏宽度、折叠和窄窗口抽屉模式。

### 6.2 CodingHome

功能：

- 项目/workspace 选择。
- 主任务输入。
- 权限、模型、推理强度。
- 推荐任务模板。
- `@` 和 `/` 发现提示。
- 空态和配置错误引导。

### 6.3 CodingThreadWorkspace

组成：

- ThreadHeader。
- RunTranscript。
- RunPlanPopover。
- ContextDrawer。
- CodingComposer。
- 恢复、错误和重试 notice。

### 6.4 RunTranscript

支持：

- 用户请求。
- Agent Markdown 结果。
- 工具摘要与展开详情。
- 审批卡。
- Diff Artifact。
- 命令输出和测试报告。
- 错误、取消、恢复和完成摘要。

长列表采用窗口化或分段渲染；命令输出和 Diff 按需加载。

### 6.5 CodingComposer

支持：

- 多行输入、Enter/Shift+Enter。
- `@文件`、`@目录` 和已选上下文 chip。
- `/命令` 和命令面板。
- 权限模式、模型和推理强度。
- 发送、停止、继续和等待审批禁用态。
- 草稿按 thread 保存，不跨项目串线。

## 9. 回退

- `v0.8.0` 内部开发完成版仍保留短期旧 UI 入口。
- UI flag 只改变 renderer，不改变后端执行和数据。
- 新 UI 失败时可回旧壳查看相同 session/run 事实。
- 不为回退删除 Artifact、Plan 或 ProjectWorkspace 数据。
- 旧 UI 不理解的新数据应安全忽略。

## 10. 零容忍问题

- UI 根据文案猜计划、审批或完成状态。
- thread 切换后旧 token/事件写入新任务。
- 停止后流继续修改当前消息。
- 关键审批只能在 Inspector 中操作。
- 本地路径、完整命令或敏感正文进入 toast。
- 1280/150% 下无法完成主链。
- 重复切换导致 SSE、定时器或监听器泄漏。
- 新 UI 开启时仍调用旧 planner。

## 11. 完成定义

`v0.8.0` 完成必须满足：

1. 新工作台完整覆盖 Coding 主链。
2. 参考 UI 的项目侧栏、首页和任务页信息架构落地。
3. 计划、工具、审批、验证和 Artifact 均来自公开事实。
4. App.vue、API、types 和 coding components 责任清晰。
5. 空态、错误、离线、窄窗口、长文本和键盘路径完整。
6. 视觉、a11y、性能、资源和安装版门禁通过。
7. `0.8.0-rc.1` 即时完整门禁通过，无 P0/P1。
