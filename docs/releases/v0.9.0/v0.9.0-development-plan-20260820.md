## 1. 版本结论

`v0.9.0` 将新 Coding Agent 从可选工作台切换为产品默认路径，并集中处理恢复、故障、真实项目兼容、可选 Git worktree 和旧链归零。

本版本不追求横向增加大量页面，而是补齐 `v0.8.0` 试用中暴露的基础契约并证明：

1. 新用户首启即可完成项目授权和首个 Coding 任务。
2. 旧用户升级后会话、项目、设置和数据完整。
3. 新 UI、project-bound run 和可信工具默认启用且可精确回退。
4. 长任务、崩溃、断线、冲突和未知副作用可恢复或人工处置。
5. 旧 planner 和旧 UI 的调用可观测并达到 `v1.0.0` 默认隔离与最终观察门槛。
6. 可选 worktree 不破坏原仓库，并保持模型无自由 Git 管理权限。
7. “新建项目”和“新建对话”成为两个清晰动作；项目拥有工作目录，对话必须绑定项目/workspace，执行属于对话中的 run。
8. 工作目录在项目创建时选择和授权，Git 分支由该目录的真实仓库信息获取；会话列表统一按 `Asia/Shanghai` 产品时区显示。
9. “替我批准”“完全访问”与上下文用量不再是占位标签，而是有后端 capability、真实运行语义、审计和失败状态的完整能力。
10. Agent 输入器移除重复模型模块，上下文用量改为 `PrivateAgent` 旁的圆环；点击执行后进入可审计的执行详情，展示公开决策链和真实命令。
11. 对“检查本机是否安装 MySQL”等可执行请求，能力就绪时必须创建真实 run、经过权限判定并调用工具/命令；不得只返回手工操作教程。能力未就绪时必须明确阻塞原因和恢复入口，不得伪装成任务已完成。
12. 当前安装版中“替我批准”“完全访问”和上下文用量的不可用状态必须在 v0.9.0 内修复；控件可见、可选择但不改变 Runtime，或长期只显示“不可用”，均不算交付。
13. 已配置全局 Ollama/远程 Provider 的用户不得因为缺少独立 Coding model profile 被困在无效的“前往设置”循环；设置页必须能创建、验证、选择和恢复 profile，升级安装必须提供幂等导入路径。

### 2.2 明确不做

- 物理删除旧数据库表和个人助手领域数据。
- 任意 Git 命令或模型自动 push。
- 自动创建 PR 或发布。
- 多 Agent、云同步和团队协作。
- 插件市场和自动化系统重做。
- macOS/Linux 正式发布。
- 在 RC 阶段增加新工具或改变公开契约。
- 展示、记录或导出模型隐藏 chain-of-thought；本版本交付的是结构化公开决策摘要和执行证据链。
- 把“当前用户目录”默认值解释为自动授权整个用户目录，或把“完全访问”解释为管理员提权、绕过操作系统权限或取消凭据/远程外发硬边界。

## 3. 默认值策略

### 3.1 新安装

- 默认显示 Coding Home。
- 没有项目时提供“新建项目”和“新建对话”两个独立动作；新建项目先选择并授权工作目录。
- 新建对话必须绑定一个项目/workspace；用户未选择时预选固定的“当前用户目录”默认项目候选，但首次使用前仍需确认授权范围，不自动扩大 trusted path。
- 默认权限为 `confirm`，不是 `workspace`。
- 优先推荐本地、支持原生工具调用的模型 profile。
- 高风险 PatchSet/命令 flag 只有在版本发布门禁通过后才默认可用。
- 自动化、MCP 和远程数据外发保持默认关闭。

### 3.2 升级安装

- 保留原有 session、项目、Provider、知识库和设置。
- 已有项目幂等补建 root workspace。
- 旧 session 保持 legacy kind，用户可从“更多工作区”访问。
- 不自动把旧聊天绑定到最近项目。
- 旧的未绑定会话继续以 legacy/unbound 状态显示；只有用户显式选择项目后才迁移绑定，不批量绑定到当前用户目录。
- 时间迁移只补齐时区语义，不改写消息先后：历史 UTC/naive 数据经一次性规则规范化，列表显示统一转换为 `Asia/Shanghai`。
- 不自动扩大旧 trusted path 或命令 profile。

### 3.3 回退

- 保留短期 `PA_CODING_AGENT_UI_ENABLED=false` 回退。
- 关闭 project-bound run 后旧兼容聊天仍可使用。
- 回退不删除新 plan、Artifact 或 workspace 数据。
- RC 候选验证期间每次回退必须记录低基数原因和结果。

## 4. Git Worktree

### 4.1 范围

Worktree 是可选能力，默认仍使用项目根 workspace。

用户可以在新任务时选择：

- 当前 workspace。
- 新建隔离 worktree。

### 4.2 创建

创建前显示：

- 原项目。
- base branch/ref 和 HEAD。
- 新分支名。
- worktree 绝对路径。
- 磁盘占用和清理策略。

应用服务使用固定 Git argv，不经过模型和 shell。建议默认分支前缀 `agent/`，实际命名可配置并进行冲突校验。

### 4.3 生命周期

状态：

- creating
- active
- dirty
- conflict
- missing
- cleanup_pending
- archived

规则：

- 任务归档不自动删除 dirty worktree。
- 删除前检查未提交变更、未追踪文件和占用进程。
- 清理必须确认影响范围，并提供失败后的手工命令说明。
- 模型不能调用 worktree create/remove 工具。

## 5. 项目、对话与 Agent 能力

### 5.1 产品对象与创建流程

统一术语与归属：

```text
Project（项目）
└── Workspace（工作目录；根目录或可选 worktree）
    └── Conversation（对话）
        └── Run / Execution（一次执行）
            └── Turn / Tool / Command / Approval / Artifact
```

- 原“新建任务”产品动作更名为“新建项目”；任务不再作为与项目平级的容器，一次具体任务由对话中的 user turn/run 表达。
- “新建项目”负责选择并授权工作目录、建立 project/root workspace、读取 Git facts 和设置默认权限/profile；创建失败不得留下半绑定项目。
- “新建对话”与“新建项目”分开：可从 Agent 会话栏直接新建，也可在项目内新建；任何新对话都必须具有非空 `project_id` 和 `workspace_id`。
- 用户未显式选择项目时，界面预选内置“当前用户目录”项目候选。该默认值只解决归属和起始目录，不自动授权整个用户目录写入或命令执行；首次副作用仍遵守 `confirm` 和 trusted-path 建立流程。
- 对话创建后不允许因切换侧栏选择而静默改变工作目录；需要更换目录时创建/选择另一个 workspace，并把新的 run 快照绑定到稳定 id。
- 现有 legacy/unbound 会话保留可读和导出能力；用户显式选择项目后才迁移，不按最近项目或用户目录批量猜测绑定。

工作目录与 Git：

- 工作目录在项目创建或 workspace 创建时确定并持久化，必须是规范化、存在且经过授权的目录；重解析点、UNC、长路径和路径失效有明确状态。
- Git 分支、HEAD、dirty、仓库根和 detached 状态由后端固定 argv Git service 从当前工作目录读取，组件不执行 shell、不从标题字符串推断。
- 非 Git 目录是合法项目，显示“非 Git 项目”；Git 仓库嵌套、目录移出仓库或外部切换分支时刷新真实 facts，并用 generation/cursor 防止旧响应覆盖新项目。

### 5.2 会话时间与 `Asia/Shanghai`

- 产品时区固定为 IANA `Asia/Shanghai`；会话列表、消息时间、执行事件和“最近任务”统一按该时区格式化，24 小时制显示。
- 数据库继续保存 timezone-aware UTC instant 作为唯一排序事实，避免把无时区本地时间写入数据库；API 使用带 `Z`/offset 的 RFC 3339，客户端转换为 `Asia/Shanghai`。这满足“按上海时间存取和显示”的产品语义，同时保证升级、排序和跨环境一致。
- 会话 `created_at/updated_at/last_activity_at` 的写入、SSE 事件时间、离线重水合和旧数据 backfill 使用同一时间服务；禁止组件分别调用本机 locale 形成不一致时间。
- 验收覆盖 UTC 跨日、上海零点、夏令时库输入（上海无 DST 但仍使用 IANA 规则）、系统时区非上海、离线重连和旧 naive 时间迁移。

### 5.3 三档命令权限真实契约

| UI 模式 | Runtime 语义 | 强制边界 |
|---|---|---|
| 总是询问 `confirm` | 写文件、应用补丁或执行命令前逐次请求审批 | 只读动作仍受项目授权和敏感数据策略限制；审批展示影响范围 |
| 替我批准 `workspace` | 当前项目/workspace 内、命中安全 command/tool profile 的操作自动批准 | 越界、未知、高风险、远程外发、凭据访问和破坏性动作继续询问或拒绝 |
| 完全访问 `full_access` | 在当前 OS 用户本来可访问的本机范围内，允许 Runtime 对常规文件和命令免逐次审批 | 不获得管理员权限；不绕过 OS/UAC；凭据、秘密、远程外发和系统级破坏动作仍有硬阻断/独立确认 |

- `/capabilities` 必须分别声明 `workspace_auto_approve`、`full_access`、审计和撤销支持；UI 只有在后端真实支持且配置完整时启用对应选项。
- `workspace` 与 `full_access` 不能互相别名。每个 run 持久化 permission snapshot，执行器再次校验；前端选择、请求载荷、审批事件和审计记录必须一致。
- `full_access` 默认关闭，只能由用户在当前会话/项目显式二次确认后启用；显示范围、持续时间和风险，支持立即撤销，并在切换项目、退出应用或到期时自动失效。
- 全部免审批动作仍记录工具、脱敏参数、命令、工作目录、时间、退出码和结果；后台不能因为自动批准而跳过审计、取消和 emergency stop。
- capability 缺失、版本不匹配、审计不可写或撤销通道异常时失败关闭，降级为 `confirm`，不得静默继续使用更高权限。

### 5.4 上下文用量与自动压缩

- Runtime/ModelGateway 公开 typed context budget：`used_tokens`、`max_context_tokens`、`reserved_output_tokens`、`usage_percent`、`source`、`compaction_state`、`last_compacted_at` 和错误状态。
- 用量来自 provider usage、受验证 tokenizer 或 Runtime 统一计数，不按字符数/消息数伪造。无法准确计量的 profile 显示“不可用”和原因，不显示虚假百分比。
- 输入器删除矩形“上下文用量不可用”模块，改为 `PrivateAgent` 状态旁的紧凑圆环；圆环以颜色/进度表示用量，hover 和键盘 focus 弹层显示具体 used/limit、百分比、保留输出预算、压缩阈值和最近压缩结果。
- 圆环必须有文本替代、`aria-label` 和非颜色状态；窄窗口/150% 缩放不遮挡模型入口或执行按钮。
- 达到阈值时自动生成短期摘要并压缩旧上下文，保留最新用户请求、系统/项目约束、未完成计划、审批和关键工具事实；压缩前后记录可公开事件。
- 压缩失败、tokenizer 不可用或预算仍超限时停止新执行并给出恢复路径，不静默截断；摘要、长期记忆候选和自动检索继续遵守隐私、来源、去重和会话隔离策略。

### 5.5 Agent 输入器与执行详情

- 删除独立 `test-model · 未配置` 模块及其状态、空占位、快捷键和重复配置入口；当前模型/profile/本地或远程属性统一收敛到可点击的 `PrivateAgent` 入口。
- 输入器保留附件、权限下拉、`PrivateAgent`、上下文圆环和“执行/停止”；模型未配置时点击 `PrivateAgent · 未配置` 进入现有 Provider 配置，执行按钮保持禁用并说明原因。
- 新对话空态允许输入目标；点击“执行”后创建稳定 run 并进入具体 execution 视图。创建失败留在草稿态，不能生成空 run 或丢失输入。
- execution 视图按 turn 展示“用户目标 → 公开决策摘要 → 计划/当前步骤 → 工具与命令 → 审批 → 输出/验证 → 最终回答”，支持停止、恢复、断线重水合、复制回答和定位 Artifact。
- 用户所称“模型的全思路链路”实现为结构化、可公开、可审计的决策与执行链：目标、方法、关键判断、依据、下一步、风险和验证；不得读取、持久化或展示隐藏 chain-of-thought。
- 每条实际命令显示脱敏命令文本、工作目录、状态、开始/结束时间、stdout/stderr 摘要、退出码、耗时和重试；无命令的 turn 明确显示“本轮未执行命令”。

### 5.6 实机试用纠偏：可执行请求不得退化为纯问答

当前安装版把“看一下本机是否装了 MySQL”回答成用户自行操作教程，且没有创建 run、权限请求、工具调用或命令事件。这属于 Agent 主链未接通，不能以已有输入框、状态标签或“本轮未执行命令”的展示判定 5.5 已完成。

- 提交后先区分信息问答与可执行意图。包含“检查本机”“查看项目”“运行测试”“修改文件”等动作，且项目/workspace、Provider、Runtime 和所需 capability 均就绪时，必须进入 durable Agent Runtime；不得静默切回普通聊天模型。
- 以 Windows 的 MySQL 检查为首个固定验收样例：通过安全诊断 profile 依次检查可执行文件、客户端版本、服务端可执行文件和可查询的服务事实，例如固定 argv 的 `where.exe mysql`、`mysql --version`、`where.exe mysqld` 及 typed service probe。模型不能拼接任意 shell，也不能把单个 PATH 未命中直接等同于“未安装”。
- `confirm` 模式在执行前展示命令、工作目录和影响并等待批准；`workspace/full_access` 按 5.3 的真实契约处理。拒绝、超时、命令缺失、PATH 未配置、服务存在但客户端缺失、退出码异常和 Runtime 失败必须形成不同的结构化结果。
- execution 视图实时展示“用户目标 → 公开决策摘要 → 检查计划 → 权限判定/审批 → 实际工具或命令 → 输出与退出码 → 证据化结论”。这里的“思考过程”是面向用户的决策摘要和执行依据，不是模型隐藏 chain-of-thought。
- 没有成功取得足够证据时不得断言“已安装/未安装”；结论必须注明证据、未完成检查和下一步。没有工具/命令事件的可执行 turn 不得显示“已完成”或“已记录”。
- 模型未配置、Provider 不可达、Runtime/工具能力关闭、项目/workspace 未绑定或权限能力不可用时，原位显示具体阻塞项和“配置 PrivateAgent/选择项目/重试”操作；只有用户明确选择“仅回答方法”时才允许退回教程式回答。
- 删除输入器中独立的 `PrivateAgent · test-model · 未配置` 模块，包括隐藏 DOM、旧状态、快捷键和占位间距。执行按钮左侧仅保留一个 `PrivateAgent · 未配置/已配置` 状态按钮，作为模型与 Provider 的唯一配置入口。
- `PrivateAgent` 状态必须可点击、可键盘聚焦并有可读标签；点击进入现有 Provider 配置，保留当前会话和输入草稿，返回 Agent 后重新拉取 capability/profile 状态。未配置时执行按钮禁用并紧邻说明原因，配置成功后无需新建会话即可执行。

### 5.7 实机试用纠偏：权限模式与上下文用量必须真实可用

本节把用户所称“替我审批”“完全放行”分别映射到现有产品契约“替我批准 `workspace`”“完全访问 `full_access`”，不新增含义重复的第四、第五种模式。当前安装版中三项能力不可用是发布阻断缺陷，不能以置灰控件、静态标签或前端模拟值关闭问题。

- Agent 页面加载时必须从 Runtime `/capabilities` 获取权限与上下文能力，并展示 `loading/available/unavailable/error` 的真实状态、原因、版本和恢复操作；前端不得根据模型名称猜测支持情况。
- “替我批准”必须真正写入会话权限选择，并在创建 run 时形成不可变的 `workspace` permission snapshot。项目授权范围内、命中安全 profile 的操作自动批准；越界、未知、高风险、凭据和远程外发仍询问或拒绝，并产生完整审计。
- “完全访问”必须使用独立 `full_access` capability 和执行路径。首次开启进行二次确认，明确有效范围、持续时间和硬边界；支持立即撤销、切换项目/退出/到期自动失效。它只继承当前 OS 用户已有权限，不等于管理员提权或取消安全边界。
- 权限选择不可用时必须在下拉项旁说明具体原因，例如 Runtime 版本不支持、审计通道不可写、项目未授权或 Provider/sidecar 未连接，并提供“配置/更新 Runtime/重新授权/重试”入口；禁止点击后无响应或静默回到 `confirm`。
- 上下文圆环必须接入当前会话和当前模型 profile 的真实 token budget，并随用户消息、模型输出、工具结果和压缩事件更新。默认支持的本地 profile 在正常配置下不得长期显示“上下文用量不可用”。
- token 用量优先采用 Provider 返回值，其次使用经模型 profile 校验的 tokenizer；两者都不可用时才显示“不可用”，同时给出缺失字段、受影响能力和修复入口。不得用字符数、消息数或固定百分比伪造。
- 圆环详情至少显示已用/上限、百分比、预留输出预算、压缩阈值、数据来源、最近更新时间和压缩状态；切换模型、项目或会话后先清空旧值，再加载新快照，不能闪现上一会话数据。
- 三项状态与 `PrivateAgent` 配置入口联动：配置完成或 Runtime 重连后原位重新探测，无需新建对话或重启应用；配置往返继续保留草稿、权限选择和当前会话。
- 安装版验收必须用真实 sidecar、真实 Provider/profile 和真实 run，证明 `workspace` 自动批准、`full_access` 独立放行/撤销以及 token 用量随 turn 变化；只通过前端 mock、截图或组件测试不能关闭此缺陷。

### 5.8 实机试用纠偏：Provider 与 Coding model profile 配置闭环

当前安装版已经保存 `PA_OLLAMA_BASE_URL` 和 `PA_LLM_MODEL`，但 Coding 首页仍显示“模型 Provider 未配置”。代码链表明首页实际依赖 `/agent-model-profiles?enabled_only=true`：设置页只维护全局 Provider，前端只有 profile 查询，没有创建/更新调用；后端虽有 `PUT /agent-model-profiles/{id}`，升级 reconcile 也未导入旧配置。因此“前往设置”会进入无法完成修复的循环，属于发布阻断缺陷，而不是用户项目损坏或简单的 Ollama 未启动。

- 明确区分两层事实：全局 Provider 负责连接地址、凭据和默认模型；Coding model profile 负责具体模型标识、是否本地、原生工具调用、流式输出、结构化输出、视觉、上下文窗口、usage 来源和启用状态。两层必须有可追溯映射，不能只靠相同的显示名称猜测。
- 为 `model_profiles` 增加稳定的具体模型路由字段（至少 `model_name/model_id`；如需多 endpoint，再使用非秘密的 Provider 配置引用），并以 additive migration 回填既有 profile。Provider secret 继续留在系统凭据边界，不写入 profile、前端状态、日志或诊断包。
- Runtime 创建 run 时必须按选中的 profile 解析具体 provider + model，不得忽略 profile 后回落到全局 `llm_model/openai_model/claude_model`；profile 被删除、禁用、模型变化或 Provider 失联时失败关闭并返回精确阻塞原因。
- 在设置页增加“Agent/Coding 模型”管理区：列出 profile，支持从当前 Ollama/OpenAI/Claude 配置新建或导入、编辑能力声明、验证连接与模型存在性、设为默认、启用/停用和删除。所有写操作通过 typed API/service，组件不得直接拼 URL 或操作数据库。
- 配置流程必须验证 Provider 可达、模型存在和原生工具调用能力。工具能力不得仅按模型名称推断；使用受限 probe 或用户明确确认形成可审计的 capability 事实。不支持工具调用的模型可保留为只读问答 profile，但不能作为 Coding 默认项。
- 升级安装发现“全局 Provider 已配置且没有 Coding profile”时执行幂等迁移：若只有一个本地 Ollama 模型且受限 probe 通过，可自动创建稳定 ID 的默认 profile；存在歧义、远程外发、凭据缺失或 probe 不通过时显示一次性导入向导，不得静默扩大远程数据使用范围。
- 新安装在连接向导保存 Provider 后直接进入 profile 创建/验证步骤；保存成功后重新拉取 `/agent-model-profiles`、`/capabilities` 和 context budget，在原页面解除阻塞，不要求用户新建项目、重启应用或重复输入配置。
- `PrivateAgent` 唯一配置入口和 Coding 首页“前往设置”必须定位到同一个 profile 管理区，并带上 `returnTo`。往返保留当前项目、会话、草稿、权限选择和滚动位置；成功后自动返回，失败则原位显示原因与重试。
- 将笼统的“模型 Provider 未配置”拆分为 `feature_disabled/profile_missing/provider_unreachable/model_missing/tools_unsupported/credentials_missing/probe_failed/profile_disabled` 等可操作状态；仅 `profile_missing` 使用“创建 Coding 模型”，不能把所有故障都引导到同一个设置首页。
- 禁止把手工改 MySQL、直接插入 `model_profiles`、要求用户自行调用隐藏 API 或编辑 `%APPDATA%` `.env` 作为正式解决方案；这些只能用于诊断，安装版必须完成 UI/API/迁移闭环。

## 6. 恢复与未知状态

### 6.1 Run 恢复

启动时：

1. 获取 owner lock。
2. reconcile orphaned run。
3. 恢复 waiting_approval checkpoint。
4. 对幂等已提交 execution 回放结果。
5. 对非幂等或 partial_unknown execution 停止并要求人工处置。
6. 重新建立 UI projector 和事件 cursor。

### 6.2 人工处置

UI 必须明确区分：

- 确认未执行，可安全重试。
- 已执行且结果已验证，可继续。
- 执行结果未知，不可自动重试。
- PatchSet 部分状态，需要查看 Git Diff/文件状态。
- 命令可能留下进程或外部副作用。

人工操作包括：

- 标记已完成并继续。
- 标记失败并结束。
- 重新验证文件/Git 状态。
- 查看诊断与恢复说明。

模型不能替用户处理 unknown 副作用。

## 7. 兼容归零与隔离准备

需要观测：

- legacy `/tools/plan` 调用。
- 旧 tool-call approve/reject。
- 旧 UI 启动和回退原因。
- 无 project/workspace 的新 run 创建。
- Runtime disabled fallback。
- 不支持原生工具模型的 fallback。

最终观察与隔离门槛：

1. 新桌面消息进入旧 planner 为 0。
2. 升级前 pending tool call 已耗尽或可归档。
3. 旧 UI 只因显式回退进入，不因默认或异常自动进入。
4. 即时门禁和真实项目测试中无不可解释 legacy 调用；连续自然日归零由 v1.0 最终观察确认。
5. `v1.0.0` 已有升级和支持说明。

## 11. 零容忍问题

- 新安装默认授予 workspace 自动写或更高权限。
- 升级后旧数据丢失或隐式绑定错误项目。
- worktree 操作破坏原仓库或删除 dirty 目录。
- unknown execution 自动重试。
- 旧 planner 与新 Runtime 对同一请求并行执行。
- 取消/退出后残留进程。
- telemetry 泄露代码、路径或命令正文。
- 新对话没有项目/workspace，或被静默绑定到最近项目、错误目录或未确认的整个用户目录授权。
- Git 分支由前端文本推断、切换项目后显示旧分支，或为了读取分支让模型执行自由 Git 命令。
- 会话时间受操作系统本地时区漂移、UTC/上海时间混排，或迁移后改变历史消息先后。
- “替我批准”只改变 UI 标签，真实执行仍逐次询问/无审计，或越界和高风险动作被自动放行。
- 用 `workspace` 冒充 `full_access`，完全访问没有显式确认/撤销/到期，或借此绕过 OS 权限、凭据和远程外发边界。
- 上下文圆环显示字符数伪造的百分比、负数/超过 100%、上一会话旧值，或压缩静默丢失最新请求和未完成计划。
- 删除模型模块后无法进入 Provider 配置，或同一模型/profile 在多个控件显示互相冲突的状态。
- 点击执行后仍停留在无详情空态，命令/审批/验证不可追溯，或以“全思路链路”为名记录/展示隐藏 chain-of-thought。
- 项目、模型和 Runtime 已就绪时，可执行请求只返回“请自行打开终端”等教程，没有创建真实 run 或工具/命令事件。
- 没有执行证据却显示“已完成/已记录”，把 PATH 未命中直接判定为软件未安装，或将命令失败伪装成成功结论。
- 阻塞项被静默隐藏、普通聊天回答冒充 Agent 执行结果，或 `PrivateAgent` 状态不可点击、配置往返丢失当前草稿。
- “替我批准”或“完全访问”可见但不可选择、点击无响应、选择后不改变 run 权限，或两者映射到同一个后端模式。
- “完全访问”没有二次确认、独立 capability、撤销或到期机制，或者“替我批准”越过项目授权和安全 profile 自动放行。
- 默认支持的模型正常配置后上下文用量仍长期不可用，状态不随 turn 更新，切换会话沿用旧值，或缺少原因与恢复入口。
- 已有可用 Provider/模型却因 profile 为空被困在“前往设置”循环，或者设置页无法创建、验证和选择 Coding profile。
- profile 显示一个模型但 Runtime 实际使用全局旧模型，按名称猜测工具能力，或把 Provider secret 写入 profile/API/日志。
- 升级导入重复创建 profile、静默启用远程外发，或要求用户手工修改数据库、隐藏 API、配置文件才能进入项目。
