# PrivateAgent v0.9.0 开发计划书

> 制定日期：2026-08-20
> 实施基线：`v0.8.0` 内部开发完成版
> 版本主题：Coding Agent 默认切换与可靠性
> 内部交付目标：`0.9.0-alpha.1 → 0.9.0-beta.1 → 0.9.0-beta.2 → 0.9.0-rc.1 → 0.9.0`
> 观察策略：本版本只执行即时门禁；真实自然日观察顺延至 `v1.0.0-rc.1`
> 策略依据：[观察期顺延决策](../observation-policy-20260820.md)
> 前置计划：[v0.8.0 开发计划](../v0.8.0/v0.8.0-development-plan-20260820.md)

## 1. 版本结论

`v0.9.0` 将新 Coding Agent 从可选工作台切换为产品默认路径，并集中处理恢复、故障、真实项目兼容、可选 Git worktree 和旧链归零。

本版本不追求新增大量功能，而是证明：

1. 新用户首启即可完成项目授权和首个 Coding 任务。
2. 旧用户升级后会话、项目、设置和数据完整。
3. 新 UI、project-bound run 和可信工具默认启用且可精确回退。
4. 长任务、崩溃、断线、冲突和未知副作用可恢复或人工处置。
5. 旧 planner 和旧 UI 的调用可观测并达到 `v1.0.0` 默认隔离与最终观察门槛。
6. 可选 worktree 不破坏原仓库，并保持模型无自由 Git 管理权限。

## 2. 版本范围

### 2.1 必须交付

| 领域 | v0.9.0 交付 |
|---|---|
| 默认切换 | Coding UI、project-bound run、真实计划和可信工具默认值 |
| 首启/升级 | 项目授权、Provider、权限、命令 profile 引导与旧数据兼容 |
| 可靠性 | crash/restart、断线、审批恢复、unknown execution、长任务验证 |
| Worktree | 可选、显式创建和清理的隔离 workspace |
| 搜索与管理 | 项目/线程搜索、归档、重命名、置顶和最近任务 |
| 兼容治理 | 旧 planner/UI telemetry、弃用提示、隔离门槛和回退开关 |
| 性能与安全 | 大项目、长 transcript、输出洪泛、路径/Git/进程故障注入 |

### 2.2 明确不做

- 物理删除旧数据库表和个人助手领域数据。
- 任意 Git 命令或模型自动 push。
- 自动创建 PR 或发布。
- 多 Agent、云同步和团队协作。
- 插件市场和自动化系统重做。
- macOS/Linux 正式发布。
- 在 RC 阶段增加新工具或改变公开契约。

## 3. 默认值策略

### 3.1 新安装

- 默认显示 Coding Home。
- 没有项目时引导授权目录。
- 默认权限为 `confirm`，不是 `workspace`。
- 优先推荐本地、支持原生工具调用的模型 profile。
- 高风险 PatchSet/命令 flag 只有在版本发布门禁通过后才默认可用。
- 自动化、MCP 和远程数据外发保持默认关闭。

### 3.2 升级安装

- 保留原有 session、项目、Provider、知识库和设置。
- 已有项目幂等补建 root workspace。
- 旧 session 保持 legacy kind，用户可从“更多工作区”访问。
- 不自动把旧聊天绑定到最近项目。
- 不自动扩大旧 trusted path 或命令 profile。

### 3.3 回退

- 保留短期 `PA_CODING_AGENT_UI_ENABLED=false` 回退。
- 关闭 project-bound run 后旧兼容聊天仍可使用。
- 回退不删除新 plan、Artifact 或 workspace 数据。
- RC 候选验证期间每次回退必须记录低基数原因和结果。

## 4. Git Worktree

### 4.1 范围

Worktree 是可选能力，默认仍使用项目根 workspace。

用户可以在新任务时选择：

- 当前 workspace。
- 新建隔离 worktree。

### 4.2 创建

创建前显示：

- 原项目。
- base branch/ref 和 HEAD。
- 新分支名。
- worktree 绝对路径。
- 磁盘占用和清理策略。

应用服务使用固定 Git argv，不经过模型和 shell。建议默认分支前缀 `agent/`，实际命名可配置并进行冲突校验。

### 4.3 生命周期

状态：

- creating
- active
- dirty
- conflict
- missing
- cleanup_pending
- archived

规则：

- 任务归档不自动删除 dirty worktree。
- 删除前检查未提交变更、未追踪文件和占用进程。
- 清理必须确认影响范围，并提供失败后的手工命令说明。
- 模型不能调用 worktree create/remove 工具。

## 5. 恢复与未知状态

### 5.1 Run 恢复

启动时：

1. 获取 owner lock。
2. reconcile orphaned run。
3. 恢复 waiting_approval checkpoint。
4. 对幂等已提交 execution 回放结果。
5. 对非幂等或 partial_unknown execution 停止并要求人工处置。
6. 重新建立 UI projector 和事件 cursor。

### 5.2 人工处置

UI 必须明确区分：

- 确认未执行，可安全重试。
- 已执行且结果已验证，可继续。
- 执行结果未知，不可自动重试。
- PatchSet 部分状态，需要查看 Git Diff/文件状态。
- 命令可能留下进程或外部副作用。

人工操作包括：

- 标记已完成并继续。
- 标记失败并结束。
- 重新验证文件/Git 状态。
- 查看诊断与恢复说明。

模型不能替用户处理 unknown 副作用。

## 6. 兼容归零与隔离准备

需要观测：

- legacy `/tools/plan` 调用。
- 旧 tool-call approve/reject。
- 旧 UI 启动和回退原因。
- 无 project/workspace 的新 run 创建。
- Runtime disabled fallback。
- 不支持原生工具模型的 fallback。

最终观察与隔离门槛：

1. 新桌面消息进入旧 planner 为 0。
2. 升级前 pending tool call 已耗尽或可归档。
3. 旧 UI 只因显式回退进入，不因默认或异常自动进入。
4. 即时门禁和真实项目测试中无不可解释 legacy 调用；连续自然日归零由 v1.0 最终观察确认。
5. `v1.0.0` 已有升级和支持说明。

## 7. 里程碑

### H0 · 默认值与升级契约（1–2 天）

任务：

1. 冻结新安装和升级用户默认矩阵。
2. 定义 UI、Runtime、工具和 Provider flag 组合。
3. 更新 capabilities、诊断和 telemetry。
4. 建立旧数据升级 fixture。
5. 定义 `v1.0.0` 默认隔离和最终观察门槛。

退出条件：

- 默认值不隐式扩大权限。
- 所有回退原因可解释。

### H1 · 新 UI 默认与首启流程（2–3 天）

任务：

1. 新 UI 默认开启。
2. 优化项目授权、Provider 和权限首启引导。
3. 迁移旧项目为 root workspace。
4. 将旧工作区放入“更多工作区”。
5. 保留显式旧 UI 回退。

退出条件：

- 新用户可在首次启动完成首个任务。
- 旧用户升级不丢失入口或数据。

### `0.9.0-alpha.1`

H0–H1 完成后：

- 新安装/升级 E2E、默认 flag 和旧数据 fixture 通过。
- 内部 Alpha 不更新稳定 updater。

### H2 · 恢复、人工处置与故障注入（2–3 天）

任务：

1. 完善 crash/restart 和 projector 重水合。
2. 实现 unknown execution 人工处置 UI/API。
3. 覆盖 sidecar 强杀、DB 中断、SSE 中断和 Provider 中断。
4. 覆盖 PatchSet partial、HEAD 漂移和命令残留。
5. 增加恢复时间和错误率 telemetry。

退出条件：

- 无无法取消、无法解释且永久运行的 run。
- unknown 副作用不自动重试。

### H3 · 可选 Worktree（2–3 天）

任务：

1. 实现固定 Git argv 的 worktree service。
2. 实现创建/列表/状态/归档/清理 API。
3. 接入新任务 workspace 选择和 ThreadHeader。
4. 覆盖 dirty、冲突、缺失路径和占用失败。
5. 完成 Windows 路径长度和重解析点测试。

退出条件：

- 原项目不会因 worktree 失败被修改。
- dirty worktree 不会被自动删除。

### `0.9.0-beta.1`

H2–H3 完成后：

- 恢复/unknown/worktree 契约和安装版 smoke 通过。
- 真实项目样本覆盖 Python、Vue/Node 和 Rust。

### H4 · 搜索、管理与旧工作区整合（1–2 天）

任务：

1. 项目、workspace 和 thread 全局搜索。
2. Thread 归档、重命名、置顶和最近任务。
3. 旧业务工作区放入次级入口。
4. 补齐旧 session 与新 thread 的跳转和说明。
5. 大量项目/任务性能优化。

退出条件：

- 用户无需旧导航完成 Coding 主流程。
- 旧数据仍可找到和导出。

### H5 · 可靠性、安全与最终观察准备（2–3 天）

任务：

1. 长 run、长 transcript、大 Diff 和输出洪泛压力。
2. 路径、Git、审批、权限和远程 Provider 故障注入。
3. 重复启动/退出、owner lock 和进程清理。
4. 兼容 telemetry、默认隔离清单和观察后删除候选清单。
5. 完成从 `v0.5.0-rc.4`/`v0.8.0` 内部完成版升级与应用回退。

退出条件：

- P0/P1 为 0。
- 旧调用和回退原因可被完整解释。

### `0.9.0-beta.2`

H4–H5 完成后：

- 功能冻结候选形成。
- 完整门禁、升级、回退、updater 和安装版 QA 通过。

### H6 · RC 硬化与开发完成检查点（1–2 天）

1. 冻结 `0.9.0-rc.1` 代码、安装包和证据。
2. 在 Python、Vue/Node、Rust 真实项目上执行一次完整即时场景矩阵。
3. 记录 legacy 调用、恢复、审批、失败率和进程残留。
4. 门禁通过后形成 `0.9.0` 内部开发完成版，不切公开 updater。
5. 输出 `v1.0.0` 契约冻结、兼容隔离和最终观察准入报告。

## 8. 测试与最终观察准备

本版本即时测试必须覆盖以下场景，并把同一矩阵交给 v1.0 最终自然日观察：

- 三类真实项目：Python、Vue/Node、Rust。
- 根 workspace 与 worktree。
- PatchSet create/update/delete/rename。
- 测试成功和失败。
- 用户拒绝、取消和审批过期。
- 一次 sidecar 强杀和恢复。
- 一次模型/数据库中断。
- 一次 Git HEAD 外部变化。
- 三次正常退出和一次异常退出。

记录聚合信息，不记录用户代码正文、完整路径、命令输出或隐藏推理。

## 9. 回退

- RC 候选期间保留新 UI、project-bound run、PatchSet、command 和 worktree 独立 flag。
- 回退到旧 UI 不改变后端 run 事实。
- 关闭 worktree 后现有 worktree 只读展示，不自动删除。
- 应用回退保留 schema，不执行破坏性 downgrade。
- `v1.0.0` 默认隔离旧链并开始最终观察前，必须验证这一回退策略。

## 10. 零容忍问题

- 新安装默认授予 workspace 自动写或更高权限。
- 升级后旧数据丢失或隐式绑定错误项目。
- worktree 操作破坏原仓库或删除 dirty 目录。
- unknown execution 自动重试。
- 旧 planner 与新 Runtime 对同一请求并行执行。
- 取消/退出后残留进程。
- telemetry 泄露代码、路径或命令正文。

## 11. 完成定义

`v0.9.0` 完成必须满足：

1. Coding Agent 成为新安装和升级后的默认主线。
2. 首启、项目授权、任务执行和恢复体验完整。
3. 可选 worktree 安全且不影响根 workspace。
4. 真实项目故障注入和安装版门禁通过。
5. 旧 planner/UI 调用达到 `v1.0.0` 默认隔离与最终观察门槛。
6. 旧业务数据仍可访问和导出。
7. `0.9.0-rc.1` 即时完整门禁通过且无 P0/P1。

## 12. 向 v1.0.0 交接

- 兼容调用归零报告。
- 旧壳、旧 planner、旧审批和兼容 API 的默认隔离清单及观察后物理清理候选清单。
- 从 `v0.5.0-rc.4`、`v0.8.0`、`v0.9.0` 内部完成版的升级/回退证据。
- 真实项目即时测试报告与 v1.0 最终观察场景矩阵。
- 1.0 公开契约候选、已知限制和支持范围。
