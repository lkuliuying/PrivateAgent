> 制定日期：2026-08-20
> 实施基线：`v0.8.0` 内部开发完成版
> 版本主题：Coding Agent 默认切换与可靠性
> 内部交付目标：`0.9.0-alpha.1 → 0.9.0-beta.1 → 0.9.0-beta.2 → 0.9.0-rc.1 → 0.9.0`
> 观察策略：本版本只执行即时门禁；真实自然日观察顺延至 `v1.0.0-rc.1`
> 策略依据：[观察期顺延决策](../observation-policy-20260820.md)
> 前置计划：[v0.8.0 开发计划](../v0.8.0/v0.8.0-development-plan-20260820.md)
> 试用反馈承接：2026-08-22（项目/对话拆分、Asia/Shanghai 会话时间、Agent 输入器精简、执行详情入口，以及“替我批准/完全访问/上下文用量”真实能力）

## 1. 版本结论

`v0.9.0` 将新 Coding Agent 从可选工作台切换为产品默认路径，并集中处理恢复、故障、真实项目兼容、可选 Git worktree 和旧链归零。

本版本不追求横向增加大量页面，而是补齐 `v0.8.0` 试用中暴露的基础契约并证明：

1. 新用户首启即可完成项目授权和首个 Coding 任务。
2. 旧用户升级后会话、项目、设置和数据完整。
3. 新 UI、project-bound run 和可信工具默认启用且可精确回退。
4. 长任务、崩溃、断线、冲突和未知副作用可恢复或人工处置。
5. 旧 planner 和旧 UI 的调用可观测并达到 `v1.0.0` 默认隔离与最终观察门槛。
6. 可选 worktree 不破坏原仓库，并保持模型无自由 Git 管理权限。
7. “新建项目”和“新建对话”成为两个清晰动作；项目拥有工作目录，对话必须绑定项目/workspace，执行属于对话中的 run。
8. 工作目录在项目创建时选择和授权，Git 分支由该目录的真实仓库信息获取；会话列表统一按 `Asia/Shanghai` 产品时区显示。
9. “替我批准”“完全访问”与上下文用量不再是占位标签，而是有后端 capability、真实运行语义、审计和失败状态的完整能力。
10. Agent 输入器移除重复模型模块，上下文用量改为 `PrivateAgent` 旁的圆环；点击执行后进入可审计的执行详情，展示公开决策链和真实命令。

### 2.2 明确不做

- 物理删除旧数据库表和个人助手领域数据。
- 任意 Git 命令或模型自动 push。
- 自动创建 PR 或发布。
- 多 Agent、云同步和团队协作。
- 插件市场和自动化系统重做。
- macOS/Linux 正式发布。
- 在 RC 阶段增加新工具或改变公开契约。
- 展示、记录或导出模型隐藏 chain-of-thought；本版本交付的是结构化公开决策摘要和执行证据链。
- 把“当前用户目录”默认值解释为自动授权整个用户目录，或把“完全访问”解释为管理员提权、绕过操作系统权限或取消凭据/远程外发硬边界。

## 3. 默认值策略

### 3.1 新安装

- 默认显示 Coding Home。
- 没有项目时提供“新建项目”和“新建对话”两个独立动作；新建项目先选择并授权工作目录。
- 新建对话必须绑定一个项目/workspace；用户未选择时预选固定的“当前用户目录”默认项目候选，但首次使用前仍需确认授权范围，不自动扩大 trusted path。
- 默认权限为 `confirm`，不是 `workspace`。
- 优先推荐本地、支持原生工具调用的模型 profile。
- 高风险 PatchSet/命令 flag 只有在版本发布门禁通过后才默认可用。
- 自动化、MCP 和远程数据外发保持默认关闭。

### 3.2 升级安装

- 保留原有 session、项目、Provider、知识库和设置。
- 已有项目幂等补建 root workspace。
- 旧 session 保持 legacy kind，用户可从“更多工作区”访问。
- 不自动把旧聊天绑定到最近项目。
- 旧的未绑定会话继续以 legacy/unbound 状态显示；只有用户显式选择项目后才迁移绑定，不批量绑定到当前用户目录。
- 时间迁移只补齐时区语义，不改写消息先后：历史 UTC/naive 数据经一次性规则规范化，列表显示统一转换为 `Asia/Shanghai`。
- 不自动扩大旧 trusted path 或命令 profile。

### 3.3 回退

- 保留短期 `PA_CODING_AGENT_UI_ENABLED=false` 回退。
- 关闭 project-bound run 后旧兼容聊天仍可使用。
- 回退不删除新 plan、Artifact 或 workspace 数据。
- RC 候选验证期间每次回退必须记录低基数原因和结果。

## 4. Git Worktree

### 4.1 范围

Worktree 是可选能力，默认仍使用项目根 workspace。

用户可以在新任务时选择：

- 当前 workspace。
- 新建隔离 worktree。

### 4.2 创建

创建前显示：

- 原项目。
- base branch/ref 和 HEAD。
- 新分支名。
- worktree 绝对路径。
- 磁盘占用和清理策略。

应用服务使用固定 Git argv，不经过模型和 shell。建议默认分支前缀 `agent/`，实际命名可配置并进行冲突校验。

### 4.3 生命周期

状态：

- creating
- active
- dirty
- conflict
- missing
- cleanup_pending
- archived

规则：

- 任务归档不自动删除 dirty worktree。
- 删除前检查未提交变更、未追踪文件和占用进程。
- 清理必须确认影响范围，并提供失败后的手工命令说明。
- 模型不能调用 worktree create/remove 工具。

## 5. 项目、对话与 Agent 能力

### 5.1 产品对象与创建流程

统一术语与归属：

```text
Project（项目）
└── Workspace（工作目录；根目录或可选 worktree）
    └── Conversation（对话）
        └── Run / Execution（一次执行）
            └── Turn / Tool / Command / Approval / Artifact
```

- 原“新建任务”产品动作更名为“新建项目”；任务不再作为与项目平级的容器，一次具体任务由对话中的 user turn/run 表达。
- “新建项目”负责选择并授权工作目录、建立 project/root workspace、读取 Git facts 和设置默认权限/profile；创建失败不得留下半绑定项目。
- “新建对话”与“新建项目”分开：可从 Agent 会话栏直接新建，也可在项目内新建；任何新对话都必须具有非空 `project_id` 和 `workspace_id`。
- 用户未显式选择项目时，界面预选内置“当前用户目录”项目候选。该默认值只解决归属和起始目录，不自动授权整个用户目录写入或命令执行；首次副作用仍遵守 `confirm` 和 trusted-path 建立流程。
- 对话创建后不允许因切换侧栏选择而静默改变工作目录；需要更换目录时创建/选择另一个 workspace，并把新的 run 快照绑定到稳定 id。
- 现有 legacy/unbound 会话保留可读和导出能力；用户显式选择项目后才迁移，不按最近项目或用户目录批量猜测绑定。

工作目录与 Git：

- 工作目录在项目创建或 workspace 创建时确定并持久化，必须是规范化、存在且经过授权的目录；重解析点、UNC、长路径和路径失效有明确状态。
- Git 分支、HEAD、dirty、仓库根和 detached 状态由后端固定 argv Git service 从当前工作目录读取，组件不执行 shell、不从标题字符串推断。
- 非 Git 目录是合法项目，显示“非 Git 项目”；Git 仓库嵌套、目录移出仓库或外部切换分支时刷新真实 facts，并用 generation/cursor 防止旧响应覆盖新项目。

### 5.2 会话时间与 `Asia/Shanghai`

- 产品时区固定为 IANA `Asia/Shanghai`；会话列表、消息时间、执行事件和“最近任务”统一按该时区格式化，24 小时制显示。
- 数据库继续保存 timezone-aware UTC instant 作为唯一排序事实，避免把无时区本地时间写入数据库；API 使用带 `Z`/offset 的 RFC 3339，客户端转换为 `Asia/Shanghai`。这满足“按上海时间存取和显示”的产品语义，同时保证升级、排序和跨环境一致。
- 会话 `created_at/updated_at/last_activity_at` 的写入、SSE 事件时间、离线重水合和旧数据 backfill 使用同一时间服务；禁止组件分别调用本机 locale 形成不一致时间。
- 验收覆盖 UTC 跨日、上海零点、夏令时库输入（上海无 DST 但仍使用 IANA 规则）、系统时区非上海、离线重连和旧 naive 时间迁移。

### 5.3 三档命令权限真实契约

| UI 模式 | Runtime 语义 | 强制边界 |
|---|---|---|
| 总是询问 `confirm` | 写文件、应用补丁或执行命令前逐次请求审批 | 只读动作仍受项目授权和敏感数据策略限制；审批展示影响范围 |
| 替我批准 `workspace` | 当前项目/workspace 内、命中安全 command/tool profile 的操作自动批准 | 越界、未知、高风险、远程外发、凭据访问和破坏性动作继续询问或拒绝 |
| 完全访问 `full_access` | 在当前 OS 用户本来可访问的本机范围内，允许 Runtime 对常规文件和命令免逐次审批 | 不获得管理员权限；不绕过 OS/UAC；凭据、秘密、远程外发和系统级破坏动作仍有硬阻断/独立确认 |

- `/capabilities` 必须分别声明 `workspace_auto_approve`、`full_access`、审计和撤销支持；UI 只有在后端真实支持且配置完整时启用对应选项。
- `workspace` 与 `full_access` 不能互相别名。每个 run 持久化 permission snapshot，执行器再次校验；前端选择、请求载荷、审批事件和审计记录必须一致。
- `full_access` 默认关闭，只能由用户在当前会话/项目显式二次确认后启用；显示范围、持续时间和风险，支持立即撤销，并在切换项目、退出应用或到期时自动失效。
- 全部免审批动作仍记录工具、脱敏参数、命令、工作目录、时间、退出码和结果；后台不能因为自动批准而跳过审计、取消和 emergency stop。
- capability 缺失、版本不匹配、审计不可写或撤销通道异常时失败关闭，降级为 `confirm`，不得静默继续使用更高权限。

### 5.4 上下文用量与自动压缩

- Runtime/ModelGateway 公开 typed context budget：`used_tokens`、`max_context_tokens`、`reserved_output_tokens`、`usage_percent`、`source`、`compaction_state`、`last_compacted_at` 和错误状态。
- 用量来自 provider usage、受验证 tokenizer 或 Runtime 统一计数，不按字符数/消息数伪造。无法准确计量的 profile 显示“不可用”和原因，不显示虚假百分比。
- 输入器删除矩形“上下文用量不可用”模块，改为 `PrivateAgent` 状态旁的紧凑圆环；圆环以颜色/进度表示用量，hover 和键盘 focus 弹层显示具体 used/limit、百分比、保留输出预算、压缩阈值和最近压缩结果。
- 圆环必须有文本替代、`aria-label` 和非颜色状态；窄窗口/150% 缩放不遮挡模型入口或执行按钮。
- 达到阈值时自动生成短期摘要并压缩旧上下文，保留最新用户请求、系统/项目约束、未完成计划、审批和关键工具事实；压缩前后记录可公开事件。
- 压缩失败、tokenizer 不可用或预算仍超限时停止新执行并给出恢复路径，不静默截断；摘要、长期记忆候选和自动检索继续遵守隐私、来源、去重和会话隔离策略。

### 5.5 Agent 输入器与执行详情

- 删除独立 `test-model · 未配置` 模块及其状态、空占位、快捷键和重复配置入口；当前模型/profile/本地或远程属性统一收敛到可点击的 `PrivateAgent` 入口。
- 输入器保留附件、权限下拉、`PrivateAgent`、上下文圆环和“执行/停止”；模型未配置时点击 `PrivateAgent · 未配置` 进入现有 Provider 配置，执行按钮保持禁用并说明原因。
- 新对话空态允许输入目标；点击“执行”后创建稳定 run 并进入具体 execution 视图。创建失败留在草稿态，不能生成空 run 或丢失输入。
- execution 视图按 turn 展示“用户目标 → 公开决策摘要 → 计划/当前步骤 → 工具与命令 → 审批 → 输出/验证 → 最终回答”，支持停止、恢复、断线重水合、复制回答和定位 Artifact。
- 用户所称“模型的全思路链路”实现为结构化、可公开、可审计的决策与执行链：目标、方法、关键判断、依据、下一步、风险和验证；不得读取、持久化或展示隐藏 chain-of-thought。
- 每条实际命令显示脱敏命令文本、工作目录、状态、开始/结束时间、stdout/stderr 摘要、退出码、耗时和重试；无命令的 turn 明确显示“本轮未执行命令”。

## 6. 恢复与未知状态

### 5.1 Run 恢复

启动时：

1. 获取 owner lock。
2. reconcile orphaned run。
3. 恢复 waiting_approval checkpoint。
4. 对幂等已提交 execution 回放结果。
5. 对非幂等或 partial_unknown execution 停止并要求人工处置。
6. 重新建立 UI projector 和事件 cursor。

### 5.2 人工处置

UI 必须明确区分：

- 确认未执行，可安全重试。
- 已执行且结果已验证，可继续。
- 执行结果未知，不可自动重试。
- PatchSet 部分状态，需要查看 Git Diff/文件状态。
- 命令可能留下进程或外部副作用。

人工操作包括：

- 标记已完成并继续。
- 标记失败并结束。
- 重新验证文件/Git 状态。
- 查看诊断与恢复说明。

模型不能替用户处理 unknown 副作用。

## 7. 兼容归零与隔离准备

需要观测：

- legacy `/tools/plan` 调用。
- 旧 tool-call approve/reject。
- 旧 UI 启动和回退原因。
- 无 project/workspace 的新 run 创建。
- Runtime disabled fallback。
- 不支持原生工具模型的 fallback。

最终观察与隔离门槛：

1. 新桌面消息进入旧 planner 为 0。
2. 升级前 pending tool call 已耗尽或可归档。
3. 旧 UI 只因显式回退进入，不因默认或异常自动进入。
4. 即时门禁和真实项目测试中无不可解释 legacy 调用；连续自然日归零由 v1.0 最终观察确认。
5. `v1.0.0` 已有升级和支持说明。

## 8. 里程碑

### H0 · 默认值与升级契约（1–2 天）

任务：

1. 冻结新安装和升级用户默认矩阵。
2. 定义 UI、Runtime、工具和 Provider flag 组合。
3. 更新 capabilities、诊断和 telemetry。
4. 建立旧数据升级 fixture。
5. 定义 `v1.0.0` 默认隔离和最终观察门槛。
6. 冻结 Project → Workspace → Conversation → Run 身份、外键、默认用户目录候选和 legacy/unbound 迁移契约。
7. 冻结 `Asia/Shanghai` 产品时区、UTC 事实存储和旧 naive 时间 backfill 规则。
8. 冻结 `confirm/workspace/full_access`、context budget/compaction 与公开执行链 DTO/event/capability。

退出条件：

- 默认值不隐式扩大权限。
- 所有回退原因可解释。
- 项目/会话不存在空归属或猜测绑定；权限与上下文 UI 不依赖占位常量。

### H1 · 新 UI 默认与首启流程（2–3 天）

任务：

1. 新 UI 默认开启。
2. 优化项目授权、Provider 和权限首启引导。
3. 迁移旧项目为 root workspace。
4. 将旧工作区放入“更多工作区”。
5. 保留显式旧 UI 回退。
6. 将“新建任务”改为“新建项目”，并与“新建对话”分开；完成目录选择/授权、默认用户目录候选和对话项目绑定。
7. Agent 输入器删除重复模型模块，接入统一 `PrivateAgent` 配置入口、权限下拉和上下文圆环。
8. 会话列表、消息和最近任务统一使用 `Asia/Shanghai` 展示服务。

退出条件：

- 新用户可在首次启动完成首个任务。
- 旧用户升级不丢失入口或数据。
- 所有新对话都有稳定项目/workspace；项目创建失败不会留下半授权目录或空会话。

### H1-A · Agent 权限、上下文与执行详情（3–5 天）

任务：

1. 实现 `workspace` 自动批准的安全 profile、越界/高风险回退、run snapshot 和完整审计。
2. 实现独立 `full_access` capability、二次确认、会话级有效期、撤销、自动失效、硬阻断和 emergency stop。
3. 在 ModelGateway/Runtime 接入准确 token 计量、输出预算、压缩阈值、短期摘要、压缩事件和失败恢复。

## 10. 回退

- RC 候选期间保留新 UI、project-bound run、PatchSet、command 和 worktree 独立 flag。
- 回退到旧 UI 不改变后端 run 事实。
- 关闭 worktree 后现有 worktree 只读展示，不自动删除。
- 应用回退保留 schema，不执行破坏性 downgrade。
- `v1.0.0` 默认隔离旧链并开始最终观察前，必须验证这一回退策略。

## 11. 零容忍问题

- 新安装默认授予 workspace 自动写或更高权限。
- 升级后旧数据丢失或隐式绑定错误项目。
- worktree 操作破坏原仓库或删除 dirty 目录。
- unknown execution 自动重试。
- 旧 planner 与新 Runtime 对同一请求并行执行。
- 取消/退出后残留进程。
- telemetry 泄露代码、路径或命令正文。
- 新对话没有项目/workspace，或被静默绑定到最近项目、错误目录或未确认的整个用户目录授权。
- Git 分支由前端文本推断、切换项目后显示旧分支，或为了读取分支让模型执行自由 Git 命令。
- 会话时间受操作系统本地时区漂移、UTC/上海时间混排，或迁移后改变历史消息先后。
- “替我批准”只改变 UI 标签，真实执行仍逐次询问/无审计，或越界和高风险动作被自动放行。
- 用 `workspace` 冒充 `full_access`，完全访问没有显式确认/撤销/到期，或借此绕过 OS 权限、凭据和远程外发边界。
- 上下文圆环显示字符数伪造的百分比、负数/超过 100%、上一会话旧值，或压缩静默丢失最新请求和未完成计划。
- 删除模型模块后无法进入 Provider 配置，或同一模型/profile 在多个控件显示互相冲突的状态。
- 点击执行后仍停留在无详情空态，命令/审批/验证不可追溯，或以“全思路链路”为名记录/展示隐藏 chain-of-thought。
