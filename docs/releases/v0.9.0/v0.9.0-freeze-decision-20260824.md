## 1. 决议

`v0.9.0` 自本决议起执行**功能范围封版**：不再接收新的 Agent 能力、UI 方向、Provider、工具类型、数据模型重构或权限模式。后续 Agent 全面改造统一进入 `v1.0.0`。

封版分为两个层次：

1. **范围封版：GO。** v0.9 的功能边界、公开行为和兼容策略停止变化。
2. **不可变代码基线：`fe7bd1a`。** Python、Vue、Tauri、Cargo 及锁文件版本已统一为 `0.9.0`。安装包、签名、SHA 和 updater 仍须在干净提交上由正式发布流水线生成；在这些证据完成前，不宣称二进制已封版。

这一区分避免把“停止加功能”误写成“已经产生可复现发布物”。

### 1.1 S0 补充口径

1. **安装与签名：内部工程证据已具备，公开发布仍阻断。** `0.9.0` NSIS 安装包、updater minisign、manifest、installer/sidecar SHA 与 clean install/覆盖升级/应用回退/卸载保留 smoke 已生成并通过；Authenticode 无证书，已以 `code_signed=no` 与 unsigned note 如实记录。负责人评审决定：干净候选提交的全量 release check 通过后可进入 S2；Authenticode 未补齐前，仍禁止创建公开 tag、上传公开 updater `latest` 或声称正式二进制已发布。
2. **Python 依赖：`pyproject.toml` 定义，`uv.lock` 锁定发布。** `requirements.txt` 仅作 pip 本地开发便利入口，不要求完整镜像，不得用于发布构建或可复现性验收。
3. **分支先于 tag。** `release/0.9.x` 已指向 `fe7bd1a` 作为维护线；现在不创建公开 `v0.9.0` tag。待 Authenticode、干净候选证据绑定和公开发布授权完成后，由发布负责人在对应候选提交上创建 annotated `v0.9.0` tag。S2 只依赖内部工程门禁，不依赖公开 tag。

## 2. v0.9 最终范围

封入 v0.9 的能力仅包括现有交接包已经声明并实现的内容：

- Coding Workbench 默认主线与显式 legacy 回退；
- `Project → Workspace → Conversation → Run` 绑定与迁移审计；
- 后端唯一 Agent 执行循环、durable event、审批暂停/恢复和 unknown 人工处置；
- 多文件 PatchSet、受控项目命令、验证结果和 Artifact；
- `confirm`、`workspace`、`full_access` 三档产品权限及授予/撤销/到期；
- 可选 Git worktree 生命周期；
- Provider/model profile 配置、探测、默认路由和旧配置导入；
- 真实 context usage、确定性压缩、执行详情和公开决策摘要；
- 会话重命名、归档、置顶、搜索以及 Windows/Asia-Shanghai 产品时间语义；
- 当前安全、故障恢复、性能、无障碍和视觉回归门禁。

以下内容不再进入 v0.9：

- Agent 协议重做、Thread/Turn/Item 新领域模型；
- 双向 IPC、生成式协议契约、统一事件 envelope；
- OS 级命令沙箱和通用 Shell；
- 工具路由器、生命周期、策略和执行器的模块化重写；
- `AGENTS.md` 分层发现、Skills、Hooks、Agent 内统一 MCP；
- 多 Agent、子 Agent、远程执行、云同步、浏览器/Computer Use；
- 旧执行链物理删除。

## 3. 封版后允许变更

仅允许以下变更进入 v0.9，且每项都必须附回归测试和封版说明：

1. P0/P1 数据损坏、权限绕过、秘密泄漏、重复副作用或不可恢复崩溃修复；
2. 阻止安装、启动、升级、回退或卸载的发布问题；
3. 测试、构建、签名、manifest 和版本一致性修复；
4. 与当前实现保持一致的文档纠错；
5. 不改变公开行为的依赖安全补丁。

不符合以上条件的请求进入 v1.0 backlog。封版后发生代码变更时，候选号递增并重跑完整门禁，不沿用旧证据。

## 6. 维护策略

- v0.9 只接受 `0.9.x` 维护修复；不回迁 1.0 的新协议、新数据模型或新执行器。
- v1.0 迁移必须能读取 v0.9 数据，并保留明确的应用回退路径；不要求破坏性 schema downgrade。
- v1.0 的 shadow/replay 只能重放公开事件或模型输入，绝不对同一用户请求双执行工具副作用。
- v0.9 legacy 回退在 v1.0 stable 前保留；物理清理由 `v1.1.0` 独立执行。
