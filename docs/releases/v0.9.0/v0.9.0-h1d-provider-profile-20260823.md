# v0.9.0 H1-D 实机试用纠偏执行记录：Provider/profile 配置闭环（2026-08-23）

> 依据：[开发计划](./v0.9.0-development-plan-20260820.md) §1.13、§2.1、§5.8、
> 里程碑 H1-D、§9 新增矩阵、§11 新增零容忍、完成定义第 19–20 项
> 基线：v0.9.0 H1-B/H1-C 代码完成版（本分支）
> 性质：增量纠偏；全部 schema 变更 additive（迁移 0033），既有契约不破坏

## 1. 纠偏背景

第四轮安装版试用：`.env` 已有 `PA_OLLAMA_BASE_URL` 与 `PA_LLM_MODEL`，
但 Coding 首页仍显示“模型 Provider 未配置”。代码链核实：

- 首页依赖 `GET /agent-model-profiles?enabled_only=true`；`model_profiles`
  表为空 → `homeState=provider-unconfigured`；
- 设置页只维护全局 Provider，没有 profile 创建/编辑入口；前端只有只读
  GET，没有 upsert/probe/导入调用；
- 升级 reconcile 不导入旧配置 → “前往设置”进入无法完成修复的循环；
- 且 `_model_gateway_for_run` 三个分支的 model 全部取全局 settings
  （`llm_model/openai_model/claude_model`），profile 只提供路由策略——
  “显示一个模型、实际用全局旧模型”的零容忍隐患。

## 2. 实施内容

### 2.1 schema：具体模型路由字段（迁移 0033，additive）

`model_profiles` 新增两列（幂等 `information_schema` 检查，风格与
0031/0032 一致；正式回退保留 schema）：

| 列 | 类型 | 语义 |
|---|---|---|
| `model_name` | VARCHAR(200) NULL | 具体模型路由字段：Runtime 实际传给 Provider 的 model 标识；历史 profile 为 NULL，由升级 reconcile 幂等回填或设置页补全 |
| `is_default` | BOOLEAN NOT NULL DEFAULT 0 | 默认 Coding profile 标记（服务层排他维护唯一性） |

### 2.2 Runtime 按 profile 路由（不回落全局旧模型）

`_model_gateway_for_run`：Ollama/OpenAI/Claude 三分支的 `model` 一律取
`profile.model_name`；字段缺失 → `ModelProfileUnsupported` 失败关闭并给出
精确原因（设置页可补全/验证）。`run.model_profile_id` 为 None 的
legacy/历史 run 保持全局 ProviderRouter（v0.6.0 行为不变）。

创建链默认绑定：coding run 未显式选择 profile 时绑定当前默认项并持久化；
无默认项时保持旧兼容路由并记录低基数遥测
`agent_run_create:profile_default_missing`。既有 run 保留创建时快照，
后续默认切换不改写历史。

### 2.3 typed API（全部经 `PA_CODING_PERMISSION_MODELS_ENABLED` 门控）

| 端点 | 语义 |
|---|---|
| `GET /agent-model-profiles[?enabled_only]` | 列表（响应新增 `model_name/is_default`） |
| `GET /agent-model-profiles/{id}` | 详情 |
| `PUT /agent-model-profiles/{id}` | upsert（请求新增 `model_name/is_default`） |
| `DELETE /agent-model-profiles/{id}` | 删除 |
| `POST /agent-model-profiles/{id}/probe` | 受限探测（新增） |
| `POST /agent-model-profiles/{id}/set-default` | 排他设为默认（新增） |
| `POST /agent-model-profiles/import` | 幂等导入全局配置为默认 profile（新增） |
| `GET /agent-model-profiles/import-status` | 旧配置导入状态（一次性向导依据） |

受限探测状态码（冻结词汇，全部低基数、无 secret）：
`ok / profile_disabled / model_route_missing / tools_unsupported /
feature_disabled / credentials_missing / provider_unreachable /
model_missing / probe_failed`。Ollama 走 `/api/tags`（3s 超时、
`:latest` 兼容）；OpenAI 走 `/models`（Bearer，401/403 → 凭据无效）；
Claude 无列表端点，仅验证凭据存在不发起计费请求。**工具能力不按模型
名称推断**：探测通过但 `native_tool_calls=false` → `tools_unsupported`。

### 2.4 升级幂等导入（启动 reconcile + 一次性向导）

`v090_upgrade.reconcile_model_profiles`（挂在既有启动 reconcile，flag
门控，失败只记日志不阻断启动）：

1. 既有 profile 缺 `model_name` 时，从全局同 provider 配置幂等回填；
2. profile 为空且全局已配置：**仅本地 Ollama** 且受限 probe 通过时自动
   创建稳定 ID 默认 profile（`ollama-default`），导入状态
   `auto_imported`；远程/凭据缺失/歧义/失败一律不自动导入，交给一次性
   向导（不静默扩大远程数据使用范围）。

`POST /import`（用户显式）：幂等——已有任何 profile 直接返回既有默认项；
探测失败回滚删除（不留下不可用默认项）；精确状态码失败关闭。
导入状态经 `settings.coding_profile_import_state`
（pending/auto_imported/imported/dismissed/not_needed）只展示一次。

### 2.5 前端闭环

- **typed client**：`features/coding/api/modelProfiles.ts` 补齐
  list/get/upsert/delete/probe/set-default/import/import-status；
  组件不拼 URL、不接触任何 secret。
- **设置页管理区**（`ModelProfilesPanel.vue`，设置页第 05 卡片）：
  列表（默认/停用/工具能力徽标）、创建、编辑、验证（行内状态+详情）、
  设为默认、启用/停用、删除；旧配置导入横幅（验证并导入/不再提示）。
- **同一配置区 + returnTo**：`PrivateAgent` 入口（旧页）与 Coding 首页
  阻塞操作（创建/前往设置）、任务页模型类阻塞卡片统一
  `configure-provider` → `openModelSettings(returnTo)`；设置页呈现返回栏
  并滚动定位管理区；保存后自动返回原视图并 `store.refresh()` 原位重探测
  解除阻塞；项目/会话/草稿/权限选择由既有机制保留。
- **阻塞状态拆分**：`provider-unconfigured` 拆为
  `feature_disabled`（能力位关闭：重试/更新语义）与
  `profile_missing`（一键导入 + 创建入口）；导入失败按状态码给出中文
  恢复文案（不可达/模型缺失/凭据缺失/远程未启用/无全局配置）。

## 5. 红线核对（§11 新增零容忍）

- 有可用 Provider 却因 profile 空被困“前往设置”循环 → 已修复（导入闭环）；
  设置页可创建/验证/选择。
- profile 显示一个模型但 Runtime 用全局旧模型 → 路由强绑定
  `model_name`，缺失失败关闭；按名称猜测工具能力 → 探测不推断，能力
  显式声明。
- Provider secret → profile/API/日志 → 全链路无 secret 字段（导入/探测
  只读全局凭据引用；面板文案明示“不含任何密钥”）。
- 升级导入重复创建/静默启用远程外发 → 幂等（已有 profile 不创建）；
  远程仅用户显式确认路径；要求手工改库/隐藏 API/配置文件 → UI/API/
  迁移闭环完成，手工手段仅诊断用途。

## 6. 已知边界

- 打包安装版（NSIS）同链路终验随发布流水线执行（与 v0.7.0 以来门禁
  口径一致）；本记录提供代码层与浏览器级串联证据。
- Claude 无模型列表端点：探测仅验证凭据存在，不验证模型存在性（不发
  计费请求），文案如实说明。
- 历史 profile（v0.7.0 创建）`model_name` 为 NULL 时，启动回填依赖
  全局配置同 provider；若全局配置已变更，需在设置页手动补全（运行期
  失败关闭并给出精确指引，不静默回落全局旧模型）。
