## 1. 纠偏背景

第二、三轮实机试用暴露两类发布阻断问题：

1. **可执行请求退化为纯问答**（§5.6）：「看一下本机是否装了 MySQL」被回答为
   手工操作教程，没有创建 run、权限请求、工具调用或命令事件。根因：命令面
   上没有任何可用的诊断命令 profile（`where.exe mysql` 等仅存在于计划文字），
   模型无工具可调，只能退回文字回答；且无证据门槛，文字回答被呈现为完成。
2. **安装版权限与上下文能力不可用**（§5.7）：「替我批准」「完全访问」与
   上下文用量在安装版置灰/长期不可用。根因：桌面 sidecar 未注入任何
   v0.9.0 能力位（命令工作流/命令 profile/自动批准/完全访问/上下文预算
   全部默认 False），capability 握手如实报告「不支持」。

## 2. H1-B · Agent 动手主链（§5.6）

### 2.1 内置只读诊断 profile（MySQL 检查固定验收样例）

`core/diagnostic_profiles.py`（新增）：

| profile | 固定 argv | 解析器 |
|---|---|---|
| `diag_where_mysql` | `where.exe mysql` | plain |
| `diag_mysql_version` | `mysql --version` | plain |
| `diag_where_mysqld` | `where.exe mysqld` | plain |
| `diag_service_<svc>`（mysql/mysql57/mysql80/mysql84/mariadb） | `sc.exe query <svc>` | windows_service_probe（新增，typed 服务状态） |

安全边界：全部 `safe` + `allow_network=False`；`_resolve_command` 对项目
profile 未命中的命令按最长前缀匹配内置集；未知工具精确 argv 规则保证
前缀后零追加参数（模型不能拼 shell/服务名）；内置集是代码事实，不可经
API 变更。命令工具描述向模型公开全部诊断 argv（能力就绪的前提）。

`_workspace_command_risk`：无项目 profile 时可执行命令面 = 内置只读诊断
集 → `SAFE`，「替我批准」对诊断命令真实免逐次询问；未命中内置诊断的
命令仍在执行层拒绝。内置诊断豁免 workspace TOCTOU 复核（精确 argv 结构
性无网络入口），数据库项目 profile 的复核规则不变。

### 2.2 可执行意图路由与证据门槛（禁止静默降级为纯问答）

- `core/executable_intent.py`（新增）：低基数启发式判定（动作动词/教程
  标记/咨询语境），纯函数不调模型；「仅回答方法」类提问不强制证据。
- `POST /agent-runs` 创建链：能力校验链通过且消息判定为可执行意图时，
  注入完成条件 `min_tool_executions=1`（并放宽 `max_failed_tools` 至 16——
  诊断命令的失败退出码本身是证据）与 `EXECUTABLE_INTENT_POLICY` 系统提示
  段；条件持久化到 run 记录，审批恢复/重启续跑重读同一组条件。
- `WorkflowCompletionOutputVerifier` 新增 `min_tool_executions`：基于
  durable executions 事实计数，零执行证据的「完成」宣称 →
  `output_validation_failed` 失败关闭（不产生假完成记录）。
- 遥测：`executable_intent`（coding/routed）低基数计数。

### 2.3 失败关闭状态与恢复入口（前端）

- `useRunStream` 暴露 `createErrorCode`：CodingApiError 结构化解析
  （修复此前 `[object Object]` 呈现）；创建失败无 run 投影、不开流。
- `model/runBlocking.ts`（新增）：后端创建链全部 error_code → 阻塞项 +
  原因 + 恢复动作（配置 PrivateAgent/选择项目/重新授权/重试）。
- `CodingThreadWorkspace`：创建失败原位渲染阻塞卡片（`role=alert`）+
  恢复按钮 + 草稿回填（`restoreRequest`，@ 行还原为 chip，不丢失输入）。
- `RunTranscript`：无 durable run 时不显示误导性「重连中」提示；完成但
  零工具/命令事件如实标注「本轮未执行工具/命令…不含执行证据」。
- `TaskComposerV2`：模型未配置时执行按钮禁用且原因紧邻按钮（§5.6）。

## 3. H1-C · 权限与上下文可用性（§5.7）

### 3.1 安装版能力位注入（发布阻断修复）

`apps/desktop/src-tauri/src/lib.rs`：

- `ConfigData` 新增 14 个 v0.9.0 能力位字段，**产品默认 `true`**
  （计划 §1.3「可信工具默认启用且可精确回退」；发布门禁已通过）；
  `.env` 解析/渲染往返完整，显式 `false` 即精确回退（§3.3）。
- `start_sidecar` 注入全部 14 个 `PA_*` env（与 .env 落盘值一致）。
- 红线声明：能力可用性声明不是权限授予——默认权限模式仍为 `confirm`，
  不扩大既有 trusted path 或命令 profile。
- Rust 单测：legacy 配置默认 true + 显式 false 回退两个往返用例。

### 3.2 capability 握手与权限选项真实状态

- `/capabilities` 新增 `coding_full_access_audit`、`coding_full_access_revoke`
  （§5.3 审计/撤销独立声明）、`coding_diagnostic_commands_enabled`。
- CodingComposer：`full_access` 可用性 = 能力位 ∧ 审计 ∧ 撤销（显式
  `false` 失败关闭）；不可用选项在项旁说明具体原因（禁止无响应项）。
- 权限选择按会话（thread）持久化（`pa_coding_permission_<threadId>`），
  只存合法枚举值，能力位缺失回落 `confirm`（不静默升权）；选择真实进入
  run 创建体形成权限快照（e2e 断言 `permission_mode=workspace`）。

### 3.3 上下文圆环真实可用性

- 圆环数值来源不变（后端 typed budget：provider usage/受验证 tokenizer/
  Runtime 统一计数，绝不按字符数伪造）；新增呈现：数据来源、最近更新
  时间、不可用时的恢复入口文案（§5.7 详情要求）。
- 窗口重新聚焦即原位重新探测（配置往返/Runtime 重连后无需新建会话）。

## 6. 已知边界

- 可执行意图判定是低基数启发式（关键词），误判只影响是否注入证据门槛，
  不改变权限/执行语义；教程式提问显式优先。
- 内置诊断集当前只覆盖 Windows MySQL 检查样例（计划指定首个验收样例）；
  扩展新诊断命令需代码评审（固定 argv + 零网络 + safe）。
- `max_failed_tools` 放宽至 16 仅作用于可执行意图注入路径；诊断命令失败
  仍是证据，模型须按证据如实陈述（系统提示约束 + 输出校验既有红线）。
