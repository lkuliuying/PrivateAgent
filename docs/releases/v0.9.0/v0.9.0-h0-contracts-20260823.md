> 日期：2026-08-23（dev/0.9.0）

本文档冻结 v0.9.0 的默认值矩阵、flag 组合、身份模型、时区契约、三档权限
capability、上下文 budget/compaction 与公开执行链 DTO/event。任何破坏性变更

## 1. 默认值矩阵

### 1.1 新安装

| 项 | 默认值 | 说明 |
|---|---|---|
| Coding UI | 开启 | 前端默认进入 Coding Home；`?coding=0` / `pa_coding_workbench=0` / `/capabilities.coding_agent_ui_enabled=false` 显式回退旧 UI |
| 项目对象 | 空 | 无项目时提供「新建项目」与「新建对话」两个独立动作 |
| 新建项目 | 先选目录并授权 | 创建 project + root workspace + Git facts + 默认权限/profile；失败不留半绑定项目 |
| 新建对话 | 必须绑定项目 | `project_id`/`workspace_id` 非空；未选择时预选「当前用户目录」候选（见 §4），首次副作用仍走 `confirm` |
| 权限模式 | `confirm` | 新安装默认权限为 `confirm`；**不是** `workspace`，更不是 `full_access` |
| workspace 自动批准 | 门禁后启用 | 安装版经发布门禁后默认开启（`PA_CODING_WORKSPACE_AUTO_APPROVE_ENABLED=true` 写入安装版 .env），开发默认关闭 |
| full_access | 关闭 | 仅用户在会话级显式二次确认后授予；默认永不自动启用 |
| 高风险 PatchSet/命令 flag | 门禁后可用 | 维持 v0.7.0 口径，发布门禁通过才默认可用 |
| 自动化 / MCP / 远程外发 | 关闭 | 不变 |

### 1.2 升级安装

| 项 | 行为 |
|---|---|
| session/项目/Provider/知识库/设置 | 全部保留，不物理删除 |
| 已有项目 | 启动时幂等补建 root workspace（`/projects/{id}/workspaces/root/ensure` 语义） |
| 旧 session | 保持 `kind=legacy`；从「更多工作区」访问 |
| 旧未绑定会话 | `legacy/unbound`（`project_id IS NULL`）原样显示；只有用户显式选择项目后经 `POST /sessions/{id}/bind-project` 迁移，不批量绑定、不按最近项目猜测 |
| trusted path / 命令 profile | 不自动扩大 |
| 时间 | 只补齐时区语义（序列化层），不改写消息先后（§5） |

### 1.3 回退

| 回退键 | 语义 |
|---|---|
| `PA_CODING_AGENT_UI_ENABLED=false` | 后端 capabilities 声明关闭，前端回退旧 UI；短期保留 |
| `?coding=0` / `pa_coding_workbench=0` | 前端本地回退 |
| `PA_PROJECT_BOUND_RUNS_ENABLED=false` | 旧兼容聊天仍可用；不删除新 plan/Artifact/workspace 数据 |
| worktree flag 关闭 | 现有 worktree 只读展示，不自动删除 |

## 2. Flag 组合（UI / Runtime / 工具 / Provider）

### 2.1 新增后端 flag（全部默认关闭，依赖校验见 §2.3）

| flag | 依赖 | 语义 |
|---|---|---|
| `coding_agent_ui_enabled` | — | capabilities 声明；前端默认切换依据。安装版默认可置 true |
| `coding_workspace_auto_approve_enabled` | `project_bound_runs_enabled` + `coding_command_profiles_enabled` | `workspace` 档真实自动批准的 capability 位 |
| `coding_full_access_enabled` | `project_bound_runs_enabled` | 独立 `full_access` capability；授予/撤销/到期/审计 |
| `coding_context_budget_enabled` | `project_bound_runs_enabled` | 上下文 budget/compaction 公开端点与事件 |
| `coding_execution_detail_enabled` | `project_bound_runs_enabled` + `agent_run_event_stream_enabled` | execution 视图聚合端点与 `decision.summary` 事件 |
| `coding_worktree_enabled` | `project_bound_runs_enabled` | 可选 worktree 创建/清理（H3） |

### 2.2 既有 flag 处置

- v0.5.0–v0.7.0 全部 flag 默认值**不变**（不隐式扩大权限）。
- `coding_permission_models_enabled` 保持独立（与 v0.7.0 一致，不进依赖链）。
- 开启顺序：project-bound → plan → stream →（budget/execution/worktree/auto-approve/full_access 任意顺序，但 auto_approve 额外要求 command profiles）。关闭顺序相反。

### 2.3 依赖校验（config.py）

- `coding_workspace_auto_approve_enabled` 需 `project_bound_runs_enabled` 且 `coding_command_profiles_enabled`。
- `coding_full_access_enabled`、`coding_context_budget_enabled`、`coding_execution_detail_enabled`、`coding_worktree_enabled` 均需 `project_bound_runs_enabled`。
- 违反即启动失败（fail fast），与既有 `validate_v060_flag_order`/`validate_v070_coding_flag_order` 同语义。

## 3. /capabilities 扩展（additive）

v0.9.0 在 `RuntimeCapabilities` 上新增字段（全部默认 False，旧客户端忽略）：

```text
coding_agent_ui_enabled: bool = False
project_bound_runs_enabled: bool = False
coding_workspace_auto_approve: bool = False
coding_full_access_supported: bool = False
coding_context_budget_enabled: bool = False
coding_execution_detail_enabled: bool = False
coding_worktree_enabled: bool = False
product_timezone: str = "Asia/Shanghai"     # 常量，产品时区声明
```

语义约束：

- `coding_workspace_auto_approve=true` ⇔ flag 开启且命令 profile 子系统可用。
- `coding_full_access_supported=true` ⇔ `coding_full_access_enabled` flag 开启。
  `workspace` 与 `full_access` 不得互相别名：两个字段独立、语义独立、审计独立。
- UI 只有在对应字段为 true 且配置完整时启用对应权限选项；否则选项置灰并说明。

## 4. 身份模型与迁移契约

### 4.1 对象层级（冻结）

```text
Project（项目）
└── Workspace（kind=root|git_worktree；根目录或可选 worktree）
    └── Conversation/Session（kind=legacy|coding；coding 必须非空 project_id+workspace_id）
        └── Run / Execution（AgentRun；project+workspace 快照）
            └── Turn / Tool / Command / Approval / Artifact（durable 事件与表）
```

### 4.2 契约（冻结）

1. 任何 `kind=coding` 的新会话必须具有非空 `project_id` 与 `workspace_id`（v0.6.0 已有，保持）。
2. 「新建项目」与「新建对话」是两个独立动作；前端不得把新建对话静默升级为新建项目。
3. 「当前用户目录」候选：内置候选项目指向当前 OS 用户主目录（`Path.home()`）。
   - 只解决归属与起始目录，**不**自动授权整个用户目录写入或命令执行；
   - 不自动加入 trusted path；首次副作用仍遵守 `confirm`；
   - 候选在会话创建时显式选择才落库，创建请求必须携带真实 `project_id`。
4. 对话创建后不因侧栏切换静默改变工作目录；更换目录 = 选择/创建另一 workspace。
5. legacy/unbound 会话（`kind=legacy` 且 `project_id IS NULL`）保留可读与导出；
   绑定唯一入口 `POST /sessions/{id}/bind-project`：
   - 请求必须携带 `project_id` + `workspace_id`（归属一致校验，复用会话创建链）；
   - 绑定后 `kind` 升为 `coding`，记录 `bound_at`（updated_at 语义不变，不改写消息先后）；
   - 无批量绑定端点；无按最近项目/用户目录的自动猜测。
6. 项目创建失败不得留下半绑定项目：project 行与其 root workspace 在同一事务提交。

### 4.3 旧数据升级

- 迁移编号延续：下一个 Alembic revision = `0031`（down_revision=`0030`）。
- 0031 为 additive：新增 `session_project_bindings`（绑定审计）与
  `full_access_grants`（§6.3）表，不改动既有列；回退保留 schema，不执行破坏性
  downgrade（计划 §10）。

## 5. 会话时间与 Asia/Shanghai（冻结）

1. 产品时区固定为 IANA `Asia/Shanghai`，24 小时制；常量 `PRODUCT_TIMEZONE` 单点定义。
2. 数据库继续保存 naive UTC instant（`DATETIME(fsp=3)` + 连接 `time_zone='+00:00'`，
   现状保持）作为唯一排序事实；**不**迁移改写历史时间值。
3. API 序列化统一：新增 `core/timeutil.format_rfc3339_utc(dt)` 输出
   `YYYY-MM-DDTHH:MM:SS.mmmZ`；sessions/messages 响应使用 `str` 字段 + 该格式化
   （时间字段由 `datetime` 类型改为带 Z 字符串，客户端统一按 RFC 3339 解析）。
   该变更对旧前端宽容：旧前端 `new Date("...Z")` 解析仍正确。
4. 旧 naive/UTC 数据 backfill 规则：**值不变**，只在序列化层统一加 `Z`——历史
   先后顺序由 UTC 值保持，满足「不改写消息先后」。
5. 客户端统一 `services/timeDisplay.ts`：`Intl.DateTimeFormat(..., {timeZone:
   "Asia/Shanghai", hour12: false})` 单一实现，替换散落 `toLocaleString`/重复
   相对时间实现；禁止组件各自调用本机 locale。
6. 验收覆盖：UTC 跨日、上海零点、系统时区非上海、离线重连、旧数据迁移。

## 6. 三档命令权限真实契约（冻结）

### 6.1 模式集合

```python
PERMISSION_MODES = {"readonly", "confirm", "workspace", "full_access"}
```

- `readonly`/`confirm`/`workspace` 语义保持 v0.7.0 冻结。
- `full_access` 为 v0.9.0 新增，**不**是 `workspace` 的别名。

### 6.2 Runtime 语义与强制边界（计划 §5.3 表格落地）

| 模式 | Runtime 语义 | 强制边界 |
|---|---|---|
| `confirm` | 写文件/补丁/命令逐次审批 | 只读动作仍受项目授权与敏感数据策略限制 |
| `workspace` | 当前项目/workspace 内命中安全 command/tool profile 的操作自动批准 | 越界、未知、高风险、远程外发、凭据访问、破坏性动作继续询问或拒绝 |
| `full_access` | 当前 OS 用户可访问的本机范围内常规文件/命令免逐次审批 | 不获得管理员权限；不绕过 OS/UAC；凭据、秘密、远程外发、系统级破坏动作仍有硬阻断/独立确认 |

### 6.3 capability / 快照 / 授予

- `/capabilities` 分别声明 `coding_workspace_auto_approve` 与 `coding_full_access_supported`（§3）。
- 每个 run 持久化 `permission_snapshot_json`（既有），新增键 `granted_full_access: bool`；
  执行器在每次工具调用前再次校验快照与授予有效性。
- `full_access` 授予表 `full_access_grants`：
  `id, session_id, project_id, granted_at, expires_at, revoked_at, revoke_reason`。
  - 有效期：默认 4 小时（`coding_full_access_ttl_minutes`，60..1440）；
  - 到期/退出应用（启动时 reconcile 未过期但进程已换的授予）/切换项目 → 自动失效；
  - 撤销端点 `DELETE /full-access-grants/{id}`，即时生效；
  - 授予仅对显式二次确认后的当前会话/项目生效，不跨项目扩散。
- 审计：全部免审批动作仍记录工具、脱敏参数（sha256+摘要）、命令、工作目录、
  时间、退出码与结果（复用 ToolExecution durable 事实）；自动批准不跳过审计、
  取消与 emergency stop。
- **失败关闭**：capability 缺失、版本不匹配、审计不可写或撤销通道异常时降级为
  `confirm`，run 事件 `permission.downgraded` 记录原因（低基数），不得静默继续
  使用更高权限。

### 6.4 错误码（additive）

```text
full_access_unsupported      409   # flag 未开启时请求 full_access
full_access_grant_expired    409   # run 执行期授予过期
full_access_revoked          409   # 授予被撤销
permission_downgraded        (事件，非 HTTP 错误)
```

## 7. 上下文 budget / compaction（冻结）

### 7.1 端点

`GET /sessions/{id}/context-budget`（flag `coding_context_budget_enabled` 关闭 → 409
`coding_mode_disabled`）：

```json
{
  "used_tokens": 0,
  "max_context_tokens": 0,
  "reserved_output_tokens": 0,
  "usage_percent": 0,
  "source": "provider_usage | tokenizer | runtime_count | unavailable",
  "compaction_state": "idle | compacting | compacted | failed",
  "last_compacted_at": null,
  "error_code": null,
  "error_reason": null
}
```

- 用量只来自 provider usage、受验证 tokenizer 或 Runtime 统一计数；
  不按字符数/消息数伪造。无法准确计量的 profile → `source="unavailable"` +
  `error_reason`，前端显示「不可用」，不显示虚假百分比。
- `usage_percent` 域：0..100（四舍五入整数）；超限时封顶 100 并置 `error_code=
  "budget_exceeded"`，禁止负数/超过 100 的裸数值。
- 会话隔离：端点只返回该会话最近一次真实计量，不跨会话复用旧值。

### 7.2 压缩

- 阈值：`usage_percent >= compaction_threshold`（默认 80，配置
  `coding_context_compaction_threshold`）时，下一轮执行前自动生成短期摘要并压缩
  旧上下文；保留最新用户请求、系统/项目约束、未完成计划、审批与关键工具事实。
- 事件（durable，additive 到 `STABLE_EVENTS`）：
  `context.compaction_started`、`context.compaction_completed`、`context.compaction_failed`。
- 压缩失败、tokenizer 不可用或预算仍超限 → 停止新执行（`budget_exceeded`），
  给出恢复路径（新开会话/清理上下文），不静默截断。

### 7.3 前端呈现

- 输入器删除矩形「上下文用量不可用」模块，改为 `PrivateAgent` 状态旁紧凑圆环
  `ContextUsageRing`：进度/颜色 + 文本替代 + `aria-label` + 非颜色状态；
  hover/键盘 focus 弹层显示 used/limit、百分比、保留输出预算、压缩阈值与最近
  压缩结果；窄窗口/150% 缩放不遮挡模型入口或执行按钮。
- 状态映射：`unavailable`→不可用（原因）、`compacting`→压缩中、`failed`→失败+恢复入口。

## 8. 公开执行链与 execution 视图（冻结）

1. 执行视图数据来源 = durable 事件流（既有 29 类事件）+ 新增公开决策摘要事件：
   - `decision.summary`（additive 到 `STABLE_EVENTS`）：payload 键
     `goal/method/key_judgments/rationale/next_steps/risks/verification`，
     全部为结构化公开摘要文本；**不**含隐藏 chain-of-thought。
   - Runtime 在每轮模型完成后从已有公开事实（计划状态、工具结果、验证结果）
     生成摘要；模型未产生公开摘要时该轮显示「无公开摘要」，不伪造。
2. `GET /agent-runs/{id}/execution-detail`（flag `coding_execution_detail_enabled`
   关闭 → 409）：按 turn 聚合 —— 用户目标、公开决策摘要、计划/当前步骤、工具与
   命令（脱敏命令文本、工作目录、状态、起止时间、输出摘要、退出码、耗时、重试）、
   审批、输出/验证、最终回答；无命令的 turn 显式 `commands: []`（前端显示
   「本轮未执行命令」）。
3. 新对话空态点击「执行」：创建稳定 run（`client_request_id` 幂等）后进入
   execution 视图；创建失败留在草稿态，不生成空 run、不丢失输入。
4. 命令脱敏沿用后端 `_redact_line` 语义与前端 `redaction.ts`。
5. 隐私：不读取、不持久化、不展示隐藏 chain-of-thought；telemetry 只记聚合计数。

## 9. 兼容归零观测（H0 定义，H5 验收）

需观测（telemetry path additive）：

```text
legacy_session_bind           # POST /sessions/{id}/bind-project 计数
full_access_grant             # granted/expired/revoked/denied
permission_downgrade          # 降级原因低基数计数
context_budget_poll           # available/unavailable/error
```

v1.0.0 默认隔离与最终观察门槛（本版本只达成「即时门禁可解释」）：

1. 新桌面消息进入旧 planner 为 0；
2. 升级前 pending tool call 耗尽或可归档；
3. 旧 UI 只因显式回退进入；
4. 无不可解释 legacy 调用；
5. v1.0.0 升级与支持说明就位。
