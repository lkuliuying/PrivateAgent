## 1. H2 · 恢复与人工处置（达成）

| 交付 | 落点 |
|---|---|
| unknown 执行人工处置三决策 | `agents/executions.py resolve_unknown`：`succeeded`（须附输出事实）/ `failed` / **`not_executed`**（新增；确认未执行，重试仍由用户显式发起） |
| 重新验证文件/Git 状态 | `POST /agent-runs/{id}/executions/{eid}/revalidate`：只读返回工作区路径存在性 + Git 分支/HEAD/dirty 事实，不改变执行状态、不自动重试 |
| 非 unknown 拒绝改判 | 非 `unknown` 状态处置 → 409 + `rejected` 遥测（防静默篡改事实） |
| 恢复耗时观测 | `agents/recovery.py acquire`：reconcile 时长与孤儿计数入结构化日志（低基数） |
| 人工处置遥测 | `manual_execution_resolution`（succeeded/failed/not_executed/revalidated/rejected） |
| 既有基础 | crash/restart reconcile（v0.6.0 C5）、waiting_approval checkpoint 保留可恢复、sidecar/SSE/DB 中断覆盖（既有套件） |

**退出条件核对**：无无法取消/无法解释且永久运行的 run（reconcile 终态化 running；waiting_approval 保留人工恢复）；unknown 副作用不自动重试（决策词汇冻结测试反向断言无 `retry`/`auto_retry`/`skip`）。

## 2. H3 · 可选 Worktree（达成）

| 交付 | 落点 |
|---|---|
| 固定 Git argv 服务 | `core/git_worktree.py`：`create_subprocess_exec` 无 shell；分支名/路径白名单；超时失败关闭 |
| 仓库判定修正 | `is_git_repository` 用 `--show-toplevel` 与规范化路径比较（Windows normcase），避免把父仓库内子目录误判 |
| 创建/预览/清理 API | `routes_worktrees.py`：`GET /worktrees/preview`（原项目/基础分支/HEAD/新分支/路径/清理策略）、`POST /workspaces/worktree`、`POST /workspaces/{id}/cleanup` |
| 生命周期状态 | 迁移 0032：`workspace_status_enum` 追加 `creating`/`cleanup_pending`（既有状态保留） |
| 失败不留半绑定 | 落库失败即 `git worktree remove` 回收现场；创建失败复核原仓库 HEAD 未变 |
| 模型隔离 | worktree 操作仅 HTTP 端点，不注册任何模型工具 |

**退出条件核对**：原仓库不因 worktree 失败被修改（创建前后 HEAD 复核 + 测试断言分支仍为 main）；dirty worktree 不被自动删除（409 `worktree_dirty`，目录保留）。
