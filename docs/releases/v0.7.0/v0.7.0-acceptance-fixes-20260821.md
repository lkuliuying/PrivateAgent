## 1. P0-1：模型 profile 没有驱动实际 Provider

**问题**：Run 选择的 `model_profile_id` 只被校验和保存，执行仍使用全局
Provider；`reasoning_effort` 未生效；权限快照固定声明
`remote_provider_data_policy=no_send`——若全局启用远程 Provider，即使选择
本地 profile，也可能把工作区上下文发送到远程。

**修复**：

| 位置 | 变更 |
|---|---|
| `api/routes_agent_runs.py` | 新增 `_model_gateway_for_run(db, run)`：按 run 绑定的 `model_profile_id` 解析实际 ModelClient——本地 profile（provider=ollama / is_local）强制 Ollama 本地路由（绝不因全局远程设置发送远程）；远程 profile（openai/claude）要求全局 `remote_provider_enabled`（否则 422 fail-fast），secret 仍从全局原生凭据读取；profile 删除/禁用/能力变化 → 失败关闭，不静默回退全局 |
| 同上（create 端点） | 创建校验加强：远程 provider 需全局启用（422 `model_profile_unsupported`）；provider 白名单（ollama/openai/claude）；`reasoning_effort` 必须落在 profile 声明集合（422）；coordinator.start 传入按 run 解析的 model 与 reasoning_effort |
| 同上（approve 端点） | resume 改用 `_model_gateway_for_run`（不再用全局注入）；传 `run.reasoning_effort` |
| 同上（快照） | `remote_provider_data_policy` 按实际路由：本地 → `no_send`（真实）；远程启用 → `send`（如实声明） |
| `agents/contracts.py` | `ModelRequest` 增加 `reasoning_effort`（additive，≤32 字符） |
| `agents/runtime.py` | `AgentRuntime` 构造接受 `reasoning_effort` 并透传到每个 `ModelRequest` |
| `agents/coordinator.py` | `start`/`resume`/`_execute` 传递 `reasoning_effort` 到两处 runtime 构造 |
| `llm/adapters.py` | OpenAI 系请求体透传 `reasoning_effort`（o 系列参数；Ollama/Claude 不透传，本地模型无此概念） |

**回归测试**（`tests/test_v070_acceptance_fixes.py`）：
`test_local_profile_forces_local_route_even_with_remote_enabled`（本地 profile +
全局远程启用 → provider_name=ollama）、`test_remote_profile_run_creation_rejected_without_remote`
（422 fail-fast）、`test_remote_profile_drives_remote_route_and_snapshot_send`
（coordinator 收到远程 gateway + 快照 send）、
`test_reasoning_effort_validated_and_passed_to_coordinator`（集合校验 + 透传）、
`test_openai_adapter_payload_carries_reasoning_effort`（请求体字段）、
`test_profile_deleted_after_create_fails_closed`（resume 失败关闭）。

## 2. P0-2：项目命令可通过后缀参数越出 workspace

**问题**：白名单和 profile 都只比较 argv 前缀；`cargo test --manifest-path
C:/outside/Cargo.toml`、`npm run build --prefix C:/outside`、`python -m pytest
C:/outside/test_payload.py` 均被判定为白名单；项目 profile 全 safe 时命令
工具免确认执行。

**修复**（`core/command_workflow.py` + `core/code_tools.py`）：

- 新增 `_reject_out_of_workspace_args(root, remaining)`：前缀之后剩余参数中
  路径特征 token 必须解析在 workspace 内——盘符/绝对路径/UNC 直接拒绝；
  `..` 上级引用与相对子路径经 `resolve_within` 校验（工作区内引用允许）；
  `--flag=path` 等号形式取 value 检查。
- `_resolve_command` 匹配 profile 或全局白名单后，对剩余参数执行校验；
- `code_tools.py` 新增 `whitelisted_prefix_length`（`is_whitelisted_command`
  改为其包装，行为不变）。

**回归测试**：`test_command_profile_rejects_out_of_workspace_args`（验收三案例
+ 等号形式 + `..` 越界全部拒绝；`./Cargo.toml` 工作区内允许）、
`test_global_whitelist_remaining_args_guarded`（全局白名单剩余参数同样受控）。

## 3. P1-1：PatchSet 在持久化终态前删除回滚备份

**问题**：文件已提交并验证后，代码先清理 `.pa-bak` 再写 DB `applied`；若 DB
提交失败，留下「磁盘已修改、PatchSet 仍 previewed/pending」的幽灵状态且无法
自动回滚。

**修复**（`core/patch_set_service.py`）：成功路径改为**先持久化终态**
（`set_all_files_status(applied)` + `transition_status(previewed→applied)`，
内部 commit），DB 提交成功后再清理临时文件/备份；清理失败仅记日志（残留
`.pa-bak` 无害，状态已 applied 可解释）。失败/回滚路径原本就是先 DB 后清理，
未改动。

**回归测试**：`test_apply_persists_terminal_state_before_backup_cleanup`
（monkeypatch `transition_status` 断言执行时备份尚在，证明顺序）、
`test_apply_cleanup_failure_does_not_block_terminal_state`（清理失败不阻断
applied 终态）。

## 4. P1-2：Windows 设备路径校验不完整

**问题**：`nul.txt`/`CON.md`/`com1.json` 被当前校验接受（只比较完整 part）；
路径唯一性未按 Windows 大小写规则归一化。

**修复**（`core/patch_set_service.py`）：

- 新增 `_windows_device_name(part)`：按 MSDN 命名规则提取——去除扩展名
  （第一个 `.` 之前）、去除尾随点与空格后 lower，再与设备名集合比较；
  `nul.txt`/`CON.md`/`com1.json`/`con.`/`con ` 全部拒绝，`console.txt`/
  `nulll.txt` 允许。
- `_check_path_uniqueness`：唯一性键改为 `path.lower()`（Windows 大小写
  不敏感），`Readme.md` 与 `readme.md`、rename 目标大小写变体均判重复。

**回归测试**：`test_windows_device_names_with_extension_rejected`、
`test_path_uniqueness_case_insensitive`。
