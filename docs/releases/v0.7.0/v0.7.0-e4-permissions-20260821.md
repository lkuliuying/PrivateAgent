## 3. 测试覆盖（计划第 9 节矩阵，E4 行）

- 单元/契约：三模式能力映射 + 非法/遗留模式拒绝（read_only/full_access → ValueError/422）；快照契约字段（permission_mode/capabilities/workspace{id, root_path_sha256}/command_profile_version/patch_limits/remote_provider_data_policy）；快照绝不包含 root_path 原文；模型 profile 请求无 secret 字段。
- 集成/API：profile CRUD（flag 门控 409 / 正常 CRUD / 422 字段校验）；run 创建校验（默认 readonly、快照完整、legacy 模式 422、模型不支持 422）；dispatcher 三模式（readonly 隐藏写工具、confirm 注册写工具、workspace 命令 risk 动态化）。
- 故障/安全：workspace safe 命令免审批执行成功；restricted 命令执行时拒绝（`test_restricted_command_rejected_at_execution`）；profile 切换不自动获批既有 run（`test_profile_switch_does_not_auto_approve_existing_run`）；readonly run 写调用 DENY。

结果：`tests/test_v070_permissions.py` **24 passed**；v0.7.0 全套 **107 passed**（含解除的 2 个 xfail）；既有 Agent run 回归（runs_api/command_workflow/patch_workflow/runtime/tools/approvals/contracts/executions）**108 passed / 1 skipped**；全量 `tests/` **934 passed / 2 skipped**，零失败。

## 4. 实现要点与修复记录

- **v0.6.0 冻结契约回归（本里程碑最大修复）**：E4 早期实现把「默认预览」一律按 readonly 处理，破坏了 v0.6.0 冻结的默认 bundle 契约（7 个只读工具 + flag 开启的写工具可见）与契约 §4.1（readonly 应自动允许「搜索、读取、Git 状态/Diff」）。修复：`permission_mode` 解析默认 None（v0.6.0 行为，回退契约 §10）；readonly 授予集从 `{filesystem.read}` 扩展为 `{filesystem.read, database.query, process.execute}`（只读工具可见性所需，快照声明 `{"filesystem.read"}` 保持不变——快照是声明、授予集是运行时实现）。3 个回归测试（command_workflow/patch_workflow/agent_runs_api）由红转绿。
- **MySQL REPEATABLE READ 悬空事务（历史快照测试）**：`ProjectCommandProfileRepository.create` 末尾 `db.refresh(p)` autobegin 新读事务，测试 session 在 REPEATABLE READ 下看不到 HTTP 请求（client engine）提交的后续 run；修复为 profile 创建后 `await db.commit()` 结束悬空读事务，并提前捕获 `profile_id`（rollback 会 expire 对象触发 MissingGreenlet，commit 在 expire_on_commit=False 下不过期）。
- **conftest 双重执行陷阱**：`from tests.conftest import` 触发 conftest 模块二次执行（pytest 以不同模块名导入）污染 `cfg.db_url`；调试改为用 db 引擎实际信息，不用 conftest import。
- **restricted 双重防护**：注册层（ToolCapabilityPolicy RESTRICTED 恒 DENY）+ 执行层（`_resolve_command` 匹配 restricted profile 即拒绝）——即使 future 引入绕过注册层的路径，执行层仍拦截；MVP 无任何 restricted 自动放行渠道。
- **workspace 模式命令 risk 动态化边界**：项目无 enabled profile → risk None（契约默认 confirm 审批）；全部 safe → SAFE 自动允许；存在 confirm/restricted → CONFIRM 整体把关（restricted 在执行时仍被拦截）。
- **dispatcher factory 全异步化**：按 run 快照构建需读 DB，factory 改 async 后 coordinator 调用点同步 `await`，`AgentToolBundle` 类型注解同步更新。

## 5. 安全契约核对（计划第 4/11 节）

- readonly：写文件/命令/网络/MCP 全部无入口（注册过滤 + 能力 DENY 双保险）；confirm：写操作需人工审批；workspace：仅项目内已配置 safe profile 自动允许，restricted 永不自动获批。
- 每次 run 保存权限快照；快照只存非秘密摘要（root_path_sha256 而非 root_path 原文、remote_provider_data_policy 而非 secret/token）；历史 run 不因 profile 变化修改。
- 不支持原生工具调用的模型仅限只读问答，run 创建即 422，不进入 Coding 执行循环。
- Provider secret 保持在原生凭据边界：模型 profile 请求/响应 schema 无任何 secret 字段，服务层不接收不持久化（`test_model_profile_upsert_request_has_no_secret_field` 冻结）。

## 6. 可回退性（计划第 10 节）

- `PA_CODING_PERMISSION_MODELS_ENABLED` 关闭：profile API 409 隐藏，run 创建不校验 profile（默认 readonly 语义保留，零破坏）。
- 无权限模式的 run（v0.6.0 历史/非 coding run/默认预览）走 v0.6.0 路径：flag 开启的工具全部可见；关闭 PatchSet/命令 flag 后单文件 propose_patch/apply_patch_to_workspace 与只读工具不受影响。
- schema 全部 additive：model_profiles 新表、permission_mode/permission_snapshot_json 列不破坏既有表；快照键 `permission_mode` 为 E4 新契约（v0.6.0 时期无快照契约）。
- partial/unknown execution 仍只能人工处置（E1 契约），权限模式不改变该语义。
