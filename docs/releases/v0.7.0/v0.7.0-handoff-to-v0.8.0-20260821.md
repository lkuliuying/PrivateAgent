## 1. Coding 主链 DTO 与事件样本

### 1.1 PatchSet 工具输入（`propose_patch_set` / `apply_patch_set` 共用）

flag `PA_CODING_PATCHSET_ENABLED` 关闭时两个工具整体不可见；`apply_patch_set`
必须消费 ToolApproval（approval 记录与 `tool.approval_required` /
`tool.approval_resolved` 事件对应）。

```json
{
  "run_id": "7a66f8e1-d423-4e36-9aa7-659b77d15753",
  "base_head_sha": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "operations": [
    { "operation": "create", "path": "calc.py", "new_content": "def add(a, b):\n    return a + b\n" },
    { "operation": "update", "path": "main.py", "expected_old_sha256": "a" * 64, "new_content": "..." },
    { "operation": "delete", "path": "old.py", "expected_old_sha256": "b" * 64 },
    { "operation": "rename", "old_path": "src/a.py", "new_path": "src/b.py", "expected_old_sha256": "c" * 64 }
  ]
}
```

- `run_id` 由工具构造时绑定，模型不可改；`base_head_sha` 必须等于 run 创建快照
  （漂移拒绝，`git_snapshot_failed`）。
- `apply_patch_set` 额外要求 `preview_version` + `expected_parameters_hash`
  （预览返回）；任一不匹配 → `patchset_preview_stale` 409。
- 硬上限：文件数 ≤32、单文件 ≤500 KiB、总输入 ≤5 MiB、总 Diff 输出 ≤2 MiB
  （超出 → `patchset_invalid` 422）；二进制内容默认拒绝。
- 路径必须是 workspace 内规范化相对路径；拒绝绝对路径、`..`、设备路径
  （NUL/CON/COM1 等）、ADS（`file:stream`）、符号链接/目录联接/重解析点逃逸。

### 1.2 预览输出（`propose_patch_set`）

```json
{
  "patch_set_id": "ps-1",
  "preview_version": 1,
  "base_head_sha": "0123...",
  "parameters_hash": "d" * 64,
  "truncated": false,
  "file_count": 2,
  "additions": 12,
  "deletions": 3,
  "diff_total_bytes": 420,
  "files": [
    {
      "operation": "update",
      "path": "calc.py",
      "old_sha256": "e" * 64,
      "new_sha256": "f" * 64,
      "diff_text": "--- a/calc.py\n+++ b/calc.py\n@@ -1 +1 @@\n-def add(a, b):\n+def add(a, b): return a + b\n",
      "truncated": false
    }
  ]
}
```

- 预览持久化 PatchSet id/版本/参数哈希/base HEAD/每文件旧 SHA；磁盘只读，零写入。
- `truncated=true` 时不能直接应用（`patchset_truncated` 422），必须拆分重预览。
- 审批后参数、文件 SHA、workspace 或 HEAD 变化必须重新预览（`patchset_preview_stale` 409）。

### 1.3 命令输出 additive 字段（`run_whitelisted_command` / `run_whitelisted_command_trusted`）

v0.6.0 字段（args/cwd/returncode/stdout/stderr/output/truncated/succeeded/
cancelled/processes_remaining/profile）之上追加：

```json
{
  "args": ["uv", "run", "pytest", "-q"],
  "cwd": "F:/Program/Example",
  "returncode": 0,
  "output": "...",
  "succeeded": true,
  "processes_remaining": 0,
  "profile": "py-tests",
  "profile_version": 1,
  "parsed": {
    "parser": "pytest",
    "summary": "3 passed in 0.12s",
    "failures": [],
    "truncated": false,
    "passed": 3,
    "failed": 0,
    "skipped": 0,
    "errors": 0
  }
}
```

- `parsed` 是执行层对**已脱敏、有界输出**的确定性解析（11 种冻结 parser：
  pytest/ruff/mypy/compileall/npm_test/npm_build/npm_lint/vue_tsc/cargo_test/
  cargo_check/plain），供 WorkflowCompletionVerifier / Artifact 与报告引用，
  不信任模型文本声明。
- `failures` 条目：`{file(≤2048), line, column, code(≤128), message(≤4000)}`，
  最多 50 条；`summary` ≤8000；未知 parser 回落 plain。
- 命令继续使用 argv 数组（不经 shell）；`env_allowlist` 白名单注入仍拒绝
  代理/凭据类变量；`cwd_rel` 解析到 workspace 内（越界拒绝）。

### 1.4 run 权限快照（`agent_runs.permission_snapshot_json`，每次 run 保存）

```json
{
  "permission_mode": "confirm",
  "capabilities": ["filesystem_read", "filesystem_write", "process_execute"],
  "workspace": { "id": 12, "root_path_sha256": "64hex" },
  "command_profile_version": 1,
  "patch_limits": { "max_files": 32, "max_total_bytes": 5242880 },
  "remote_provider_data_policy": "no_send"
}
```

- 快照只存非秘密摘要：`root_path_sha256` 而非 root_path 原文、策略而非 secret。
- 历史 run 快照不因 profile 变化修改（E4 退出条件）。
- 错误响应与日志不得含 `root_path` 原文（脱敏规则沿用 v0.6.0 交接契约 §4.1）。

### 1.5 模型 profile（`GET/PUT/DELETE /agent-model-profiles[/{id}]`）

```json
{
  "id": "local-coder",
  "provider": "ollama",
  "display_name": "Local Coder",
  "is_local": true,
  "native_tool_calls": true,
  "supports_streaming": true,
  "supports_structured_output": true,
  "supports_vision": false,
  "context_tokens": 32768,
  "reasoning_efforts": ["low", "medium", "high"],
  "usage_reporting": true,
  "enabled": true
}
```

- flag `PA_CODING_PERMISSION_MODELS_ENABLED` 关闭时全部 409 `coding_mode_disabled`。
- 请求/响应 schema 无任何 secret 字段；服务层不接收、不持久化 secret/token/API key。
- 能力是 profile 显式声明的事实，**不通过模型名称猜测**。

### 1.6 完成条件（`agent_runs.completion_conditions_json`）

```json
{
  "must_succeed_tools": ["apply_patch_set"],
  "max_failed_tools": 0,
  "require_verified": true,
  "must_pass_command_profiles": ["py-tests"],
  "no_pending_patchsets": true,
  "final_git_diff": "nonempty"
}
```

- 模型不能自行降低完成条件；未满足 → `completion_conditions_unmet` 409 /
  `output_validation_failed` 失败关闭，run 不得 completed。
- 求值基于 durable 事实：`agent_tool_executions`（succeeded/verified）、
  `coding_patch_sets`（无 previewed 未决）、workspace Git diff（any/nonempty/empty；
  非 git 目录不可判定即失败关闭）。

### 1.7 v0.7.0 新增 durable 事件样本（additive，带 `(run_id, sequence)` 严格递增）

| event type | payload 样本 |
|---|---|
| `patch_set.preview_created` | `{"patch_set_id": "ps-1", "preview_version": 1, "file_count": 2, "truncated": false, "base_head_sha": "0123..."}` |
| `patch_set.applied` | `{"patch_set_id": "ps-1", "preview_version": 1, "verified": true}` |
| `patch_set.rolled_back` | `{"patch_set_id": "ps-1", "reason": "apply 失败已完整回滚"}` |
| `patch_set.failed` | `{"patch_set_id": "ps-1", "error_code": "patchset_conflict", "error_message": "..."}` |
| `patch_set.unknown` | `{"patch_set_id": "ps-1", "reason": "回滚失败，人工处置"}` |

- 投影语义：preview_created 追加预览视图；applied 更新状态；rolled_back/failed/
  unknown 更新状态（终端可解释）。v0.6.0 的 plan.created/plan.updated/
  plan.item_changed/artifact.created 及 runProjector 语义不变。
- `artifact.created` payload 结构不变，`kind` 集合扩展（见 1.8）。

### 1.8 Artifact kind 全集（`ARTIFACT_KINDS` 冻结 11 种）

- Artifact 只保存脱敏、有界、可展示内容；原始 execution 记录仍是审计事实源。

### 2.2 E2E 脚本化模型（v0.8.0 复用）

- `_ScriptedModel`：按脚本序列逐回合返回固定响应（工具调用/文本），用于确定性 E2E。
- `_ChainScriptedModel`：回合间携带上下文（如把读取结果注入下一回合参数）。
- `_FullLoopModel`：完整「读取→计划→修改→测试→报告」闭环脚本模型。
- `_resume_until_terminal`：批准 → resume 循环直到终态；`_facts_loader`：
  executions + patch sets + git diff 事实断言；`_dispatcher`：完整工具面
  （授予集 `{filesystem.read, filesystem.write, process.execute, database.query}`，
  与 `routes_agent_runs` confirm 授予集一致）；`_make_project`：真实项目 +
  `TrustedPathRepository.authorize` 授权。

## 3. 权限和模型 profile 列表

### 3.1 权限模式（`PERMISSION_MODES = {readonly, confirm, workspace}`）

| 模式 | 自动允许 | 需要确认 | 默认拒绝 |
|---|---|---|---|
| `readonly` | 搜索、读取、Git 状态/Diff | 无 | 写文件、命令、网络 |
| `confirm` | 搜索、读取、只读 Git | PatchSet（全部四类）、项目命令 | workspace 外、任意命令 |
| `workspace` | 搜索、读取、已授权 PatchSet、匹配项目命令 profile | delete/rename、异常大 PatchSet、特殊命令 | workspace 外、系统配置、任意网络 |

- `read_only` / `full_access` 不再是合法值（创建 coding run → 422
  `permission_mode_invalid`）；`confirm` 为两版集合交集保留。
- restricted 工具**不因 profile 切换自动获批**：注册层（ToolCapabilityPolicy
  RESTRICTED 恒 DENY）+ 执行层（`_resolve_command` 匹配 restricted profile 即拒绝）
  双重防护。
- `workspace` 模式命令 risk 动态化：项目无 enabled profile → risk None（默认
  confirm 审批）；全部 safe → SAFE 自动允许；存在 confirm/restricted → CONFIRM
  整体把关。

### 3.2 模型 profile 字段（`model_profiles` 表）

```text
id (≤128, PK), provider (≤100), display_name (≤200),
is_local (bool), native_tool_calls (bool),
supports_streaming / supports_structured_output / supports_vision (bool),
context_tokens (int), reasoning_efforts (json 数组),
usage_reporting (bool), enabled (bool), created_at, updated_at
```

- `native_tool_calls=False` 的模型仅限只读问答：coding run 创建 → 422
  `model_profile_unsupported`，不进入 Coding 执行循环。
- 无 secret 字段；Provider secret 保持在原生凭据边界（v0.6.0 移交的
  provider/原生凭据链路）。

### 3.3 项目命令 profile（`project_command_profiles` additive 扩展）

```text
profile_version (int, 默认 1), cwd_rel (≤2048, workspace 内相对目录),
env_allowlist (json 数组), allow_network (bool, 默认 false),
result_parser (冻结 11 枚举), risk_level (safe|confirm|restricted, 默认 confirm),
capability (≤64), max_output_bytes (int), description (≤512)
```

- update 即 `profile_version+1`；每次 coding run 快照记录最高版本；
  版本变化不修改历史 run（快照写入一次性）。

## 4. 状态矩阵（空态/运行/审批/失败/取消/重连/完成）

### 4.1 run 状态机（v0.6.0 冻结，v0.7.0 沿用）

`pending → running → {completed, failed, cancelled, timed_out, limit_exceeded}`；
`waiting_approval` 是运行中可暂停可恢复态（重启 reconcile 不失败关闭、批准续跑）。

### 4.2 PatchSet 状态机（`coding_patch_sets.status`）

```text
previewed → applied（全部文件 applied 且回读 verified）
previewed → failed（任一失败且完整回滚成功）
previewed → rolled_back（应用失败后完整回滚）
previewed → partial_unknown（无法完整回滚；人工处置，永不自动重放）
previewed → rejected（审批拒绝）
```

文件级 `coding_patch_set_files.status`：`pending → applied | rolled_back | unknown`。

### 4.3 审批状态机（`tool_approvals.status`）

`pending → {approved, rejected, expired, cancelled}`；`approved → consumed`
（一次性 token 消费，重复消费拒绝）。过期语义：`approve()` 对仍 pending 但超
TTL 的审批在事务内 `_expire_if_needed` → 标记 expired 并抛
`ToolApprovalExpiredError`（零消费、不自动重放；人工取消是唯一收敛路径）。

### 4.4 场景 × 状态矩阵

| 场景 | run | patch_set | 文件 | 审批 | 处置入口 |
|---|---|---|---|---|---|
| 空态（创建后） | running/waiting | — | — | — | 只读工具可见；写工具按模式注册 |
| 运行中（预览） | running | previewed | pending | — | propose 零写入；apply 需审批 |
| 审批等待 | waiting_approval | previewed | pending | pending | 批准 → resume 续跑；拒绝/取消 → rejected |
| 审批过期 | waiting_approval | previewed | pending | expired | 人工取消（唯一收敛）；不自动重放 |
| 应用成功 | running | applied | applied | consumed | verified=true；patch_set.applied 事件 |
| 内容冲突 | failed | failed | rolled_back | consumed | patchset_conflict；磁盘保持外部编辑 |
| HEAD 漂移 | failed | **previewed** | pending | consumed | git_snapshot_failed；零部分状态，人工重预览 |
| 应用失败已回滚 | failed | rolled_back | rolled_back | consumed | 逆序回滚 + 回读验证 |
| 回滚失败 | failed | partial_unknown | unknown | consumed | 人工处置；再次 apply 拒绝 |
| 取消 | cancelled | previewed/rejected | pending | cancelled/expired | cancel_waiting_approval |
| 重启（审批中） | waiting_approval | previewed | pending | pending | reconcile 不碰；批准续跑全链恢复 |
| 重启（崩溃后） | failed | applied/rolled_back | 终态 | consumed | 终态 Artifact 重建幂等 |
| 完成 | completed | applied | applied | consumed | 完成条件基于 durable 事实满足 |
| 完成条件未满足 | failed | 不定 | 不定 | 不定 | output_validation_failed；不得 completed |

### 4.5 flag 独立回退矩阵

| 组合 | PatchSet 工具 | 命令工具 | run_plan | 只读工具 | 单文件可信工作流 |
|---|---|---|---|---|---|
| 全关 | 不可见 | 不可见 | 不可见 | 保留 | 保留 |
| 仅 patchset | 可见 | 不可见 | 不可见 | 保留 | 保留 |
| 仅 command | 不可见 | 可见 | 不可见 | 保留 | 保留 |
| 仅 run_plan | 不可见 | 不可见 | 可见 | 保留 | 保留 |

`PA_CODING_PATCHSET_ENABLED` / `PA_CODING_COMMAND_PROFILES_ENABLED` /
`PA_CODING_ARTIFACTS_ENABLED` 依赖 project-bound；`PA_CODING_PERMISSION_MODELS_ENABLED`
独立。关闭任一 flag 只隐藏对应工具/API，不需要 schema downgrade；关闭 Artifact
UI 不删除 execution 事实；partial/unknown 只能人工处置，不能通过回退自动重跑。

## 5. 不得展示的敏感字段和隐藏推理清单

| 数据 | 约束 | 正确形态 |
|---|---|---|
| `root_path` 原文 | 不得进入错误响应、日志、toast、Artifact、快照 | 快照存 `root_path_sha256`；诊断包内脱敏 |
| approval token | 不得返回/展示明文 | 库中只存 `approval_token_sha256`；一次性消费 |
| Provider secret / API key | 不得进入 model_profiles、命令 env、Artifact、日志、Vue | 保持在原生凭据边界；env_allowlist 拒绝代理/凭据类 |
| 命令原始输出 | Artifact/报告不得内嵌完整输出 | `parsed` 摘要（≤8000）+ failures ≤50 条 + truncated |
| diff 原文 / new_content | patch_preview/patch_applied metadata 不含 | metadata 只含文件清单与统计 |
| 本地绝对路径 | 错误响应与日志不得含 | 相对路径（rel_path）、workspace id、root_path_sha256 |
| 模型隐藏推理 | 不向用户展示 chain-of-thought 原文 | 仅展示最终输出与工具事实 |
| 完成条件判定 | 不得由模型文本声明 | WorkflowCompletionVerifier 基于 durable 事实求值 |
