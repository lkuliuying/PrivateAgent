## 4. 实现要点与修复记录

- **E5 门禁测试初版三处断言与服务真实行为不一致，均已对齐**：
  - `_dispatcher` 测试 helper 的 capability 授予集缺 `DATABASE_QUERY`，导致 read_file/grep_code/git 等只读工具被 policy DENY、不进入 `model_definitions()`（模型不可见）。修复：授予集补齐 `{filesystem.read, filesystem.write, process.execute, database.query}`，与 `routes_agent_runs` 的 confirm 授予集一致。
  - 闭环读取改用 `read_code_file`（project_id + rel_path，不暴露绝对路径）：`read_file` 是文档读取工具（仅 .txt/.md/.markdown/.pdf/.docx），代码文件读取应走 coding 专用工具，且 read_code_file 的输入面更符合「不暴露任意路径」的安全契约。
  - `_make_project` 补 trusted path 授权（镜像真实应用 `ProjectService.authorize`）：read_code_file/propose 的路径授权依据是 `trusted_paths` 表，E2E 级测试必须走真实授权链。
- **HEAD 漂移状态语义对齐（E1 冻结）**：`PatchSetService.apply` 在进入应用前检测 HEAD 漂移（`git_snapshot_failed`），patch_set 保持 `previewed`（从未进入 applying，零部分状态），不是 `failed`。门禁断言改为：apply execution failed（error_message 含 HEAD/漂移）+ patch_set `previewed`（人工处置入口 = 重新预览）。
- **审批过期语义**：`approve()` 对「仍 pending 但已超 TTL」的审批在事务内触发 `_expire_if_needed` → 标记 expired 并抛 `ToolApprovalExpiredError`。门禁直接断言该路径（不再先调 `expire_due()` 全局批量过期——共享测试库残留其他 run 的到期审批会污染计数，且先过期后再 approve 会走 `ToolApprovalConflictError` 分支，两者语义不同）。
- **`AgentRunResult` 无 `error_code` 字段**（只有 `error` 文本）：失败关闭的错误码断言统一改为查 run 记录（`repository.get_run(run_id).error_code`），与 alpha.2 门禁惯例一致。
- **事件记录属性名**：`AgentRunRepository.list_events` 返回 ORM 记录，事件类型字段是 `event_type`（StrEnum 与字符串可比较），不是 `type`。

## 5. 安全契约核对（计划第 2/4/11 节）

- 闭环全程不暴露任意 Shell/PowerShell 字符串：命令走白名单 profile（argv 数组），测试断言 `parsed.passed` 与 `processes_remaining=0`。
- 不自动访问 workspace 外路径：read_code_file 以 project_id + rel_path 解析（`resolve_within`）；PatchSet 路径校验在 E1 冻结。
- 不自动 commit/push/部署/发布：E2E 中 git 仅用于快照/HEAD 检测，外部 commit 被识别为漂移并失败关闭。
- 不通过模型文本声明验证成功：完成条件由 WorkflowCompletionOutputVerifier 基于 executions/patch_sets/git diff durable 事实求值；模型文本只在条件满足后结束循环。
- 不把 PatchSet 拆成互不关联的单文件写入：闭环使用多文件 PatchSet（update + create 原子应用）。
- 审批过期/拒绝/取消均无自动重放：expired 审批零消费、取消是唯一收敛路径、resume 只重放已批准的那一次 pending 调用。

## 6. 可回退性（计划第 10 节）

- flag 矩阵实测：全关时只读工具 + `propose_patch`/`apply_patch_to_workspace` 单文件可信工作流保留；`coding_patchset_enabled` / `agent_command_workflow_enabled` / `agent_run_plan_enabled` 各自独立关闭只影响对应工具族；readonly 模式 + 全关时只读工具面完整。
- partial/unknown execution 仍只能人工处置（E1 契约）；重启恢复（reconcile + resume）不改变该语义——审批过期场景验证了「不自动重跑」。
- 本里程碑无 schema/flag 变更，纯测试与文档交付。
