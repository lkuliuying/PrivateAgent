# PrivateAgent v0.7.0 开发计划书

> 制定日期：2026-08-20
> 实施基线：`v0.6.0` 内部开发完成版
> 版本主题：可信编码执行 MVP
> 内部交付目标：`0.7.0-alpha.1 → 0.7.0-alpha.2 → 0.7.0-beta.1 → 0.7.0-rc.1 → 0.7.0`
> 观察策略：本版本只执行即时门禁；唯一自然日观察顺延至 `v1.0.0-rc.1`
> 策略依据：[观察期顺延决策](../observation-policy-20260820.md)
> 前置计划：[v0.6.0 开发计划](../v0.6.0/v0.6.0-development-plan-20260820.md)

## 1. 版本结论

`v0.7.0` 把 `v0.5.0` 的可信单步工作流与 `v0.6.0` 的 project-bound run 组合为可真实完成编码任务的执行闭环。

版本完成后，Agent 必须能在一个明确 workspace 内：

1. 搜索、读取和理解代码。
2. 生成可审查的多文件 PatchSet。
3. 经权限策略或审批原子应用 PatchSet。
4. 运行项目预配置的测试、lint、类型检查和 build。
5. 用可信 verifier 判断文件和命令结果。
6. 产出可恢复的 Diff、测试和最终报告 Artifact。
7. 在取消、超时、冲突和进程重启后收敛到可解释状态。

## 2. 复用与边界

直接复用：

- `ToolSpec`、`VersionedToolRegistry`、capability policy。
- ToolApproval、ToolExecution、checkpoint 和 execution claim。
- `propose_patch`、`apply_patch_to_workspace` 和命令工作流。
- FileDiff、Shell、CodeCommand 和 WorkflowCompletion verifier。
- `v0.6.0` 的 ProjectWorkspace、RunPlan、事件和 run projector 契约。

本版本不得：

- 暴露任意 Shell/PowerShell 字符串。
- 自动访问 workspace 外路径。
- 自动 commit、push、部署或发布。
- 通过模型文本声明验证成功。
- 把 PatchSet 实现成多个互不关联的单文件写入。
- 在 UI 组件中直接执行命令或写文件。

## 3. 版本范围

### 3.1 必须交付

| 领域 | v0.7.0 交付 |
|---|---|
| PatchSet | create/update/delete/rename、多文件预览、原子应用、哈希和 HEAD 冲突检测 |
| 项目命令 | 固定 argv/profile、cwd、环境白名单、流式输出、超时和进程树清理 |
| Artifact | Diff、文件清单、测试/lint/build 结果、最终报告 |
| 验证 | 文件回读、命令结果、完成条件和失败关闭 |
| 权限 profile | readonly/confirm/workspace 三模式及 run 快照 |
| 模型 profile | Provider 能力、工具支持、推理强度和本地/远程标识 |
| 恢复 | 审批、取消、重启、unknown execution 和人工处置 |

### 3.2 明确不做

- 新 Coding Workbench 全面上线。
- 自动 Git worktree 创建。
- 任意目录递归删除。
- 二进制 Patch。
- 交互式长期终端。
- 自动 PR、commit、push、部署和发布。
- HTTP/SQL 工作流的 UI 重做。

## 4. 安全契约

### 4.1 权限模式

| 模式 | 自动允许 | 需要确认 | 默认拒绝 |
|---|---|---|---|
| `readonly` | 搜索、读取、Git 状态/Diff | 无 | 写文件、命令、网络 |
| `confirm` | 搜索、读取、只读 Git | PatchSet、项目命令 | workspace 外、任意命令 |
| `workspace` | 搜索、读取、已授权 PatchSet、匹配的项目命令 profile | 高影响删除、异常大 PatchSet、特殊命令 | workspace 外、系统配置、任意网络 |

`workspace` 不等于整机完全访问。restricted 工具不能因 profile 切换自动获批。

每次 run 保存：

- permission mode
- capability 集合
- workspace id/root hash
- 项目命令 profile 版本
- Patch/命令限制
- 远程 Provider 数据策略

### 4.2 模型 profile

模型 profile 公开：

- id、Provider、模型显示名。
- local/remote。
- native tool calls。
- streaming、structured output、vision。
- context tokens。
- reasoning effort 集合。
- usage/cost reporting。

不支持原生工具调用的模型只能用于只读问答，不进入 Coding 执行循环。

## 5. PatchSet 设计

### 5.1 输入

```text
project_id
workspace_id
base_head_sha
operations[]:
  create { path, new_content }
  update { path, expected_old_sha256, new_content }
  delete { path, expected_old_sha256 }
  rename { old_path, new_path, expected_old_sha256, optional_new_content }
```

限制：

- 文件数、单文件大小、总输入字节和总 Diff 字节有硬上限。
- 路径必须是 workspace 内规范化相对路径。
- 拒绝绝对路径、`..`、设备路径、ADS、符号链接和重解析点逃逸。
- 默认拒绝二进制文件。
- delete/rename 的风险高于普通 update。

### 5.2 预览与审批

- 预览保存 PatchSet id、版本、参数哈希、base HEAD 和每个文件旧 SHA。
- UI 审批显示文件数、增删行、create/update/delete/rename 分类和截断状态。
- 预览被截断时不能直接应用，必须拆分为可完整审查的 PatchSet。
- 审批后参数、文件 SHA、workspace 或 HEAD 变化必须重新生成预览。

### 5.3 原子应用

应用顺序：

1. 再次校验 workspace、HEAD、路径和所有旧 SHA。
2. 在同一 workspace 内准备临时文件和回滚 manifest。
3. 全量准备成功后进入提交阶段。
4. 执行 rename/create/update/delete。
5. 回读所有目标并核对新 SHA/不存在状态。
6. 任一步失败执行回滚并验证。
7. 无法完整回滚时标记 `partial_unknown`，阻止自动续跑。

## 6. 项目命令设计

项目 command profile 声明：

- 固定 executable。
- 允许的子命令与参数模式。
- workspace 内 cwd。
- timeout、输出和进程上限。
- 环境变量白名单。
- 是否允许网络。
- 结果解析器。
- risk 和 capability。
- profile version。

MVP profile 优先覆盖：

- Python：pytest、ruff、mypy、compileall。
- Node：npm test、npm run build、npm run lint、vue-tsc。
- Rust：cargo check、cargo test。
- 项目自定义命令只能由用户预先保存和启用。

命令继续使用 argv 数组，不经 shell。取消、超时和应用退出必须清理完整进程树，并验证无残留端口或锁。

## 7. Artifact 与完成验证

Artifact 类型：

- `patch_preview`
- `patch_applied`
- `command_result`
- `test_report`
- `lint_report`
- `build_report`
- `final_report`

Artifact 只保存脱敏、有界、可展示内容；原始 execution 仍是审计事实源。

Coding 完成条件可声明：

- 必须成功的工具。
- 最大失败工具数。
- 是否必须 verified。
- 必须通过的 command profile。
- 是否必须无未决 PatchSet。
- 是否要求最终 Git Diff 非空或为空。

模型不能自行降低完成条件。

## 8. 里程碑

### E0 · 契约与威胁模型（1–2 天）

任务：

1. 冻结 PatchSet、Artifact、permission/model profile 契约。
2. 建立多文件写、删除、rename 和命令的威胁清单。
3. 先提交失败契约测试、fixture 和 feature flag。
4. 确定 execution 幂等和 unknown 处置语义。

退出条件：

- 高风险能力默认关闭。
- 不存在绕过 ToolSpec/approval/execution/verifier 的入口。

### E1 · PatchSet 预览与原子应用（3–4 天）

任务：

1. 实现 PatchSet repository/service/tool。
2. 实现多文件统一 Diff 和预览 Artifact。
3. 实现路径、HEAD、SHA 和 TOCTOU 防护。
4. 实现准备、提交、回滚和回读验证。
5. 覆盖 create/update/delete/rename。

退出条件：

- 未审批零写入。
- 成功写入全部 verified。
- 冲突和失败不留下未解释部分状态。
- unknown 状态不自动重放。

### `0.7.0-alpha.1`

E0–E1 完成后：

- PatchSet 契约、单元、数据库和文件系统故障测试通过。
- 不更新正式 updater。

### E2 · 项目命令与结果解析（2–3 天）

任务：

1. 统一 command profile 版本和解析。
2. 接入 project/workspace 绑定。
3. 完善 Windows 进程树清理。
4. 增加流式输出和输出分页。
5. 实现测试/lint/build 结果解析器。

退出条件：

- 非白名单 argv、cwd 和环境变量全部拒绝。
- 取消/超时/退出后残留进程为 0。
- 大输出不阻塞、不无限增长。

### E3 · Artifact 与完成条件（2–3 天）

任务：

1. 建立 Artifact repository/API。
2. 将 PatchSet、命令和 verifier 结果投影为 Artifact。
3. 接入 WorkflowCompletionVerifier。
4. 增加最终报告模板与来源引用。
5. 扩展公开事件和 DTO。

退出条件：

- Artifact 可恢复、可分页、可脱敏。
- 未满足完成条件时 run 不得 completed。

### `0.7.0-alpha.2`

E2–E3 完成后：

- “修改 → 测试 → 验证 → 报告”后端主链通过。
- 审批、取消、失败和重启恢复 fixture 冻结。

### E4 · 权限与模型 profile（2–3 天）

任务：

1. 实现三种权限模式和 run 快照。
2. 实现模型 profile/capability API。
3. 将 Provider secret 保持在原生凭据边界。
4. 增加权限扩大、profile 变化和远程数据策略测试。
5. 提供现有 UI 可用的最小设置入口。

退出条件：

- 权限模式可解释且默认最小。
- profile 变化不修改历史 run。
- 模型能力不通过名称猜测。

### E5 · Coding E2E 与恢复（2–3 天）

任务：

1. 完成真实示例项目 E2E。
2. 注入文件冲突、Git HEAD 漂移、命令失败和 sidecar 重启。
3. 覆盖审批过期、拒绝和取消。
4. 验证 run/project/workspace/Artifact 全链恢复。
5. 验证关闭每类 flag 的独立回退。

退出条件：

- 一个真实任务可以可信完成。
- 失败路径无重复副作用和幽灵状态。

### `0.7.0-beta.1`

E4–E5 完成后：

- 完整门禁、安装版 Coding smoke 和升级回退通过。
- 生成 beta evidence、manifest、flags 和已知问题。

### E6 · RC 与开发完成检查点（1–2 天）

1. 冻结 ToolSpec、profile、Artifact 和错误契约。
2. 执行 release-check-full、安装/updater/回退演练。
3. 冻结 `0.7.0-rc.1` 并执行一次完整即时门禁复核。
4. 门禁通过后形成 `0.7.0` 内部开发完成版，不切公开 updater，立即交接 v0.8.0。

## 9. 测试矩阵

| 场景 | 单元/契约 | 集成/E2E | 安装版/故障 |
|---|---|---|---|
| PatchSet create/update/delete/rename | 必须 | 必须 | 磁盘/权限故障 |
| SHA/HEAD 冲突 | 必须 | 必须 | 外部编辑注入 |
| 原子回滚 | 必须 | 必须 | 中途崩溃 |
| 项目命令 | 必须 | 必须 | 超时/进程树 |
| Artifact | 必须 | 必须 | 截断/脱敏 |
| 权限 profile | 必须 | 必须 | 越权/切换 |
| 模型 profile | 必须 | 必须 | 不支持工具/远程 |
| 完成条件 | 必须 | 必须 | verifier 失败 |

## 10. 回退

- 每类新工具使用独立 flag。
- 关闭 PatchSet 后保留单文件可信工作流和只读工具。
- 关闭 command profile 后不影响 PatchSet。
- 关闭 Artifact UI 不删除 execution 事实。
- 应用回退保留新表和 profile，不执行破坏性 downgrade。
- partial/unknown execution 只能人工处置，不能通过回退自动重跑。

## 11. 零容忍问题

- PatchSet 半写入且没有明确回滚/unknown 状态。
- workspace 外写入、链接逃逸或设备路径访问。
- 任意命令或 shell 控制符执行。
- 取消后残留子进程。
- 模型绕过完成条件或权限 profile。
- Secret 进入命令输出、Artifact、日志或 Vue。
- verifier 失败仍将 run 标为 completed。

## 12. 完成定义

`v0.7.0` 完成必须满足：

1. 真实项目可以完成读取、计划、修改、测试和报告闭环。
2. PatchSet 多文件操作原子、可审查、可验证。
3. 项目命令受 profile、权限、超时和进程树边界约束。
4. Artifact 和完成条件均有 durable 事实。
5. 权限和模型 profile 契约稳定。
6. 取消、冲突、拒绝、重启和 unknown 状态可恢复。
7. `0.7.0-rc.1` 即时完整门禁通过且无 P0/P1。

- 不得展示的敏感字段和隐藏推理清单。
