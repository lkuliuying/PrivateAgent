## 3. 测试覆盖（计划第 9 节矩阵，E2 行）

- 解析器单元：11 种各 1–2 例（统计计数、失败条目、无 code 后缀、cargo error+location 合并、截断 50 条上限、字段有界、未知回落）。
- profile 校验：cwd_rel 5 种非法形态、env_allowlist 3 种非法形态（含凭据类拒绝）、result_parser/risk_level/max_output_bytes 非法值，API 层 422 映射（含 PATCH 非法不递增版本）。
- CRUD/版本：create 默认 version=1、update 递增、非法更新拒绝。
- 执行落地：profile 前缀匹配（含 Windows 路径大小写）、cwd_rel 子目录、env_allowlist 注入且无凭据残留、越界旧数据执行时拒绝、非白名单拒绝。
- 真实执行：`run_whitelisted_command_trusted` 输出含 profile/profile_version/parsed；`CommandProfileService.run` 同落地。
- run 快照：coding run 创建后 `permission_snapshot_json` 含 `command_profile_version`（最高版本）。

## 4. 实现要点与修复记录

- **前缀匹配大小写 bug（既有）**：`_resolve_command` 前缀匹配未对 `args` 转小写，
  Windows 路径 `F:\Program\...` 永远匹配不上小写 profile 前缀；修复为双方 lower 比较。
- **解析器锚点 MULTILINE**：全部 `^...$` 行锚点正则补 `re.MULTILINE`（findall 默认只
  匹配字符串首尾，导致多行输出只解析第一行）。
- **mypy code 可选**：`error: msg [code]` 的 `[code]` 后缀在真实输出中可缺失；
  正则改为可选组，无 code 的行不产出 code 字段。
- **npm_build TS 前缀剥离**：`error TS2322: msg` 的 TS 代码剥离到 `code` 字段。
- **cargo location 缩进**：`  --> src/lib.rs:10:5` 行首缩进空格，`^-->` 修正为 `^\s*-->`。
- **repo.update 缺 profile_version 参数（断点）**：service 递增版本后 `**kwargs` 透传
  会 TypeError；repo.update 补参数并写入 values。
- **`_validate_profile_fields` 断点收尾**：service 已调用但函数未定义（NameError 风险）；
  本次补齐定义，并覆盖 capability/description 校验。
- **快照写读隔离**：coding run 快照断言经 client fixture 重绑的 factory 新建 session
  查询（MySQL REPEATABLE READ，同 E1 `_run_events` 约定）。

## 5. 安全契约核对（计划第 4 节）

- env_allowlist 配置期与执行期双重拒绝代理/凭据类变量（Provider secret 保持在
  原生凭据边界）；命令环境仍由 `build_safe_environment` 白名单构造。
- cwd_rel 解析始终经 `resolve_within`（root 内校验），配置期 + 执行期双防御。
- 命令继续使用 argv 数组（不经 shell）；超时/取消沿用 Job Object 进程树清理。
- `parsed` 基于执行层已脱敏、有界输出，不信任模型文本声明验证成功。

## 6. 可回退性（计划第 10 节）

- `PA_CODING_COMMAND_PROFILES_ENABLED` 默认关闭；关闭时 profile 新字段/解析对
  legacy 命令路径零影响（`_resolve_command` 无 profile 时行为与 v0.6.0 一致）。
- schema 全部 additive：输出字段（profile_version/parsed）、DB 列、API DTO 均向后兼容。
- 移除的 xfail 均以真实测试替换；剩余 2 个 xfail（E4 门禁）strict=True 保持提醒。
