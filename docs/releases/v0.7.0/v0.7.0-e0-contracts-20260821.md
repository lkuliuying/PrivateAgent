## 1. 与 v0.6.0 交接契约的兼容性

v0.7.0 冻结以下 v0.6.0 契约**不变**（直接复用）：

- durable 事件：`plan.created` / `plan.updated` / `plan.item_changed` /
  `artifact.created` 及其 runProjector 投影语义（plan 视图重建 / version
  更新 / item status 更新 / artifact 追加），payload 结构不变。
- `AgentRun` 创建模式判定（legacy / coding_context_incomplete 422 /
  coding_mode_disabled 409 / coding 幂等创建）、`client_request_id`
  幂等重放、`request_payload_sha256` 指纹比对。
- `ProjectWorkspace` 状态机、`RUNNABLE_WORKSPACE_STATUSES`、路径规范化
  与 `root_path_sha256` 大小写不敏感哈希。
- ToolSpec / VersionedToolRegistry / ToolCapabilityPolicy /
  ValidatedToolDispatcher、ToolApproval / ToolExecution / checkpoint /
  execution claim、`propose_patch` / `apply_patch_to_workspace` 单文件
  可信工作流、FileDiff / Shell / CodeCommand / WorkflowCompletion verifier。
- 迁移链 head = `0029`；v0.7.0 新迁移为 `0030`（additive，正式回退不
  执行破坏性 downgrade）。

v0.7.0 **显式替换** v0.6.0 契约（禁止静默扩大，见 §4）：

- `PERMISSION_MODES` 由 `{read_only, confirm, full_access}` 替换为
  `{readonly, confirm, workspace}`；`read_only` / `full_access` 不再是
  合法 run 创建值。`confirm` 保留（两版集合交集）。

v0.7.0 **新增** durable 事件（additive，全部带 `(run_id, sequence)`
严格递增语义，payload 脱敏有界，不改变 v0.6.0 事件形态）：

| event type | 必需 payload | 投影语义 |
|---|---|---|
| `patch_set.preview_created` | `patch_set_id`, `preview_version`(≥1), `file_count`(≥0), `truncated`, `base_head_sha` | 追加 PatchSet 预览视图（前端不覆盖） |
| `patch_set.applied` | `patch_set_id`, `preview_version`, `verified`(=true) | 更新 PatchSet 状态为 applied |
| `patch_set.rolled_back` | `patch_set_id`, `reason`(≤512) | 更新 PatchSet 状态为 rolled_back |
| `patch_set.failed` | `patch_set_id`, `error_code`(≤64), `error_message`(≤4000) | 更新 PatchSet 状态为 failed |
| `patch_set.unknown` | `patch_set_id`, `reason`(≤512) | 更新 PatchSet 状态为 partial_unknown（人工处置） |

`artifact.created` payload 结构不变；`kind` 集合扩展见 §3。

## 2. PatchSet 契约

### 2.1 工具与 flag

| 工具 | version | flag | risk | capability | 幂等 |
|---|---|---|---|---|---|
| `propose_patch_set` | `1.0.0` | `PA_CODING_PATCHSET_ENABLED` | safe | FILESYSTEM_READ | IDEMPOTENT |
| `apply_patch_set` | `1.0.0` | `PA_CODING_PATCHSET_ENABLED` | confirm | FILESYSTEM_READ + FILESYSTEM_WRITE | NON_IDEMPOTENT |

- 两个工具都绑定 run（构造时接收 `db` + `run_id`，通过 AgentRunRepository
  读取 run 的 project_id/workspace_id 与 Git 快照）。
- `propose_patch_set` 只读零写入；`apply_patch_set` 必须消费 ToolApproval
  （approval 记录与 `tool.approval_required` / `tool.approval_resolved`
  事件对应）。
- 关闭 flag 后 PatchSet 工具整体不可见；单文件 `propose_patch` /
  `apply_patch_to_workspace` 与只读工具不受影响（回退契约 §10）。

### 2.2 输入（`propose_patch_set` / `apply_patch_set` 共用）

```text
run_id                      (string, ≤36, 由工具构造时绑定，模型不可改)
base_head_sha               (string, 64 hex；必须等于 run 创建快照，漂移拒绝)
operations[]                (1..32 项)
  create   { path, new_content }
  update   { path, expected_old_sha256, new_content }
  delete   { path, expected_old_sha256 }
  rename   { old_path, new_path, expected_old_sha256, optional new_content }
```

- `apply_patch_set` 额外要求 `preview_version` + `expected_parameters_hash`
  （预览返回）；任一不匹配 → `patchset_preview_stale` 409，必须重新预览。
- 硬上限：文件数 ≤32、单文件 ≤500 KiB、总输入 ≤5 MiB、总 Diff 输出
  ≤2 MiB（超出 → `patchset_invalid` 422）。
- 路径必须是 workspace 内规范化相对路径；拒绝绝对路径、`..`、设备路径
  （`NUL`/`CON`/`COM1` 等）、ADS（`file:stream`）、符号链接/目录联接/
  重解析点逃逸。路径校验与 v0.5.0 `resolve_within` 语义一致。
- 默认拒绝二进制文件（含 NUL 字节或非 UTF-8 → `patchset_invalid`）。
- 同一 PatchSet 内路径必须唯一（含 rename 目标）；`create` 与 `delete`
  不得作用于同一路径。
- `delete` / `rename` 风险高于 `update`：`workspace` 模式下仍需确认
  （§4.1 高影响删除），`confirm` 模式全部操作需审批。

### 2.3 预览输出（`propose_patch_set`）

```text
patch_set_id, preview_version(≥1), base_head_sha,
parameters_hash(64 hex), truncated(bool),
file_count, additions, deletions, diff_total_bytes,
files[]: { operation, path, new_path?, old_sha256?, new_sha256?,
           diff_text(截断时有界), truncated(bool) }
```

- 预览持久化 PatchSet id、版本、参数哈希、base HEAD 和每个文件旧 SHA；
  磁盘只读，零写入。
- 预览被截断（`truncated=true`）时**不能直接应用**：`apply_patch_set`
  返回 `patchset_truncated` 422，必须拆分为可完整审查的 PatchSet。
- 审批后参数、文件 SHA、workspace 或 HEAD 变化必须重新生成预览
  （`patchset_preview_stale` 409）。

### 2.4 状态机

`coding_patch_sets.status`：

```text
previewed → applied（全部文件 applied 且回读 verified）
previewed → failed（任一失败且完整回滚成功）
previewed → rolled_back（应用失败后完整回滚）
previewed → partial_unknown（无法完整回滚；人工处置，永不自动重放）
previewed → rejected（审批拒绝）
```

文件级 `coding_patch_set_files.status`：`pending → applied | rolled_back |
unknown`。

### 2.5 原子应用（`apply_patch_set` 执行顺序）

1. 再次校验 run/workspace 匹配、`check_path`、HEAD 未漂移、所有路径合法、
   所有 `expected_old_sha256` 与磁盘一致（TOCTOU：重解析在写前执行）。
2. 同一 workspace 内准备全部临时文件（create/update/rename 的新内容）
   与回滚 manifest（delete/rename/update 的旧文件备份或旧 SHA）。
3. 全量准备成功后才进入提交阶段；提交顺序：rename → create → update →
   delete（rename 先于同路径其他操作，delete 最后）。
4. 任一步失败：按逆序回滚已应用操作并回读验证。
5. 回滚也失败 → `partial_unknown`，禁止自动续跑（dispatcher 侧
   `NON_IDEMPOTENT` + repository 状态检查双重保证）。
6. 全部成功 → 回读所有目标核对新 SHA / 不存在状态，全部通过才
   `applied` + `verified=true`。

### 2.6 威胁清单（E0 冻结）

| # | 威胁 | 防护 |
|---|---|---|
| T1 | PatchSet 半写入且无明确状态 | 回滚 manifest + 逆序回滚 + partial_unknown 终态 |
| T2 | 单文件写入成功、整体失败后状态误报 | 全量准备→提交→回读验证三段式；状态由 repository 事务更新 |
| T3 | 预览后文件被外部编辑（SHA 漂移） | apply 时重读全部旧 SHA，不匹配 `patchset_conflict` 409 |
| T4 | 预览后 Git HEAD 漂移 | apply 时重读 workspace HEAD 与 run 快照比对，`git_snapshot_failed` |
| T5 | 路径逃逸（`..`/绝对路径/链接/ADS/设备名） | `resolve_within` 规范化 + 最终组件链接拒绝 + 设备路径黑名单 |
| T6 | 参数与预览不一致（模型中途改参数） | `parameters_hash` + `preview_version` 强校验 |
| T7 | 截断预览被直接应用（模型未见全貌） | `truncated` 时 apply 硬拒绝 |
| T8 | 重复 apply 导致重复写入 | NON_IDEMPOTENT + approval 一次消费 + execution claim 去重 |
| T9 | delete/rename 被伪装成 update 蒙混审批 | 操作分类进入审批展示；workspace 模式 delete/rename 仍需确认 |
| T10 | 大文件/大 Diff 撑爆内存或审批界面 | 文件数/单文件/总字节硬上限 + 分页 + 截断标记 |
| T11 | rename 撞已有目标文件 | rename 目标路径唯一性校验 + 目标存在时冲突拒绝 |
| T12 | 回滚本身失败（崩溃/权限） | 回滚失败即 `partial_unknown`，禁止自动重试 |

## 3. Artifact 契约

`agent_run_artifacts.kind` 集合扩展（additive，0028 旧值保留）：

```text
v0.6.0: diff, file, command_output, test_report, summary
v0.7.0 新增: patch_preview, patch_applied, command_result,
            lint_report, build_report, final_report
```

- `test_report` 两版共用（v0.6.0 已冻结）。
- Artifact 只保存脱敏、有界、可展示内容；原始 execution 记录仍是审计
  事实源（回退契约：关闭 Artifact UI 不删除 execution 事实）。
- 新增 kind 由 `PA_CODING_ARTIFACTS_ENABLED` 控制写入；`artifact.created`
  事件形态不变。
- `final_report` 的 metadata 必须包含来源引用（run_id、关键 step_id、
  tool 名列表），不得内嵌完整命令输出或文件内容。

## 4. 权限模式契约

### 4.1 三模式（替换 v0.6.0 C0-D07 集合）

| 模式 | 自动允许 | 需要确认 | 默认拒绝 |
|---|---|---|---|
| `readonly` | 搜索、读取、Git 状态/Diff | 无 | 写文件、命令、网络 |
| `confirm` | 搜索、读取、只读 Git | PatchSet（全部四类）、项目命令 | workspace 外、任意命令 |
| `workspace` | 搜索、读取、已授权 PatchSet、匹配项目命令 profile | delete/rename、异常大 PatchSet、特殊命令 | workspace 外、系统配置、任意网络 |

- `workspace` 不等于整机访问；`restricted` 工具**不因 profile 切换自动
  获批**（ToolCapabilityPolicy 的 RESTRICTED 分支不变）。
- `PERMISSION_MODES = {"readonly", "confirm", "workspace"}`；`read_only` /
  `full_access` 不再是合法值（替换测试见 §9）。

### 4.2 run 权限快照（每次 run 保存，持久化后不可静默扩大）

```json
{
  "permission_mode": "confirm",
  "capabilities": ["filesystem_read", "filesystem_write", "process_execute"],
  "workspace": {"id": 12, "root_path_sha256": "64hex"},
  "command_profile_version": 1,
  "patch_limits": {"max_files": 32, "max_total_bytes": 5242880},
  "remote_provider_data_policy": "no_send"
}
```

- 快照写入 `agent_runs.permission_snapshot_json`；错误响应与日志不得含
  `root_path` 原文（脱敏规则沿用交接契约 §4.1）。
- 历史 run 快照不因 profile 变化修改（E4 退出条件）。

## 5. 模型 profile 契约

新表 `model_profiles`（`PA_CODING_PERMISSION_MODELS_ENABLED` 控制 API）：

```text
id (≤128, PK), provider (≤100), display_name (≤200),
is_local (bool), native_tool_calls (bool),
supports_streaming / supports_structured_output / supports_vision (bool),
context_tokens (int), reasoning_efforts (json 数组),
usage_reporting (bool), enabled (bool), created_at, updated_at
```

- **不支持原生工具调用的模型只能用于只读问答，不进入 Coding 执行循环**
  （`model_profile_unsupported` 422；run 创建时校验）。
- 模型能力**不通过名称猜测**：`native_tool_calls` 等能力字段是 profile
  显式声明的事实（E4 退出条件）。
- Provider secret 保持在原生凭据边界：`model_profiles` 不存任何 secret/
  token/API key；`permission_snapshot_json` 只存非秘密策略摘要。

## 6. 项目命令 profile 版本化契约

`project_command_profiles` additive 扩展（E2 实施，`PA_CODING_COMMAND_PROFILES_ENABLED`）：

```text
profile_version (int, 默认 1), cwd_rel (≤2048, workspace 内相对目录),
env_allowlist (json 数组), allow_network (bool, 默认 false),
result_parser (enum: pytest|ruff|mypy|compileall|npm_test|npm_build|
  npm_lint|vue_tsc|cargo_test|cargo_check|plain),
risk_level (enum: safe|confirm|restricted, 默认 confirm),
capability (≤64), max_output_bytes (int), description (≤512)
```

- 命令继续使用 argv 数组，不经 shell；取消/超时/退出必须清理完整进程
  树并验证无残留端口或锁（沿用 v0.5.0 Job Object）。
- MVP profile 优先覆盖：Python（pytest/ruff/mypy/compileall）、Node
  （npm test/build/lint、vue-tsc）、Rust（cargo check/test）。
- 项目自定义命令只能由用户预先保存和启用；非白名单 argv、cwd、
  环境变量全部拒绝（`command_profile_invalid` 422）。
- 每次 run 快照记录 command profile 版本；版本变化不修改历史 run。

**命令输出 additive 扩展（E2 落地）**：`run_whitelisted_command` 输出
在 v0.6.0 字段（args/cwd/returncode/stdout/stderr/output/truncated/
`succeeded`/cancelled/processes_remaining/profile）之上追加：

```text
profile_version (int ≥1)：匹配 profile 的版本号（未匹配省略）
parsed (object|null)：按 profile.result_parser 解析的结构化结果
  {parser, summary(≤8000), failures[≤50], truncated}
  可选计数：passed/failed/skipped/errors/warnings（均 ≥0）
  失败条目：{file(≤2048), line, column, code(≤128), message(≤4000)}
```

- `parsed` 是执行层对**已脱敏、有界输出**的确定性解析，供
  WorkflowCompletionVerifier / Artifact 与报告引用（不信任模型文本声明）；
- `max_output_bytes` 折算为输出截断上限（默认 30k 字符，profile 可收紧），
  截断时 `truncated=true`；
- `env_allowlist` 白名单注入仍拒绝代理/凭据类变量（Provider secret
  保持在原生凭据边界）；`cwd_rel` 非空时解析到 workspace 内（越界拒绝）。

## 7. 完成条件契约

沿用 `agent_runs.completion_conditions_json`（0026 冻结结构）并扩展：

```text
must_succeed_tools[]、max_failed_tools、
require_verified、must_pass_command_profiles[]、
no_pending_patchsets (bool)、final_git_diff (enum: any|nonempty|empty)
```

- 模型不能自行降低完成条件（`completion_conditions_unmet` 409 时 run
  不得 completed，verifier 失败仍 completed 属零容忍问题）。
- 满足条件由 `WorkflowCompletionVerifier` 基于 durable executions 事实
  求值（不信任模型文本声明）。

## 8. Feature flags（E0 冻结，全部默认关闭）

| flag | 依赖 | 说明 |
|---|---|---|
| `PA_CODING_PATCHSET_ENABLED` | project-bound | PatchSet 多文件工具 |
| `PA_CODING_COMMAND_PROFILES_ENABLED` | project-bound | 命令 profile 版本化 + 结果解析 |
| `PA_CODING_ARTIFACTS_ENABLED` | project-bound | Artifact 扩展 kind + 最终报告 |
| `PA_CODING_PERMISSION_MODELS_ENABLED` | 无 | 权限三模式 + 模型 profile API |

- 开启顺序：project-bound → 各编码 flag；关闭顺序相反；关闭任一 flag
  只隐藏对应工具/API，不需要 schema downgrade（回退契约 §10）。
- 全部编码 flag 关闭时，v0.6.0 行为完全不变。
