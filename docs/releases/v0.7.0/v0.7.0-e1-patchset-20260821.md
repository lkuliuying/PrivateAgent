## 3. 测试覆盖（计划第 9 节矩阵，E1 行）

- 四类操作 create/update/delete/rename：全链路 + 统一 Diff + 提交顺序（rename→create→update→delete）。
- SHA/HEAD 冲突：预览后外部编辑（patchset_conflict）、Git HEAD 漂移（git_snapshot_failed，零写入）。
- 原子回滚：回读验证失败回滚、提交中途失败回滚（`_CommitFailed`，已执行部分逆序恢复）、回滚失败 → partial_unknown。
- 磁盘/权限故障：`_CommitFailed` 注入模拟 IO 失败；`.pa-*` 临时文件零残留断言。
- 路径安全：8 种越界/设备名/ADS/NUL/反斜杠参数化拒绝；二进制内容拒绝；重复路径（含 rename 目标冲突）拒绝。
- truncated（T7）与 stale 预览（T6）硬拒绝。
- flag 回退：关闭后两个工具不可见、单文件可信工作流保留（`test_patchset_tools_invisible_when_flag_off`）。

## 4. 实现要点与修复记录

- **SHA 文本语义**：磁盘回读统一 `read_text`（universal newline）后 UTF-8 编码计算，
  与预览/声明 SHA（LF）一致，避免 Windows CRLF 字节哈希不一致（对齐
  `patch_workflow` 既有约定）。
- **rename 源删除**：`_commit_all` rename = 新路径就位 + 删除源；源删除失败视同已执行
  （回滚删除新文件并恢复源），杜绝「rename 源仍存在」与孤儿新文件。
- **失败路径临时文件清理**：`_handle_failure` 两个出口（rolled_back / partial_unknown）
  均调用 `_cleanup_staged`，未执行 ops 的 `.pa-stg` / `.pa-bak` 不残留。
- **事件写读隔离**：`_emit_event` 独立事务写 durable 事件；测试断言经 conftest 重绑的
  factory 新建 session 查询（MySQL REPEATABLE READ 快照早于独立写入，主 session
  不可见；生产路径每请求独立 session 无此问题）。
- **审批前置**：`apply_patch_set` 通过 ValidatedToolDispatcher + SqlToolApprovalRequester
  消费 ToolApproval；测试 run 写入 `tool.requested`（running tool step）满足审批投影。
