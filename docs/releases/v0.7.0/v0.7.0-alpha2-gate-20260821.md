## 4. 实现要点与修复记录

- **E0 §2.4 rejected 路径缺口（上轮修复）**：审批拒绝未回写 PatchSet → 状态悬空。`cancel_waiting_approval` flag 门控 `mark_rejected_for_run`，拒绝即 `rejected` 终态。
- **record_event / reconcile 陈旧缓存读（生产代码缺陷，测试捕获）**：`expire_on_commit=False` 的 session 中，`db.get`/`SELECT` 对 identity map 已缓存对象不刷新属性 → `last_event_sequence` 陈旧 → `expected` 校验通过但实际 sequence 已占用 → `uk_agent_run_event_sequence` 冲突。修复：`record_event` 的 run 读取与 `reconcile` 的 run 读取均改为 `with_for_update + populate_existing=True`（当前读 + 强制刷新）。
- **PatchSet durable 事件与 runtime 事件流序列竞争（生产代码缺陷，主链 E2E 捕获）**：`patch_set_service._emit_event` 经独立 session 用 `run.last_event_sequence + 1` 分配序列，而 runtime 在工具执行前已把 TOOL_STARTED 提交为 N（内存 next=N+1）；工具执行中 `_emit_event` 写入 N+1，随后 runtime 的 TOOL_COMPLETED=N+1 冲突。修复：runtime 在每次工具执行后 `sync_sequence()`（sink 提供 `latest_sequence` 读 DB 最新已提交序列，内存序列取 max 校准），TOOL_COMPLETED 等后续事件与外部 durable 事件衔接；resume（`_resume_drive`）路径同样校准。checkpoint 序列基于校准后 next，恢复语义不变。
- **契约缺陷：`base_head_sha` pattern 误用 64 位 SHA-256**：真实 git HEAD 是 40 位 SHA-1，`PROPOSE_PATCH_SET_OUTPUT.base_head_sha` 复用 `_SHA256_PATTERN`（`^[0-9a-f]{64}$`）导致真实 git 项目 propose 输出校验失败。修复：新增 `_GIT_HEAD_PATTERN`（`^[0-9a-f]{40,64}$`，兼容未来 SHA-256 仓库），仅 `base_head_sha` 使用；`parameters_hash` 等应用内 SHA-256 不变。
- **测试驱动重构**：propose/apply/command 全部经 `AgentRuntime.run` 驱动（`SqlAgentRunEventSink` 持久化），TOOL_REQUESTED 投影创建 tool step，execution claim 契约完整；新增 `_ChainScriptedModel`（propose 输出动态构造 apply 参数，apply 依赖 preview 的 patch_set_id 无法预构造）；run.started 由 runtime 发出（`start_event=False`），避免 `PersistentAgentRunner.run` 无条件 create_run 的 PRIMARY 冲突。
- **回归补漏（E2 遗留）**：`run_whitelisted_command.output` 冻结 digest 未随 E2 additive 契约（profile_version/parsed）更新 → 更新 `test_workflow_contracts.py` 冻结值；`patch_sets._execute_command` 新增 `env` 参数后 `test_phase4_patch_sets.fake_exec` 签名未适配 → 补 `env=None`。

## 5. 安全契约核对（计划第 4/11 节）

- 命令只经 argv 数组与白名单 profile（真实 pytest 进程树清理 processes_remaining==0），不暴露任意 Shell/PowerShell 字符串。
- 完成条件全部基于 durable 事实（executions / coding_patch_sets / Git 快照）求值；模型文本不能宣称验证成功（`require_verified` + `final_git_diff` + Shell verifier 组合）。
- 审批一次性 token 消费；拒绝零写入；unknown/partial 状态不自动重放（claim unknown → `execution_state_unknown` 拒绝自动重试）。
- 报告 Artifact 脱敏：不内嵌完整命令输出、diff 原文与绝对路径。

## 6. 可回退性（计划第 10 节）

- 本次未新增 flag；行为修复（当前读/序列校准）在既有 flag 语义下生效，关闭 PatchSet/命令 flag 后不影响只读工具与单文件可信工作流。
- runtime 序列校准仅在 sink 提供 `latest_sequence` 时生效（getattr 探测），内存 sink/测试 sink 零影响；事件序列仍满足 E0 严格契约（每次提交 `expected = last + 1`）。
- 既有事件/DTO 契约（plan.created / plan.updated / plan.item_changed / artifact.created）未改动，`patch_set.*` 事件保持 additive。
