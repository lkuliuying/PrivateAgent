## 4. 行为变更（对调用方可见）

1. **F-002 预检失败关闭**：coding run 明确 file.mutate 意图但本轮没有任何
   可真正落盘的工具入口（Patch/PatchSet flag 全关或 readonly 权限）时，
   创建从 202 变为 409 结构化错误。受影响的既有 H1-B 用例已按新契约更新
   （开启 patch flag 后验证门槛持久化）。遥测新增低基数路径 `tool_preflight`
   （blocked/allowed），公开契约测试同步登记。
2. **完成判定收口（单一判断实现）**：`min_tool_executions` 与
   `require_successful_file_write` 两个条件族自本迭代起由
   `evaluate_completion` 唯一求值；路由装配时旧 verifier 对应分支让位
   （传 0/False），不再双判。契约由持久化 `completion_conditions_json`
   确定性重建，create/resume 得到同一 `contract_id`。
3. **F-008 修复**：显式"只预览/不要写入"请求清除 filesystem.write 要求，
   不再注入 `require_successful_file_write`，proposal 即可完成；同时豁免
   写入预检。规则层新增公开辅助 `core.executable_intent.has_preview_only_marker`。
