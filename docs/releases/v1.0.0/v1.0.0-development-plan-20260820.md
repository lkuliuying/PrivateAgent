> 计划以 [v1.0.0 Agent 架构代际升级开发计划](./v1.0.0-agent-rearchitecture-plan-20260824.md) 为准。

> 制定日期：2026-08-20
> 实施基线：`v0.9.0` 内部开发完成版
> 版本主题：本地 Coding Agent 稳定发布
> 发布目标：`1.0.0-beta.1 → 1.0.0-beta.2 → 1.0.0-rc.1 → 1.0.0`

## 1. 版本结论

`v1.0.0` 是 Coding Agent 重构路线的稳定收口版本。本版本不新增工具和大功能，只完成公开契约冻结、旧执行链隔离、升级回退、可靠性、安全、文档和正式发布。

稳定版产品定义：

- 单用户、本地优先的 Windows Coding Agent 桌面应用。
- 以 Project → Workspace → Thread → Run 为核心。
- 具备搜索、读取、多文件 PatchSet、项目命令、验证和 Artifact。
- 权限、模型、路径、Git、审批和副作用可审计。
- 长任务可取消、可恢复、可诊断。
- 前端只消费公开运行事实，不参与 Agent 决策循环。

## 2. v1.0 支持范围

### 2.1 正式支持

- Windows 10/11 x64。
- Tauri 安装版和本地 FastAPI sidecar。
- MySQL 事实库和现有 Chroma 索引边界。
- 本地 Ollama 与已支持的远程 Provider。
- 原生工具调用模型。
- 项目根 workspace 和可选 Git worktree。
- Python、Node/Vue、Rust 常见项目命令 profile。
- 项目授权、代码读取、PatchSet、验证和最终报告。
- 安装、覆盖升级、自动更新、应用回退和数据保留。

### 2.2 已知边界

- macOS/Linux 不作为正式支持平台。
- 不提供云同步、多人协作和多租户。
- 不提供任意 Shell、自动 push、PR 或部署。
- 不提供完整 IDE、LSP、调试器和交互终端。
- 自动化和插件市场保留现有能力，不属于 1.0 Coding 主线承诺。
- 旧个人助手业务数据保留，但不作为 1.0 主界面核心体验。

## 3. 版本范围

### 3.1 必须交付

| 领域 | v1.0.0 交付 |
|---|---|
| 契约冻结 | Run、Plan、Tool、Approval、Artifact、Workspace、Permission、Model Profile |
| 旧链隔离 | 旧 planner、前端工具续跑和旧 UI 默认禁用，保留显式回退 |
| 数据兼容 | `v0.5.0-rc.4`、`v0.8.0`、`v0.9.0` 内部完成版升级与应用回退 |
| 安全 | 路径、审批、命令、Provider、日志、诊断、凭据和更新链 |
| 可靠性 | 长任务、恢复、unknown execution、进程清理和数据一致性 |
| 性能/UX | 大项目、长 transcript、视觉、a11y、资源和启动体验 |
| 文档 | 使用、架构、API、安全、测试、部署、升级、故障与已知限制 |
| 发布 | 正式安装包、签名、manifest、公开 updater、14 天 RC 证据 |

### 3.2 明确不做

- 任何新的模型 Provider、工具类别或数据库架构重写。
- 物理删除旧个人助手业务表。
- 破坏性 schema downgrade。
- RC 期间调整视觉方向或信息架构。
- 为追求 1.0 标签隐藏已知限制或降低门禁。

## 4. 公开契约冻结

冻结以下契约：

1. Project、ProjectWorkspace 和 CodingThread DTO。
2. AgentRun 创建、查询、取消和状态集合。
3. RunPlan item、版本和状态。
4. AgentRun durable event 类型、顺序和错误格式。
5. ToolApproval、ToolExecution、输出分页和人工处置。
6. PatchSet、项目命令和 Artifact。
7. Permission/Profile 和 ModelProfile。
8. Context 来源、引用、隐私和远程 Provider 标识。
9. 诊断、capabilities、兼容 telemetry 和 feature flag。

冻结后：

- 破坏性变化进入 `v2.0.0` 或明确的兼容迁移版本。
- `v1.x` 只允许 additive 字段和向后兼容事件。
- UI 不得消费数据库内部字段或隐藏 Runtime 状态。

## 5. 旧链隔离

`v1.0.0-rc.1` 观察前执行默认隔离，但不物理删除兼容路径：

- 桌面新消息默认不调用 `/tools/plan`，旧调用只在显式 legacy 回退下可达。
- 前端 plan-then-reply 和 tool result 二次提交不参与默认主链。
- `buildAgentPlan()` 不再产生权威状态，只供显式旧 UI 读取历史数据。
- 旧 ChatView/WorkspaceShell 双轨隐藏到显式诊断回退入口。
- 临时 UI flag 收敛为一个有 telemetry 的 legacy 回退开关。
- 可删除与兼容回退无关的重复状态组件和 re-export，但不得破坏旧数据读取。

暂不删除：

- 旧数据库表和历史记录。
- 读取旧 session/tool-call 的兼容 API。
- 数据导出和诊断所需 repository。
- 个人助手次级工作区所需 API。

兼容路径的物理删除统一推迟到 v1.0 最终观察通过后的独立版本，不能在 RC 观察后夹带删除代码。

## 6. 升级与回退矩阵

必须实机覆盖：

| 来源 | 目标 | 重点 |
|---|---|---|
| `v0.5.0-rc.4` | `v1.0.0-rc.1` | 旧项目、session、工具执行、Provider 和 schema 跨版本升级 |
| `v0.8.0` 内部完成版 | `v1.0.0-rc.1` | 新 UI 数据与默认值切换 |
| `v0.9.0` 内部完成版 | `v1.0.0-rc.1` | 直接升级、worktree 和兼容隔离 |
| `v1.0.0-rc.1` | `v0.9.0` 内部完成版 | 应用回退、schema 保留、数据可读 |
| 全新安装 | `v1.0.0-rc.1` | 首启、项目授权、Provider 和首个任务 |

升级前：

- 创建数据库 clone 和精确表计数/hash manifest。
- 记录 schema、应用版本、项目/workspace/session/run/artifact 计数。
- 校验磁盘空间、备份和凭据引用。

升级后：

- 数据计数和关键关系一致。
- root workspace 回填幂等。
- 未决审批和 run 可恢复或明确归档。
- 旧会话仍可访问和导出。
- 回退旧应用时不要求 schema downgrade。

## 7. 安全与可靠性门禁

### 7.1 安全

- Loopback API token、Host、Origin 和 CSP。
- OS keyring 与远程 Provider secret。
- 路径穿越、符号链接、重解析点、ADS 和设备路径。
- PatchSet SHA、HEAD、TOCTOU、partial rollback。
- 命令 argv/profile、环境白名单、超时和进程树。
- 审批参数替换、过期、重放和双消费。
- RAG/项目资料提示注入和权限升级尝试。
- 日志、诊断、Artifact、通知和备份脱敏。
- updater 签名、公开 endpoint 和安装包身份。

### 7.2 可靠性

- 24 小时长 run/空闲混合压力。
- 5,000+ transcript/event 投影。
- 大 Diff、输出洪泛和截断。
- sidecar、MySQL、Ollama、Provider 和网络故障。
- owner lock 竞争和应用重复启动。
- 正常退出、强杀、重启和 unknown execution。
- 磁盘满、只读目录、文件占用和 Git 冲突。
- Windows 125%/150% 缩放和窗口最小尺寸。

## 9. 里程碑

### R0 · 1.0 范围与契约冻结（1–2 天）

任务：

1. 冻结支持矩阵、公开契约和已知限制。
2. 审核 v0.9 兼容归零报告。
3. 冻结默认禁用/保留/观察后删除候选清单。
4. 建立 1.0 测试、升级和证据矩阵。
5. 禁止新增功能进入 1.0。

退出条件：

- 1.0 范围不再变化。
- 所有默认禁用项有 telemetry 证据和回退方案。

### R1 · 旧链隔离与工程收口（2–3 天）

任务：

1. 从默认路径移除前端 planner 和二次提交逻辑，保留显式 legacy 回退。
2. 默认隐藏旧 UI 双轨，把临时 flag 收敛为单一回退开关。
3. 清理不影响回退的 re-export、重复类型和无调用组件。
4. 保留旧数据读取/导出边界。
5. 执行 dead code、bundle 和依赖审计。

退出条件：

- 同一请求只有一个 Runtime 主链。
- App.vue、API、types 和 coding feature 边界稳定。
- 旧数据仍可读取。

### `1.0.0-beta.1`

R0–R1 完成后：

- 功能和公开契约冻结。
- 全量自动化、页面和兼容测试通过。
- 不更新正式 updater。

### R2 · 升级、回退与数据验证（2–3 天）

任务：

1. 完成三来源升级矩阵。
2. 验证数据库 clone、行数、关系和 hash。
3. 完成应用回退与数据保留。
4. 完成 worktree、未决审批和 orphan run 迁移。
5. 更新 database upgrade runbook。

退出条件：

- 数据损坏和丢失为 0。
- 回退不需要破坏性 downgrade。

### R3 · 全门禁与故障硬化（2–3 天）

任务：

1. 完整安全回归和故障注入。
2. 长任务、长 transcript 和大项目压力。
3. 进程、SSE、监听器、内存和临时文件清理。
4. 视觉、a11y、性能和安装版 smoke。
5. 修复全部 P0/P1 和发布阻断 P2。

退出条件：

- release-check-full 无失败。
- P0/P1 为 0。
- 所有失败路径可恢复或明确结束。

### `1.0.0-beta.2`

R2–R3 完成后：

- 形成 RC 候选。
- 升级/回退/安装/安全/性能证据完整。
- 仅允许阻断缺陷修复。

### R4 · 文档、发布物与 RC 准备（1–2 天）

任务：

1. 完成用户、架构、API、安全和运维文档。
2. 构建签名安装包和 updater manifest。
3. 生成 qa-evidence、release-check、flags、SHA 和已知问题。
4. 完成公开更新通道匿名下载与 in-app 演练。
5. 冻结唯一候选 commit 和二进制。

退出条件：

- 文档与实际产品一致。
- 所有证据绑定同一 commit、版本和安装包。

### R5 · 全部开发完成后的 `1.0.0-rc.1` 14 天观察

观察规则：

- 候选代码、安装包和 updater 资产冻结。
- 每日记录启动、退出、run、审批、恢复、失败和 updater 状态。
- 不记录用户代码、完整路径、命令输出或隐藏推理。
- 任何功能代码修改必须升 rc 版本并重新开始观察。
- 文档补充必须声明不属于候选代码。

观察至少覆盖：

- Python、Vue/Node、Rust 真实项目。
- 根 workspace 与 Git worktree。
- 多文件 PatchSet 和项目命令。
- 审批、拒绝、取消、冲突和恢复。
- 本地和远程 Provider。
- 正常退出、异常退出、数据库/模型中断。
- updater 检查、下载、验签、安装、重启和数据保留。

通过门槛：

- 无未处置 P0/P1。
- 数据损坏、重复副作用、审批绕过和秘密泄漏为 0。
- 无不可解释 legacy 调用。
- 无长期 orphan run 或残留进程。
- 关键错误率、恢复率和性能在既定门槛内。

### R6 · `1.0.0` 稳定发布

1. 将版本统一为 `1.0.0`。
2. 重新执行完整 release-check 和版本一致性检查。
3. 构建正式安装包、签名和 manifest。
4. 发布源码仓库稳定 Release。
5. 发布公开 updater 资产并切换 latest。
6. 匿名下载校验 SHA 和签名。
7. 从 RC 安装版执行一次正式 updater 演练。
8. 更新 CHANGELOG、README、文档索引和支持说明。

## 11. 零容忍问题

- 数据损坏或丢失。
- 重复 Patch/命令副作用。
- 审批或权限绕过。
- workspace 外访问或路径逃逸。
- unknown execution 自动重试。
- 失败或未验证结果显示为完成。
- 取消/退出后残留进程或永久 run。
- Secret 或用户代码进入日志、诊断、通知或发布证据。
- 正式 updater 资产、版本、签名或 SHA 不一致。
- 新旧执行链同时处理同一请求。

## 12. 回退

- 正式发布前保留 `v0.5.0-rc.4` 公开基线和 `v0.9.0` 内部完成版安装包、签名与 manifest。
- updater 在 v1.0 stable 前继续指向既有公开基线，不自动 schema downgrade。
- `v0.9.0` 内部完成版应能忽略 1.0 additive 数据并读取核心历史。
- 新增数据保留，必要时通过“更多工作区”或导出访问。
- 如发现数据或安全阻断问题，停止 latest 发布并回退 updater，而不是热修隐藏。

## 13. 完成定义

`v1.0.0` 只有在以下条件全部满足时完成：

1. Coding Agent 是唯一默认主链。
2. 前端不参与 Agent 决策循环。
3. Project、Workspace、Thread、Run、Plan、Tool、Approval 和 Artifact 契约冻结。
4. 真实项目读取、修改、测试、验证和报告主链稳定。
5. 权限、路径、Git、命令、Provider 和凭据边界通过安全验收。
6. 崩溃、断线、取消、冲突和 unknown execution 可恢复或人工处置。
7. 从 `v0.5.0-rc.4` 和内部完成版升级、应用回退不丢数据。
8. 旧 planner/UI 默认隔离且显式回退可用；物理删除有观察后的独立计划。
9. 自动化、安装版、视觉、a11y、性能和发布门禁全绿。
10. `1.0.0-rc.1` 完成 14 天观察，无未处置 P0/P1。
11. 正式安装包、签名、manifest、Release 和 updater 一致。
