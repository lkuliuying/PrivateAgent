### 1.1 负责人评审补充决议

1. **全量 pytest 门禁超时从 600 s 调整为 900 s。** 独立实测 1093 passed / 2 skipped 耗时 581.07 s，调整只增加进程等待窗口，不减少用例、不改变失败判定，不属于产品性能阈值放宽。
2. **Authenticode 改为公开发布硬门禁，不阻断 S2。** 内部 v0.9 工程基线以 updater minisign 已验证 + `code_signed=no` + unsigned note 进入后续开发；未补齐 Authenticode 前禁止公开 `v0.9.0` tag、上传公开 updater `latest` 或宣称已正式发布。
3. **ADR 评审结论：** ADR-001/002/003/005 转 Accepted；ADR-004 转 `Accepted with implementation gate`。MIC + Job Object 基线接受，但现有防火墙证据未覆盖任意子进程工具链，网络默认关闭仍阻断 S4 退出/`alpha.2`，不阻断 S2/S3。
4. **性能预算批准保持上位计划 §19.3 默认值。** M1 只作后端代理，M4/M5 在 S5 真实桌面 harness 复核；复核不自动触发阈值放宽。

## 2. 修订后的执行顺序与门禁

```text
S0（代码封版：已完成）
  ├── S1 ADR + Spike（已完成并评审）
  └── S0-R 发布流水线收拢（安装/updater 签名/smoke 已完成）
           │
           └──► 干净候选提交 + release-check-full 全绿后进入 S2
S2 schema draft 锁定 → S3 → S4 → S5(beta.1) → S6 → S7(beta.2) → S8 → S9(rc.1 + 14 天) → 1.0.0
```

Authenticode 证书、公开 `v0.9.0` tag 和公开 updater `latest` 保持独立发布阻断，不被 S2 开工吸收或伪造为已完成。

全局开工约束（上位计划 §25）维持不变：sandbox spike 未证明可行前，不开始大规模实现。

### S2 · Domain、Protocol 与 Store（约 2 周）→ `1.0.0-alpha.1`

前置：S1 评审完成 + **干净候选提交上 S0-R 内部门禁全绿（D1 + §1.1）**。Authenticode 不阻断 S2，但继续阻断公开发布。

任务：v1 schema（`agent_v2/protocol/schema/`）；codegen（Pydantic + TS + JSON Schema bundle + method registry，CI 零 diff）；golden fixtures；additive migration（表名按 ADR-003，测试库按 D6）；command/event/snapshot/read-model stores；`initialize`、thread/turn 基础方法；v0.9 event → v2 Item 离线 mapper；contract/golden/migration/replay 测试。

门禁：空模型/假工具下完整创建并重放 Turn；codegen diff = 0；replay checksum 一致。
停止条件：前后端出现手写漂移 → 修 codegen 而非手工对齐。
退出：协议/领域/Store 骨架可重放，零手写漂移。

### S3 · Runtime、Provider 与 Context（约 2 周）

任务：Turn Orchestrator 七段（admission / context assembly / model loop / item lifecycle / tool lifecycle 接口 / terminalization / recovery）；steer/interrupt/budget/compaction；Provider adapters 迁入 + capability catalog + Turn 级 profile 快照；Context fragments 六种 kind + 真实 usage（缺失显示 unavailable）；`AGENTS.md` 分层发现（32 KiB 预算、provenance、快照）；崩溃/断线/owner/恢复测试。

门禁：无副作用工具下，Ollama / OpenAI-compatible / Claude 三类 Provider 均能完成、取消、恢复 Turn；无 provider-specific 泄漏。
停止条件：v0.9 golden replay 不一致且无迁移说明 → 阻断。

### S4 · Tool Engine、Sandbox 与 Approval（约 3 周）→ `1.0.0-alpha.2`

任务：registry / router / lifecycle / lease / audit 主链；统一 exec（argv 优先、环境白名单、超时、输出续读、kill tree）；Windows sandbox 生产实现（失败关闭；`full_access` 仍受秘密/审计/外发硬边界约束）；approval policy（canonical argv/cwd/env diff/sandbox hash 绑定、防重放、单次消费）；apply-patch/PatchSet handler；Git/worktree、RAG/HTTP/SQL adapters；fuzz + 路径/网络/命令/secret/unknown 测试。

门禁：主链 100% 走 v2；未审批的 workspace 外写入 / 网络外发 / 提权 = 0；unknown 非幂等自动重试 = 0。
停止条件：任一审批绕过或越界写入 → P0 阻断，修复后全量重跑。

### S5 · Agent RPC 与桌面主链（约 2 周）→ `1.0.0-beta.1`

任务：Tauri transport（按 ADR-002，含一次性高熵 bearer、严格 Origin/Host、消息大小限制、reconnect、bounded queue）；`features/agent-v2/`（ThreadStore / ItemProjector / generated client 禁手改）；thread/turn/item 全 UI + steer/interrupt + 连接恢复；5000+ Item 虚拟化/分页；原生 prompt/confirm 全替换设计系统对话框；新安装默认 v2 + 显式回退（记录原因与计数）；unknown item 安全渲染 + 诊断。

门禁：真实 Windows 安装版端到端完成读→改→测→验；1 万次重复/断线事件模拟中丢失/重复可见 Item = 0；UI 无 provider-specific 分支、无内部 DB 字段依赖。
停止条件：UI 仍依赖内部 DB 字段 → 不得进 Beta。
备注：**Beta 1 起 protocol v1 只 additive，不再新增 P0。**

### S6 · 扩展、管理与产品闭环（约 1–2 周）

任务：Thread 搜索/归档/重命名/分页（P1 可裁剪）；capability catalog + feature maturity UI；context/instruction diagnostics；MCP P1 MVP（allowlist + schema + 审批 + 审计，不影响 P0 时推进）；model/profile、permission/sandbox、recovery 设置闭环。

裁剪规则：任何 P1 威胁 P0 或 S8 排期 → 立即延期，无损退出。

### S7 · 数据迁移与 Legacy 隔离（约 2 周）→ `1.0.0-beta.2`

任务：v0.5/v0.8/v0.9 → v1 升级矩阵（时间戳克隆演练按 D6，禁止操作日常应用库）；v0.9 Conversation/Run 显式/批量受控迁移（可暂停/续跑/重入，失败隔离到 migration report）；v1 应用回退到 v0.9 只读历史；legacy REST/SSE facade + 调用 telemetry + 归零报告；故障注入（重复请求、断线、进程杀死、owner 切换、未决审批、orphan migration）；database upgrade/rollback runbook。

门禁：数据丢失 = 0；重复副作用 = 0；迁移可续跑；新旧 executor 互斥；行数/hash/关系不一致即阻断。
证据：`migration-report-v090-to-v100.json` 初版 + 归零报告。

### S8 · 发布硬化（约 2 周）

任务：全量安全威胁矩阵（上位计划 §18 九类）+ 最小 CSP 启用 + IPC/token/secret redaction 复验；24h soak（5000+ Item、大输出、大 Diff、磁盘满、强杀）+ 1000 混合 Turn soak；性能验收（基线 + 预算，阈值审批按 D7）；资源/视觉/a11y/安装版/updater；全套文档；**D8 前置准备：三个可重置试用项目（Python / Vue-Node / Rust）+ 本地与至少一个远程 Provider 凭据**；release report、manifest、SHA、签名，全部绑定同一候选。

门禁（上位计划 §17.2 八条硬门槛全量生效）：
1. schema/codegen diff = 0；
2. 10,000 次重复/断线事件模拟中丢失和重复可见 Item = 0；
3. 1,000 个混合 Turn soak 中永久 orphan、重复副作用、残留进程 = 0；
4. 未审批的 workspace 外写入、网络外发、权限提升 = 0；
5. unknown 非幂等执行自动重试 = 0；
6. secret/用户代码进入日志、诊断、通知和发布证据 = 0；
7. 5000 Item 页面不全量挂载，交互与内存无未解释退化；
8. P0/P1 缺陷 = 0；P2 必须有 owner、影响和延期理由。

### S9 · RC 观察与稳定发布（14 自然日 + 2–3 工作日）

任务：发布 `1.0.0-rc.1` 并冻结候选代码/schema/安装包/updater 资产；三类项目试用（按 D8 准备）；审批/拒绝/取消/steer/冲突/unknown/恢复/升级/updater 全矩阵；**项目/发布负责人每日执行并签署观察记录（D8）**；功能代码变化 → 升 `rc.N+1` 并 Day 1 重启观察；通过后统一 `1.0.0`，重跑完整门禁发布稳定资产。

停止条件：发现数据损坏、审批绕过、重复副作用或秘密泄漏 → 立即停止 latest/updater。
