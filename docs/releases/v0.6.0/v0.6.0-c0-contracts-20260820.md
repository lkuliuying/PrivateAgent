# PrivateAgent v0.6.0 C0 契约与迁移设计

> 制定日期：2026-08-20
> 状态：设计冻结；业务代码已获准从 `0.5.0-rc.4` 工程基线实施
> 基线：`0.5.0-rc.4` / commit `9250da6` / schema `0026`
> 上位计划：[v0.6.0 开发计划](./v0.6.0-development-plan-20260820.md)

## 1. C0 结论

本文件冻结 `v0.6.0` 的 ProjectWorkspace、Coding Session、project-bound AgentRun、RunPlan、Artifact 和事件续读契约，作为后端、前端与测试共同输入。

冻结结论：

1. 复用现有 `projects`、`sessions`、`agent_runs`、`run_steps` 和 `agent_run_events`，不建立第二套 Runtime。
2. 新字段和新表全部 additive；旧客户端可忽略，旧版应用回退时保留数据。
3. Coding 模式必须显式携带 project/workspace，不允许根据最近项目、当前页面或工具参数反推授权。
4. RunPlan 是后端事实，不再由前端根据文案启发式生成。
5. 创建幂等、计划版本和事件 sequence 分别解决重复运行、旧计划覆盖和断线重放问题。
6. `v0.6.0` 只创建 root workspace，不自动创建 Git branch 或 worktree。

## 2. 当前实现基线

当前代码已有：

- `projects.root_path` 与项目授权、扫描、搜索、读取和 Git 状态接口。
- `sessions` 仅包含 id、title 和时间戳，没有项目归属。
- `agent_runs` 可选绑定 session，具有 provider/model、限制、状态、完成条件和最后事件 sequence。
- `run_steps` 是一次运行的模型/工具执行步骤，不等价于用户计划。
- `agent_run_events` 已按 `(run_id, sequence)` 唯一，可通过 `after_sequence` 分页续读。
- 前端 `AgentWorkspace` 仍通过 `buildAgentPlan(messages, streaming)` 推导展示计划。
- `agent_runs` 创建接口只接受 session/message/knowledge_base/limits/completion_conditions。

因此 `v0.6.0` 是在现有事实层上增加项目上下文和真实计划，不迁移或复制既有执行数据。

## 3. 冻结决策

| ID | 决策 |
|---|---|
| C0-D01 | `ProjectWorkspace` 为项目路径实例；`Project` 继续表示用户授权项目，不把两者合并。 |
| C0-D02 | Session 是 CodingThread 的兼容载体；通过 `kind=legacy/coding` 区分，不新增第二张 thread 主表。 |
| C0-D03 | Coding run 必须同时绑定 session、project 和 workspace；任一缺失都拒绝。 |
| C0-D04 | `client_request_id` 在非空时全局唯一；重复请求返回原 run，绝不启动第二个 coordinator。 |
| C0-D05 | workspace 路径以数据库中的规范化绝对路径为事实源；前端提交路径无效。 |
| C0-D06 | Git HEAD/branch/dirty 是 run 创建时只读快照，不自动 checkout、建分支或清理工作区。 |
| C0-D07 | 权限模式只允许 `read_only`、`confirm`、`full_access`；快照持久化后本轮不可静默扩大。 |
| C0-D08 | RunPlan 使用独立 plan item 表，不复用 `run_steps` 或 `agent_task_steps`。 |
| C0-D09 | durable 事件 sequence 继续由现有 repository 分配；SSE heartbeat 不占 sequence。 |
| C0-D10 | 关闭新 flag 后所有 legacy 请求继续走 `0.5.0` 主链，不自动绑定最近项目。 |

## 4. 数据库迁移预览

迁移从当前 head `0026` 顺延。实现时允许根据一次迁移的 DDL 风险拆分文件，但字段语义不得漂移。

### 4.1 `0027_project_workspaces_and_run_context`

#### `project_workspaces`

| 字段 | 类型与约束 |
|---|---|
| `id` | BIGINT，自增主键 |
| `project_id` | BIGINT，FK `projects.id`，非空 |
| `kind` | VARCHAR(32)，`root` / `git_worktree`；本版本只创建 `root` |
| `root_path` | VARCHAR(2048)，规范化绝对路径，非空 |
| `root_path_sha256` | CHAR(64)，规范化路径哈希，非空 |
| `branch_name` | VARCHAR(512)，可空，只读快照 |
| `head_sha` | VARCHAR(64)，可空 |
| `status` | VARCHAR(32)，active/missing/dirty/archived/conflict |
| `last_used_at` | DATETIME(3)，可空 |
| `created_at` / `updated_at` | DATETIME(3)，非空 |

约束与索引：

- unique `(project_id, root_path_sha256)`，避免 Windows 路径大小写或分隔符变体重复建 workspace。
- index `(project_id, status, last_used_at)`。
- service invariant：一个 active project 恰好一个 active root workspace；MySQL 不使用不可移植的 partial unique index。
- 项目归档只把 workspace 标记 archived，不物理删除运行审计关系。

路径规范化：

1. 先解析绝对路径并规范分隔符。
2. Windows 用大小写不敏感形式计算 `root_path_sha256`，展示仍保留规范化原路径。
3. 禁止 `..`、未解析环境变量和空路径进入数据库。
4. 创建 run 时重新验证路径存在、位于项目授权范围且 workspace/project 匹配。

#### `sessions` additive 字段

| 字段 | 类型与规则 |
|---|---|
| `project_id` | BIGINT，可空，FK `projects.id` |
| `workspace_id` | BIGINT，可空，FK `project_workspaces.id` |
| `kind` | VARCHAR(32)，非空，默认 `legacy` |
| `last_run_id` | CHAR(36)，可空，FK `agent_runs.id` 使用逻辑引用或延后建 FK，避免迁移环 |
| `pinned_at` | DATETIME(3)，可空 |
| `archived_at` | DATETIME(3)，可空 |

规则：

- 旧 session 统一保持 `kind=legacy`，不回填 project/workspace。
- 创建 coding session 时 project/workspace 必须成对写入并在同一事务验证。
- legacy session 不得因打开项目页面而被自动升级为 coding。

#### `agent_runs` additive 字段

| 字段 | 类型与规则 |
|---|---|
| `project_id` | BIGINT，可空 |
| `workspace_id` | BIGINT，可空 |
| `base_head_sha` | VARCHAR(64)，可空 |
| `base_branch_name` | VARCHAR(512)，可空 |
| `base_git_dirty` | BOOLEAN，可空 |
| `model_profile_id` | VARCHAR(128)，可空 |
| `reasoning_effort` | VARCHAR(32)，可空 |
| `permission_mode` | VARCHAR(32)，可空 |
| `permission_snapshot_json` | JSON，可空，只保存非秘密策略快照 |
| `client_request_id` | VARCHAR(64)，可空，唯一 |

索引：

- unique `client_request_id`；MySQL 允许多个 NULL，兼容旧 run。
- index `(project_id, workspace_id, created_at)`。
- index `(session_id, created_at)` 继续保留。

### 4.2 `0028_run_plans_and_artifacts`

#### `run_plan_items`

| 字段 | 类型与规则 |
|---|---|
| `id` | CHAR(36)，主键；由 trusted code 或受限 safe tool 生成 |
| `run_id` | CHAR(36)，FK `agent_runs.id`，非空 |
| `plan_version` | INTEGER，非空，从 1 开始 |
| `item_key` | VARCHAR(128)，同一 run 内稳定 |
| `ordinal` | INTEGER，非空 |
| `title` | VARCHAR(512)，非空 |
| `detail` | TEXT，可空 |
| `status` | VARCHAR(32)，pending/in_progress/completed/blocked/failed/cancelled |
| `evidence_json` | JSON，可空，只放有界引用，不放完整命令输出或秘密 |
| `created_at` / `updated_at` | DATETIME(3)，非空 |

约束：

- unique `(run_id, plan_version, item_key)`。
- unique `(run_id, plan_version, ordinal)`。
- 同一 run 同时最多一个 `in_progress`，由 repository 事务锁和条件更新保证。
- plan version 只增不减；旧 version 更新返回冲突。
- item completed 不自动把 run 标记 completed。

#### `agent_run_artifacts`

| 字段 | 类型与规则 |
|---|---|
| `id` | CHAR(36)，主键 |
| `run_id` | CHAR(36)，FK `agent_runs.id` |
| `step_id` | CHAR(36)，可空，FK `run_steps.id` |
| `kind` | VARCHAR(32)，diff/file/command_output/test_report/summary |
| `title` | VARCHAR(512)，非空 |
| `rel_path` | VARCHAR(2048)，可空，只允许 workspace 相对路径 |
| `content_sha256` | CHAR(64)，可空 |
| `metadata_json` | JSON，可空，脱敏且有界 |
| `created_at` | DATETIME(3)，非空 |

`v0.6.0` 只冻结产物引用，不新增任意文件下载或外部上传能力。

### 4.3 回填与回退

升级顺序：

1. 建表和新增 nullable/default 字段。
2. 按 project id 分页，为每个现有 project 幂等插入一个 root workspace。
3. 不回填旧 session 和旧 agent_run 的 project/workspace。
4. 新代码首次读取 project 时再次执行幂等 `ensure_root_workspace`，覆盖迁移中断恢复。
5. 先开启 workspace 只读 API，再开启 project-bound run，最后开启 plan 与 SSE。

应用回退：

- 旧 `0.5.0` 应用忽略新增表/列并继续读取旧字段。
- 正式应用回退不执行 Alembic downgrade，不删除 workspace、plan 或 artifact 数据。
- 开发环境 downgrade 必须先删除 `0028` 表，再移除 `0027` 列和 workspace 表；只用于空库/克隆库验证。
- 迁移或回填失败时保持新 flag 关闭，旧聊天链路仍可用。

## 5. Coding 与 legacy 创建模式

### 5.1 模式判定

| 输入 | 模式 | 结果 |
|---|---|---|
| project/workspace/client_request_id/permission_mode 全部缺失 | legacy | 沿用 `0.5.0` 行为 |
| 上述任一字段出现，但未全部出现 | invalid_partial_coding_context | HTTP 422，零 run 创建 |
| 全部出现且 flag 关闭 | coding_disabled | HTTP 409/503，零 run 创建，legacy 仍可用 |
| 全部出现且归属/授权/路径验证通过 | coding | 幂等创建 project-bound run |

Coding 模式还要求：

- `session_id` 非空且 session.kind 为 `coding`。
- session.project_id/workspace_id 与请求完全一致。
- workspace.project_id 与请求 project_id 一致且 status 可运行。
- workspace 路径存在并仍在 trusted project root 内。
- `model_profile_id`、`reasoning_effort` 和 permission mode 都通过服务端 allowlist。

任何一步失败都不能退回 legacy，也不能改绑到最近项目。

### 5.2 创建幂等

1. 在事务中按 `client_request_id` 查询现有 run。
2. 不存在时创建 run 和初始 `run.created` 事件，提交后才启动 coordinator。
3. 唯一键冲突时重新读取并返回已有 run。
4. 重复请求的 session/project/workspace/message hash 不一致时返回 `client_request_conflict`，不复用也不新建。
5. API 响应增加 `idempotent_replay: boolean`，旧客户端可忽略。

## 6. API 与 DTO

### 6.1 Workspace API

```text
GET  /projects/{project_id}/workspaces
GET  /projects/{project_id}/workspaces/{workspace_id}
POST /projects/{project_id}/workspaces/root/ensure
```

`ensure` 只幂等登记项目现有 root，不创建目录、分支或 worktree。

## 7. RunPlan 契约

### 7.1 safe tool

内部工具名冻结为 `update_run_plan`，risk=`safe`，不授予文件、进程、网络或数据库 capability。模型输入只允许：

```json
{
  "expected_plan_version": 2,
  "items": [
    {
      "item_key": "inspect_failure",
      "title": "定位失败测试",
      "detail": "读取测试和实现",
      "status": "in_progress"
    }
  ]
}
```

限制：

- 1–32 个 item；title 最长 512，detail 最长 4000。
- item_key 只允许 `[a-z0-9][a-z0-9_-]{0,127}`。
- 同时最多一个 in_progress。
- completed/failed/cancelled 不能回到 pending 或 in_progress。
- expected version 不匹配时失败，不做 last-write-wins。

### 7.2 快照响应

`GET /agent-runs/{run_id}` 增加：

```json
{
  "plan": {
    "version": 3,
    "items": []
  },
  "artifacts": []
}
```

快照是重连纠偏事实；前端临时 token 或动画状态不得覆盖它。

## 8. 事件与 SSE

新增 durable 事件：

| event type | 必需 payload |
|---|---|
| `plan.created` | `plan_version`, `items` |
| `plan.updated` | `previous_version`, `plan_version` |
| `plan.item_changed` | `plan_version`, `item_key`, `previous_status`, `status` |
| `artifact.created` | `artifact_id`, `kind`, `title`, `step_id` |

新增接口：

```text
GET /agent-runs/{run_id}/events/stream?after_sequence=N
```

传输规则：

- 首先续发数据库中 `sequence > N` 的 durable 事件，再订阅新事件。
- heartbeat 每 15 秒发送 SSE comment，不写数据库、不增加 sequence。
- 客户端重复连接同一 after_sequence 可收到相同事件，由 `(run_id, sequence)` 去重。
- 断线不取消 run；切换 session 或组件卸载时客户端 AbortController 只关闭本地连接。
- run 终态后发送终态 durable 事件并正常关闭；重连仍可从数据库完整回放。
- 事件 payload 脱敏、有界，不包含完整命令输出、API key、本地环境变量或审批 token。

## 9. 错误码

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `coding_context_incomplete` | 422 | Coding 字段只提供了一部分 |
| `coding_mode_disabled` | 409 | project-bound run flag 未开启 |
| `session_not_coding` | 409 | session 不是 coding 类型 |
| `session_workspace_mismatch` | 409 | session 与 project/workspace 不一致 |
| `workspace_not_found` | 404 | workspace 不存在 |
| `workspace_unavailable` | 409 | missing/archived/conflict |
| `workspace_outside_trust` | 403 | workspace 不在项目授权范围 |
| `workspace_path_changed` | 409 | 规范化路径或路径哈希漂移 |
| `git_snapshot_failed` | 409 | 无法获得要求的 Git 快照 |
| `client_request_conflict` | 409 | 相同幂等键对应不同请求 |
| `plan_version_conflict` | 409 | expected plan version 已过期 |
| `plan_transition_invalid` | 422 | item 状态转换非法 |
| `event_sequence_conflict` | 500 | durable sequence 分配冲突，run 失败关闭 |

错误响应不得包含本地绝对路径；详细路径仅可进入受控诊断包并脱敏。

## 10. Feature flags 与 telemetry

| Flag | 默认值 | 控制范围 |
|---|---:|---|
| `PA_PROJECT_BOUND_RUNS_ENABLED` | false | workspace API、coding session 与 project-bound run 创建 |
| `PA_AGENT_RUN_PLAN_ENABLED` | false | `update_run_plan`、plan 表与 plan 事件 |
| `PA_AGENT_RUN_EVENT_STREAM_ENABLED` | false | 新 durable event SSE；旧分页事件接口继续可用 |

开启顺序固定为 project-bound → plan → stream；关闭顺序相反。任一 flag 关闭不得影响 legacy run、旧 chat stream、审批或工具执行。

telemetry 仅保存计数标签：

- `agent_run_create`: mode=`legacy/project_bound`, outcome=`created/replayed/rejected`
- `coding_session_create`: outcome=`created/rejected`
- `run_plan_update`: outcome=`created/updated/conflict/invalid`
- `run_event_stream`: outcome=`connected/reconnected/completed/aborted/error`
- `workspace_resolve`: outcome=`resolved/missing/mismatch/untrusted`

不得记录 message、路径、branch、SHA、命令、模型输出或权限快照正文。
