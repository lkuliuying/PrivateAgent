## 1. ProjectWorkspace 与 project-bound run DTO 示例

### 1.1 Workspace DTO（`GET/POST /projects/{project_id}/workspaces*`）

flag `PA_PROJECT_BOUND_RUNS_ENABLED` 关闭时整体 404（legacy 主链不受影响）。
`ensure` 只幂等登记项目现有 root，不创建目录、分支或 worktree。

```json
{
  "id": 12,
  "project_id": 8,
  "kind": "root",
  "root_path": "F:/Program/Example",
  "branch_name": "main",
  "head_sha": "0123456789abcdef",
  "status": "active",
  "last_used_at": null,
  "created_at": "2026-08-25T10:00:00.000Z",
  "updated_at": "2026-08-25T10:00:00.000Z"
}
```

- `kind`：`root` / `git_worktree`（v0.6.0 只创建 `root`）。
- `status`：`active` / `missing` / `dirty` / `archived` / `conflict`；创建 run 只允许
  `active` / `dirty`（`RUNNABLE_WORKSPACE_STATUSES`）。
- `root_path` 是数据库中的规范化绝对路径（事实源）；前端提交的路径无效。
- 唯一约束 `(project_id, root_path_sha256)`；Windows 大小写不敏感哈希，避免路径变体重复建 workspace。
- 项目归档只把 workspace 标记 `archived`，不物理删除运行审计关系。

### 1.2 Session DTO 新字段（`sessions` additive）

```json
{
  "kind": "coding",
  "project_id": 8,
  "workspace_id": 12,
  "last_run_id": null,
  "pinned_at": null,
  "archived_at": null
}
```

旧 session 统一 `kind=legacy` 且其余字段为 null；不回填 project/workspace；
legacy session 不得因打开项目页面自动升级为 coding。

### 1.3 AgentRun 创建请求 DTO（Coding 模式）

```json
{
  "session_id": 123,
  "message": "修复测试失败",
  "project_id": 8,
  "workspace_id": 12,
  "model_profile_id": "local-coder",
  "reasoning_effort": "high",
  "permission_mode": "confirm",
  "client_request_id": "7a66f8e1-d423-4e36-9aa7-659b77d15753"
}
```

模式判定（§5.1）：五字段（project_id/workspace_id/client_request_id/permission_mode 及
model 字段组）全缺 → legacy；部分出现 → `coding_context_incomplete` 422（零 run 创建）；
全出现但 flag 关 → `coding_mode_disabled` 409；全出现且校验通过 → coding 幂等创建。

### 1.4 AgentRun 响应新增字段

```json
{
  "id": "run-id",
  "session_id": 123,
  "status": "running",
  "project_id": 8,
  "workspace_id": 12,
  "base_head_sha": "0123456789abcdef",
  "base_branch_name": "main",
  "base_git_dirty": false,
  "model_profile_id": "local-coder",
  "reasoning_effort": "high",
  "permission_mode": "confirm",
  "client_request_id": "7a66f8e1-d423-4e36-9aa7-659b77d15753",
  "idempotent_replay": false,
  "plan": { "version": 1, "items": [] },
  "artifacts": []
}
```

- `idempotent_replay`：重复 client_request_id 返回已有 run 时为 true。
- `plan` / `artifacts` 是重连纠偏事实；前端临时 token 或动画状态不得覆盖。
- `permission_snapshot_json` 不原样返回前端，只投影可展示的 mode/capability 摘要。

## 2. 全部 plan/run/tool/approval 事件字典

事件统一形态：`{run_id, sequence, type, created_at, step_id?, payload}`，
`(run_id, sequence)` 严格递增、不重复不回退。

### 2.1 v0.6.0 稳定（durable）公开事件

| event type | 必需 payload | 进入 runProjector 投影 |
|---|---|---|
| `plan.created` | `plan_version`(≥1), `items`[1..32 × {item_key,title,status}] | 是（重建 plan 视图） |
| `plan.updated` | `previous_version`(≥1), `plan_version`(>previous) | 是（只更新 version） |
| `plan.item_changed` | `plan_version`(≥1), `item_key`(1..128), `previous_status`, `status` | 是（更新 item status） |
| `artifact.created` | `artifact_id`, `kind`, `title`(≤512), `step_id`(可空, ≤36) | 是（追加 artifact） |

### 2.2 既有 run/tool 事件（durable 但 v0.6.0 不进入 plan/artifact 投影）

| event type | 语义 |
|---|---|
| `run.started` / `run.completed` / `run.failed` / `run.cancelled` / `run.timed_out` / `run.limit_exceeded` | run 生命周期 |
| `context.prepared` | 上下文准备完成（payload 为有界 observability 元数据，不含选中源正文） |
| `model.started` / `model.completed` | 模型回合 |
| `output.validation_started` / `output.validation_passed` / `output.validation_failed` | 输出校验 |
| `tool.requested` / `tool.started` / `tool.completed` / `tool.failed` | 工具生命周期 |
| `tool.approval_required` / `tool.approval_resolved` | 审批（与 ToolApproval 记录对应） |
| `chat.output_persisted` | 聊天输出落库 |

SSE 传输：durable 事件才有 sequence；临时 delta（token 增量等）只推进 seen sequence，
不改变投影视图。`GET /agent-runs/{run_id}/events/stream?after_sequence=N` 首先续发
`sequence > N` 的 durable 事件再订阅新事件；heartbeat 每 15 秒一条 SSE comment
（`: heartbeat`），不写数据库、不增加 sequence。断线不取消后台 run；run 终态后发送
终态事件并正常关闭，重连仍可完整回放。事件 payload 脱敏有界，不包含完整命令输出、
API key、本地环境变量或审批 token。

## 3. 重连和恢复 fixture

### 3.1 快照纠偏契约（`GET /agent-runs/{run_id}`）

响应 `plan`/`artifacts` 字段是 durable 事实；重连后前端必须用快照覆盖投影视图。
`lastSequence` 取快照侧序列与本地已见序列的较大者，避免 SSE 续读回退。

### 3.2 runProjector（前端，`apps/desktop/src/features/agent/runProjector.ts`）

- 公开接口：`createRunProjection(runId)`、`applyDurableEvent(projection, event)`、
  `reconcileWithSnapshot(projection, snapshot, lastSequence?)`、`switchRun(projection, runId)`。
- 幂等规则：`(run_id, sequence)` 去重——重复/乱序/旧事件安全忽略；异 run 事件拒绝。
- 非 durable 事件只推进 `lastSequence`，不改 plan/artifacts 视图。
- 切换 thread 后旧 run 的迟到事件被拒绝（run_id 不匹配）。
- Vitest 单测覆盖：重复、乱序、重连、切换、legacy（15 项）。

### 3.3 开发 fixture（`apps/desktop/src/dev/runFixtures.ts`）

- `buildRunPlanFixture(runId)`：标准「定位失败 → 修复 → 验证」流，含重复与乱序
  迟到事件（模拟客户端重试与重连竞态），快照 version=2 与事件流一致。
- `buildLegacyRunFixture(runId)`：flag 关闭（无 plan/artifacts）的 legacy run。
- fixture 仅开发模式/UI Lab/测试使用，生产构建不引用；禁止虚构后端状态。

### 3.4 Python 侧 fixture 与故障注入（`tests/`）

- 契约测试冻结于 C0（13 项）+ C2/C3/C6-前置 扩展，覆盖：
  - 模式判定（legacy / partial / disabled / coding）、幂等 replay 与 payload 冲突
    （同 client_request_id 不同 message hash → `client_request_conflict`）。
  - RunPlan 乱序/版本冲突（CAS）、状态机非法转换、`event_sequence_conflict`。
  - SSE 断线重连（after_sequence 续读）、断线不取消 run、终态后重放。
  - flag 回退（关闭后 legacy 主链可用）、workspace 路径缺失/漂移/越权拒绝。

## 4. 权限、路径和 Git 快照约束

### 4.1 权限快照（C0-D07）

- `permission_mode` allowlist：`read_only` / `confirm` / `full_access`（v0.7.0 的
  readonly/confirm/workspace 三模式需在 v0.7.0 冻结时替换/扩展本集合，禁止静默扩大）。
- `permission_snapshot_json` 只保存非秘密策略快照；持久化后不可静默扩大。
- 任何错误响应不得包含本地绝对路径；详细路径仅可进入受控诊断包并脱敏。

### 4.2 路径约束

1. `root_path` 先解析绝对路径并规范分隔符。
2. Windows 用大小写不敏感形式计算 `root_path_sha256`，展示保留规范化原路径。
3. 禁止 `..`、未解析环境变量和空路径进入数据库。
4. 创建 run 时重新验证路径存在、位于项目授权范围（trusted root）且 workspace/project 匹配。
5. 路径丢失 → workspace 标 `missing` 失败关闭，不自动改绑、不隐式扩大授权。

### 4.3 Git 快照

- `base_head_sha` / `base_branch_name` / `base_git_dirty` 是 run 创建时只读快照；
  后续 HEAD 漂移不影响已创建 run 的审计事实。
- 无法获得要求的 Git 快照 → `git_snapshot_failed` 409，零 run 创建。
- Git/path/权限快照不得进入未脱敏日志或 toast（telemetry 只保存计数）。

### 4.4 RunPlan 约束（v0.7.0 PatchSet 阶段沿用）

- `update_run_plan` 内部 safe 工具：risk=safe、无 capability，1–32 item，
  title ≤512、detail ≤4000，`item_key` 匹配 `[a-z0-9][a-z0-9_-]{0,127}`。
- 状态机：`pending → {in_progress, cancelled}`；`in_progress → {completed, blocked,
  failed, cancelled}`；`blocked → {in_progress, cancelled, failed}`；
  `completed/failed/cancelled` 终态不可回退。
- 同时最多一个 `in_progress`（repository 事务锁 + 条件更新保证）。
- CAS：`expected_plan_version` 必须是当前最新版本 + 1，过期失败（`plan_version_conflict`
  409），不做 last-write-wins——旧模型回合不能覆盖新计划。
- item completed 不自动把 run 标记 completed。

### 4.5 错误码（冻结，C0 §9）

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `coding_context_incomplete` | 422 | Coding 字段只提供了一部分 |
| `coding_mode_disabled` | 409 | project-bound run flag 未开启 |
| `session_not_coding` | 409 | session 不是 coding 类型 |
| `session_workspace_mismatch` | 409 | session 与 project/workspace 不一致 |
| `workspace_not_found` | 404 | workspace 不存在 |
| `workspace_unavailable` | 409 | missing/archived/conflict |
| `workspace_outside_trust` | 403 | workspace 不在项目授权范围 |
| `workspace_path_changed` | 409 | 规范化路径或路径哈希漂移 |
| `git_snapshot_failed` | 409 | 无法获得要求的 Git 快照 |
| `client_request_conflict` | 409 | 相同幂等键对应不同请求 |
| `plan_version_conflict` | 409 | expected plan version 已过期 |
| `plan_transition_invalid` | 422 | item 状态转换非法 |
| `event_sequence_conflict` | 500 | 事件 sequence 冲突（不可重放） |

## 5. 新工具接入所需的 project/workspace 解析服务

### 5.1 ProjectWorkspaceService（`src/personal_assistant/core/workspaces.py`）

| 方法 | 语义 |
|---|---|
| `get(workspace_id)` | 读取 workspace（含状态） |
| `ensure_root_workspace(project)` | 幂等补建 root workspace（迁移中断恢复兜底；新代码首次读取 project 时调用） |
| `touch_last_used(workspace_id, at?)` | 更新最近使用时间 |
| `update_status(workspace_id, status)` | 状态迁移（missing/archived/conflict/dirty/active） |
| `check_path(ws)` | 校验路径存在；缺失时标 `missing` 返回 False |

### 5.2 新工具接入 checklist（v0.7.0 新增 PatchSet/命令工具时）

1. 工具构造时接收 `db` + `run_id`（参考 `build_run_plan_tool_spec`），通过
   `AgentRunRepository` 读取 run 的 project_id/workspace_id 与 Git 快照。
2. 任何 workspace 外路径访问前必须重新执行 `ProjectWorkspaceService.check_path`
   与 trusted root 包含性校验（TOCTOU 防护在 v0.7.0 E1 冻结）。
3. 工具 spec 冻结：`ToolSpec(name/version/description/input_schema/output_schema/
   risk_level/required_capabilities/timeout_ms/max_input_bytes/max_output_bytes/
   idempotency/supports_cancellation/redaction_policy/executor)`。
4. 工具结果必须经过 `ToolRedactionPolicy` 脱敏；错误响应不得含绝对路径。
5. 副作用必须先经 ToolApproval（v0.5.0 既有链路），approval 记录与
   `tool.approval_required` / `tool.approval_resolved` 事件对应。

### 5.3 ContextBuilder 项目片段（`src/personal_assistant/context/sources.py`）

- `prepare_agent_context(..., project_id, workspace_id, git_snapshot)` 注入
  `ContextFragmentKind.PROJECT` 片段（有界、无秘密）：项目指令（如果有）、
  workspace 规范化路径与状态、Git HEAD/branch/dirty 摘要、显式上下文来源标记。
- 预算：`max_project_tokens=min(800, total)`，超预算按既有 context budget 规则截断。

## 6. 兼容 flag 与 telemetry 报告

### 6.1 Feature flag（开启顺序固定）

| flag | 默认 | 说明 |
|---|---|---|
| `PA_PROJECT_BOUND_RUNS_ENABLED` | false | project/workspace 绑定、幂等创建、workspace API |
| `PA_AGENT_RUN_PLAN_ENABLED` | false | RunPlan 持久化 + plan/artifact 事件 |
| `PA_AGENT_RUN_EVENT_STREAM_ENABLED` | false | SSE 续读流 |

- 配置校验：plan 依赖 project-bound，stream 依赖 plan；关闭顺序相反。
- 关闭全部 flag 后旧聊天/旧任务/旧 UI 行为完全不变，无需 schema downgrade。
- 迁移/回填失败时保持新 flag 关闭，旧链路仍可用。

### 6.2 Telemetry 标签（低基数，只保存计数）

| path | modes | outcomes |
|---|---|---|
| `agent_run_create` | legacy / project_bound | created / replayed / rejected |
| `coding_session_create` | project_bound | created / rejected |
| `run_plan_update` | project_bound | created / updated / conflict / invalid |
| `run_event_stream` | project_bound | connected / reconnected / completed / aborted / error |
| `workspace_resolve` | project_bound | resolved / missing / mismatch / untrusted |

禁止记录：message、路径、branch、SHA、命令、模型输出或权限快照正文。
诊断 `coding_agent` 摘要只计数，不落路径/Git 快照（`scripts/telemetry_window_report.py` 可聚合）。

### 6.3 迁移与回退（v0.7.0 继续遵守）

- 迁移链 head = `0029`（0027 workspace+run context / 0028 plan+artifact / 0029 fingerprint）。
- 升级顺序：建表 → 按 project 分页幂等插入 root workspace → 不回填旧 session/run →
  新代码首次读取再次 `ensure_root_workspace` → 按 flag 顺序开启能力。
- 应用回退：旧应用忽略新表/新列继续读旧字段；不执行破坏性 downgrade；新表新列保留。
- 开发环境 downgrade 仅限空库/克隆库演练：先删 0028 表，再移除 0027 列与 workspace 表。
- v0.6.0 已加固：DB revision 不在迁移链内时跳过迁移继续启动（旧库回退后新版可恢复）。
