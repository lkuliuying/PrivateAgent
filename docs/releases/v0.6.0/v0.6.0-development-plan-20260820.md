# PrivateAgent v0.6.0 开发计划书

> 制定日期：2026-08-20
> 规划基线：`0.5.0-rc.4`（`9250da6`，schema `0026`）
> 实施前置：`v0.5.0-rc.4` 冻结工程基线（已满足）
> 版本主题：Coding 领域与运行事实底座
> 内部交付目标：`0.6.0-alpha.1 → 0.6.0-alpha.2 → 0.6.0-beta.1 → 0.6.0-rc.1 → 0.6.0`
> 观察策略：本版本只执行即时门禁；唯一自然日观察顺延至 `v1.0.0-rc.1`

## 1. 版本结论

`v0.6.0` 只建立 Coding Agent 的领域事实和运行契约，不承担完整新 UI，也不扩大高风险工具范围。

版本完成后必须具备：

1. 一个项目可以拥有一个根 workspace 和未来可扩展的 Git worktree。
2. CodingThread 与 AgentRun 明确绑定 project/workspace。
3. 每次 run 保存 Git HEAD、模型、权限和请求幂等快照。
4. 执行计划由后端持久化并通过稳定事件发布。
5. 前端能够按 run id 和 sequence 重放公开事实，不再依赖启发式计划。
6. 旧 session、旧聊天、旧 AgentTask 和旧 UI 保持可用。

## 2. 已有基线与禁止重复建设

直接复用：

- `AgentRuntime`、`AgentRunRepository`、`RunStep` 和 `AgentRunEvent`。
- AgentRun coordinator、owner lock、checkpoint 和 orphan reconcile。
- ContextBuilder 与项目代码工具。
- `projects`、`project_files`、`trusted_paths` 和项目授权流程。
- API Bearer token、Host/Origin/CSP 与 Tauri sidecar 边界。
- 现有 `api/http.ts`、`api/runtime.ts` 和通知/确认 store。

禁止：

- 新建第二套 Runtime 或第二张 AgentRun 主表。
- 用旧 `agent_tasks` 直接替代一次 AgentRun。
- 在 Vue 中维护权威计划状态。
- 为新页面引入 Router、Pinia 或 Web CRUD 框架。
- 在本版本开启任意 Shell、目录删除或自动 Git 分支操作。

## 3. 版本范围

### 3.1 必须交付

| 领域 | v0.6.0 交付 |
|---|---|
| 数据模型 | `project_workspaces`、session/run 绑定字段、run 计划项与 Artifact 最小契约 |
| Run 创建 | project/workspace 校验、Git 快照、权限/模型快照、创建幂等 |
| Coding Context | 项目指令、workspace、Git 状态和显式上下文来源 |
| 真实计划 | `update_run_plan`、计划版本、状态约束、durable plan 事件 |
| 事件接口 | run 快照、after_sequence 续读、SSE 流与重连语义 |
| 前端底座 | Coding DTO、run projector 原型、恢复 fixture 和兼容入口 |
| 诊断与遥测 | project-bound/legacy 路由计数、恢复和错误类别 |

### 3.2 明确不做

- 多文件写入和批量文件操作。
- 新 Coding Workbench 正式视觉实现。
- 新 UI 默认切换。
- 自动创建 Git branch/worktree。
- 旧 planner 或旧 UI 物理删除。
- 自动化、插件市场和第三方发布。

## 4. 公开契约

### 4.1 ProjectWorkspace

建议新增 `project_workspaces`：

| 字段 | 约束 |
|---|---|
| `id` | BIGINT 主键 |
| `project_id` | FK，项目归档时保留审计关系或显式归档 workspace |
| `kind` | `root` / `git_worktree`，本版本只创建 `root` |
| `root_path` | 规范化绝对路径，最长 2048 |
| `branch_name` | 可空，只读快照 |
| `head_sha` | 可空，40/64 字符兼容未来对象格式 |
| `status` | active/missing/dirty/archived/conflict |
| `last_used_at` | 可空 |
| timestamps | 毫秒精度 |

一个 active project 至少有一个 `root` workspace；旧 project 在迁移或首次读取时幂等补建。

### 4.2 Session 与 AgentRun

`sessions` 增加可空字段：

- `project_id`
- `workspace_id`
- `kind`
- `last_run_id`
- `pinned_at`
- `archived_at`

`agent_runs` 增加：

- `project_id`
- `workspace_id`
- `base_head_sha`
- `model_profile_id`
- `reasoning_effort`
- `permission_snapshot_json`
- `client_request_id`

`client_request_id` 在有效范围内唯一；重复请求返回原 run，不新建执行。

### 4.3 RunPlan

新增 `run_plan_items`，状态限定为：

- pending
- in_progress
- completed
- blocked
- failed
- cancelled

规则：

- 同一 plan version 的 item id 唯一。
- 同时最多一个 `in_progress`。
- completed 需要可选 `evidence_json`，但不能自动等价于 run 完成。
- 更新使用 plan version 或事件 sequence 防止旧模型回合覆盖新计划。

### 4.4 AgentRun 创建 DTO

新增字段保持可选，只有 Coding 模式强制要求：

```json
{
  "session_id": 123,
  "project_id": 8,
  "workspace_id": 12,
  "message": "修复测试失败",
  "model_profile_id": "local-coder",
  "reasoning_effort": "high",
  "permission_mode": "confirm",
  "client_request_id": "uuid"
}
```

旧调用不携带这些字段时继续进入现有兼容 profile，不得被错误绑定到最近项目。

### 4.5 事件

新增稳定事件：

- `plan.created`
- `plan.updated`
- `plan.item_changed`
- `artifact.created`

新增 SSE：

```text
GET /agent-runs/{run_id}/events/stream?after_sequence=N
```

要求：

- durable event 使用严格递增 sequence。
- 重复 after_sequence 请求幂等。
- SSE heartbeat 不写数据库。
- token delta 为临时传输，完整模型结果仍持久化。
- 断线不取消后台 run。
- 重连用快照覆盖未完成临时文本。

## 5. 里程碑

### C0 · 契约冻结与迁移设计（1–2 天）

任务：

1. 冻结 ProjectWorkspace、session/run 新字段和 plan 事件。
2. 编写数据库迁移预览与回滚说明。
3. 冻结 Coding/legacy 创建模式判定。
4. 先提交 DTO、Schema、fixture 和失败契约测试。
5. 确定新增 feature flag 与 telemetry 标签。

退出条件：

- 契约评审完成。
- 所有新字段 additive 且旧客户端可忽略。
- 不存在根据“最近打开项目”隐式授权的设计。

### C1 · ProjectWorkspace 与会话绑定（2–3 天）

任务：

1. 新增 workspace 模型、repository、service 和 API。
2. 为旧项目幂等建立 root workspace。
3. 扩展 session 创建、列表和详情 DTO。
4. 增加项目/工作区归档与缺失路径状态。
5. 前端增加类型化项目/workspace 选择 API。

退出条件：

- 旧项目数据和文件索引不变。
- 同一项目不会重复创建多个 root workspace。
- 项目路径丢失时失败关闭，不自动改绑。

### `0.6.0-alpha.1`

C0–C1 完成后形成内部检查点：

- schema upgrade/clone/应用回退通过。
- ProjectWorkspace 契约和 API 测试通过。
- 不更新稳定 updater 通道。

### C2 · Project-bound Run 与 Coding Context（2–3 天）

任务：

1. 扩展 AgentRun create 和 response DTO。
2. 校验 session/project/workspace 归属。
3. 保存 HEAD、模型和权限快照。
4. 实现 `client_request_id` 创建幂等。
5. ContextBuilder 加入项目指令、workspace 和 Git 摘要。
6. 增加路径变化、HEAD 变化和 workspace 缺失错误码。

退出条件：

- 一个请求只创建一个 run。
- run 不依赖前端当前选择推断路径。
- 未授权或错配 workspace 100% 拒绝。
- 远程 Provider 数据边界可解释。

### C3 · 真实计划与事件续读（2–3 天）

任务：

1. 新增 `update_run_plan` 内部 safe 工具。
2. 持久化 plan item 和版本。
3. 事件投影支持 plan/artifact。
4. 增加 SSE 续读、heartbeat、重连和快照纠偏。
5. 错误、取消、limit 和等待审批状态统一。

退出条件：

- UI 无需根据文案推断计划。
- 计划乱序和旧版本更新被拒绝。
- SSE 断线后不新建替代 run。

### `0.6.0-alpha.2`

C2–C3 完成后形成内部检查点：

- project-bound run 主路径和兼容路径矩阵通过。
- 计划、取消、等待审批和重连 fixture 冻结。
- Python 契约、恢复和 API 测试通过。

### C4 · 前端 Run Projector 原型（1–2 天）

任务：

1. 增加 Coding contracts 与 `runProjector`。
2. 按 `(run_id, sequence)` 幂等投影。
3. 区分 durable 结果和临时 delta。
4. 切换 thread 后拒绝旧事件。
5. 提供开发 fixture，不改默认生产 UI。

退出条件：

- projector 单测覆盖重复、乱序、重连和切换。
- 现有 UI 行为不回退。

### C5 · 兼容、诊断与恢复（1–2 天）

任务：

1. 增加 project-bound/legacy 路由 telemetry。
2. 扩展诊断快照，不记录项目正文或绝对路径。
3. 覆盖进程重启、owner lock 和 orphan run。
4. 验证旧 session 和 AgentTask 不受新关系影响。
5. 提供关闭新 flag 的精确回退。

退出条件：

- 兼容原因全部可解释。
- 回退不需要 schema downgrade。
- 恢复不重复执行副作用。

### `0.6.0-beta.1`

C4–C5 完成后：

- 全量 Python/Vue/Rust/Playwright 门禁通过。
- 安装版完成创建、断线、重启和回退 smoke。
- 数据库升级和旧应用回退通过。

### C6 · RC 硬化与开发完成检查点（1–2 天）

任务：

1. 冻结公开 DTO、事件和错误码。
2. 执行 release-check-full 与安装升级演练。
3. 生成 manifest、flags、SHA、QA evidence 和已知问题。
4. 冻结 `0.6.0-rc.1` 并执行一次完整即时门禁复核。
5. 门禁通过后形成 `0.6.0` 内部开发完成版，不切公开 updater，立即交接 v0.7.0。

## 7. 迁移与回退

- 迁移编号从当前 head 后顺延，实际编号在实现时冻结。
- 旧 project 首次读取或迁移时创建 root workspace，过程幂等。
- 新 FK 在兼容期可空，不重写旧 session。
- 关闭 `PA_PROJECT_BOUND_RUNS_ENABLED` 后，旧聊天继续工作。
- 应用回退保留新表和新列，不执行破坏性 downgrade。
- 计划或事件数据损坏时 run 失败关闭，不回退到前端启发式状态。

## 8. 零容忍问题

- workspace 错配或隐式扩大授权。
- 同一 client request 创建多个有效 run。
- 事件 sequence 重复或回退。
- 旧 plan 覆盖新 plan。
- 断线后创建替代 run 或重复副作用。
- Git/path/权限快照进入未脱敏日志或 toast。
- 关闭 flag 后旧主链不可用。

## 9. 完成定义

`v0.6.0` 完成必须满足：

1. ProjectWorkspace、CodingThread、AgentRun 和 RunPlan 契约稳定。
2. project-bound run 可创建、续读、取消和恢复。
3. 真实计划由后端持久化和发布。
4. 前端 projector 可以完全消费公开事件。
5. 旧会话、旧任务和旧 UI 不回退。
6. 数据库升级与应用回退不丢数据。
7. `0.6.0-rc.1` 即时完整门禁通过，没有未处置 P0/P1。

## 10. 向 v0.7.0 交接

交接包必须包含：

- ProjectWorkspace 与 project-bound run DTO 示例。
- 全部 plan/run/tool/approval 事件字典。

- 权限、路径和 Git 快照约束。
- 新工具接入所需的 project/workspace 解析服务。
- 兼容 flag 与 telemetry 报告。
