## 4. 开工方式

1. 从 `9250da6` 对应工程基线创建 `codex/v0.6.0` 开发分支。
2. 将版本切到首个实际开发节点时同步六处版本源和 lock。
3. 第一批提交只增加 C0 DTO、Schema、fixture 和失败契约测试。
4. 第二批开始 `0027`/`0028` additive 迁移与 C1 实现。
5. C0–C1 全部门禁通过后形成 `0.6.0-alpha.1` 事实检查点。
6. 不切公开 updater latest；中间版本仅生成内部证据和安装包。

## 5. 仍然有效的限制

- 不从前端当前页面或“最近项目”推断 project/workspace 授权。
- 不建立第二套 Runtime、Thread 主表或前端计划状态机。
- 不新增 Router、Pinia、Tailwind、Ant Design Vue 或 VueUse。
- 不在 v0.6.0 自动创建 Git branch/worktree。
- 所有迁移 additive，旧应用回退不执行破坏性 downgrade。
- 高风险能力继续走后端/sidecar、审批、验证和可恢复路径。

## 6. 后续观察

本版本不执行自然日观察。v0.6.0 的 RC 只做即时全门禁和开发完成检查点；累计长期观察在 `v1.0.0-rc.1` 功能、文档、安装包和发布资产全部冻结后从 Day 1 重新开始。
