# PrivateAgent 观察期顺延决策（2026-08-20）

> 决策状态：生效
> 适用范围：`v0.5.0-rc.4` 至 `v1.0.0`
> 最终观察节点：`v1.0.0-rc.1`

## 1. 决策

项目不再为 `v0.5.0`、`v0.6.0`、`v0.7.0`、`v0.8.0` 或 `v0.9.0` 设置自然日观察等待。全部 Coding Agent 功能开发、集成和硬化完成后，在 `v1.0.0-rc.1` 执行唯一一次 14 个自然日整体观察。

新路线：

```text
0.5.0-rc.4 冻结工程基线
  → v0.6.0 开发完成检查点
  → v0.7.0 开发完成检查点
  → v0.8.0 开发完成检查点
  → v0.9.0 开发完成检查点
  → v1.0.0 功能/文档/发布物全部开发完成
  → v1.0.0-rc.1 冻结
  → 唯一一次 14 天整体观察
  → v1.0.0 stable
```

## 2. 对 v0.5.0 观察的处置

`v0.5.0-rc.4` 已在 2026-08-11 至 2026-08-20 留下 Day 1 和 Day 10 事实记录。自本决策生效起：

- 原 v0.5.0 观察停止继续计时，不形成 Day 14 pass/fail 结论。
- 已采集的测试、updater、数据快照和 6/6 可信工作流证据保留为工程基线证据。
- 这些样本不能折算进最终 `v1.0.0-rc.1` 的 14 天观察。
- 不再要求先发布 `v0.5.0` stable 才能开发 `v0.6.0`。
- `0.5.0-rc.4` commit `9250da6` / schema `0026` 直接作为 `v0.6.0` 的代码与迁移基线。

旧计划和检查点继续保留为历史事实；与本决策冲突的“等待 Day 14”“观察通过后才开工/发布”描述均由本文件取代。

## 3. 中间版本规则

### 3.1 v0.6.0–v0.9.0

每个版本仍执行 alpha、beta、RC 和开发完成检查点，但不等待 7 天或 14 天：

- alpha：契约和主体实现检查点。
- beta：范围完整，执行全量自动化、升级/回退和安装版 smoke。
- RC：冻结该版本公开契约，执行即时完整门禁并生成绑定证据。
- 开发完成版：RC 门禁通过且 P0/P1 为 0 后形成内部里程碑，可立即进入下一版本。

中间版本默认不切换公开 updater `latest`，不把内部完成检查点表述为经过长期使用验证的公开稳定版。

### 3.2 代码变更

- 中间 RC 后如需修复，升 `rc.N+1` 并重新执行该版本全部即时门禁。
- 不因中间 RC 修改启动自然日观察，因为最终只有 v1.0 观察。
- `v1.0.0-rc.1` 冻结后任何功能代码修改都必须升 RC，并从零重新开始 14 天观察。

## 4. v1.0 最终观察

最终观察只能在以下开发工作全部结束后开始：

1. `v0.6.0`–`v0.9.0` 开发完成检查点全部通过。
2. v1.0 公开契约、默认值、升级回退和支持范围冻结。
3. 用户、架构、API、安全、测试、部署、升级和故障文档完成。
4. `v1.0.0-rc.1` 安装包、sidecar、manifest、签名和 updater 资产绑定同一 commit。
5. release-check-full、真实项目 smoke、视觉、a11y、性能、安全和数据门禁全绿。
6. P0/P1 为 0，发布阻断 P2 已关闭或有明确处置。

观察至少覆盖 Python、Vue/Node、Rust 项目，根 workspace/worktree，多文件 PatchSet，项目命令，审批/拒绝/取消/冲突/恢复，本地与远程 Provider，正常/异常退出，数据库/模型中断和完整 updater 链路。

## 5. 兼容路径处置

由于自然日观察被移动到所有功能开发之后：

- 旧 planner、旧 UI 和兼容 API 在 v1.0 RC 中默认禁用并隔离，但不在观察前物理删除。
- 最终观察必须证明默认主链没有不可解释 legacy 调用，并验证显式回退仍可工作。
- 物理删除兼容路径放到 v1.0 stable 之后的独立版本，不在最终 RC 观察后夹带删除代码。

这样可以避免“为了观察归零先删除回退路径”与“RC 候选必须冻结”之间的冲突。

## 6. 风险补偿

顺延观察会扩大最终 RC 前的累计变更量，因此中间版本必须保留：

- 全量单元、契约、集成、Playwright、Cargo 和迁移门禁。
- 每版本真实项目与安装版 smoke，不以自然日等待替代即时质量验证。
- additive 迁移、应用回退、feature flag 和旧主链显式回退。
- 每个检查点绑定 commit、版本、schema、installer SHA、flag 和已知问题。
- 零容忍安全问题即时阻断后续开发，不等到 v1.0 观察才处理。

## 7. 当前开工结论

`v0.6.0` 从本决策生效起可以进入业务代码开发。第一批实现仍按 C0 契约要求，先落 DTO、Schema、fixture 和失败测试，再进入 C1 ProjectWorkspace 与 Session 绑定。
