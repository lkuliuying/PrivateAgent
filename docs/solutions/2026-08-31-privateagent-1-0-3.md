# 问题：PrivateAgent 1.0.3 模型能力与管理员日志不可用修复总结

## 问题描述

记录日期：2026-08-31。范围：另一台 Windows 电脑安装 PrivateAgentRemote 1.0.3 后模型能力不可用，以及管理员端日志模块不可用。

本文保留 1.0.3 修复阶段的记录。后续用户授权的 1.0.4 安装包构建、GitHub 草稿上传及源码提交见[交付记录](../releases/remote-v1.0.4-test.1-20260831.md)；生产服务器应用和真实账号验收仍待维护者确认。

**当前结论：根因已定位，本机代码修复、运行包修复工具及相关验证已完成；尚未收到服务器应用补丁、重新启动和真实账号验收的回执，不能认定已修复上线。**

用户反馈的两个报错为：

- 模型：`Runtime 未启用 Coding 模型能力位（或版本过旧）。请更新 Runtime 或在配置中启用后重试。`
- 日志：`日志接口尚未上线或日志类型不存在，请确认服务器版本`。

本次已核对安装客户端及其本机执行器，安装包大小和 SHA256 与交接记录一致。源码追踪表明，模型配置、模型调用和管理员日志由云端提供；项目、文件和工具操作仍由本机执行器处理，未发现上述云端请求被错误分流到本机的依据。

### 根因与证据

| 问题 | 已取得的证据 | 判断 |
| --- | --- | --- |
| 服务源码与实际安装副本不一致 | `/opt/private-agent/current/src/personal_assistant` 已有新增模块及路由注册，但按服务账号、解释器、进程环境和工作目录重建检查时，应用解析到 `/opt/private-agent/venv/lib/python3.12/site-packages/personal_assistant`；后者缺少日志路由、桌面模型代理路由和日志读取模块 | 修改源码目录没有同步实际安装副本，能够解释日志接口不存在，并会阻断桌面模型代理调用 |
| 云端模型能力未启用 | 同一检查环境加载出的 `coding_permission_models_enabled=false`；前端将模型配置接口的 `409 + coding_mode_disabled` 映射为能力未开启 | 必须显式配置必要的模型权限开关，不能只补齐路由 |
| 模型代理存在潜在字段错误 | 使用真实 `ModelProfile` 对象测试时，访问 `reasoning_efforts` 复现 `AttributeError`；ORM 实际字段为 `reasoning_efforts_json` | 需同步修复，否则启用能力后，带推理强度的请求仍可能失败 |

用户提供的服务器 `git pull` 输出只证明远程对象已拉取、合并因本地修改和未跟踪文件冲突而中止，不能视为服务器更新成功。应保留已有定向补丁和 `alembic/env.py` 修复，不使用强制覆盖解决此冲突。

以上运行环境结论来自用户在 FinalShell 中执行诊断脚本后提供的回执，不是对原服务进程 Python 内存的直接观测。启动环境中的 `unset` 单独不足以证明功能关闭，本次判断采用的是配置加载结果。

## 代码变化摘要

本次没有重新开发已有日志接口或本机执行器，主要完成了以下修复与交付：

1. **修复模型代理字段引用。** 将 `profile.reasoning_efforts` 改为 `profile.reasoning_efforts_json`，保留原有模型选择和异常处理边界。
2. **修正测试替身并补充回归覆盖。** 使用真实 ORM 对象，验证支持的推理强度可正常解析；不支持或未声明的强度返回 422，且不会继续调用模型网关。旧测试替身错误地包含不存在的字段，此前掩盖了该缺陷。
3. **新增运行包定向修复工具。** 提供 `check`、`apply`、`rollback`，将已核对的五个文件补齐到实际安装副本，同时应用代理字段修复。
4. **编写服务器操作与回滚说明。** 覆盖只读预检、停止单个服务、应用补丁、必要配置变更、恢复服务和真实验收。
5. **修正临时诊断脚本的退出问题。** 详见下节；该问题属于诊断工具，不属于业务服务故障。

截至整理时，业务修复和新增交付文件仍在本机工作区，未提交、未推送，未构建或发布新客户端安装包。

## 解决方案

### 1. 定向修复实际加载的安装副本

本次选择对已知运行包做有备份的应急补丁，避免整体重装、切换 `PYTHONPATH` 或 editable 安装将未核对文件引入运行环境，也避免覆盖服务器安装副本中的其他修复。后续正式发布仍应统一源码、构建产物与安装版本。

固定目标位于 `/opt/private-agent/venv/lib/python3.12/site-packages/personal_assistant`：

```text
config.py
main_api.py
api/routes_admin_logs.py
api/routes_desktop_model.py
core/admin_logs.py
```

工具只读服务器源码，并校验来源与目标摘要、文件类型和 Python 语法；遇到未知改动或路径异常时拒绝覆盖。应用和回滚均要求 Supervisor 明确报告 `private-agent STOPPED`。写入前生成完整备份清单，采用原子替换并保留文件权限和属主；支持重复执行识别、部分写入失败后的回滚，并拒绝覆盖后续未知修改。

备份目录为 `/opt/private-agent/rollback-connected-runtime-1.0.3`，权限 0700，仅保存运行包源码及恢复清单，不包含凭据、部署环境文件或数据库。

### 2. 仅开启必要的云端模型能力

在现有 `/etc/supervisord.d/private-agent.ini` 的 `[program:private-agent]` 配置中，将 `PA_CODING_PERMISSION_MODELS_ENABLED` 设为 `"true"`，保留其他环境项，不覆盖整行配置，不修改源码中的全局默认值。

不顺带开启 `PA_CODING_AGENT_UI_ENABLED` 或其他功能开关。联网版工作台的能力声明来自本机执行器；云端模型列表还取决于当前账号的模型 profile，开启能力不等于自动配置可用模型。

### 3. 单独处理诊断脚本的假超时

早期诊断脚本把 `PYTHONINSPECT` 设为非空字符串 `"0"`，导致终端场景下结果已输出，子进程却进入交互等待，最终报告超时。此前非交互检查未覆盖该场景。

本机 v3 已改为移除该环境变量，并将子进程标准输入设为 `subprocess.DEVNULL`。真实终端测试已复现旧行为，并验证修正后正常退出。因此，超时不能被解释为“没有获得模块或配置结果”，也不能据此判定业务服务本身卡死。

### 4. 服务器应用步骤与待验收项

完整命令、停止条件和回滚步骤见[服务器修复操作说明](../connected-runtime-1.0.3-repair.md)。本总结不替代该操作说明。

- [ ] 只读预检得到 `CHECK_PASSED`，停止单个服务后应用补丁，取得 `APPLIED_AND_VERIFIED` 或 `ALREADY_APPLIED`。
- [ ] 仅修改必要模型开关，重新加载该程序并确认状态稳定为 `RUNNING`。
- [ ] 真实管理员账号检查四类日志来源，确认接口和实际读取均正常。
- [ ] 当前账号获取可用模型 profile，并完成一次无敏感内容的真实模型请求，包括支持的推理强度。
- [ ] 联网客户端复验本机目录建项目、文件读取与审批修改；拒绝或取消后不得写文件。

上述项目截至本文记录时均未取得本轮修复后的验收回执。

## 注意事项

- **生产状态仍待确认。** 源码存在、诊断通过、匿名接口返回 401 或 Supervisor 显示 `RUNNING`，均不能代替真实账号模型调用和管理员日志验收。
- **应急补丁不等于正式发布。** 工具直接更新安装副本，不更新 wheel 的 `dist-info/RECORD`；后续重装可能覆盖补丁，正式版本应从包含修复的可追溯提交重新构建。
- **维护操作存在短时停机。** 先结束客户端任务并确认现有数据备份。服务重启仍执行原有 Alembic 检查；本次未新增迁移，也未绕过检查。
- **模型配置与密钥独立验收。** 模型 profile 按账号生效；重启可能清除只在内存中保存的供应商 Key，需要用户在安全配置页面重新保存，不导出凭据。真实推理可能产生费用。
- **日志权限不扩大。** 当前实现将日志不可读报告为 503，与此次接口缺失的 404 不同。若修复后出现 503，应按具体路径和服务账号另行核对，不改为 root 运行或放宽为全局可读写。日志轮转后的权限保持仍待验证。
- **保留现有服务器改动。** 不执行 `reset --hard`、`clean` 或删除冲突文件；不改数据库、Nginx、其他服务及正式更新源。回滚仅恢复工具备份的运行包文件及本次改动的模型开关。

本次排查说明，后续部署校验必须同时记录源码提交、安装包来源、服务解释器、实际模块解析路径和真实账号接口结果；单看源码文件或服务存活不足以证明新功能已经生效。
