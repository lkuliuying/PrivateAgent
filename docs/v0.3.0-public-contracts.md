> - 归属检查点：`0.3.0-alpha.2`（A5：legacy 兼容与契约冻结）

## 1. `/capabilities`

GET `/capabilities`，不探测依赖，返回固定字段：

| 字段 | 类型 | 语义 |
|---|---|---|
| `chat_execution_mode` | `"agent_runtime" \| "legacy"` | 桌面端唯一接管信号；`agent_runtime` 时新消息直接进 `/chat/stream` Runtime 路径 |
| `legacy_tool_planner_enabled` | bool | 恒等于 `chat_execution_mode == "legacy"`（互斥） |
| `agent_read_only_tools_enabled` | bool | 只读工具门禁 |
| `rag_chat_runtime_enabled` | bool | `chat_execution_mode == "agent_runtime"` 且 RAG 工具与输出验证均开启 |

### 1.1 v0.5.0 B0 additive 扩展（2026-08-09）

以下字段为 **additive 追加**，默认 `false`，不改变既有字段语义；旧字段与新字段
集合由 `tests/test_public_contracts.py` 冻结：

| 字段 | 类型 | 语义 |
|---|---|---|
| `patch_workflow_enabled` | bool | Patch 工作流开关（`PA_AGENT_PATCH_WORKFLOW_ENABLED`） |
| `command_workflow_enabled` | bool | 命令工作流开关（`PA_AGENT_COMMAND_WORKFLOW_ENABLED`） |
| `http_workflow_enabled` | bool | HTTP/API 工作流开关（`PA_AGENT_HTTP_WORKFLOW_ENABLED`） |
| `sql_readonly_workflow_enabled` | bool | 只读 SQL 工作流开关（`PA_AGENT_SQL_READONLY_WORKFLOW_ENABLED`） |

四个开关彼此独立、默认关闭，不存在同时开启多类工作流的总开关；契约表见
`docs/v0.5.0-b0-contracts-20260809.md` §2–§3。

端点不存在时按旧后端处理；字段顺序与 JSON 序列化无关，客户端按字段名消费。

## 2. `/chat/stream` SSE

`POST /chat/stream`，`text/event-stream`，每帧 `data: {json}\n\n`。请求体：`session_id: int`、`message: str`、`knowledge_base: bool`、`tool_result?: {tool_name, output}`。

### 2.1 事件集合

| 事件 | 字段 | 出现规则 |
|---|---|---|
| `run` | `run_id: str` | Runtime 路径首个事件，标识 durable run |
| `token` | `content: str` | 增量文本，可多条；最终 `done` 前如有剩余内容会补发最后一条 |
| `approval` | `run_id`、`approval: {id, run_id, tool_call_id, tool_name, tool_version, arguments_sha256, risk_level, required_capabilities: list[str], status, expires_at, created_at}` | 每条待审审批只播报一次 |
| `done` | `run_id`、`message_id: int`、`content: str`（完整回答）、`sources: list`（RAG 来源，见 §5）、`memories: list`（当前恒为 `[]`） | 成功终态唯一结束帧 |
| `title` | `title: str` | 仅首轮生成标题 |
| `error` | `run_id?: str`、`message: str` | 失败关闭/预算不足/持久层不可用/运行终止 |

### 2.2 顺序与终态

- Runtime 成功顺序：`run` → `token*` → `done`（可能插 `approval` 与 `title`）；
- `done` 只发一次；错误路径只有 `error`（可能跟 `run`），不伪造 `done`；
- 失败关闭场景（含首 delta 前后失败、缺终止帧、验证失败、数据库不可用）只发 `error`；
- 取消/断线可能无任何终态帧（前端已断开），run 事实通过 `GET /agent-runs/{run_id}` 读取；
- legacy 路径事件同为 `token/done/title/error`，但 `done` 无 `run_id`/`sources` 语义。

### 2.3 断线续传

`GET /chat/agent-runs/{run_id}/stream` 重连同一 run，不创建替代 run；输出顺序与终态判定与主流一致。页面刷新后的恢复不依赖旧进程内存。

## 3. Agent run 状态集合

`AgentRunStatus`（`src/personal_assistant/agents/contracts.py`）：

```
created, running, waiting_approval, completed, failed, cancelled, timed_out, limit_exceeded
```

- 终态：`completed / failed / cancelled / timed_out / limit_exceeded`；
- 待审批：`waiting_approval`；
- 运行中：`created / running`。

## 4. Agent run 公开事件类型

`AgentEventType`，payload 不包含模型隐式推理、raw approval token 或完整敏感输入：

```
run.started
context.prepared
model.started
model.completed
output.validation_started
output.validation_passed
output.validation_failed
tool.requested
tool.started
tool.approval_required
tool.approval_resolved
tool.completed
tool.failed
run.completed
run.failed
run.cancelled
run.timed_out
run.limit_exceeded
chat.output_persisted
```

`context.prepared` payload 键（`context_event_payload`，不含正文内容）：

```
estimated_tokens, section_tokens, history_included, memory_included,
rag_included, summary_included, sensitive_excluded, truncated,
decisions[{id, kind, included, reason, estimated_tokens}], decisions_truncated
```

## 5. RAG 来源与引用结构

`done.sources` 与 `POST /agent-runs/{run_id}/approvals` 之外，RAG 引用在完成投影时使用持久化引用证据复核；`done.sources[]` 固定键：

```
doc_name, ordinal, chunk_id, heading, score, fusion_score, bm25_score,
rerank_score, matched_via: list[str], matched_keywords: list[str]
```

引用证据不可用时拒绝展示（`AgentChatOutputProjectionError`），不降级发布。

## 6. 审批接口

| 端点 | 语义 |
|---|---|
| `GET /agent-runs/{run_id}/approvals` | 该 run 全部审批记录 |
| `GET /agent-runs/sessions/{session_id}/pending-approvals` | 会话下 `waiting_approval` run 的 pending 审批 |
| `POST /agent-runs/{run_id}/approvals/{approval_id}/approve` | 批准并恢复 run（一次性 token 消费），返回 `202` |
| `POST /agent-runs/{run_id}/approvals/{approval_id}/reject` | 拒绝并收敛 run |
| `POST /agent-runs/{run_id}/cancel` | 请求取消 |

审批对象 `AgentToolApprovalResponse` 固定键：

```
id, run_id, step_id, tool_call_id, tool_name, tool_version, arguments_sha256,
risk_level, required_capabilities: list[str], status, expires_at, decision_at, consumed_at, created_at
```

`approval.status ∈ {pending, approved, rejected, expired, consumed}`。错误语义：过期 `410`、非待审批 `409`、不存在 `404`。

## 7. 摘要可见元数据

- `StructuredConversationSummary` 固定键：`goal, decisions, completed, pending, constraints, important_facts, errors, files, tools, next_steps`（全部为字符串数组或字符串）；
- ContextBuilder 注入时只暴露 `summary_included` 计数，不暴露摘要正文以外的敏感信息；
- 原始消息永不被摘要删除或改写。

## 8. compatibility mode/outcome 枚举

`CompatibilityTelemetry._LABELS` 固定（新增 path 必须先扩展 `_LABELS`）：

| path | modes | outcomes |
|---|---|---|
| `/tools` | `legacy_registry` | `returned` |
| `/tools/plan` | `legacy_full`, `runtime_filtered` | `planned`, `not_planned`, `error` |
| `/chat/stream` | `agent_runtime`, `agent_runtime_rag`, `legacy_runtime_disabled`, `legacy_tool_result`, `legacy_rag_tools_disabled`, `legacy_output_verification_disabled` | `routed` |
| `/chat/agent-runs/:id/stream` | `agent_runtime` | `reconnected`, `not_found` |
| `/agent-runs` | `agent_runs_api` | `created` |
| `/tool-calls/:id/approve` | `legacy_tool_call` | `succeeded`, `failed`, `conflict`, `not_found` |
| `/tool-calls/:id/reject` | `legacy_tool_call` | `rejected`, `conflict`, `not_found` |
| `/tool-calls` | `all`, `session_filtered` | `returned` |
| `/tool-calls/:id` | `legacy_tool_call` | `found`, `not_found` |

scope 形如 `<origin>:<version>`，`origin ∈ {process, qa}`；窗口基线行 path 为 `__window__`。不包含用户正文标签。

## 9. 错误码词汇（UI 文案事实字段）

run 级 `error_code` 固定词汇：

| error_code | 对应状态 | 含义 |
|---|---|---|
| `max_steps` | `limit_exceeded` | 步数超限 |
| `max_tool_calls` | `limit_exceeded` | 工具调用数超限 |
| `wall_time` | `timed_out` | 最长耗时超限 |
| `output_validation_failed` | `failed` | 输出验证失败关闭 |
| `cancelled` | `cancelled` | 显式取消 |
| `approval_expired` | `cancelled` | 审批过期收敛 |
| `disconnected` | `cancelled` | SSE 断线收敛 |
| `process_restarted` | `failed` | 进程重启导致孤儿 run 收敛 |
| `process_restarted_after_cancel` | `cancelled` | 取消后进程重启收敛 |
| `state_unknown` | `failed` | 状态未知收敛 |

其他异常类型名（如 Provider 错误）可能作为 `error_code` 出现，UI 不得据此解析控制流。

## 10. 冻结约定

1. 本文档与 `tests/test_public_contracts.py` 必须同步变更；
2. 新增 telemetry path、SSE 事件、状态或错误码属于破坏性变更，需更新 UI 计划并重跑相关 E2E；
3. legacy 物理删除推迟到 `0.6.0+`，本 Alpha 不删除 `/tools`、`/tools/plan`、旧 `/tool-calls*`；
4. `0.4.0-alpha` UI 实现仅依赖本文档契约。
