# 私人助手 Agent · 第二阶段需求文档

> 版本：v0.1 · 日期：2026-07-04
> 前置阶段：第一阶段已具备 Tauri + Vue 桌面端、FastAPI 本地后端、Ollama、MySQL、嵌入式 ChromaDB、会话、知识库、RAG、设置/状态页、sidecar 打包预研。
> 第二阶段定位：从“本地问答助手”升级为“受控工作台助手”，增加可审批的工具调用、文件/工作区能力、知识库增强、任务执行可视化，并对 UI 页面风格和交互效果做一次大改造。

---

## 1. 阶段目标

第二阶段要解决的问题：
1. 用户不只想问资料，还想让助手帮忙处理本机工作资料。
2. 用户需要看到助手做了什么、用了哪些工具、读了哪些文件、为什么这样回答。
3. 第一阶段 UI 功能可用，但信息层级、视觉风格、动效、工作台感还不够，需要整体升级。
4. 在引入工具调用前，必须建立权限、审批、执行记录和失败恢复机制，避免助手失控操作本机。

第二阶段完成后，产品应具备：
- 可审批的工具调用。
- 本地文件/目录读取与摘要。
- 知识库批量导入、重建索引、引用详情增强。
- 任务执行面板，显示每次工具调用的输入、输出、耗时、状态。
- 全新的桌面 UI 信息架构和视觉系统。

## 2. 用户故事

### 2.1 文件资料处理
作为用户，我希望选择一个本地文件或文件夹，让助手读取、总结、问答或加入知识库。

验收：
- 可以在 UI 中选择本地文件或目录。
- 助手读取文件前必须展示权限说明并等待确认。
- 读取完成后能生成摘要或加入知识库。
- 失败时能看到失败原因。

### 2.2 受控工具调用
作为用户，我希望助手在需要执行工具时先提出计划，让我确认后再执行。

验收：
- 助手准备调用工具时，界面展示工具名、参数、风险级别、预期结果。
- 用户可以批准、拒绝、取消。
- 工具执行结果进入对话上下文。
- 所有工具调用都有审计记录。

### 2.3 知识库增强
作为用户，我希望更清楚地管理本地知识库，而不是只看到文档列表。

验收：
- 支持批量导入。
- 支持重新索引。
- 支持查看引用片段详情。
- 支持重复文档检测。
- 支持文档启用/禁用。
- 支持按文档名、状态、时间搜索/筛选。

### 2.4 任务执行可视化
作为用户，我希望看到助手执行任务的过程，而不是只看到最终回答。

验收：
- 对话中有“执行步骤”或“活动流”。
- 每个步骤显示状态：等待审批、执行中、成功、失败、已取消。
- 能展开查看工具输入/输出摘要。
- 失败任务可重试。

### 2.5 UI 大改造
作为用户，我希望桌面应用看起来像一个成熟的工作台，而不是简单 Demo。

验收：
- 主界面信息层级清晰，聊天、知识库、任务、设置有明确入口。
- 页面视觉风格统一，具备现代桌面应用质感。
- 流式输出、引用展开、工具执行、导入进度有自然动效。
- 窗口在 900px 到 1600px 宽度下都不拥挤、不重叠。

## 3. 第二阶段范围

### 3.1 做

1. **工具调用底座**
   - Tool Registry：注册可用工具。
   - Tool Invocation：统一调用协议。
   - Tool Approval：危险操作前审批。
   - Tool Audit：执行记录入库。

2. **本地文件工具**
   - 选择文件/目录。
   - 读取文本文件。
   - 提取文件摘要。
   - 将文件加入知识库。
   - 文件大小、类型、权限校验。

3. **知识库增强**
   - 批量导入。
   - 重建索引。
   - 文档启用/禁用。
   - 搜索与筛选。
   - 引用详情面板。

4. **任务/活动流**
   - 展示工具计划。
   - 展示审批状态。
   - 展示执行记录。
   - 支持失败重试。

5. **UI 大改造**
   - 重做主框架布局。
   - 重做聊天页。
   - 重做知识库页。
   - 新增任务/活动页。
   - 重做设置/状态页。
   - 建立设计变量、组件规范、动效规范。

### 3.2 不做

- 不做完全自主 Agent。第二阶段所有有风险工具都必须审批。
- 不做系统级写操作，例如删除任意文件、修改注册表、启动未知程序。
- 不做云同步、多用户、账号体系。
- 不做浏览器自动控制和复杂联网研究 Agent。
- 不做 OCR、图片理解、音频输入。
- 不做长期记忆系统，最多做对话摘要和任务记录。

## 4. 功能需求

### 4.1 工具调用底座

工具分级：

| 等级 | 含义 | 示例 | 是否需要审批 |
|---|---|---|---|
| safe | 只读、低风险 | 查询健康状态、读取知识库元数据 | 否 |
| confirm | 读取本地文件、消耗资源 | 读取用户选择的文件、批量导入 | 是 |
| restricted | 有潜在破坏性 | 写文件、删除文件、执行命令 | 第二阶段不开放 |

需求：
- 后端定义 `ToolDefinition`：name、description、risk_level、input_schema、output_schema。
- 工具调用统一生成 `tool_calls` 记录。
- 需要审批的工具先进入 `pending_approval`。
- 用户批准后才执行。
- 拒绝后将拒绝结果写回对话。

验收：
- 至少实现 3 个工具：`read_file`、`summarize_file`、`import_to_kb`。
- 工具调用全程有状态记录。
- 拒绝审批时，不执行工具。

### 4.2 文件/工作区能力

需求：
- 用户可以通过 Tauri 文件选择器选择文件或目录。
- 后端只允许访问用户显式选择过的路径。
- 支持 `.txt`、`.md`、`.markdown`、`.pdf`、`.docx`。
- 文件读取前检查大小，默认单文件上限 30MB。
- 目录批量导入时默认上限 200 个文件。
- 读取失败时展示具体原因。

验收：
- 选择文件后，助手能读取并生成摘要。
- 选择目录后，系统能列出可导入文件，并让用户确认。
- 未授权路径不能被工具读取。

### 4.3 知识库增强

需求：
- 文档列表支持搜索、状态筛选、启用/禁用。
- 支持批量导入。
- 支持重建单个文档索引。
- 支持重建全部索引。
- 支持引用详情：文档名、片段序号、原文片段、chunk_id。
- 支持重复导入提示：跳过、重新索引。

验收：
- 批量导入时能看到每个文件状态。
- 禁用文档后，RAG 不再检索该文档。
- 引用详情能展开查看原文片段。

### 4.4 任务/活动流

需求：
- 新增活动流模型：记录工具调用、导入任务、索引任务。
- 对话页右侧或底部显示当前会话活动流。
- 每条活动包含：类型、标题、状态、开始时间、结束时间、耗时、错误信息。
- 可查看工具输入/输出摘要。

验收：
- 工具调用时能看到活动卡片。
- 导入文档时能看到进度和结果。
- 失败活动可重试或复制错误信息。

### 4.5 UI 大改造

第二阶段 UI 从“功能页拼接”升级为“桌面工作台”。

信息架构：
- 左侧：主导航 rail，入口为聊天、知识库、任务、设置。
- 中左：会话/文档/任务列表，根据当前页面切换。
- 中央：主工作区。
- 右侧：上下文检查器，用于显示引用、工具步骤、运行状态。
- 底部：轻量状态栏，显示后端、模型、知识库、当前任务状态。

视觉方向：
- 风格：冷静、专业、本地工作台感，避免营销页风格。
- 颜色：深浅双主题预留；默认浅色，以雾白、石墨、银灰为基础，使用青蓝作为主强调色，琥珀用于警告，红色用于危险操作。
- 字体层级：紧凑、清晰，适合长时间阅读和多任务处理。
- 卡片：只用于独立对象，例如消息、文档、活动记录；页面区域不要层层套卡。
- 圆角：控制在 6-8px，避免过度圆润。

交互效果：
- 流式回答使用轻量打字状态和光标。
- 工具调用使用步骤展开动画。
- 引用片段点击后在右侧检查器定位展示。
- 批量导入使用队列式进度。
- 页面切换使用短过渡，避免花哨。
- 按钮、开关、筛选器、输入框要有清晰 hover、focus、disabled 状态。

验收：
- 900px、1200px、1600px 宽度下不出现文字重叠。
- 对话、知识库、任务、设置四个主页面视觉风格统一。
- 关键操作不依赖说明文字也能理解。
- 工具审批弹窗能明确表达风险和操作结果。

## 5. 数据需求

第二阶段新增表草案：

```sql
CREATE TABLE tool_calls (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id    BIGINT,
  tool_name     VARCHAR(128) NOT NULL,
  risk_level    ENUM('safe','confirm','restricted') NOT NULL,
  status        ENUM('pending_approval','approved','rejected','running','succeeded','failed','cancelled') NOT NULL,
  input_json    JSON,
  output_json   JSON,
  error_message TEXT,
  created_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  INDEX idx_tool_session (session_id, created_at),
  INDEX idx_tool_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE trusted_paths (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  path        VARCHAR(2048) NOT NULL,
  kind        ENUM('file','directory') NOT NULL,
  granted_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_trusted_path (path)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

第一阶段表增强：
- `documents` 增加 `enabled BOOLEAN NOT NULL DEFAULT TRUE`。
- `documents` 增加 `last_indexed_at` 或复用 `indexed_at`。
- `doc_chunks` 可增加 `preview` 或继续用 `content` 直接展示引用。

## 6. API 需求

新增 API 草案：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/tools` | 获取工具列表 |
| POST | `/tools/plan` | 生成工具调用计划 |
| POST | `/tools/{id}/approve` | 批准工具调用 |
| POST | `/tools/{id}/reject` | 拒绝工具调用 |
| GET | `/tool-calls` | 查询工具调用记录 |
| GET | `/activities` | 查询活动流 |
| POST | `/files/authorize` | 记录用户选择并授权的路径 |
| POST | `/files/summarize` | 总结已授权文件 |
| POST | `/documents/batch-import` | 批量导入文档 |
| POST | `/documents/{id}/reindex` | 重建文档索引 |
| PATCH | `/documents/{id}` | 启用/禁用文档 |
| GET | `/chunks/{id}` | 查看引用片段详情 |

## 7. 非功能需求

- 安全：默认禁止未经授权的本地路径读取。
- 审计：所有工具调用必须记录输入、输出、状态和时间。
- 可撤销：第二阶段不开放破坏性写操作，因此不要求复杂回滚。
- 性能：批量导入必须后台执行，不能阻塞 UI。
- 隐私：文件内容只保存在本机；未来云端模型接入时，工具输入上云必须二次确认。
- 可测试：工具调用、审批、拒绝、RAG 引用、批量导入都要有测试。

## 8. 第二阶段验收清单

1. 新 UI 工作台框架完成，四个主页面可用：聊天、知识库、任务、设置。
2. 工具调用底座完成，至少 3 个工具可用。
3. 需要审批的工具必须先展示审批卡片，批准后才执行。
4. 文件读取只允许访问用户授权路径。
5. 知识库支持批量导入、启用/禁用、重建索引、引用详情。
6. 活动流能展示工具调用和导入任务状态。
7. 前端构建、后端测试、Tauri cargo check 全部通过。
8. 关键 UI 页面通过桌面截图验收，不出现重叠、拥挤、风格不统一。

---

## 9. 定版结论

第二阶段不是做“完全自主 Agent”，而是做一个**可控、可审计、可解释的本地工作台助手**。它能读取用户授权的文件，执行受控工具，增强知识库，并通过全新的 UI 把助手的思考、检索、工具执行和结果呈现出来。
