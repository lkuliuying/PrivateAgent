# 个人 Agent 工作台 UI 重构提示词

请基于我提供的界面预览图，对当前个人 Agent 项目的前端页面进行一次完整重构。预览图用于确定信息架构、视觉层级、布局比例和交互方向，不要求机械逐像素复制；请结合现有技术栈与实际功能，做成可以长期维护、真实可用的产品界面。

## 一、工作方式

不要直接开始大范围改代码。请按以下顺序执行：

1. 扫描项目目录、前端入口、路由、布局组件、状态管理、样式体系和依赖。
2. 运行当前项目并检查现有页面；如果可以使用浏览器或截图工具，请记录主要页面在重构前的实际状态。
3. 总结当前页面存在的问题，包括信息架构、内容层级、空间利用、组件复用、响应式、交互反馈和视觉一致性。
4. 列出准备修改、新增和保留的文件，并给出简短实施计划。
5. 在不破坏现有业务功能、接口调用、路由和数据结构的前提下完成重构。
6. 完成后运行 lint、类型检查、构建和现有测试；修复本次修改引入的问题。
7. 再次运行页面并进行视觉检查，重点检查溢出、遮挡、滚动、空状态、长文本、小屏适配和交互状态。
8. 最后汇报实际修改内容、验证结果、仍存在的限制，以及建议的下一步。

如果项目实际结构与本提示词的假设冲突，以项目真实代码为准，但需要保持下面的产品目标。

## 二、产品定位

这是一个个人 AI Agent 工作台，不是普通聊天应用，也不是数据看板。页面需要让用户随时看清：

- Agent 当前正在做什么；
- 整个任务的计划与完成进度；
- Agent 调用了哪些工具、读取或修改了哪些文件；
- 哪些步骤正在运行、失败、等待确认或已经完成；
- 最终产生了哪些文件、代码差异和其他产物。

整体体验可以具备现代编码 Agent 工作台的专业感，但不要复制 Codex 或其他产品的 Logo、品牌元素、文案和完全相同的组件造型，需要形成项目自己的产品身份。

## 三、核心布局

采用桌面优先的三栏工作台：

### 1. 左侧导航栏

- 建议宽度 220–248px，可折叠成图标栏；
- 顶部展示项目自己的品牌标识和名称；
- 设置醒目的“新建任务”按钮；
- 主要入口包括：任务、Agent、知识库、集成和设置；
- 下方展示最近任务或会话，并显示简洁的运行/完成状态；
- 底部放置用户入口；
- 左栏使用深青灰背景，但不要做成高饱和霓虹风。

### 2. 中央任务工作区

中央区域是页面的视觉和功能核心，需要保持足够宽度：

- 顶部栏包含面包屑、任务名称、运行状态和必要操作；
- 使用独立的计划组件展示任务步骤；
- 步骤至少支持 pending、running、completed、blocked、failed；
- 主体使用时间线或活动流组织 Agent 消息、工具调用、终端执行、确认请求和执行结果；
- 工具调用默认显示人类可读的动作摘要，可展开查看完整内容；
- 文件修改以差异卡片或变更摘要展示，并提供查看 Diff 的入口；
- 不要把所有信息都包装成相同的聊天气泡；
- 将关键结果和普通执行日志做出明显层级差异。

### 3. 右侧上下文栏

- 建议宽度 320–380px，可隐藏；
- 使用 Files、Context、Artifacts 等页签；
- Files 展示与当前任务相关的文件树及修改状态；
- Context 展示当前引用的知识、环境、变量或附件；
- Artifacts 展示生成的文档、图片、代码和报告；
- 右栏视觉权重低于中央区域，不要与中央内容争抢注意力。

### 4. 底部任务输入区

- 在中央工作区底部常驻，但不能遮挡最后一条内容；
- 支持多行输入、附件、快捷操作、发送/停止按钮；
- 清楚显示当前模式、Agent 或模型；
- 将已引用的文件和上下文显示为可移除的标签；
- 运行过程中将主按钮切换为暂停或停止状态；
- 支持 Enter 发送、Shift+Enter 换行，并提供清晰的键盘提示。

## 四、视觉规范

使用青色、白色和冷灰色构建专业、克制、有质感的视觉系统。

建议设计变量：

```css
--background: #f5f9fa;
--surface: #ffffff;
--surface-muted: #edf5f6;
--primary: #08aeb5;
--primary-hover: #07959c;
--primary-soft: #dff7f7;
--sidebar: #082832;
--text-primary: #172b32;
--text-secondary: #667b82;
--border: #dce8ea;
--success: #21a67a;
--warning: #d89a32;
--danger: #db5a65;
```

其他要求：

- 建立统一的颜色、字体、间距、圆角、阴影、层级和动效变量；
- 使用清晰的 8px 间距体系；
- 卡片圆角控制在 10–14px，输入区可稍大；
- 主要通过留白、浅色背景差异和 1px 边框建立层级；
- 阴影保持轻柔，只用于浮层、输入区和关键悬浮组件；
- 青色只用于主要动作、选中状态、运行状态和少量强调；
- 保证正文、次要文字、边框和状态颜色满足可访问性对比度；
- 图标使用项目现有图标库，保持尺寸和描边风格一致；
- 不使用大面积玻璃拟态、强烈渐变、霓虹光效、装饰性 3D 元素或无意义图表。

## 五、交互与动效

动效需要表达状态变化，而不是单纯装饰：

- 侧栏折叠、页签切换和面板展开使用 160–240ms 的平滑过渡；
- 运行中的计划步骤可以使用非常轻微的青色脉冲；
- 新活动进入时使用短距离淡入与位移；
- 工具调用展开/折叠需要保持内容位置稳定；
- 任务完成时提供克制的成功反馈，不使用夸张粒子效果；
- 支持 `prefers-reduced-motion`，关闭非必要动画；
- 如果项目已经使用 Anime.js，请复用它实现复杂序列；如果没有安装，先判断 CSS transition 是否足够。只有确有必要时才添加依赖，并在最终说明中写明。

## 六、必须覆盖的界面状态

不要只实现一张静态理想状态，请补全并检查：

- 首次进入的空状态；
- 有历史任务的普通状态；
- Agent 正在分析与执行；
- 工具调用折叠和展开；
- 文件正在修改；
- 等待用户授权或确认；
- 执行失败及可重试；
- 用户主动停止；
- 任务完成并生成多个产物；
- 侧栏折叠；
- 内容很多时的独立滚动；
- 长任务名称、长文件名和长日志；
- 1280px、1440px、1920px 宽度；
- 较窄窗口下隐藏右侧栏并压缩左侧栏，而不是挤坏中央工作区。

## 七、组件与代码要求

- 将页面拆分成职责明确、可复用的组件，不要把所有内容写在一个大组件中；
- 状态类型、任务步骤、活动类型和产物类型应有明确的数据模型；
- 相同状态的颜色、图标和文案从统一映射中生成；
- 避免到处散落硬编码颜色、尺寸和重复 JSX/模板；
- 保留并复用项目中质量良好的现有组件；
- 不要为了视觉重构改写无关后端逻辑；
- 不删除现有功能；如果某项功能缺少真实数据，使用与现有模型兼容的适配层或明确的临时数据，不要伪造后端实现；
- 不引入多个功能重复的 UI 或动画库；
- 保证 TypeScript 类型、无障碍语义、键盘操作、焦点状态和按钮可点击区域完整。

## 八、验收标准

重构完成后应满足：

1. 用户进入页面后能够在数秒内识别当前任务、执行阶段和下一步；
2. 中央工作区是最明显的视觉焦点；
3. 计划、工具调用、代码变更、确认请求和最终产物具有不同的表现形式；
4. 三个区域能独立滚动，底部输入区不会遮挡内容；
5. 在 1280px 宽度下仍能正常完成核心任务；
6. 所有主要操作都有 hover、focus、active、disabled 和 loading 状态；
7. 页面不存在明显的文字截断、内容溢出、对齐偏差或无意义留白；
8. 原有业务能力和路由保持可用；
9. lint、类型检查、构建和相关测试通过；
10. 最终效果与参考图在结构、层级和气质上保持一致，同时拥有本项目自己的名称和视觉身份。

请现在先完成项目检查并输出重构计划，然后继续实施，不要只停留在建议或示例代码阶段。
