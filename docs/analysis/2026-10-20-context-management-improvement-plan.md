## 1. 目标与首轮交付范围

在现有本机 API Key 架构上，改进两条现有链路：短期记忆负责同一会话的任务连续性和证据找回；长期记忆负责跨会话的相关经验召回、来源核对和人工维护。项目规则继续由 AGENTS.md 等现有入口管理，不创建第二套授权或规则系统。

首轮按顺序完成 **M0 → M1 → M2 → M3 → M4 → M5**，并完成相应验收。已有阶段先检查、补齐和验证，不重新覆盖实现。每个阶段保持可独立验证，不要求为了阶段划分拆成多个框架或公共服务。

| 阶段 | 交付内容 | 主要收益 | 相对工作量 |
|---|---|---|---|
| M0 | 固定基线与长任务回归场景 | 能判断后续改变是否有效 | 小 |
| M1 | 上下文分项计量与界面明细 | 查清规则、工具、历史等分别占用多少 | 中 |
| M2 | 重要证据选择与结构化交接摘要 | 减少压缩后丢失关键发现、混淆验证状态 | 较大 |
| M3 | 当前会话归档搜索 | 不知道原始 ID 时也能找到历史证据 | 中 |
| M4 | 面向当前步骤的长期记忆召回 | 减少无关记忆，找回与正在执行步骤有关的信息 | 中 |
| M5 | 长期记忆的来源对照、重复提示和过期维护 | 降低重复、冲突和陈旧事实的维护成本 | 中 |

首轮保持全部用户原文进入现有历史投影的行为。因此，**首轮不能解决用户原文本身无限累积的问题**；该项列入第 10 节，必须先验证约束保真能力。

首轮不引入向量数据库、embedding 服务、新模型调用、新后台服务、新的必填配置或数据库表迁移，不升级依赖或重建锁文件。继续使用现有 SQLite、工具目录、模型接口、预算与恢复机制。

### 3.2 当前限制与应保留的行为

- 当前压缩保留全部用户原文及最近两个完整消息组，较早事实进入索引；原文不删除。
- 当前未提交代码已将事实投影调整为优先失败与修改证据，再补近期普通事实；模型摘要已有来源排序参数。仍最多读取 24 个来源，单条摘录最多 1000 字符，输出最多 8 项、1024 tokens；相关片段位于长正文中部时，现有首尾摘录仍可能漏掉它。
- 文本采用保守字节估算，图片采用独立估算；完整请求受输出预留、安全余量、字节和条数限制。
- 长期记忆默认总开关关闭，最多召回 8 条、约 6000 UTF-8 字节；当前查询主要取目标前 500 字。
- 已支持 read_context_content，但通常要先知道 item_id 或 archive_ref；当前记忆 search 管理接口也不能替代当前会话归档搜索。
- 长期记忆已有 active / pending_review / stale、expected_version、来源、修订及遗忘墓碑。本轮不回溯重提取旧记忆，不自动批量修改状态，不扩大后台来源范围。
- Responses 的 provider_state 已有续接机制，不能把“已有续接状态”写成“已有原生 compaction”。
- readonly_agents.py 只保留旧子任务的历史查询和取消清理，当前不创建新子任务。

这些是设计与实现观察，不是已经证明发生的线上故障，也不是性能基准结果。

## 6. M2：关键证据选择与交接摘要

### 6.1 先选择重要来源，再生成摘要

保留现有来源数量、摘录和模型调用预算边界，先调整选择顺序，不直接抬高上限。优先级如下：

1. 当前目标与要求对应、尚未解决的失败证据。
2. 当前步骤及下一步依赖的接口、文件与用户决定来源。
3. 本轮真实修改及相关验证结果。
4. 仍有效的既有摘要来源。
5. 最近的普通读取、重复结果及其他辅助信息。

同一来源去重；重复读取同一版本文件不反复占用候选名额。普通内容相同不代表可合并不同的真实执行记录，尤其不能合并写入回执或授权来源。

同优先级使用明确、稳定的排序；低优先级普通读取应优先选择近期内容，不能因 ordinal 升序使最早的普通结果占满名额。无关或已经解决的旧失败不应永久压过当前步骤，使用现有 reflection 与目标状态判断，不从单个 success 字段推断问题已解决。

当前步骤相关的调用与对应结果一起选取：不能只因为调用参数命中路径就选中调用，却把真正说明问题的工具结果遗漏。配对使用本会话的来源条目和实际调用组，不能仅靠可能复用的 call_id 跨运行关联。

摘录按当前步骤相关词和已知结果位置选择，并保留来源 ID、摘录范围与截断标记。工具 JSON 优先抽取已有公开结果字段中的相关区段；普通文本取命中词附近的窗口；无法定位时沿用有界首尾摘录。单条和整批预算保持不变，不能把整个工具正文或 provider_state 带进摘要。增加“关键错误位于长正文中部”的回归，不引入额外摘要模型调用。

### 6.2 形成六类交接内容

| 内容 | 优先事实来源 | 处理要求 |
|---|---|---|
| 当前目标与验收条件 | 当前 task_interpretation、goal_version | 程序投影，不由模型重写授权 |
| 生效限制与适用规则 | 原始用户来源、确定性策略、已核对规则 | 附来源，不能因摘要丢失而放开 |
| 当前计划与下一步 | planning.context、当前步骤状态 | 当前计划优先于旧摘要中的计划 |
| 关键发现与决定 | 工具证据、用户决定、公开模型说明 | 区分观察、用户要求和模型报告 |
| 修改与验证 | executions、已有文件快照及工作区版本 | 修改成功不等于验证成功 |
| 未解决问题 | reflection、失败记录、计划待核对项 | 无关成功读取不能清除问题 |

可在现有 checkpoint JSON 中增加可选版本和派生字段，保留旧 messages、summary、summary_strategy 等读取能力。首轮不新增表，不强制重写旧检查点。没有足够来源的旧记录显示“未知/待核对”。

证据记录至少包含原始调用与结果引用、事实类别及已知版本信息。只有实际工具执行记录、快照或验证器能给出版本和验证状态；模型生成的解释不能补造字段。优先复用现有完成验证器的失效规则，不建立第二套“任务成功”判定。

同一相关文件/工作区版本已变化时，旧证据不能作为当前已验证完成。尚无法证明影响范围的情况标为需复核，不能推断未受影响。

### 6.3 压缩提交、兼容与降级

- 保留全部用户原文与最近两个完整组，维持现有工具配对校验。
- 交接状态尽量由确定性数据构成，模型摘要只补充有来源的解释；保留现有严格 JSON、来源、敏感内容和路由校验。
- 不能把 provider_state 或隐藏推理发送给通用摘要、搜索、公开事件或 UI。近期原生调用组保留完整供应商状态及结果；较早组按原有安全方式整体压缩。
- 摘要请求仍使用现有供应商路由与计费记账，保留主任务至少一次调用机会，取消和超时不自动重试。
- 信息不足时保留未解决项与来源引用，不把错误猜成事实；新的语义解释不能替代原始证据。
- 提交前继续校验 generation、目标/计划版本、规则、权限、模型、项目根及历史末序号。任何 await 后发现来源或版本变化，不提交过时视图。
- 必需内容和候选摘要先经过完整请求预算；有收益且可容纳才提交。摘要失败回退事实索引，仍放不下则显式停止，不能为“继续运行”删约束或裁剪不透明状态。
- 完整来源索引继续归档，不能把所有 evidence 元数据无限塞回每轮请求。

### 验收

1. 早期关键证据在大量无关读取后仍被选中，或有明确可检索引用；不能仅因时间较早消失。
2. 连续两次以上压缩后，当前目标、约束、待办和未解决问题均可核对来源。
3. 修改文件后，之前测试结果不能直接满足当前完成验收。
4. 伪造来源、错误格式、秘密、超时、取消、配置变化与磁盘失败都保持原历史和旧有效检查点可读。
5. 不增加额外自动重试、总结模型次数或隐藏费用；不更改用户原文，不重放副作用。
6. 早期重要结果与调用保持关联；同优先级的噪声不会长期占满来源；长正文中间的关键片段可进入有来源摘录。目标、计划版本在摘要等待期间变化时，旧交接不提交。

## 7. M3：搜索当前会话归档

### 拟新增工具契约

工具名：search_context_history。只读，只针对执行器绑定的当前会话。

| 入参 | 建议限制 |
|---|---|
| query | 必填，非空，最多 200 字符；文字查询，不接受正则、SQL 或脚本 |
| role | 可选，限定 user / assistant / tool |
| tool_name | 可选，限定合法工具标识符，服务端验证 |
| limit | 默认 5，范围 1～10 |

结果包含：item_id、ordinal、角色/工具名、来源及信任标记、有限摘录、必要的公开版本信息，并说明可通过 read_context_content 续读。单条摘录最多 400 字符，整个结果最多 8 KiB UTF-8；达到上限时返回明确截断标记，提示缩小查询。

### 实施要求

- 首版复用现有当前会话历史上限和公开投影进行有界搜索，不启用 FTS 数据库迁移、不建常驻索引。
- 按中文双字、英文标识符、路径等现有可用方式匹配，采用确定性排序；未命中就返回未命中，不生成答案或虚构相关来源。tool_name 必须与存储的实际工具名匹配，不依赖正文里是否重复出现名称。
- 查询不接受 session_id、project_id 或任意文件路径，身份与会话只能由当前运行绑定。
- 与 read_context_content 一样执行路径访问限制：存在 access_scopes 且无法证明历史范围时，禁止搜索。可见工具过滤和实际执行层都要检查，不能只在前端隐藏。
- 搜索公开且经过敏感内容过滤的投影；provider_state 不参与搜索、排序、摘录或结果序列化。不能通过命中词、错误信息或日志泄漏敏感原文。
- 外部工具资料继续携带不可信来源标记；搜索结果不能升级为指令、授权或已完成事实。
- 将新工具纳入现有 ToolSpec、输入输出校验、tool_catalog 的 DEFERRED_TOOLS 与搜索关键词，按需加载后下一轮才调用。
- 扩展工具目录不应使无关任务总是携带新工具 schema；旧执行协议不支持按需加载时保持既有兼容行为并复测预算。
- 结果必须能接续已有 read_context_content；不修改原始 item_id、摘要和 payload。

### 验收

能用错误词、路径或工具名找回早期证据；支持中文；排序稳定；空查询、超长查询、非法过滤均被拒绝；分页原文可核对；跨会话、路径受限、秘密和原生状态均无泄漏；新增工具不破坏原 26k 窗口回归。

## 8. M4：围绕当前步骤召回长期记忆

### 8.1 构建随任务变化的查询

复用现有 memories.search/recall_with_details，将查询信号从“目标前 500 字”调整为有界的组合：当前目标、当前进行中步骤、明确关联的项目路径/符号，以及有效追加要求。采用确定性提取与长度配额，不增加查询改写模型调用。

组合查询继续不超过现有 500 字符上限。分别为目标、步骤、有效追加要求和路径/符号分配长度，先保留各来源的有效词项再分配剩余额度，不能拼接后又只截开头。查询仅用于相关性，不参与授权解析；追加要求从现有任务状态取得，不另读整份用户数据库或扫描项目源码来生成查询。

当前步骤、目标或有效追加要求变化后重建查询，不沿用旧步骤召回结果；缓存如果并非必要就不添加。查询日志与公开事件只记录来源类别、计数等必要元数据，不新增完整查询正文日志。

### 8.2 先过滤，再排序和截取

自动注入按以下顺序处理：

1. 从当前项目及本机身份内允许的跨项目偏好范围读取候选。
2. 先排除 deleted、pending_review、stale 及敏感内容，再做候选上限截取。
3. 按当前步骤、目标、路径/符号的命中、人工维护标记和更新时间稳定排序；同分使用确定性标识兜底。
4. 最后按最多 8 条、约 6000 UTF-8 字节的预算选入实际请求，预算紧张时继续整体移出可选记忆。

不要只在现有 search 调用上追加过滤而遗漏空查询分支。管理页和明确的查找/纠正工具仍需看见待复核条目；不能把管理查询统一改为 active_only，从而让用户无法解决冲突。召回解释可保留有界的排除计数或原因，但非活跃条目不能占用有效候选名额。

### 8.3 区分偏好与任务事实

保留现有 scope、kind、origin、status，不新增“永久可信”字段：

- 人工维护、active 的 preference 可作为少量未命中参考候选，建议最多 2 条，排在相关命中之后，不挤掉高相关结果；这是偏好保底额度，不是自动认定永远有效。
- project / workflow / reference 条目即使由人工保存，也必须与本轮信号相关才自动注入；零匹配自动条目继续排除。
- 时间、版本、环境或路径相关内容即使匹配，也只作为可能过时的参考；不能自动代表当前现场事实或扩大权限。存在明确冲突时沿用复核状态，不按更新时间直接覆盖。
- 旧数据缺失新解释字段时保留兼容读取；不能通过一次扫描批量重分类、自动启用旧条目或改变用户开关。

### 8.4 可解释性与验收

现有 memory_context 明细保留实际条目 ID、版本、来源与排除原因，按需增加可选的匹配来源类别（目标、当前步骤、追加要求、路径或偏好保底）。界面沿用 SessionMemoryPanel，不把偏好保底伪装成关键词命中，也不复制敏感词和额外原文。

以下均用临时 SQLite 和合成任务验证：

1. 目标开头无关、后半段包含关键接口时，或只在当前步骤/追加要求出现中文路径时，相关记忆仍可命中。
2. 超过 20 条高匹配但非活跃记忆存在时，相关 active 条目仍能进入候选；空查询同样不能被非活跃条目挤占。
3. 人工偏好保底、无关人工项目事实排除、相关事实优先、未命中自动条目排除均符合约定，且总条数与字节上限不变。
4. 步骤切换、开关关闭、来源删除、冲突复核、遗忘后再次生成、读取后版本变化，均维持现有边界；管理页仍能找到待复核项。
5. 召回解释与实际发给模型的条目版本一致；本轮未注入时不能显示成已使用。

同义但无词项重叠的召回能力不作为首轮承诺，不为了通过用例增加隐式同义词模型调用。

## 9. M5：降低长期记忆的维护成本

### 9.1 来源与冲突对照

复用 MemorySettingsPanel、MemoryEvidence 和现有来源/修订/复核接口。在同一个复核区域并列展示当前条目、新候选、版本、scope/kind、来源时间及可按需打开的原句；明确区分用户直接陈述、人工条目和模型生成内容。来源 ID 存在只证明可追溯，不能宣称模型总结必然得到原文支持。

保留采用新值、保留旧值、人工纠正等已有操作。并发编辑返回 409 时保留编辑草稿并提示刷新核对，不能自动重试覆盖。来源缺失或由设置页手动创建时如实显示，不补造会话引用；旧版本缺少元数据时显示未知。

### 9.2 有界的疑似重复提示

首版只在用户打开记忆管理页或主动查询时，对现有列表计算派生提示，不新增后台任务、模型调用、数据库表或必填字段。只比较同 scope 且属于同一项目/用户范围的非遗忘条目。

优先提示同 topic_key、规范化标题相同或规范化正文相同的条目；规范化只做空白和大小写等明确处理。提示必须展示命中理由，不能将相似认定为冲突，也不能宣称已解决无词项重叠的同义重复。不应把每一对相似条目都铺成列表；按重复组展示，并沿用现有列表数量上限。

复用既有编辑和逐条遗忘操作：每个写入按原有 expected_version 核对，遗忘保持现有确认流程。首轮不增加“一键合并并删除其他条目”按钮，不把多个独立请求描述成原子合并，也不把不同来源会话强行改成单一来源。若需要跨条目的原子合并与多来源持久化，列入后续专项设计。

### 9.3 易变事实和过期维护

在复核区域显示已存更新时间、来源和当前状态，提供已有标记 stale、查看来源、纠正或重新确认的入口。列表可按待复核/过期筛选；不按固定天数批量删除，不把普通偏好仅因时间较早判为无效，不在后台重新启用 stale 条目。

本轮不新增 TTL 字段，不自动扫描工作区来证伪旧记忆，不改变后台提取模型、每日限额、至少两条有效用户消息等来源条件；失败或取消会话的自动经验提取不纳入首轮。疑似环境/版本事实提示只辅助人工判断，不能替代现场核实。

### 验收

1. 同范围的同主题、同标题或同正文条目可以对照；不同项目事实、跨项目与项目范围不误合并，遗忘内容不参与提示。
2. 来源分页、来源缺失、人工无来源、旧修订、待复核、stale 均有准确展示；没有来源时不显示“已验证”。
3. 查看、排序和筛选不写入数据、不开启生成、不增加模型调用；只有用户的明确管理动作改变条目。
4. 复核、编辑、遗忘的版本冲突保持草稿及已提交状态，取消操作不改变条目；不能把已遗忘正文从修订或旧提示重新展示。
5. 复用附近组件、API 与浏览器用例检查宽/窄窗口及键盘交互；源码和测试通过不等于真实安装包验收。

## 11. 回归与验收矩阵

在附近用例上扩展，不为每个字段编写镜像测试，不新增测试框架。

| 场景 | 必须观察到的行为 |
|---|---|
| 早期约束，随后大量读取与两次压缩 | 用户原文与限制未被改写；工具仍执行原有拦截 |
| 用户追加目标或明确解除局部限制 | 当前版本的任务策略生效；旧摘要不能重新加入或解除限制 |
| 未满足条件、引用、外部文档注入 | 不制造执行义务，不获得权限 |
| 早期关键发现，后续大量噪声 | 重要来源被保留或能被搜索定位、续读 |
| 关键结论位于长工具结果中部 | 摘录带来源和范围，不能只保留首尾却漏掉结论 |
| 失败后成功读取其他文件 | 原失败仍作为未解决问题存在 |
| 修改文件后引用旧测试结果 | 完成验证要求重新核对相关证据 |
| 多次压缩、归档读取和来源变化 | ID、摘要、引用与代次一致，不提交旧目标视图 |
| 取消、超时、存储失败或规则变化 | 原历史和旧有效检查点保持可读，无自动副作用重放 |
| 极小窗口、未知容量、超大必需输入 | 保守计量或显式停止，不静默截断约束 |
| 图片、Responses 原生状态 | 计入预算，公开投影与搜索不泄漏内部状态 |
| 新工具发现与旧协议 | 当前可见工具、下一轮加载及预算规则保持一致 |
| 记忆关闭、冲突、遗忘与步骤切换 | 不越权开启、不复生，召回解释对应本轮结果 |
| 非活跃记忆超过候选上限 | 有效候选仍可进入自动召回，管理查询保留待复核可见性 |
| 无关人工事实与相关事实同时存在 | 相关事实优先，只有有限人工 preference 可以无命中保底 |
| 重复对照、来源缺失和并发纠正 | 提示不冒充语义判断，不自动写入，409 保留草稿，不伪造来源或原子合并 |
| 旧运行和旧检查点 | 缺少新字段可读取；不能伪造新式验证或选择证据 |

首轮通过条件：上述确定性边界无回归；基线夹具可完成原有长任务；新增重要来源选择和搜索场景通过；全部模型请求仍受原有预算约束；UI 如实展示未知与估算。

报告指标包括压缩前后大小、关键来源覆盖、续读是否命中、压缩次数、调用次数和耗时。关键来源覆盖应区分“仅存库”“摘要中可见”和“经搜索找回”，不能只统计原始 ID 数量。

长期记忆用人工标注的合成样例记录前 8 条相关条目数、遗漏条目数、无关注入数、非活跃或越界条目数、预算占用；至少涵盖步骤切换、中文路径、长目标后段、重复主题和冲突。不能把低成本词面检索用例说成语义理解测试。

不得预先宣称成功率或费用改进百分比。真实模型质量需在另行授权后，使用同模型、同题目、同预算做对照；此时区分保存了信息、模型看到了信息和模型正确使用信息三个结果。首轮合成测试没有证明后者。
