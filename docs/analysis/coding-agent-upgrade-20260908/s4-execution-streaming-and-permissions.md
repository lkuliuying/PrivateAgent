## 1. 阶段目标

让 Agent 正常使用开发命令、长构建和受管理的开发服务器；及时展示工具与模型公开输出；把审批与实际执行隔离分开实现。解决 G07–G10。

本阶段不通过放开任意系统权限来换取“命令可用”，不改固定账号入口，不向客户端下发供应商密钥。首版以受审查的 argv 命令及必要的 shell 适配为主，shell 管道等复杂语法必须有独立解析/授权与隔离方案后才能暴露。

## 4. 执行会话与生命周期

### 4.1 管理模型

建议由本机应用维护按工作区绑定的有界宿主池。每个宿主只服务同一账号/工作区，运行的命令具有不可混用的 execution ID、宿主实例 ID 和会话绑定。初始并发容量建议每工作区 2 个执行、账号全局 4 个，具体值由 S0 基线校准。

默认命令在任务结束时清理；明确启动的开发服务器可标为保留到会话关闭。保留行为必须用户可见，可在会话界面关闭，不能留下不知归属的后台进程。账号退出、授权撤销、工作区关闭和应用关闭有各自清理策略，受影响进程必须停止。

### 4.2 拟议执行工具

| 工具/操作 | 输入 | 行为 |
| --- | --- | --- |
| exec_command | argv、相对 cwd、yield 时间、总超时、输出预算、是否 tty、权限请求 | 返回初始输出和已结束状态，或可续读 execution ID |
| read_execution | execution ID、输出游标、有界等待 | 增量读取，空输出也返回活跃状态 |
| write_stdin | execution ID、输入、EOF 标记、预期状态版本 | 校验当前会话与授权后写入；必要时独立批准 |
| cancel_execution | execution ID、幂等请求 ID | 回收进程树并报告是否实际停止 |
| list_executions | 当前工作区/会话范围 | 返回活跃进程及归属，不暴露其他账号数据 |

复用既有 `execution/start`、`execution/stdin/write` 等宿主协议；新增本机路由只是适配，命名由 S0 冻结。宿主会话 nonce 由应用保管，模型和公开日志不需要看到该值。

### 4.3 时间与状态

`yield_time_ms` 仅控制一次调用等待多久，不能到期就杀进程。`timeout_ms` 控制总执行期限；开发服务采用明确的保留策略，仍有应用退出和授权期限边界。初始建议普通命令默认最大 10 分钟，允许在用户授权范围内调整；实际硬上限在 S4-02 固化。

状态为 `starting → running → exited`，另有 `cancelled | timed_out | failed | unknown`。取消 API 接受请求不代表进程已退出，只有宿主确认进程树/Job 状态后才能展示“已停止”。启动、stdin、输出与取消竞态须采用状态版本或互斥处理。

## 5. 输出存储、续读与背压

- 宿主输出 sequence 与 run 事件 sequence 含义不同；应用接收后由 Store 生成全局 run 序号并保存关联。
- stdout/stderr 分块、有界队列传递；Unicode 跨块解码不能损坏中文、emoji 或 CRLF。
- 按容量批量持久化，避免每字符写 SQLite 或重写整份运行 JSON。
- UI 重连按游标读取；重复块幂等，缺块返回 gap/可用范围，不默默跳过。
- 输出超限保留明确 head/tail 或滚动窗口，记录丢弃字节/序号范围。需要完整日志时提供有界工件引用和保留策略，不声称完整记录已保留。
- 消费慢时启用背压与磁盘配额；配额不足明确失败或截断，不无限占内存。
- 任意命令输出含潜在控制序列，UI 必须按安全文本渲染，不能注入 HTML 或执行终端控制载荷。

## 6. 权限与隔离设计

### 6.1 四个独立维度

| 维度 | 需要回答的问题 | 不能替代它的机制 |
| --- | --- | --- |
| 项目范围 | 哪些路径可读、可写，工作目录在哪里 | 单纯把 cwd 设置为项目根 |
| 操作批准 | 哪类命令/补丁已授权，授权到何时 | 模型说“安全”或历史回答 |
| OS 隔离 | 子进程实际能访问哪些文件、网络、系统能力 | 程序名称白名单、Job Object |
| 生命周期 | 取消/撤权是否停止整个进程树 | 仅把 UI 状态改为 cancelled |

保留当前四种权限的用户概念，具体范围不静默扩大。`full_access` 仍不能被解释为管理员权限或默认全盘权限。若语义需变更，必须在产品文案、能力声明、授权记录和兼容说明中一致调整。

### 6.2 能力探测与降级

返回分项能力，例如文件读隔离、文件写隔离、网络隔离、PTY、进程树终止，不用单个 sandbox_available 遮盖差异。探针需要真实正反对照，库编译成功或拒绝创建进程不足以证明沙箱有效。

首选当前 Windows 原生可用的受限进程/ACL/AppContainer 等机制，但不预先承诺某个组合在目标机器一定成立。WSL/容器会引入路径和工具链迁移，不在本阶段静默启用。

如果所需隔离不可用：保留受控文件工具与可验证的只读能力；项目脚本执行需要用户明确接受可信项目执行范围，并显示实际边界。不能从“请求受限执行”静默退为普通当前用户执行。未受限可信执行可以作为明确的使用档位，但不得作为“沙箱门禁已通过”的证据。

### 6.3 授权持久化与网络

授权绑定规范化 argv/cwd、环境差异、工具版本、目标域名或网络档位、工作区身份和到期时间。脚本/配置变化影响授权语义时需重新评估。模型请求安装依赖或联网不能默认视为已有批准，用户明确授权范围可复用并可撤销。

开发工具的运行时和编译缓存目录需要按实际依赖提供最小读/写授权；不能为修复工具启动随意放开整个用户目录。秘密不注入子进程环境。获准读取某个配置也不能将其中凭据复制进模型上下文或日志。

网络授权与 shell 批准分开，能隔离网络时按目标策略执行；无法做细粒度网络限制时如实声明，不能把域名提示当内核级允许列表。账号/供应商模型请求与项目脚本网络策略也要区分。

## 7. 开发命令兼容

工具定义显式给出可用程序、版本、工作目录能力和权限原因，减少模型盲试。支持 `cwd=apps/desktop` 配合 `pnpm test` 等常见 monorepo 操作，避免只能依赖包管理器特殊参数。

argv 首选结构化数组；Windows `.cmd/.bat` 使用受审查的 quoting，不允许把未验证文本再次拼接成任意 shell。需要 shell 语法时，按受支持语法解析并应用同一权限/隔离流程，不通过 `python -c` 作为通用绕行入口。

工具缺失返回明确的程序名和所需环境；不自动下载解释器或改全局 PATH。项目要求安装依赖时，展示工作目录、将变动的清单/锁文件和网络范围，按当前授权执行。项目脚本可间接改变文件，S3 的基线与 S5 的变更审查需记录这些变化，但不要承诺能将所有变化精确归因到某个进程。

## 8. 模型增量链路

### 8.1 传输与事件

为 `LocalRunAdapter` 接入 complete_stream；本机模型使用共享流式适配器。远程代理增加经过能力协商的流式入口，保留原 `/desktop/model/complete` 兼容；拟议新入口为 `/desktop/model/stream`，实现前冻结准确 DTO、事件类型和错误格式。

新增代理接口只属于后续开发变更，不能把计划当作服务器已经部署。旧服务器不支持时在请求前选择明确的非流式能力，不发出半段文本后偷偷重新请求完整回答。

### 8.2 内容与完成语义

公开文本 delta 可以作为“处理中”的 assistant 内容展示，最终回合/完成标记必须等模型 finish 和 S1 验证结果。工具参数片段在完整组装并通过 schema 验证前绝不能执行。文本途中出现工具调用时不能把前面的文字提前记为已验证最终答案。

只处理供应商明确公开的文本或公开摘要，不采集隐藏推理。模型类型不支持某些 delta 时不伪造内容。最终消息由已确认完整输出持久化，重连不得重复插入。

### 8.3 重试、取消和 usage

首个公开 delta 前可按协议错误分类有界重试；已公开后断流应标本次尝试中断，保留有界部分内容并明确后续重试的尝试 ID。供应商不支持幂等不意味着可保证免重复计费，应记录请求尝试和 usage 完整性。

客户端取消向 Runtime、HTTP 请求和供应商连接传递。没有完整工具 JSON 不执行；模型 usage 缺失时保持未知。Profile 身份保持 S2 的快照与停用检查，不能在同一回合无提示切换模型。

## 9. 预计修改范围

现有：`apps/exec-host/src/main.rs`、必要的 `sandbox.rs`；共享 execution 契约/客户端；本机 `executor.py`、`runtime.py`、`policy.py`、`core_adapter.py`、`cloud.py`、`local_models.py`、`app.py`、`store.py`；服务器模型代理；Tauri 私有传输与生命周期；桌面输出、取消和事件消费组件。

拟新增：本机执行会话管理模块、输出分块仓储、权限能力探针，以及本机流式/终端/网络对照测试。只在原生库或工具缺少必要能力时评估新增依赖，不借此批量升级锁文件。

## 11. 验收与回滚

- 长命令、持续服务与 stdin 可用，命令输出到 UI 的 p95 延迟达到总路线目标。
- 取消和撤权有进程树级证据，失败不被 UI 掩盖。
- 四种权限文案与实际能力一致，可信项目执行和受限执行不会混称。
- 本机/服务器两条模型路径完成流式与非流式兼容验收。
- M1 仅在 S0–S4 整条链路通过后提供单任务开发试用；重启续跑限制继续公开。
- 回滚时先停止接收新执行并清理受管理进程，保留输出与执行记录；不能留下后台宿主后仅切回旧 UI。
- 流式入口可按能力协商停用，但不得在活动请求中间切换协议；数据库/宿主协议回退需版本检查。
- 更新执行、权限、模型与交付说明；记录具体 Windows/Provider 支持范围及未验证能力。
