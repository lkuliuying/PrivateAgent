## 1. 阶段目标与范围

实现正常仓库开发需要的精确搜索、按行读取、局部补丁、新增目录、多文件新增/删除/移动，并保护用户原有和并发修改。解决 G06/G07，为 S5 变更审查提供操作事实。

不在本阶段自动提交或推送，不实现任意磁盘文件管理，不保证跨文件系统事务，不自动修改二进制、符号链接和子模块内容。Windows 受控 PowerShell 已提供部分目录操作，不能将这些能力误写为完全不存在；本阶段重点是统一其与专用文件工具的可审查语义。

## 4. 仓库读取与搜索

### 4.1 拟议工具契约

| 工具 | 关键输入 | 关键输出 |
| --- | --- | --- |
| read_file | 项目相对路径、起始行、行数、可选期望版本 | 行号文本、总行数、完整文件摘要、版本 ID、截断/续读信息 |
| list_directory | 项目相对目录、页大小、游标 | 稳定排序条目、下一游标、目录变化提示 |
| search_files | 字面/正则模式、glob、范围、页大小、游标 | 文件/行位置、片段、查询版本、下一游标 |
| read_tool_output | 当前任务可访问的内容引用、偏移、上限 | 有界正文与剩余范围，不返回任意内部路径 |

以上名称为设计提案，可通过旧名称的兼容适配发布。避免在当前严格 schema 中直接增加未知字段。暴露的工具目录必须反映真实可用平台能力。

### 4.2 检索规则与性能

优先使用已存在的 rg；缺失时明确降级到有界 Python 搜索或提示开发依赖，不静默安装。打包是否捆绑 rg 由依赖和许可评审决定。搜索参数采用数组，不拼任意 shell。

尊重项目忽略规则和工具自身敏感路径规则，敏感规则不能被 glob 覆盖。支持大小写选项、字面/正则区分、最大文件大小与超时；二进制返回明确跳过原因。

结果排序稳定。游标绑定查询、工作区和搜索快照/索引版本；查询或目录变化使游标失效时明确要求重新查询，不悄悄遗漏结果。正则与大目录搜索要可取消；不要在异步请求路径长时间阻塞事件循环。

首版无需全仓向量索引或语言服务器。通过精确路径、rg、文件片段和项目指令实现有效探索，再由 S6 评测判断是否需要语义索引。

## 5. 版本绑定与补丁格式

### 5.1 读取至落盘的完整冲突保护

模型看到的文件版本必须有主机生成的摘要/版本 ID。patch 请求引用该版本，主机在预览和应用前分别核对。用户在模型读取后、生成预览前修改文件，也应被识别为冲突。

路径由主机规范化，拒绝路径穿越、符号链接、junction、危险硬链接、受保护目录和大小写别名冲突。Windows reparse point 检查与文件实际打开之间仍可能竞态，关键路径应评估句柄级无跟随/身份校验，不能声称仅字符串校验消除了所有 TOCTOU。

### 5.2 拟议 PatchSet

字段：`patch_set_id`、`run_id`、`operation_id`、`workspace_id`、`base_revision`、`operations`、`preview_sha256`、`status`。每项携带操作类型、源/目标相对路径、基准文件摘要、预期结果摘要和必要 patch hunks。

内部采用现有结构化 PatchOperation 思路，保留 Provider 友好的 JSON Schema。是否增加 Codex 自由文本 patch 解析器需独立模型探针，不把自由格式支持设为首版前提。

拒绝同一集合中相互冲突的路径操作、重复目标、源目标循环、仅大小写变化未专门处理的 Windows 重命名和超出限制的 diff。目录创建限定在项目范围，记录本次创建目录，避免回滚时删除原有目录。

### 5.3 预览与批准

批准绑定 patch 集合、文件基准摘要、根目录身份和预览摘要；内容、权限或工作区变化后原批准失效。预览超长时必须能分文件续读完整内容，不能仅展示首屏后假定用户看过全部变更。

自动批准模式也执行同一预检、日志和版本检查。用户明确仅预览时不进入落盘路径。

## 6. 落盘、部分失败与回滚

### 6.1 状态与执行顺序

拟议状态：`proposed → validated → approved → applying → applied`，失败分为 `rejected | conflicted | partially_applied | failed`，回滚结果单独记录。

1. 校验所有路径、读版本、目标不存在条件、权限与操作冲突。
2. 保存预览、原内容引用、操作顺序和恢复信息；内容写入完成且摘要验证后再引用。
3. 持久化 applying 意图；只在这些事实提交后开始副作用。
4. 在同目录准备临时文件，保留支持的编码、换行和权限；以平台可靠方式替换单文件。
5. 每次落盘后验证内容/文件身份并记录结果，再进入下一项。
6. 完成后生成 patch evidence，使 S1 验证器读取；不只相信函数返回值。

SQLite 事务不能覆盖文件系统。跨文件“全有或全无”并无天然保证，必须公开部分成功状态和恢复动作。操作前后任一 crash 都要由 S3 日志识别，不能隐瞒已发生修改。

### 6.2 回滚保护

回滚前再次预览，只恢复当前摘要仍等于本次写后摘要的文件；用户在此后修改的文件标冲突并保留。新建文件只有未变化时才可撤销；新建目录只有仍为空且确由本次创建时才可清理。删除/移动的恢复要验证目标没有被新文件占用。

回滚自身也可能部分失败，应具有独立 operation ID 和日志。不能调用 `git reset --hard`、`git clean` 或整仓 restore 作为任务撤销实现。

### 6.3 Git 变更归属

任务开始保存 Git 是否可用、仓库根、HEAD、分支与 dirty 清单；非 Git 项目仍可使用文件摘要基线。不能把工作目录恰好处在父仓库内当作当前项目拥有整个父仓库。

任务内已知 patch 操作是 Agent 变更证据；整个 `git diff` 还可能包含用户和外部程序修改，应分开展示，无法归属时标外部/未知。不靠最终 diff 猜测作者。

## 7. 数据、接口与权限影响

拟新增本机 patch_set、patch_operation 与 file_snapshot 的持久化记录及索引；优先复用已有内容文件和摘要设施。准确表名、保留期、数据库版本由实现时决定。

拟议接口：现有 run 下查询补丁、预览、应用状态和回滚预览；如新增应用/回滚 mutation，必须具备操作 ID、权限校验、幂等返回和状态前置条件。模型调用与用户按钮走同一应用服务，禁止一条路径校验另一条绕过。

现有 PowerShell 写文件工具不能成为避开 patch 版本检查的默认替代项。可选择将可表达的文件动作路由到统一服务，或在编码工具目录中收缩重复入口；这是有行为影响的调整，需兼容说明。项目脚本的任意间接副作用由 S4 执行策略约束，不能声称 S3 已统一拦截脚本内部所有写入。

## 10. 验收与回滚

- 目标大文件末尾可局部修改；多文件增删改移与目录创建有可审查记录。
- 固定并发修改用例零静默覆盖，拒绝/取消不写入，部分失败明确呈现。
- 保留用户原有 Git dirty 状态，Agent 变更与外部变化不混为一谈。
- 旧整文件工具可保留受限兼容入口，但不得绕过新版版本保护；弃用行为在接口文档中明确。
- 可停止接受新 patch，保留已记录操作和预览；数据库或程序回退不能删除恢复材料。
- 交接文档列出支持的编码、链接、平台和最大 patch 范围，禁止以“多文件事务”掩盖跨文件原子性限制。
