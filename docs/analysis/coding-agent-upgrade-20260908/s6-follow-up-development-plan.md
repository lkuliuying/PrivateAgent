## 第一部分：总体路线

### 1. 目标与完成边界

本计划承接已经实现的 S0–S5，完成 S6 尚缺的工具能力、缺陷修复和真实验收。最终结果应是：在明确支持的 Windows、模型和权限组合下，用户通过实际安装的客户端完成读取项目规则、定位代码、修改、测试、纠错、审查及中断接续，结果可以核对，失败能够如实收束。

保留 Tauri/Vue、Python/FastAPI、共享核心、本机 SQLite 和 Rust exec-host 架构；保留现有账号、权限、模型供应商凭据边界。当前不安排整套界面重做、全量 Rust 重写、业务数据库迁移、Skills/MCP/浏览器/多 Agent 扩展。

## 第二部分：各阶段详细开发计划

### 阶段 A：修复评测终态、取消竞争与证据判定

**目标：** 消除本次已复现的两处 P1 缺陷，使运行时已经结束的任务及时完成记录，且保留实际结束原因。

**预计涉及文件：** [运行器](../../../scripts/run_coding_acceptance.py)、[证据模块](../../../scripts/coding_acceptance_evidence.py)、[传输模块](../../../scripts/coding_acceptance_transport.py)、[S6 交付测试](../../../tests/coding_acceptance/test_s6_delivery.py)、[S6 评测测试](../../../tests/coding_acceptance/test_s6_acceptance.py)。[本机运行时](../../../src/private_agent_local/runtime.py)与共享契约首先作为核对依据，只有确实需要共用纯常量时才做最小调整；不得为了脚本校验导入并启动业务服务。

| 任务 | 开发内容 | 交付物 |
| --- | --- | --- |
| A-01 | 核对 `completed/failed/cancelled/timed_out/limit_exceeded/interrupted` 全部终态及事件映射；采用可复用定义或一致性测试，避免再次漂移 | 终态映射及契约一致性检查 |
| A-02 | 轮询每次取得最新状态后先判断是否结束；区分运行时预算结束、用户取消、模型/执行失败和评测器自己的期限到达 | 正确的收束和失败分类 |
| A-03 | 预算取消仅在任务仍活动时提出一次逻辑请求；请求后核对最终状态，已有终态不可被改写为 cancelled；请求失败或结果未知时明确记录，不反复发送审批/工具操作 | 有界取消流程及结果记录 |
| A-04 | 事件校验接受全部合法终态，同时保留序号连续、重复/缺失终态检查；记录明确的失败原因。对协议不允许的终态后事件判错 | 可解释的事件校验结果 |
| A-05 | 将超额后取消成功、运行时先达到上下文上限、超时先结束、取消响应丢失拆为独立场景；采用受控同步点稳定制造竞争 | 确定性回归与完整复测报告 |

**验证安排：** 先直接覆盖终态与事件映射，再跑正式 IPC 场景、`--suite acceptance`、`--suite all`。原 Token 测试不能简单改成“多个终态任一即通过”；每个场景分别断言由谁结束、为何结束、是否重复调用、事件是否完整及文件是否改变。

**退出条件：** 合法终态在配置的轮询/传输等待范围内被观察并收束，不再等待 630 秒；取消与超限场景无额外写入、无审批重放；缺失或重复终态仍被拒绝；S6 专项及完整回归无未解释失败。本次出现的 632.5 秒失败保留原记录，新增修复后的证据，不覆盖历史。

**本轮退出核对（2026-09-09）：** 满足阶段 A 条件。直接测试 48 passed；S6 acceptance 128 passed；完整隔离回归 477 passed、1 项既有符号链接权限跳过；旧服务端兼容 106 passed；预检、协议生成、依赖边界、Ruff、30 题公开校准及指定 15 次回环矩阵通过。完整回归中的八个 IPC 终态场景为 2.141～3.125 秒，无额外写入或审批重放；失败、环境复验和未验证范围见阶段 A 报告。不据此启动 B～F 或解除 M3。

**风险和边界：** 同时触发的取消与自然结束是合法竞争，测试不能规定“用户看到超额后一定抢先取消”。900 秒套件上限与单题上限保持独立，不通过放大上限、跳过失败测试或强行改终态解决问题。

### 阶段 B：建立外部题集和独立判定机制

**目标：** 保留公开校准功能，增加正式评测可用的、可核对版本的外部题集，使保留题与参考答案具备真实隔离条件。

**预计涉及文件：** [题集模块](../../../scripts/coding_acceptance_catalog.py)、[运行器](../../../scripts/run_coding_acceptance.py)、[公开 fixture](../../../tests/coding_acceptance/s6_fixtures.py)、S6 测试、[评测协议](./s6-acceptance-protocol.md)。如现有文件职责过多，可增加专用题集 schema/验证模块，具体路径在该阶段实施计划中确定；以下字段是拟议设计，不是已有 API。

| 任务 | 开发内容 | 验收重点 |
| --- | --- | --- |
| B-01 | 设计 JSON 题集清单：版本、任务 ID、来源/许可、语言、主分类、分组、初始 revision、工作区摘要、可修改范围、验证命令、预算、`coding_goal`、预期系统行为 | 无密钥，无任意 Python 配置导入；未知字段、重复 ID、缺必填项均拒绝 |
| B-02 | 将公开校准与正式外部题集作为明确不同的来源；加载后冻结摘要并在运行开始/结束核对；保留已有 control/matrix 兼容入口 | 不因引入新参数破坏旧校准；修改题集后不能关联旧成绩 |
| B-03 | 仅向任务工作区物化题面、初始代码、公开测试和允许的说明；参考答案、隐藏断言及其结果留在独立验收侧 | 不能从工具读文件、命令执行、日志或评测进程配置取得答案 |
| B-04 | 按原 S6 分类准备 Python、Vue/TypeScript、Rust 各 10 题，开发集 18、保留集 12；复核任务代表性和隐藏断言有效性 | 初始失败可复现，参考实现通过，错误或取巧实现能被拒绝 |
| B-05 | 冻结质量分母、预检失败、运行失败、人工介入与题集污染处理规则；题目与判定器均纳入摘要 | 已启动的失败不被删除，重跑另立尝试，污染题不继续冒充未知题 |

**隔离要求：** 仅把隐藏测试放在工作区外不足以证明不可读取。必须核对实际命令身份及文件权限；如果采用当前用户权限的可信执行，验收材料应放到该身份无法读取的独立账号或机器。尚未证明隔离时仅允许校准，不得放行正式盲评。对任意外部仓库的恶意脚本隔离能力不作额外承诺；样例代码与依赖须先审查。

**统计口径：** 每模型计划 30 题各 3 次，共 90 次。编码分母由冻结清单中 `coding_goal=true` 的已启动次数决定。只有正式清单也采用 27 个编码目标时，分母才是 81；不能直接沿用公开 fixture 的数字。预检未启动单列且会阻止完整实验验收；开始后的超时、拒绝、工具/模型错误按预定规则进入结果。

**验证安排：** 覆盖空题集、重复任务、目录穿越、链接/重解析点、摘要变化、缺依赖、答案泄露探针、隐藏测试自修改、执行输出与时长上限。对开发集复跑正负控制；保留题参考验证由验收侧独立执行，不用于调试 Agent。

**退出条件：** 题集版本可复现，18/12 划分和分类满足计划；隐藏材料隔离有直接证据；清单、判定器、产物和每次尝试能关联；公开校准不能生成正式质量达标决议。

### 阶段 C：接通真实模型评测并补齐预算和指标

**目标：** 验证准备实际使用的模型路径，并形成可追溯的用量、等待、资源及失败记录。

**预计涉及文件：** [运行器](../../../scripts/run_coding_acceptance.py)、[评测传输](../../../scripts/coding_acceptance_transport.py)、[证据汇总](../../../scripts/coding_acceptance_evidence.py)、[本机云端调用](../../../src/private_agent_local/cloud.py)、[本机模型适配](../../../src/private_agent_local/local_models.py)、[服务器模型代理](../../../src/personal_assistant/api/routes_desktop_model.py)。后面三个产品模块先做现状核对，仅在真实联调暴露缺陷或必要指标缺口时修改；不预先重构 Provider 层。

| 任务 | 开发内容 | 交付物 |
| --- | --- | --- |
| C-01 | 将回环 fixture 与真实服务连接配置分开；真实联调通过正式客户端账号/本机 IPC/模型代理链路，不把供应商 Key 下发评测脚本 | 可选择且不可混淆的连接方式 |
| C-02 | 保留现有本机不计费质量入口；为选定的真实代理增加适配与预检，明确鉴权失败、模型不存在、能力不足、流式不支持等结果 | 逐模型与逐协议能力矩阵 |
| C-03 | 记录模型/profile、实际版本或未知性、上下文容量、运行参数、产品及题集摘要；确认权限模式与正式使用场景一致 | 可复现模型配置清单 |

| C-05 | 采集总耗时、模型/工具/审批等待、请求及重试、压缩、峰值进程、采样存储；以已有事件和执行记录为主补缺项 | 指标字典、采集测试及汇总 |

**凭据与费用：** 使用专用测试账号与受支持的安全登录/会话方式，凭据不放 CLI 参数、题集、清单或报告。真实付费调用在已有授权的模型、次数和预算内执行；没有这些输入时，完成替身验证并保持真实联调待执行。响应后才获知的 token 只能构成软预算，不能声称账单硬上限；可用时结合输出上限和供应商限额，仍需注明测量边界。

**指标约定：** 状态区间与嵌套工具耗时分开定义，避免将重叠时间相加。跨进程记录因果 ID，在同一时钟域测耗时；跨机器时间不直接相减。采样进程峰值注明间隔及可能漏掉短进程；缺用量、缺价格或缺事件均记录 unknown，必要指标无法可靠获得时保留阻断并说明原因。

**退出条件：** 目标模型沿实际产品路径完成预定正负用例；清单不含凭据；错误与预算被正确记录；没有以替身成绩证明真实供应商成功；正式评测需要的指标可核对。
