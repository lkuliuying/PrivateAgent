## 第一部分：总体路线

### 1. 目标与完成边界

本计划承接已经实现的 S0–S5，目标收敛为在用户当前 Windows 电脑和已有开发环境中运行 Agent、观察调用链并进行学习。用户通过本机客户端完成读取项目规则、定位代码、修改、测试、纠错及审查；结果可以核对，失败能够如实收束。允许使用本机源码或与其匹配的候选，不要求另建干净系统或生成正式安装包。

当前只保留 A–D 中与本机学习有关的工作，不改变原 S0–S5 的模块职责。E 的安装、历史升级和程序回退，以及 F 的正式交付、发布与配套更新任务已从活动计划移除。原 S6-T01–T12 按第三部分注明适用范围，不再整体作为发布门禁要求。

本机学习的完成标准是：

1. 当前电脑上的客户端、本机执行器和 exec-host 能启动，能选择项目及配置本机使用的模型连接。
2. 在独立练习项目中完成一次“读取 → 修改 → 执行验证 → 查看 diff 和结果”的 Agent 流程，能够说明模型调用、工具调用和状态变化。
3. 审批/拒绝、取消、已有文件保护和错误提示在实际使用路径上有效；未知副作用不自动重放，失败不显示成已验证完成。
4. 正常退出、重开后练习项目与历史可读取；按实际改动执行相关测试，记录未验证行为和已知问题。

正式 90 次模型实验、独立审阅、80% 质量指标、严格 100 样本延迟测量和 M3 放行继续作为历史或自选学习实验，不作为本次本机使用的前置条件。现有完整回归超时和历史失败仍保留真实结果，按其对当前本机功能和数据保护的影响安排修复，不能改写成已通过。开发实现、测试通过与用户实际运行结果仍分别记录。

保留 Tauri/Vue、Python/FastAPI、共享核心、本机 SQLite 和 Rust exec-host 架构；保留现有账号、权限、模型供应商凭据边界。当前不安排整套界面重做、全量 Rust 重写、业务数据库迁移、Skills/MCP/浏览器/多 Agent 扩展。

## 第二部分：各阶段详细开发计划

### 阶段 A：修复评测终态、取消竞争与证据判定

**目标：** 消除本次已复现的两处 P1 缺陷，使运行时已经结束的任务及时完成记录，且保留实际结束原因。

**预计涉及文件：** [运行器](../../../scripts/run_coding_acceptance.py)、[证据模块](../../../scripts/coding_acceptance_evidence.py)、[传输模块](../../../scripts/coding_acceptance_transport.py)、[S6 交付测试](../../../tests/coding_acceptance/test_s6_delivery.py)、[S6 评测测试](../../../tests/coding_acceptance/test_s6_acceptance.py)。[本机运行时](../../../src/private_agent_local/runtime.py)与共享契约首先作为核对依据，只有确实需要共用纯常量时才做最小调整；不得为了脚本校验导入并启动业务服务。

| 任务 | 开发内容 | 交付物 |
| --- | --- | --- |
| A-01 | 核对 `completed/failed/cancelled/timed_out/limit_exceeded/interrupted` 全部终态及事件映射；采用可复用定义或一致性测试，避免再次漂移 | 终态映射及契约一致性检查 |
| A-02 | 轮询每次取得最新状态后先判断是否结束；区分运行时预算结束、用户取消、模型/执行失败和评测器自己的期限到达 | 正确的收束和失败分类 |
| A-03 | 预算取消仅在任务仍活动时提出一次逻辑请求；请求后核对最终状态，已有终态不可被改写为 cancelled；请求失败或结果未知时明确记录，不反复发送审批/工具操作 | 有界取消流程及结果记录 |
| A-04 | 事件校验接受全部合法终态，同时保留序号连续、重复/缺失终态检查；记录明确的失败原因。对协议不允许的终态后事件判错 | 可解释的事件校验结果 |
| A-05 | 将超额后取消成功、运行时先达到上下文上限、超时先结束、取消响应丢失拆为独立场景；采用受控同步点稳定制造竞争 | 确定性回归与完整复测报告 |

**验证安排：** 先直接覆盖终态与事件映射，再跑正式 IPC 场景、`--suite acceptance`、`--suite all`。原 Token 测试不能简单改成“多个终态任一即通过”；每个场景分别断言由谁结束、为何结束、是否重复调用、事件是否完整及文件是否改变。

**退出条件：** 合法终态在配置的轮询/传输等待范围内被观察并收束，不再等待 630 秒；取消与超限场景无额外写入、无审批重放；缺失或重复终态仍被拒绝；S6 专项及完整回归无未解释失败。本次出现的 632.5 秒失败保留原记录，新增修复后的证据，不覆盖历史。

**本轮退出核对（2026-09-09）：** 满足阶段 A 条件。直接测试 48 passed；S6 acceptance 128 passed；完整隔离回归 477 passed、1 项既有符号链接权限跳过；旧服务端兼容 106 passed；预检、协议生成、依赖边界、Ruff、30 题公开校准及指定 15 次回环矩阵通过。完整回归中的八个 IPC 终态场景为 2.141～3.125 秒，无额外写入或审批重放；失败、环境复验和未验证范围见阶段 A 报告。不据此启动 B～F 或解除 M3。
