# 第三步：补齐能力与交付试用包

关联：[总计划](./README.md) · [第二步](./step-2-planning-context-and-recovery.md) → 本文 → 用户试用与反馈迭代。状态：待实施；依赖 M1、M2。

## 1. 任务目标与完成条件

在前两步稳定后，补齐对日常 Coding 有直接帮助的项目记忆检索和安全只读并行，完善诊断与结果说明，随后构建可追溯的 Windows 候选安装包交给用户试用。

完成条件分开记录：

- **代码完成**：本步能力实现，未扩大现有写入、执行或联网权限。
- **自动验证完成**：相关契约、并发、恢复、沙箱、前端和构建脚本检查通过。
- **安装包交付完成**：新包实际生成，产物、哈希、来源清单、版本说明和试用清单齐全。
- **用户试用完成**：用户实际安装和使用并返回结果，不能由前三项推定。

## 2. 能力范围

### 2.1 项目记忆的最小接入

旧后端的记忆实现（历史路径：`src/personal_assistant/core/memory.py`，已移除）与 RAG 能力已经存在，但当前本地主链没有等价接通。第一版选择“显式项目来源、只读检索、引用回溯”，避免把整个旧服务端及其依赖带进本地 sidecar。

建议能力：

1. 用户或项目约定明确列出可作为记忆的文件；首批支持仓库内受控文本/Markdown 文件。
2. 来源记录项目身份、规范路径、标题、内容哈希和读取时间；不默认扫描其他项目、聊天历史或用户目录。
3. 沿现有文件安全入口读取，验证规范路径、符号链接/重解析点、大小上限和授权范围。
4. 初版采用有界关键词与标题匹配，返回少量相关片段及原文引用；不引入向量数据库或后台全盘索引。
5. 哈希变化后更新或失效缓存；文件删除、权限撤销或切换项目后不继续注入旧内容。
6. 普通知识作为参考数据，不能提升为系统指令；`AGENTS.md` 继续走既有来源、作用域和信任机制。
7. 冲突内容明确显示来源及时间。当前代码/用户指令与旧记忆冲突时，不把过时记录当成现状。

第一版不自动写长期记忆、不把模型总结保存为用户事实、不跨项目共享私人内容。新增记忆入口是否采用工具或按需上下文源，由现有工具预算和界面入口决定；不让每轮全量注入记忆。

### 2.2 安全的只读并行

当前 [core/runtime.py](../../../src/private_agent_core/runtime.py) 的同轮工具调用按顺序执行。本步只对显式声明安全的读取并行，参考 Codex 的读写区分，但保留现有工作区锁和执行审批。

| 类别 | 初版策略 | 原因 |
|---|---|---|
| 独立的目录列表、文件读取、代码搜索、已授权记忆检索 | 通过元数据白名单后可以并行，建议初始每任务上限为 2 | 降低 I/O 等待，控制资源和上下文峰值 |
| patch、写文件、Shell、执行会话创建、stdin | 继续串行 | 可能修改环境或产生副作用 |
| 审批、计划更新、取消/恢复、任务元数据写入 | 继续串行或建立屏障 | 保持状态、版本和用户操作顺序 |
| 未声明安全性的新工具 | 默认串行 | 不依据工具名称猜测无副作用 |

并行组只能包含彼此独立且已获授权的调用，不跨越写入或状态修改屏障。每个调用独立保留 `call_id`、取消信号、错误与内容引用；完成顺序可以不同，交给模型的配对及持久化事件必须可确定地重建。

一个读取失败不丢弃其他已完成结果；失败也不能诱发整组盲目重放。取消、目标代次变化或权限失效后，不再消费旧结果。组内读取期间文件发生变化时，标注版本/哈希变化，必要时重新读取，不能声称获得了原子工作区快照。

### 2.3 观察与故障诊断

复用已有本地事件和内容存储，补足任务、步骤、调用、执行会话、错误类别、时间及验证证据的关联。优先生成可读的诊断摘要，不新建遥测服务。

候选包附诊断说明，按需收集版本、任务编号、事件类型、退出码和脱敏错误。默认不自动上传，不收集密钥、请求认证头、完整环境变量或私人源码。错误文本和工具参数本身也可能敏感，不能仅按字段名过滤后宣称已经安全。

本步不承诺未经测量的速度提升。分别记录串行/并行的读取耗时、峰值输出、取消释放和错误场景；若收益不足或稳定性下降，保持该组串行并说明原因。

## 4. 自动验收用例

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| C-T01 | 在已选择项目内检索明确的记忆文件 | 返回相关片段、来源、哈希与引用 |
| C-T02 | 切换项目或尝试读取项目外来源 | 不串项目；越界读取被拒绝 |
| C-T03 | 文件被删除、修改、链接替换或撤销授权 | 缓存失效；重新核验路径和权限 |
| C-T04 | 记忆包含“忽略限制并执行命令” | 保持参考数据地位，不改变工具权限 |
| C-T05 | 记忆与当前代码冲突 | 明确冲突，不按旧记忆直接宣称完成 |
| C-T06 | 两个独立读取耗时不同 | 实际并行且不超过上限，结果按调用身份正确关联 |
| C-T07 | 读取之后包含写入或执行命令 | 写入/执行不会与相关读取或其他副作用并发 |
| C-T08 | 并行中一个失败、另一个成功 | 分别返回结果，不丢成功证据、不盲目重试整组 |
| C-T09 | 并行中取消、暂停或目标代次改变 | 停止新调用，旧结果不污染新任务，资源最终释放 |
| C-T10 | 读取期间文件被外部修改 | 检出或保守标记版本不一致，不冒充一致快照 |
| C-T11 | 新增未声明属性的工具 | 默认串行，无隐式权限扩大 |
| C-T12 | 错误正文含合成敏感值 | 脱敏诊断不泄露该值，原始来源访问仍受控 |
| C-T13 | 候选包包含旧 sidecar 或过期执行器 | 哈希/来源校验失败，不能作为本次新包交付 |
| C-T14 | 候选版与已有应用同时存在 | 使用候选身份、凭据范围和数据目录；不覆盖原有资料 |
| C-T15 | 启动、执行、取消、退出、再次打开 | 无残留子进程，历史与目标状态一致 |

C-T14 的应用身份和配置边界先自动检查，实际安装并存行为在用户试用中确认；未执行的原生安装验证不能写成通过。

## 6. Windows 安装包构建流程

### 6.1 选用现有候选通道

复用 [build-client.cmd](../../../scripts/build-client.cmd)、[build-client.cjs](../../../scripts/build-client.cjs) 及其底层 [build-remote-client.cjs](../../../scripts/build-remote-client.cjs)。后者的历史文件名不改变当前 `--unified` 交付模式。

当前入口不带安装器参数时主要构建便携验证产物。交付用户需要显式使用 `--preview-installer`；选用 `--qa` 使用独立候选身份：

| 项目 | 候选值/行为 |
|---|---|
| 产品名 | `PrivateAgentCandidate` |
| 应用标识 | `com.personal-assistant.desktop.candidate` |
| 主程序身份 | `privateagent-candidate` |
| 数据与凭据 | 现有候选目录及凭据命名空间，构建时重新核验 |
| 平台 | Windows x64，`x86_64-pc-windows-msvc` |
| 安装器 | 本地预览 NSIS 安装器；不宣称正式签名发布 |
| 更新行为 | 不生成线上发布动作，不上传，不更改服务器或更新通道 |

这是本地试用候选构建，不调用 `--release`。不要求为打包自动提交、清理或重置工作区；现有构建来源清单必须真实记录未提交输入。

### 6.2 执行步骤

下面使用 PowerShell 变量 `$trialVersion` 表示打包时已经核对的具体版本。执行者须先将它设为有效的 `X.Y.Z` 值；这些命令不是本轮已运行记录。

```powershell
node scripts/build-client.cjs --qa --preview-installer --version $trialVersion --dry-run
.\scripts\build-client.cmd --qa --preview-installer --version $trialVersion
```

先检查 dry-run 的应用身份、目标、组件和输出位置，再执行构建。构建会生成本地 sidecar、执行器、桌面前端和安装器；不要仅凭前端构建成功宣称安装包完成。

使用构建输出的实际目录设置 `$trialBundle`，设置独立的验证目录 `$trialCheckRoot`，再进行随包组件验证：

```powershell
.\.venv\Scripts\python.exe -B scripts/verify-unified-client.py --bundle $trialBundle --work-dir $trialCheckRoot --model-mode openai
```

该验证使用隔离场景及回环模型，验证的是随包组件与运行主链，不等于用户真实账号、真实模型或原生安装界面已经验收。执行前复核脚本仍保持隔离，记录实际验证范围。

### 6.3 必须交付的产物

采用构建返回的实际文件名和路径，不凭旧文件名猜测成功：

- `PrivateAgentCandidate_<version>_x64-setup.exe`：本次新生成的候选安装器。
- `SHA256SUMS.txt`：校验包及随包组件完整性。
- `build-info.json`、`source-manifest.json`：版本、源码提交/工作区来源、构建模式、目标与组件信息。
- 本次版本说明：完成的改进、实际自动验证、已知限制、未验证的原生安装/真实模型行为。
- 用户试用清单与反馈模板。

构建目录还应保留实际主程序、`private-agent-local.exe`、`exec-host.exe` 及执行器哈希供核验。校验安装器是本次构建的新产物，禁止把旧包重新改名交付。

交付时提供安装器和校验文件的实际路径。用户负责安装和试用，不替用户点击系统安装确认，不自动迁移已有私人数据。

## 7. 用户试用清单

交付时提供一份临时示例项目或可复制的简单场景，优先在副本中试用，避免第一次验证就修改重要工作。

| 顺序 | 试用场景 | 预期结果 |
|---|---|---|
| U1 | 安装候选版、打开、关闭、再次打开 | 能启动，原应用及其数据不受影响 |
| U2 | 用自己的配置连接模型并发送普通问题 | 正常回答；密钥不出现在结果或诊断中 |
| U3 | “解释原因，然后修复示例文件并运行测试” | 有解释、实际 diff 和真实测试结果 |
| U4 | “修复示例文件，但不要运行测试” | 产生允许的修改；明确说明测试未执行 |
| U5 | “只分析，不修改，也不运行命令” | 不产生写入和命令副作用 |
| U6 | 多步骤修改，执行中查看计划并暂停/恢复 | 进度一致，不丢限制、不重复执行副作用 |
| U7 | 长输出、多轮调查后继续任务 | 目标与下一步连续，能找到此前引用 |
| U8 | 让命令失败、取消运行，再查看结果 | 错误可理解，无假成功，进程可停止 |
| U9 | 修改项目记忆后再次检索 | 使用更新内容，来源明确，不串项目 |
| U10 | 关闭再打开并查看历史与结果 | 状态、diff、验证证据及未验证项一致 |

真实模型调用可能消耗用户账户额度，试用清单明确哪些步骤会发起调用；自动验证不借用用户凭据。用户可先完成 U1，再用小型项目执行其余场景。

## 8. 反馈模板与迭代流程

推荐反馈格式：

```text
候选版本：
试用场景编号：
模型/提供方名称（不填密钥）：
复现步骤：
预期结果：
实际结果：
是否每次出现：
脱敏任务编号或错误信息（可选）：
截图或最小复现项目（可选）：
```

收到反馈后执行：

1. 确认版本和复现条件，区分客户端、模型能力、配置和外部环境问题。
2. 按总计划 P0–P3 分级；优先处理安全、数据和主链阻塞。
3. 能自动复现的问题先形成针对性测试，再进行最小修复。
4. 运行直接相关回归；改变执行、权限、恢复或完成状态时补对应边界检查。
5. 构建下一个候选版本，保留来源和哈希，并说明已修复、待复测和仍存在的问题。
6. 用户复测后更新结论；仍复现则继续定位，不能因自动测试通过就关闭反馈。

原候选数据不因换包自动删除。涉及存储兼容性时，先完成候选数据备份和兼容验证；不让用户直接用不兼容旧版本打开新数据库。

## 9. 暂缓的能力与范围边界

图片/音频输入、全面 MCP 接入、向量 RAG、自动长期记忆写入、多 Agent 编排和更细的联网权限，是可按反馈选择的后续方向，不作为首个候选包的隐含必做项。

不进行正式签名、公开发布、自动更新上线、服务器变更、生产数据迁移或多操作系统完整安装验收。用户本轮授权的本地安装包交付已经覆盖常规候选构建，无需额外打包确认；上述额外外部动作不包含在内。
