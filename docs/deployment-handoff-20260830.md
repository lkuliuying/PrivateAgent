## 1. 最终结构与责任边界

```text
Windows Tauri 客户端（远程模式，账号登录）
    → HTTPS / Nginx（沿用已有面板安装）
    → 仅监听回环地址的 Uvicorn / FastAPI
        → 仅监听回环地址的 MySQL
        → 服务器数据目录中的 ChromaDB
        → QQ SMTP / 外部模型 API

systemd → Supervisor → 单个后端进程
```

最初提出的 uWSGI + Supervisor + Nginx，在实施中采用 Uvicorn + Supervisor + Nginx：本项目是 ASGI 应用，依赖异步处理、lifespan 和流式响应，实际服务入口为 `python -m personal_assistant.server_entry`。

客户端远程模式不启动本地 Python sidecar；MySQL、ChromaDB 的健康信息属于服务器运维信息，不是用户电脑状态。普通设置页面移除运行状态，管理员控制台保留系统总览。客户端不携带服务器服务令牌，使用个人账号会话访问 API。

## 3. 部署中遇到的问题与处理

### 包管理与已有面板

DNF 存在重复源警告，且主配置排除了 MySQL 等软件包。安装失败原因是 exclude filtering，并非系统没有 MySQL 8.4。安装时使用有范围的临时排除覆盖，没有删除全部排除规则或清理其他面板软件。

Nginx 的命令入口指向已有面板安装，因此使用它的主配置、虚拟主机目录、证书和 systemd 单元，没有另外安装一套 Nginx。现有其他服务没有被接管或删除。

### Alembic 百分号插值

数据库密码经 URL 编码后可能含 `%`。Alembic 的 ConfigParser 会把它当插值语法，导致 `ValueError`。已在服务器验证的修复为：

```python
config.set_main_option("sqlalchemy.url", settings.db_url.replace("%", "%%"))
```

这只是向配置解析器转义，取回的连接 URL 保持原值，不是再次编码密码。本次将相同修改保存到仓库，防止换电脑后丢失。检查没有输出密码或连接地址。

### Supervisor 启动后立即退出

应用以非 root 账号运行，父进程 Supervisor 属于 root。原父进程检查把 `PermissionError` 错判为父进程消失，退出码为 0、应用日志为空，随后 Supervisor 报 FATAL。

本次部署在 Supervisor 环境中设置 `PA_PARENT_PID="1"`，保留该值；未把应用改为 root，也未改系统权限。这个部署绕行方案不等于已修复所有桌面父进程检测场景。

### Windows 远程客户端构建

一处失败来自把带引号的 `--outDir` 经过 npm/命令解释器再次转义，Vite 把引号当作目录名。另一处风险是把 Windows 绝对路径作为 Tauri `frontendDist`，被当作 URL 而漏嵌前端资源。

新增 [远程构建入口](../scripts/build-remote-client.cmd) 调用 Node 直接传 argv，使用相对 `frontendDist`。产物落入唯一目录，失败不会用旧 EXE 冒充成功。详见开发指南。

### 模型连接测试与状态隐私

模型列表可以获取，但按钮原来调用 Coding 专用模型 profile 探测接口，功能开关关闭时出现 `Model profiles are disabled`。当前改为已有供应商模型发现接口，检查保存的目标模型是否可见，不为了探测开启 Coding 功能。

**这项检查验证服务鉴权与模型列表，不发送聊天推理请求。** UI 明确提示“未测试聊天生成”。实际聊天、SSE、额度和生成参数仍需单独验收。

普通设置移除运行状态及健康轮询，默认进入当前模型。管理员总览显示服务器 API / MySQL / ChromaDB。后端 `/health` 同步按身份最小化返回：

| 身份 | `/health` 行为 |
|---|---|
| 未认证、无效会话 | 由鉴权中间件拒绝，401 |
| 普通账号 | 仅 API 存活结果，不探测数据库，不返回路径或错误详情 |
| 管理员会话、运维服务令牌 | 保留完整健康结果 |

`/admin/overview` 继续使用现有管理员权限校验。仅更新客户端不能保护旧后端接口，后端补丁必须另行上线。

## 4. 邮件、账号和模型交接

- QQ SMTP 保持 `smtp.qq.com:587`、SSL=false、STARTTLS=true、超时 15 秒；不要改回其他端口作为本次已验证配置。
- SMTP 使用 QQ 授权码，不是应用登录密码；二者均不进入 Git、Release 或说明正文。
- 首个管理员已创建，不要再次运行初始化流程；正式服务公开注册保持关闭。
- 本次选择 DeepSeek、`deepseek-v4-flash`、Chat Completions 格式，列表获取由用户验证成功。真实 API Key 由用户在客户端输入。
- 当前远程供应商密钥存在后端运行时内存中，重启后可能需要重新输入并保存。Windows 密钥库不能直接复制到另一台电脑当作可用凭据。
- 存在 `PA_MODEL_PROVIDER_SECRETS_JSON` 的进程环境接入，但本次没有把它改成服务器持久化方案。不能只把同名字段写入配置文件就假定已注入进程环境。

## 6. 服务器更新注意事项

本交接没有通过 SSH 操作服务器，也没有重启生产服务。服务器现有 `alembic/env.py` 有本地修复；健康路由补丁也可能由管理员另行应用。**不要对有本地改动的部署目录直接执行 reset、checkout --、clean 或强制拉取。**

下一次更新按以下顺序进行：

1. 结束正在执行的任务，记录运行版本及 `git status --short`，只检查涉及源码的差异；不要展示配置文件或密钥。
2. 做受控的数据库/数据备份并验证可恢复，备份留在受限存储，不上传 GitHub。
3. 单独保存服务器已有源码补丁；比较其内容与目标提交，确认 Alembic 转义及健康权限修复已包含。
4. 在新的发布目录获取明确提交，沿用外置配置、数据和应用虚拟环境；不要覆盖仍在运行的源码或覆盖秘密文件。
5. 在维护窗口切换后端工作目录/启动配置，验证权限与依赖后重启；若入口会迁移，先确认目标迁移差异。本次修复没有新增迁移，目标仍为 0038。
6. 检查 Supervisor、回环监听、无授权 HTTPS 401、管理员依赖健康和普通用户的信息边界；重新保存运行时模型密钥并做一次实际聊天。
7. 若失败，按记录恢复上一个完整版本；涉及数据库迁移时先遵循数据库恢复流程，不能只回退源码。

这里提供顺序而非对未知服务器状态执行的一键脚本，避免覆盖生产改动。
