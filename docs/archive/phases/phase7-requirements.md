# 私人助手 Agent · 第七阶段需求文档

> 第七阶段定位：把已经完成“主动个人中枢”的桌面 Agent，打磨成可长期依赖的个人操作系统雏形。核心不是继续堆更多页面，而是把第六阶段中仍偏静态、偏工程化、偏单点的能力，升级为真实数据驱动、可检索、可诊断、可恢复、可自动化验证的日常工作闭环。

---

## 1. 背景

前六个阶段已经完成：

- 第一阶段：桌面端、FastAPI 后端、Ollama、MySQL、ChromaDB、聊天与知识库闭环。
- 第二阶段：受控工具调用、审批状态机、授权路径、活动流和工作台 UI。
- 第三阶段：项目工作区、学习系统、文档工作台、编码工具和多步任务编排。
- 第四阶段：长期记忆、学习复习、文档集合、patch set、可编辑任务计划、Provider 路由和备份/恢复预览。
- 第五阶段：Windows 安装包、sidecar 生命周期、updater 清单、发布脚本、签名策略、发布 QA 与跨平台预研。
- 第六阶段：今日中枢、统一收件箱、提醒、长期目标、主动简报、隐私预览、Provider 调用审计和维护健康报告。

当前项目的主要不足来自真实代码和文档现状：

1. **今日页仍有静态内容**：`TodayView.vue` 中的日程安排、记忆洞察、相关来源和部分安全状态仍是固定文案或演示数据，没有完全绑定真实任务、目标、简报、文档和健康报告。
2. **缺少全局搜索与命令入口**：聊天、知识库、项目、学习、任务、记忆、收件箱、目标之间数据已经很多，但用户仍需要记住对象在哪个页面，缺少一个统一的“搜人、搜事、搜资料、搜命令”的入口。
3. **捕获入口仍不完整**：文档导入和聊天保存到收件箱已经可用，但剪贴板、截图、扫描件 OCR、网页摘录、邮件文本、快速笔记等轻量输入还没有形成统一 capture 流程；OCR 当前仍返回 `unavailable`。
4. **前端反馈仍偏工程化**：不少操作仍使用 `alert` / `prompt` / `confirm`，缺少统一 toast、确认弹窗、表单校验、失败重试和可追踪的用户通知中心。
5. **可观测性不足**：`/health` 能检查 API、Ollama、MySQL、ChromaDB，但缺少用户可读的诊断报告、最近错误、后台任务状态、日志查看、性能基线和问题导出包。
6. **端到端质量保障不足**：后端测试较完整，前端主要依赖 `npm run build`；第七阶段已补后端/API smoke 和发布 checklist，Playwright/Tauri 桌面 E2E 仍作为后续增强。
7. **远程 Provider 仍是可用但不够生产级**：OpenAI-compatible / Claude Provider 已接入，但远程流式、用量/成本、限流、失败降级、审计闭环和上下文差异预览还需要补强。
8. **数据生命周期需要治理**：多个模块使用软引用避免误删，但随之带来孤立引用、陈旧简报、重复收件箱项、过期备份、迁移状态漂移和 Chroma/MySQL 一致性问题。
9. **性能与规模边界未系统化**：大文档导入、批量重建索引、长会话、长期记忆检索、今日聚合和简报生成都需要明确耗时上限、分页策略、缓存策略和降级策略。
10. **扩展边界还不清晰**：工具、命令、Provider、导入源、通知目标仍多为内置代码路径，缺少稳定的扩展注册约定，后续接入日历、浏览器、邮件、更多 OCR 或更多模型时容易互相耦合。

第七阶段要解决的是：让用户不只是“能打开很多功能”，而是能在每天真实使用时快速找到东西、快速捕获信息、理解系统状态、放心恢复数据，并让开发者有自动化证据证明这些路径稳定。

## 2. 阶段目标

第七阶段完成后，产品应具备：

1. **真实数据驱动的今日中枢**
   - 今日页所有日程、记忆洞察、相关来源、安全状态和健康状态都来自后端真实数据或明确标注为建议。
   - 今日页支持按来源、优先级、时间和目标筛选，而不只是展示摘要计数。
   - 静态演示内容不得出现在生产模式。

2. **全局搜索与命令面板**
   - 支持在一个入口搜索会话、消息、文档、切片、项目文件、学习主题、任务、记忆、收件箱、提醒、目标和简报。
   - 支持命令面板执行常见动作：新建提醒、保存到收件箱、生成今日简报、导入文档、运行健康检查、打开设置等。
   - 搜索结果必须带来源、类型、更新时间和可跳转目标。

3. **统一捕获与 OCR 流程**
   - 提供“快速捕获”入口，支持文本粘贴、剪贴板文本、聊天消息、文档抽取结果、文件导入和 OCR 候选。
   - 扫描件 PDF 或图片可进入 OCR 队列，失败时进入收件箱或维护报告，而不是只停留在不可用提示。
   - OCR 引擎可以本地可选安装，但 UI 必须能说明当前是否可用、为什么不可用、如何降级。

4. **一致的用户反馈与通知**
   - 替换关键路径中的浏览器原生 `alert` / `prompt` / `confirm`，使用统一 toast、modal、inline error 和确认流程。
   - 重要异步操作进入通知中心：导入完成、导入失败、备份完成、提醒触发、任务完成、Provider 调用失败。
   - 所有危险操作必须显示影响范围和撤销/恢复路径。

5. **诊断中心与问题导出包**
   - 新增诊断中心，展示依赖状态、最近错误、后台任务、提醒 tick、导入队列、Provider 调用、备份状态和数据体检。
   - 支持生成诊断包：脱敏配置、健康检查、最近日志摘要、版本、迁移 head、构建信息。
   - 诊断包不得包含 API key、完整聊天内容、完整文档原文或敏感记忆。

6. **生产级 Provider 治理**
   - 远程 Provider 支持更明确的失败降级、用量估算、审计完成状态和远程上下文差异预览。
   - 远程模型调用失败时，用户能看到是认证、网络、限流、模型不存在、超时还是服务错误。
   - 远程流式可作为目标，但不得以牺牲审计和隐私预览为代价。

7. **数据完整性与清理建议**
   - 支持跨模块软引用体检：目标链接、简报来源、收件箱来源、任务证据、文档集合成员、Chroma chunk 映射。
   - 支持生成修复计划：只给建议和预览，不自动删除用户数据。
   - 支持备份包校验、迁移版本检查和恢复前风险提示。

8. **端到端 QA 与发布前证据**
   - 增加关键路径自动化测试：首次启动、聊天、知识库导入、今日页、提醒、收件箱、目标、隐私预览、备份、打包 sidecar。
   - 给第七阶段定义可重复的 smoke 脚本和人工 QA 表。
   - 文档中记录验证命令、通过标准和失败分流。

## 3. 非目标

第七阶段不做：

- 不做云同步账户体系。
- 不做完整手机 App。
- 不把邮件、浏览器、日历、微信等外部生态作为硬验收；可以定义扩展边界或做本地文本导入。
- 不做无人值守高风险自动化。命令执行、文件修改、远程发送仍需审批或显式设置。
- 不把 OCR 做成必须内置的大体积依赖。OCR 可选安装、可降级、可独立评估体积。
- 不重写现有前后端架构。第七阶段应沿用 Vue 3、Tauri、FastAPI、SQLAlchemy、MySQL、ChromaDB。
- 不把诊断包变成数据导出工具。诊断包只用于排障，必须脱敏。

## 4. 用户场景

### 4.1 每天打开应用，看到真实今日

用户打开应用进入“今日”：

1. 页面展示真实到期提醒、收件箱、复习卡片、待审批任务、目标进展和健康报告。
2. 日程区来自用户创建的提醒、任务、目标 check-in 或日程条目，不再显示固定演示时间。
3. 相关来源来自最近使用的文档、会话、简报或目标链接。
4. 用户点击任意卡片可跳转到来源，或将其保存为收件箱、提醒、任务草稿。

### 4.2 快速找到一个上下文

用户按快捷键打开全局搜索：

1. 输入“发布 checklist”。
2. 结果同时展示文档、简报、任务证据、会话消息和项目文件命中。
3. 用户可直接打开文档、跳到任务、复制引用、继续聊天或生成相关简报。

### 4.3 捕获一段零散信息

用户复制一段网页文字或会议纪要：

1. 点击“快速捕获”或使用快捷键。
2. 系统预填剪贴板文本并建议类型：收件箱、学习笔记、记忆候选、文档入库、提醒。
3. 用户选择“收件箱 + 明天提醒”。
4. 系统创建 inbox item 和 reminder，并在今日页可见。

### 4.4 处理扫描件

用户导入扫描件 PDF：

1. 文档状态明确显示“需要 OCR”或“OCR 引擎未配置”。
2. 用户可以将其加入 OCR 队列、跳过 OCR、或创建手动处理收件箱项。
3. OCR 失败时保存错误原因，进入维护报告，而不是静默失败。

### 4.5 远程模型调用失败

用户启用远程 Provider 生成简报：

1. 调用前显示上下文预览和估算大小。
2. 调用失败时，错误分类为认证失败、网络超时、限流或模型不存在。
3. 审计记录写入失败状态。
4. 用户可以切回 Ollama、本地重试、复制诊断摘要或调整 Provider 设置。

### 4.6 排障与反馈

应用启动后健康检查显示 MySQL 红色：

1. 诊断中心展示 MySQL 错误、连接配置摘要、迁移状态和最近日志。
2. 用户点击“生成诊断包”。
3. 系统导出脱敏诊断包，包含版本、配置摘要、健康检查、最近错误和日志摘要。
4. 诊断包不包含 API key、聊天全文或文档原文。

## 5. 功能需求

### 5.1 今日页真实数据化

需求：

- 移除或隐藏生产模式下的固定演示日程、固定记忆洞察、固定相关来源。
- 今日页数据来源必须来自：
  - `/today`
  - `/maintenance/health-report`
  - `/briefings`
  - `/goals`
  - `/inbox`
  - `/reminders`
  - 最近会话、最近文档、最近任务证据或最近活动。
- 支持今日页筛选：
  - 类型：学习、任务、文档、记忆、提醒、目标、系统。
  - 时间：今天、逾期、本周、未来。
  - 优先级：urgent/high/normal/low。
  - 状态：open/snoozed/done/ignored。
- 今日简报按钮必须直接生成或打开简报面板，不应只跳转聊天。
- 今日页空状态必须给出真实可执行动作：新建提醒、快速捕获、导入文档、生成简报。

验收：

- 在空数据环境中，今日页不出现演示文档名、固定日程和虚假洞察。
- 在有提醒、收件箱、目标、备份、失败活动时，今日页显示真实数据。
- 每个今日卡片都有可解释来源和可跳转目标。

### 5.2 全局搜索与命令面板

需求：

- 新增全局搜索入口，支持快捷键打开。
- 搜索对象至少覆盖：
  - 会话标题与消息。
  - 文档元数据与切片。
  - 文档集合与抽取结果。
  - 项目与项目文件。
  - 学习主题、笔记、卡片。
  - Agent 任务、任务步骤、证据。
  - 记忆、收件箱、提醒、目标、简报。
- 支持类型过滤、最近使用排序、文本相关性排序。
- 支持命令面板：
  - 新建会话。
  - 新建收件箱项。
  - 新建提醒。
  - 导入文档。
  - 生成今日简报。
  - 运行健康检查。
  - 打开设置或诊断中心。
- 搜索结果必须包含 `type`、`title`、`snippet`、`source`、`updated_at`、`action`。

验收：

- 搜索一个文档名能命中文档和相关切片。
- 搜索一个任务关键词能命中任务、证据和简报来源。
- 命令面板可以在不离开当前页面的情况下创建提醒或收件箱项。

### 5.3 快速捕获与 OCR

需求：

- 新增快速捕获入口：
  - 手动输入/粘贴文本。
  - 读取剪贴板文本。
  - 从聊天消息保存。
  - 从文档抽取结果保存。
  - 从本地文件导入。
- 捕获结果可转为：
  - inbox item。
  - reminder。
  - memory candidate。
  - learning note。
  - document note。
  - agent task draft。
- OCR 能力：
  - 支持识别“需要 OCR”的文档状态。
  - 支持本地 OCR 引擎可用性检测。
  - 支持 OCR 任务队列、状态、错误原因。
  - OCR 成功后写入文档切片或生成可确认文档笔记。
  - OCR 失败后进入维护报告和收件箱候选。

验收：

- 用户可以从剪贴板创建收件箱项和提醒。
- 扫描件 PDF 不再只返回 `unavailable`，而是有明确的队列/降级处理。
- OCR 未安装时，UI 给出可理解的原因和下一步。

### 5.4 统一反馈、确认与通知

需求：

- 新增应用级 toast/notification store。
- 替换关键路径中的 `alert` / `prompt` / `confirm`：
  - 文档导入、批量导入、删除、重建索引、OCR。
  - 元数据编辑。
  - 任务执行、补丁应用、命令运行。
  - 备份导出、恢复预览。
  - Provider 测试和远程调用。
- 危险操作使用确认 modal：
  - 删除文档。
  - 应用补丁。
  - 回滚补丁。
  - 运行命令。
  - 恢复备份。
  - 清理数据。
- 通知中心记录：
  - 异步操作开始、成功、失败。
  - 可重试动作。
  - 可跳转来源。

验收：

- 关键路径不再依赖浏览器原生弹窗。
- 用户可以在通知中心找到最近的导入失败、备份结果和任务执行结果。
- 危险操作确认信息包含影响范围。

### 5.5 诊断中心

需求：

- 新增诊断中心入口，可放在设置页或独立路由。
- 展示：
  - API、Ollama、MySQL、ChromaDB 状态。
  - 当前版本、git commit、构建时间、schema head。
  - 最近错误日志摘要。
  - 最近活动失败。
  - Provider 最近调用与失败分类。
  - 提醒 tick 状态。
  - 导入队列状态。
  - 备份状态。
  - 数据体检结果。
- 支持生成诊断包：
  - `diagnostics.json`
  - `health.json`
  - `settings.redacted.json`
  - `recent-errors.log`
  - `version.txt`
  - `migration.txt`
- 诊断包必须脱敏。

验收：

- MySQL/Ollama/ChromaDB 任一异常时，诊断中心能展示明确原因。
- 诊断包不包含 API key、完整聊天内容、完整文档原文或敏感记忆。
- 诊断包可在用户指定目录生成。

### 5.6 Provider 生产化

需求：

- 远程 Provider 调用失败分类：
  - missing_api_key。
  - unauthorized。
  - network_error。
  - timeout。
  - rate_limited。
  - model_not_found。
  - provider_error。
- 审计记录补齐：
  - started_at / finished_at。
  - duration_ms。
  - estimated_input_tokens / estimated_output_tokens。
  - error_code。
  - fallback_used。
- 支持远程 Provider 调用前后对比：
  - 计划发送的上下文类别。
  - 实际发送的上下文类别。
  - 被隐私规则剔除的项目数量。
- 支持失败后降级：
  - 回退本地 Ollama。
  - 保存为待重试收件箱。
  - 复制诊断摘要。

验收：

- 远程 Provider 认证失败时，用户看到明确分类和修复建议。
- 审计记录能区分 planned、sent、succeeded、failed、cancelled。
- 敏感记忆和禁用文档仍不能进入远程上下文。

### 5.7 数据完整性与清理建议

需求：

- 扩展维护健康报告，检查：
  - 目标链接是否悬空。
  - 简报 sources 是否悬空。
  - 收件箱 source/target 是否悬空。
  - 任务证据是否悬空。
  - 文档集合成员是否悬空。
  - Chroma chunk 与 MySQL doc_chunks 是否大致一致。
  - 已完成很久的 inbox/reminder/task 是否可归档。
  - 备份包 manifest 是否可读，schema 是否匹配。
- 支持生成 repair plan：
  - 可归档项。
  - 可删除孤立索引。
  - 可重建索引。
  - 可重新关联或忽略的软引用。
- 所有修复必须先预览再执行。

验收：

- 维护报告能识别至少三类软引用悬空。
- 修复计划不会自动删除用户数据。
- 备份校验失败时显示具体失败原因。

### 5.8 性能与规模边界

需求：

- 定义并测量关键路径基线：
  - 今日页加载。
  - 全局搜索。
  - 文档导入。
  - 批量重建索引。
  - 今日简报生成。
  - 长会话加载。
  - 备份导出。
- 后端列表接口支持分页或上限：
  - 会话消息。
  - 文档列表。
  - 活动流。
  - 审计记录。
  - 简报历史。
  - 通知中心。
- 长耗时任务必须有状态，而不是只依赖前端等待。

验收：

- 1000 条消息、500 个 inbox item、100 个文档元数据场景下，列表接口不会一次性无界返回。
- 今日页聚合有明确超时和降级结果。
- 文档中记录性能基线和测试方法。

### 5.9 端到端 QA

需求：

- 新增自动化 smoke 或前端/端到端测试能力，覆盖：
  - 首次启动向导。
  - 后端断开状态。
  - 聊天流式。
  - 文档导入和失败。
  - 今日页真实数据。
  - 收件箱创建和状态切换。
  - 提醒创建、tick、完成。
  - 目标创建和 check-in。
  - 隐私预览。
  - 诊断包导出。
- 发布前脚本应串联：
  - `uv run pytest -q`
  - `npm run build`
  - `cargo check`
  - `uv run alembic current`
  - 自动化 smoke 或可替代的桌面 smoke。

验收：

- 第七阶段至少有一条自动化 smoke 覆盖“今日页读取真实 API 数据”。
- 失败的自动化 smoke 能输出日志；Playwright/Tauri 桌面 E2E 后续增强时应补截图。
- 发布前 checklist 更新第七阶段路径。

### 5.10 扩展注册边界

需求：

  - capture source。

## 9. 安全与隐私要求

- 全局搜索不得越过 trusted paths 读取未授权文件。
- 诊断包必须脱敏 API key、数据库密码、远程 Provider key、完整文档原文、完整聊天内容和敏感记忆。
- 远程 Provider 上下文预览必须早于真实发送。
- OCR 处理本地优先；如果未来接入远程 OCR，必须单独提示数据外发。
- 通知内容不得展示敏感记忆和文档原文。
- 修复计划不得默认删除用户数据。
- 命令面板动作必须复用现有审批和风险等级。

## 12. 定版结论

第七阶段的价值是把“功能完整”推进到“长期可靠”。第六阶段已经让私人助手能主动组织一天；第七阶段要让它组织得更真实、更可查、更可诊断、更可恢复。

完成后，用户每天不需要辨别哪些内容是真数据、哪些是演示文案；遇到失败也不需要翻日志猜原因。系统会提供统一搜索、统一捕获、统一反馈、统一诊断和统一修复建议，继续保持本地优先和用户审批边界。
