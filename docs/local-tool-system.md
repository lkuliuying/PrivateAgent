# 本机 Agent 工具系统

更新日期：2026-09-22。适用于 `private_agent_local` 桌面执行链。本文记录源码能力与本机验证，不代表安装包、生产部署或真实模型验收。

## 工具边界

模型提交结构化工具调用，本机执行器负责校验、权限、审批、执行与结果记录。文件读取、搜索和补丁使用现有原生实现；测试、构建等开发命令交给已有执行会话与 `exec-host`。PowerShell 保留为注册 cmdlet 的补充入口。

决策循环保留 Responses 原生推理续接状态和消息阶段。阶段性说明不会结束任务，仍消耗现有模型轮数、时间和用量预算；完整终态中的工具请求才进入原权限与执行链。`length`、`max_tokens`、`incomplete` 等未完整响应不能执行工具或成为验收候选。公开决策摘要优先使用模型公开的本轮操作说明，缺少说明时才使用工具名称概述，不读取加密推理。最终回答继续经过既有机器证据验收与有界纠偏；原生状态、协议格式及压缩边界见[模型直连说明](direct-model-execution.md#原生推理与决策续接)。

| 组件 | 职责 |

注册表是工具声明的单一来源。模型只获得名称、说明和输入 schema；权限元数据由程序解释，远端描述不能改变它。现有路径检查、文件版本、任务限制和审批仍在最终执行边界生效。输入错误返回 `invalid_tool_arguments`；结果在记为成功前检查 JSON、大小与声明结构。保留旧导入入口和旧省略参数的默认值。

工具可见性按执行协议处理：`execution_contract_version="1.0"` 使用执行会话及按需发现工具；旧协议继续使用 `run_project_command` 并保留全量符合条件的工具定义。Git 工具仅向具有项目根 `.git` 的任务暴露，文档工具仅向已启用文档源的项目任务暴露。每次模型请求重新核对项目、权限、协作模式、用户约束及文档配置；任务进行中启用文档源后，下一次模型请求即可取得发现入口，停用后相应入口退出后续请求。

## 按需工具选择

新协议默认提供常用文件、搜索、补丁、普通命令及执行结果控制工具。`request_execution`、`list_executions`、Windows 的 `run_powershell_command` 和两个文档 MCP 入口按需加载；当前权限内存在可发现工具时才提供 `tool_search`。规划模式只允许搜索其可用工具，发现不能恢复被禁止的命令或写入。

1. 模型调用 `tool_search`，提供工具名或中英文关键词 `query`，`limit` 默认为 3、最多 5。搜索只读当前本机目录，不访问外部服务。
2. 返回 `matches`、`loaded_tools` 和使用提示。文档匹配携带 `source_id`、`source_version`、`tool_name` 和原始 `input_schema`，供已有 MCP 入口使用；远端描述及 schema 标记为不可信数据。
3. 命中的工具定义进入**下一轮实际模型请求**，参与上下文预算计算。派发集合绑定产生当前响应的请求；同一响应中先搜索、再提前调用尚未展示的工具会返回 `tool_not_available`，模型可在下一轮正确调用。
4. 每个任务最多保存 16 个已加载工具名，不持久化重复 schema、不静默淘汰。恢复任务继承名称后重新核对可用性；源版本与执行审批继续由原 MCP 边界检查，加载状态不构成授权。

搜索使用确定性词项匹配，无结果时返回空匹配；单次输出上限为 96 KiB，超限会要求减少结果或缩小查询，不加载半份结果。启用恢复协议的任务中，无新结果的重复搜索纳入原有无进展保护；新加载工具或变化的来源版本重新计数。文档搜索通过既有 `call_documentation_tool` 适配参数，兼容当前多供应商严格函数契约，未新增供应商专属工具协议。

## 任务计划与进展

### 规划模式与实施交接

能力位 `coding_planning_contract_version="1.0"` 与恢复协议共同开启桌面“规划 / 执行”选择；输入 `/plan 任务内容` 可进入规划。创建请求新增 `collaboration_mode="plan" | "default"`，默认执行模式保持原行为。协作模式与权限模式是两个独立维度。

- 规划模式允许原生文件/目录/搜索、固定 Git 查询、上下文读取、已配置文档查询及计划控制。后端在工具暴露和实际执行两处阻止写入、补丁和命令；完全访问权限不会绕过此限制。文档查询继续服从网络限制与原有审批。
- 先调研可以从代码确认的问题，再用 `request_user_input` 提出 1–3 个关键问题，每题最多 3 个建议。用户可选建议或自由回答，无默认自动提交；此工具仅向规划模式暴露，不能用于工具授权。
- 等待状态为 `waiting_input`，问题保存在运行 JSON，断线或重新打开任务后由快照恢复。回答携带 `input_id`、`expected_state_version` 和幂等 `request_id`；全部题目必须回答。回答作为用户来源更新目标版本，使原计划待核对，废弃同一旧模型响应中剩余工具。
- 追加约束、暂停、取消与服务重启均使旧问题失效。服务重启保留历史并标记中断，不自动回答或重放；等待回答的时间不消耗有效执行时长预算，仍受运行整体时长上限约束。
- 计划提交要求存在与当前目标一致的步骤，覆盖全部必需验收项，至少一个 `pending`；过时草案步骤可以 `cancelled`。规划结束记录 `answered`，显示“尚未执行”，不会伪装为实现验证通过。
- “按计划执行”携带预期计划版本、状态版本和检查点，经现场、模型、预算与权限核对后建立关联执行任务。保留目标、用户约束、计划及累计预算，写入和命令仍经过原权限链。重复请求返回同一交接回执；旧计划不被改写。“修改计划”将输入器切换为规划并保留已有草稿。

| 接口 | 输入与结果 |
|---|---|
| `POST /agent-runs/{run_id}/answer` | 控制版本、问题 ID、全部问题的文本回答；原子记录用户消息、目标修订及 `input.resolved` |
| `POST /agent-runs/{run_id}/implement-plan` | 控制版本、检查点、`expected_plan_version`；返回 `result_run_id` 并在事务提交后启动 |

新增 `input.requested`、`input.resolved`、`input.invalidated` 事件；所有事件和状态继续使用现有 SQLite schema 7，无新增数据库迁移。旧客户端应继续省略 `collaboration_mode`；新版客户端在能力位缺失时不显示新入口。

### 执行中的计划

`recovery_contract_version="1.0"` 的新运行可使用 `update_run_plan`；旧协议继续读取历史，但不暴露该工具。简单回答和一次读取不要求建计划。计划工具属于串行控制操作，只更新元数据，不授予文件、进程或网络权限，也不新增独立的规划模型调用。

输入为 `expected_plan_version`（首次为 0）、当前 `goal_version`、公开说明 `explanation` 和完整 `items`。每个步骤含稳定 `item_key`、`title`、`status`、`detail`、`requirement_ids`、`evidence_calls` 和可选的 `supersedes`。最多 32 步、同时最多一个 `in_progress`，整个输入最多 16000 UTF-8 字节。公开说明只记录进度、决定或阻塞，不要求模型内部推理。

- 状态为 `pending`、`in_progress`、`completed`、`blocked`、`failed`、`cancelled`。已有步骤不能删除；不再需要的未结束步骤应明确取消。终态不能重新打开或改写标题及既有证据，需要修正时追加后续步骤。
- 后续补救步骤可用 `supersedes` 引用排在前面的失败步骤，并保留其全部 `requirement_ids`。补救完成后解除关联失败的计划阻塞，也支持多次补救形成的链；原失败与证据不被覆盖。是否完成用户目标仍由独立验证器检查，补救勾选不能代替文件或测试证据。
- 更新必须匹配计划版本和目标版本；无效引用、非法转换及过期更新均失败关闭。证据调用必须已在当前逻辑任务或其恢复祖先中提交，并能关联执行记录和终态事件；其他任务的调用不能借用。
- 计划、完整 `plan.created` / `plan.updated` 事件及工具完成事件在同一事务中提交。已有 SQLite schema 7 的运行 JSON 保存计划，无迁移。前端兼容旧版本事件，并防止旧计划覆盖新快照。
- 追加目标会使已有计划进入 `needs_review`，重新核对后才能交付。恢复检查点核对计划与进度摘要，恢复运行继承原计划及逻辑任务预算，不重放旧工具或审批。
- 已完成步骤表示模型报告的进度；调用引用只是来源索引。待核对、未完成或受阻计划会限制交付，全部勾选仍必须经过原有文件、命令、测试及需求验证。

成功查询的停滞保护覆盖文件、目录、搜索、Git、历史内容、补丁预览及已结束命令的结果读取。相同目标、工作区、步骤状态及命令结果下，连续 3 次重复观察发出纠正提示，连续 6 次重复观察以 `no_progress` 停止；首次读取不算重复，因此单一相同查询最多执行 7 次。最多保留 64 个结果指纹，忽略每次变化的文件 `snapshot_id`，分页、新内容和新命令诊断会重新计数；`starting` / `running` 命令轮询不计停滞。原有相同失败第 3 次警告、第 4 次停止及总预算继续生效；恢复协议 1.0 另外使用下述结构化纠错保护，避免穿插无关成功读取重置失败。

## 原生查询和命令入口

- 文件查询沿用 `list_project_directory`、`read_code_file`、`search_project_files`；修改沿用先读快照、生成补丁、审批及版本校验。
- `get_git_status` 返回受路径限制的变更和分页游标；游标绑定项目、查询和版本。
- `get_git_diff` 只查询一个文件；区分暂存区与工作区，支持偏移续读和版本校验，拒绝受保护文件、越界路径及硬链接目标。
- Git 查询固定参数，关闭外部 diff、textconv、hook、pager 和 fsmonitor，设置超时及输出上限；不接受任意 Git 子命令，也不提供提交、切换分支或推送功能。
- `get_execution_capabilities` 返回当前注册程序的可用性、允许操作、PowerShell 参数、执行模式与任务限制。程序存在不等于获得执行授权。
- 普通 `exec_command` 向模型只展示 `argv`、`cwd`、`yield_time_ms`、`timeout_ms`、`output_budget`。默认受限模式、无网络、无终端/stdin、任务生命周期。
- 该普通组合在 `workspace/full_access` 权限下自动授权，在 `confirm` 下继续审批；`readonly` 与规划模式不允许运行命令。自动授权记录 `tool.auto_approved`，同时绑定参数、项目版本、程序及环境；授权撤销、规则变化、取消、已拒绝或未知结果都会阻止启动。系统沙箱不可用时失败关闭，不退回普通宿主进程。
- `request_execution` 单独展示 stdin、终端、会话保留及可信项目模式。它是申请，仍须审批并校验当前程序、环境和项目版本。旧调用的高级参数仍能解析，权限检查相同。
- 高级申请仍须审批。`write_stdin` 仅对同一任务中已明确批准启动、仍在运行、已打开 stdin 的禁网受限进程复用 `workspace/full_access` 权限；原审批、执行归属、授权摘要和状态版本必须匹配。`confirm`、可信项目进程、跨任务输入或缺少完整授权记录时仍逐次审批。身份核对或等待输入锁期间权限、归属或状态变化会拒绝本次输入；最终复核和自动授权审计位于发送锁内，旧版本输入不能重复发送。
- 现代入口直接校验并保留结构化 `argv`。受限模式支持 `python/python3 -c` 和 `node -e/--eval/-p/--print` 的短段代码，代码作为一个参数发送；Python 支持 `-c代码` 及 `-I`、`-B` 等安全前缀，Node 支持分离参数、`-pe 代码` 与 `--eval=代码`。Node 短选项紧贴代码、`--print=代码`、未支持的前置选项组合明确拒绝，不静默改写。单个参数仍最多 2000 字符。
- 新增的 eval 参数形式只允许通过现代 `restricted` 执行链，继续要求禁网、非 TTY、系统沙箱可用，并执行原有任务限制、程序与工作区版本核对、预算和进程回收。旧 `run_project_command` 和 `trusted_project` 拒绝这些 eval 形式，包括紧贴或等号形式；Node 的 data URL 预加载也明确拒绝。参数识别不构成完整代码隔离，例如既有 Python 模块和项目脚本仍可运行代码，系统沙箱才是受限进程的权限边界。通用 Shell、命令串联及其他程序的白名单规则保持不变。
- 内联代码与获准项目脚本具有相同的进程权限，继续受下述系统沙箱及保护路径约束。代码正文不会被解释为待读取的本机文件路径；审批和审计通过参数摘要绑定正文。存在禁写或限定文件范围等任务约束时，未获明确测试要求的普通命令仍被拒绝；单独的禁测试限制按下文识别结果处理，不再把未知内联代码一律拒绝。退出码和工作区变化继续记录；用户明确要求执行的命令可按 `command + evidence_policy=exit` 核验正常退出，仍须具备对应终态事件和有效工作区版本。退出 0 不直接证明代码中的业务断言、测试要求或其他用户需求成立。
- 稳定错误包括 `program_unavailable`、`command_not_allowed`、`invalid_execution_options`。参数被拒绝不能成为扩大权限的理由。

普通测试调用示例（命令仍须符合项目及用户限制）：

```json
{
  "argv": ["python", "-m", "pytest", "-q"],
  "cwd": ".",
  "yield_time_ms": 1000,
  "timeout_ms": 600000,
  "output_budget": 32000
}
```

`yield_time_ms` 只是等待首批输出的时间，不是进程超时。返回运行中后使用 `read_execution`；只有真实退出结果才能作为验证证据。高级申请完成时的事件保留原始工具名和调用 ID。

## 安全与权限边界

任务解释 `1.2` 区分全局禁止、具体路径限制和子任务语义。局部“只分析／先汇报”不禁用其他子任务的写入或检查；有明确路径时通过既有文件边界执行限制，没有路径时保留来源和原文供主模型遵循。只分析或只预览的整个任务仍禁止写入及执行。用户原文始终保留，程序提示不是完整语义或新授权。

“不要运行测试”拦截明确测试入口，以及实际调用的项目脚本、生命周期钩子和简单别名中的测试；脚本追踪最多 16 层，循环有界，`package.json` 最多读取 64 KiB。无关测试脚本不影响构建。未知或动态脚本按既有权限处理，由主模型遵循原始要求，程序不声称能证明其中绝无测试。脚本不明也不自动扩大权限。存在任务限制时 stdin 的原有检查保持不变。

“只修改 A.py，然后运行测试”允许用户明确要求的测试通过原执行权限链，项目检查配置不能单独授予这个例外。运行记录保存当时的路径限制，旧命令入口和持续执行入口都核对执行前后有界文件快照，沿用缓存／构建目录排除规则。范围外代码变化标记 `violated`，不完整快照标记 `unverified`，两者都停止后续修改并保留实际文件；不自动回退或把退出码 0 当作范围检查通过。持续进程在发布终态前保存该结果，恢复后继续保留限制。这是执行后的发现机制，不是对测试副作用的执行前隔离。

审批和系统沙箱分别决策。`confirm`、`workspace`、`full_access` 决定普通操作是否需要交互确认；普通命令始终使用 Windows AppContainer，无网络、无静默降级。旧 `run_project_command` 和受控 PowerShell 也遵守此边界，`full_access` 不授予管理员权限，不再让旧入口自动脱离沙箱。

`request_execution` 的 `trusted_project + approved` 是明确的脱离沙箱申请，每次都须用户审批。批准后进程拥有当前用户的文件和网络访问能力，应根据实际执行参数决定是否批准。任务限制、限时授权、工作区版本、程序与环境核对继续生效；自动模式和高级申请审批互不替代。

受限进程启动前扫描现有敏感对象：`.env` 及 `.env.*`、凭据目录和私钥等对象拒绝访问；`.git`、`.codex`、`.agents` 及其现有内容只读。实现为受保护对象阻止继承宽权限，并只给本次随机 AppContainer SID 必需的允许权限；同时限制父目录的删除与重命名权限。普通子树仍可读写、创建和删除。清理时移除本 SID 并恢复原继承标志，不用旧 ACL 快照覆盖其他主体的新权限。

同一受保护工作区已有重叠租约，或现有宽泛应用包授权、未知 ACE 类型、可能合并的显式与继承条目导致无法保证隔离或无损恢复时，启动失败关闭；不会为了运行命令自动切换可信模式。其他工作区与没有保护对象的工作区继续使用原有槽位上限。原生文件工具对 `.git`、`.codex`、`.agents` 延续更严格的访问拒绝，不能经补丁入口改写控制文件。

这是现有文件对象保护，不是按未来文件名持续拦截：普通可写目录中新建的 `.env` 等名字尚无动态规则。受限命令目前只支持完全禁网，**不支持按域名放行网络**；高级模式的网络批准也不应被解释为域名隔离。`get_execution_capabilities.security_policy` 明确报告这些能力与缺口。

目录扫描保留 30 秒总时限，保护对象及必要父目录最多 16384 项，ACL 恢复日志最多 8 MiB；超限、链接或硬链接等无法安全授权的情况均拒绝执行。大型仓库可能需要缩小工作区，不会截断检查后继续授予权限。

公开内容过滤在后端执行：

- 已配置模型凭据、本机会话令牌及常见凭据格式在公开输出中遮蔽；stdout/stderr 和模型增量各自维护跨分片状态，退出、取消和断流时安全收尾后记录终态。
- 模型请求在发送前过滤消息副本和原生状态中的公开内容，认证头仍使用原凭据，不修改项目文件、补丁或恢复正文。
- 文档 MCP 参数发现敏感内容时直接拒绝，在审批前和发送前复核；不把静默替换后的参数当成原审批参数发送。
- `read_code_file` 发现正文需要脱敏时拒绝返回并且不建立编辑快照，避免模型把占位符写回原文件。普通类型注解、环境变量读取和明确代码语境中的变量引用（例如“把代码改成 token=next_token”）不会仅因变量名被识别为凭据。含义不明的赋值及凭据字段仍遮蔽值；中文标点之后的指令保留。配置中的实际凭据、明确密钥格式、认证头和私钥优先过滤，代码语境不豁免。流式与完整文本使用同一规则。

过滤属于补充防护，不能识别所有业务秘密、编码或拆分重构；不处理历史数据清洗，也不替代进程隔离、路径保护和外部操作审批。本次对齐依据 Codex 官方的[审批与安全](https://learn.chatgpt.com/docs/agent-approvals-security)、[权限配置](https://learn.chatgpt.com/docs/permissions)及 [Windows 沙箱](https://learn.chatgpt.com/docs/windows/windows-sandbox)，未宣称实现其域名代理或组织托管策略。

## 并行规则

每批最多执行两个相邻、由本机注册表声明为自动授权且幂等的只读调用。当前包括文件读取、目录、搜索和 Git 查询。需要快照修改的补丁预览、写入、命令、控制和外部 MCP 调用保持串行。

调用 ID、步骤和结果按模型原始顺序记录，完成先后不改变上下文和失败计数。一个读请求失败不会丢失另一个结果；批次结束前不会开始后续写入。取消会回收并等待所有活动读取；追加约束后，包含已先完成的兄弟读取在内，旧代次结果不得进入新的模型上下文。文件读取与目录扫描避免把阻塞 I/O 放在事件循环内；后台线程结束后才完成取消，避免取消后继续修改快照。

## 技术文档 MCP

此文档 MCP 入口用于公开技术文档检索。2026-09-21 另增通用 MCP、Skills、网页/浏览器和只读子任务入口，见[工作台说明](workbench-guide.md)；下述限制仅对应原文档服务。复用项目已固定的 `mcp==2.0.0`、`httpx2==2.9.1`、`httpcore2==2.9.1` 和已有 JSON Schema 能力，未增加依赖或修改锁文件。

在桌面端“设置 → MCP → 公开文档服务”中：

1. 选择所属项目，添加公开 HTTPS 文档服务。
2. 点击“发现工具”，确认连接目标。发现只获取工具目录，不发送项目文件或会话内容。
3. 选择搜索/读取工具并启用。新服务默认停用，发现更新也会清空选择并停用。
4. 在项目任务中请求文档检索；进行中的任务在下一次模型请求刷新可用性。每次调用展示目标、工具名及完整发送参数，审批通过后才发出检索。

预填示例为 [Microsoft Learn MCP](https://learn.microsoft.com/en-us/training/support/mcp-developer-reference)，地址 `https://learn.microsoft.com/api/mcp`。用户可替换地址。没有预先创建或自动启用真实项目配置。

新协议先通过 `tool_search` 查找文档工具并加载两个 MCP 入口；搜索结果或 `list_documentation_sources` 提供已选择工具的版本及 schema，再通过 `call_documentation_tool` 提交 `source_id`、`source_version`、`tool_name`、`arguments_json`。旧协议直接使用这两个入口。结果写入原有执行记录，包含来源、配置版本、目录摘要和 `untrusted=true`，供回答引用；远端内容不是新的指令、授权或本机执行成功证据。

配置放在当前身份的现有项目 SQLite 记录 `documentation_mcp` 中，不增加数据库表。每个项目最多 8 个源，每源最多选择 16 个工具。以下本机接口沿用现有身份与 IPC 边界：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /projects/{project_id}/documentation-sources` | 读取当前项目配置 |
| `POST /projects/{project_id}/documentation-sources` | 创建默认停用的源 |
| `POST /projects/{project_id}/documentation-sources/{source_id}/discover` | 发现目录，提交 `expected_version` |
| `PUT /projects/{project_id}/documentation-sources/{source_id}/selection` | 提交版本、工具选择及启用状态 |
| `DELETE /projects/{project_id}/documentation-sources/{source_id}?expected_version=...` | 删除版本匹配的配置 |

执行边界：

- 仅公开 HTTPS 443；不接受 URL 凭据、查询参数、fragment、内网或特殊 IP。DNS 全量校验后固定 TCP 地址，TLS/SNI 保留原域名；不继承环境代理、不跟随重定向。
- 目录最长有效 24 小时；审批绑定当前源版本，发送前重新获取并比较目录摘要。删除、停用、配置变化、目录变化、用户拒绝或新增禁止联网约束都会阻止调用。
- 单次连接及查询总计 20 秒，HTTP 响应最多 512 KiB，目录及工具结果分别最多 128 KiB。SDK 支持的协议由协商决定；不自动重试工具调用，不提供模型采样、资源访问或额外交互能力。
- 首版 schema 不支持引用和正则表达式关键字；复杂目录会明确拒绝。此入口仅支持公开无认证的 HTTPS MCP；OAuth 和 stdio 使用独立通用 MCP 配置。通用入口仍不允许内网 HTTPS、环境代理或未审核的复杂 schema。
- `readOnlyHint` 等远端注解不授予权限。所选服务应由用户确认用于文档搜索/读取，后端仍把每次调用作为需审批的外部操作。参数不会自动附加文件或会话，凭据检测命中会在发送前拒绝；其他语义上的敏感内容仍须在审批时审查。
- 用户明确禁止联网时，MCP 请求和具备网络能力的可信项目命令在审批前被阻止；追加指令不会隐式解除已有禁止项。这个约束针对工具请求，不把在线模型推理描述为离线推理。

## 运行观察与项目完成检查

2026-09-21 起，本机观察器保留共享核心的模型/工具步骤 ID，并在离散事件边界保存步骤快照。工具审批前不发布实际开始事件；并行调用各自绑定步骤，持续进程的输出与终态使用创建执行时保存的关联。计划阶段只作为 `model_report` 上下文，不能代替实际工具或完成证据。历史事件缺少步骤 ID 时保持未知，不回填猜测。

正式入口为任务工具区的“观察诊断”。`GET /agent-runs/{run_id}/observer` 返回最近 100 个事件、最近 100 个步骤、总计数、截断标志、错误分类、停滞计数和完成检查结果。它不返回用户/模型正文、工具参数、命令内容、输出日志或原始错误消息；计划引用为摘要标识。复制的是该白名单 JSON，完整执行输出仍通过原有执行面板按需查看。错误分类用于定位边界，不宣称自动确认根因。

检查结果绑定验收时的目标、工作区及追加指令版本。版本变化后，仍适用的检查显示 `pending/evidence_stale`，新禁止项显示跳过。历史工作区不可访问时，诊断保留可读并标记 `scope_unavailable`。面板展示上次核验记录，刷新不执行检查；外部程序改变文件但未增加任务版本的情况，在下一次完成核验时通过磁盘摘要检测。

项目编辑中的完成检查使用以下本机鉴权接口：

| 接口 | 语义 |
| --- | --- |
| `GET /projects/{project_id}/observer-config` | 读取 `{version, enabled, checks}`，默认版本 0、禁用、空检查 |
| `PUT /projects/{project_id}/observer-config` | 提交 `{expected_version, enabled, checks}`；版本不符拒绝覆盖 |

每个项目最多 8 项，每项为 `{id, kind, scope}`。`artifact` 检查项目内文件存在且可安全回读；`test` 验证明确登记的测试命令；`command` 验证登记开发命令或项目校验脚本的退出证据。命令检查固定使用项目根目录，子目录的同名命令不能代替。测试帮助、版本和仅收集测试不能配置成测试通过条件。

配置只为修改任务提供完成条件，不自动执行命令，也不新增工具权限。运行开始保存配置快照，恢复沿用原快照；更新设置影响后续新任务。每次模型边界和验收重新应用当前用户约束：规划、只读、纯问答及禁止修改不激活检查，被禁止的测试、命令或访问路径标记跳过。用户明确指定的验收要求仍按原流程处理，不因项目检查跳过而删除。

完成检查复用原 `LocalCompletionVerifier` 的磁盘回读、执行终态关联、工作区摘要/版本、恢复来源及拒绝记录。检查开始/结果写入事件，缺失或失败证据反馈给原主模型，仍受最多两次完成纠错及原任务预算限制；观察器不新增模型调用层。文件存在与退出码通过不能证明全部业务语义正确。

对齐参考为 Codex 官方的 [App Server 事件生命周期](https://learn.chatgpt.com/docs/app-server) 和 [Stop Hooks](https://learn.chatgpt.com/docs/hooks)。本机采用内置确定性检查，不提供 Codex 任意命令/MCP Hook 的完整兼容接口，不接入独立语义评判模型。

定向隔离验证入口：`.venv\Scripts\python.exe -B scripts/run_coding_validation.py --suite observer`。实际验证结果见[观察器对齐交付记录](./solutions/2026-09-21-observer-alignment.md)，接口存在不等于已安装或已通过真实模型验收。

## 反思、纠错与独立复核

恢复协议 1.0 的任务按参数、证据、执行、权限、结果未知及验收缺口记录纠错事实，最多保留 16 项。每项记录来源运行、工具调用摘要和执行事件引用，不复制原始参数、输出或错误正文。下一轮提示要求核对原因、新依据、方案变化及预期验证；权限拒绝不建议换入口重试，副作用未知不允许自动重放。同一操作成功才解决对应错误，无关读取不会清除它；同目标、同工作区相同操作累计 3 次可纠正失败警告、4 次停止。原生命令还核对持久化终态与关联事件，反复读取同一结果只计一次。

默认仅在当前目标累计至少两次可纠正失败后启用独立质量复核。一次完成检查即使有多项失败也只计一次；权限阻塞、取消、未知副作用不触发付费复核。复核仅针对机器验收已通过且有真实文件变化证据的交付候选，普通问答、预览、计划、缺失证据或人工待确认不会因此增加模型调用。模型修正后需重新取得证据再检查，复核本身不能提升 `unknown`、`blocked` 或失败结果。

复核使用当前已配置模型、独立消息和无工具请求，读取候选交付、验收事实及最多 12 条有界历史摘录。输出必须符合 `pass/revise` schema，问题必须引用已提供来源；模型工具请求、无效响应、秘密或无来源引用均拒收。它不是完整代码审查，历史摘录未覆盖的内容不会据此认定正确。

每个逻辑任务最多 2 次复核请求，每次最多 30 秒且受剩余有效时间约束，并为主任务保留至少一次请求。请求数、tokens、缓存用量及费用计入原任务；取消或超时但可能计费的请求标记用量未知。复核不自动重试供应商调用，失败或预算不足时保留未确认结论。追加约束、暂停、取消可中断复核，目标、配置、规则或磁盘变化后丢弃过期意见。

纠错及复核状态保存在现有运行 JSON 并加入恢复检查点摘要，不变更 SQLite schema。继续任务继承失败事实与复核次数，不重放工具；新目标清除旧纠错而不重置累计预算。观察诊断显示纠错与复核事件类别，不公开复核正文或原始工具数据。未自动写入长期记忆或项目规则。

隔离验证入口：`.venv\Scripts\python.exe -B scripts/run_coding_validation.py --suite reflection`。对齐范围与验证边界见[反思纠错对齐记录](solutions/2026-09-21-reflection-alignment.md)。
