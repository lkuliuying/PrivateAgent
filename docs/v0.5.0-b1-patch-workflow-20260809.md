## 1. 交付内容

### 1.1 后端：可信执行器与 versioned 工具（`core/patch_workflow.py`）

`apply_patch_to_workspace` 已包装为 versioned `ToolSpec`（schema/risk/capability/
幂等全部取自 B0 冻结契约），执行链路：

1. **预览**：复用 `code_tools.propose_patch` 生成只读 unified diff；预览被截断时
   拒绝直接应用（必须重新生成完整分块 Diff）；
2. **写前防护**（to_thread 临界区）：
   - `resolve_within` 重解析路径（拒绝绝对路径 / `..` / 越界）；
   - `_reject_link_target` 拒绝最终组件为符号链接 / 目录联接 / 重解析点；
   - `create=True` 创建父目录后再次校验仍在根内（TOCTOU 缓解）；
   - 已有文件必须携带 `expected_old_sha256` 且与磁盘当前 SHA 一致，否则拒绝
     （过期补丁 / 冲突）；新建文件要求 `create=true`；
3. **原子写入**：同目录临时文件（`mkstemp` + fsync）+ `os.replace` 原子替换
   （替换路径本身，不跟随链接；失败清理临时文件）；
4. **回读核对**：写入后以 UTF-8 严格回读，SHA 与 `new_sha256` 一致才返回
   `verified=True`，任何不一致失败关闭；
5. **不可重放**：`non_idempotent`——崩溃后的 unknown execution 由既有 executions
   管道拒绝自动重试（`execution_state_unknown` 人工处置）。

### 1.2 后端：Registry 组合与写能力授予（`routes_agent_runs.py`）

- `PA_AGENT_PATCH_WORKFLOW_ENABLED` 开启时注册 patch 工具，且**仅此时**向
  capability policy 授予 `filesystem.write`（default-deny 保持）；
- `FileDiffResultVerifier` 在只读或 Patch 任一开启时注入（写后回读事实复核 +
  入参 `new_content` 交叉校验）；
- 新增两个只读 API：
  - `GET /agent-runs/{run_id}/approvals/{approval_id}/preview`：审批时的文件变更
    预览（基于当前磁盘事实重算，返回 rel_path / old·new SHA / diff / truncated；
    不可预览或参数不完整时 `previewable=false` + reason；未开启工作流时 404）；
  - `GET /agent-runs/{run_id}/executions`：已脱敏/限长/持久化的工具执行结果
    （UI 的产物与 Diff 事实源，不含审批 token）。

### 1.3 前端

- `AgentApprovalPreview` / `AgentToolExecution` DTO 与 `api/agentRuns.ts` 封装；
- `ApprovalCardV2`：patch 类工具审批时自动加载并展示**变更预览**（文件、旧/新
  SHA、diff 文本、新建文件徽标、截断警告）；加载失败/不可预览静默降级，不阻塞
  审批；
- `ContextRail` Files：接入真实变更摘要（`apply_patch_to_workspace` 成功执行的
  rel_path / verified / diff），「已修改」徽标 + 完整 Diff 弹窗（PaDialog）；
  App.vue 在 run 结束后与会话重载时拉取 executions 作为事实源；
- 移除占位文案（"Diff 入口将在 D3 接入"）。
