## 1. 交付内容

### 1.1 只读连接 profile（`core/sql_profiles.py` + `api/routes_sql_profiles.py`）

- `sql_readonly_profiles`（0023 建表）：dialect（仅 mysql）、host/port/database/
  username 元数据、`password_secret_ref`（keyring 引用强制）、connect_args
  （敏感键名拒绝）、max_rows/max_bytes/timeout_ms、enabled/version；
- CRUD API `/sql-profiles`（flag `PA_AGENT_SQL_READONLY_WORKFLOW_ENABLED` 门禁）；
- 备份清理已有测试覆盖（0023 起：connect_args 值清空、引用保留）。

### 1.2 只读执行器（`core/sql_workflow.py`）

- **解析层（sqlglot 30.15，已入 pyproject/uv.lock）**：单语句强制；语句类型仅
  SELECT/EXPLAIN/SHOW/DESCRIBE/WITH；AST 遍历拒绝 INSERT/UPDATE/DELETE/DDL/
  GRANT/CALL/LOCK/UNLOCK/USE/SET/LOAD/INTO 节点与 FOR UPDATE 等锁参数；
- **数据库只读事务兜底**：`START TRANSACTION READ ONLY` + 查询 + ROLLBACK，
  任何 DML 在事务内被数据库拒绝（账号配置错误也不能绕过）；
- 超时（`asyncio.wait_for` + 关闭连接）与取消（CancellationToken → 任务取消 +
  连接清理），无悬挂连接；
- 结果行数/字节双上限、疑似秘密列（password/secret/token/api_key 等）值替换
  `[REDACTED]`、大字段截断；
- 密码只经 keyring 通道（`PA_SQL_PROFILES_SECRETS_JSON`）注入进程内存，
  缺失引用/畸形条目 fail closed。

### 1.3 验证器与注册（`routes_agent_runs.py`）

- SQL flag 开启时注册 `query_readonly_sql`（`database.query` 授予）；
- `DatabaseResultVerifier` 增强 `require_read_only`（additive）：检查
  `read_only_confirmed`、row_count/columns/rows 形状与一致性。

### 1.4 keyring 通道（Rust + Python）

- `credentials.rs`：`sql.<name>.password` 账户与 `secret://os-keyring/sql/<name>/password`
  引用（校验 + 单元测试）；
- `lib.rs`：`sql-profile-secret-index.json`（≤32）、collect/commands
  （set/clear/status）、sidecar 注入 `PA_SQL_PROFILES_SECRETS_JSON`
  （仅 `sql_readonly_workflow_enabled` 时）；
- Python `load_process_sql_secret_resolver()` 一次性消费并清除环境变量。

### 1.5 UI

- Settings 卡片 07「只读数据库」：profile 列表/表单/启用切换/keyring 密码槽位；
- ApprovalCardV2：`query_readonly_sql` 结果表格（只读事务徽标、行数、截断标记、
  已脱敏列/有界行）。

### 1.6 契约 additive（B0 已冻结字段）

- `query_readonly_sql` 输出 Schema 增加可选 `statement_type`（规范化语句类型），
  更新 hash 测试与 B0 文档 §2.5。

## 3. 已知边界

- 仅 mysql dialect（v0.5.0 正式支持面）；其他 dialect 配置即拒绝；
- `SELECT ... INTO @var` 等 MySQL 用户变量写法被保守拒绝（INTO 节点）；
- 密码空串合法（本地 root 无密码场景），但 keyring 通道禁止空值注入
  （fail closed）；生产凭据必须非空。
