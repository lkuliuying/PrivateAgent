# PrivateAgent 0.3.0 开发计划：Runtime 默认聊天接管

> 计划日期：2026-08-07  
> 基线版本：`v0.2.1`  
> 基线发布提交：`a3ac17c`  
> 当前主分支：`7dcf372`，与 `origin/main` 同步、工作区干净  
> 数据库基线：`0021 (head)`  
> 目标版本：`0.3.0`  
> 核心目标：让普通聊天和知识库聊天默认进入 durable Agent Runtime，并以独立灰度方式启用本地摘要 worker。

## 1. 启动前结论

`0.2.1` 已完成正式发布，可以作为 `0.3.0` 的可靠开发基线：

- `v0.2.1` tag、完整门禁、manifest 和 GitHub Release 绑定提交 `a3ac17c`。
- 远程 Release 为正式版本，不是 draft 或 prerelease。
- 8 个远程 Release 资产的 SHA-256 与本地构建产物一致。
- 完整门禁为 `14 passed / 0 failed / 0 skipped / ok=true`，Python 为 `584 passed`。
- 应用版本统一为 `0.2.1`，数据库为 `0021 (head)`。
- 干净安装、`0.2.0 → 0.2.1` 升级、数据保留、回滚和 updater 签名负面验证通过。
- 安装版批 A 已开启：Agent API、只读工具、ContextBuilder、输出验证、RAG 工具和遥测持久化。
- 桌面退出后的 sidecar 进程树清理已修复并纳入最终门禁。
- 当前没有遗留桌面或 sidecar 进程。
- Authenticode 仍为 unsigned，已在发布说明中如实标记，不作为本版本功能阻断项。

因此，`0.3.0` 可以进入开发，但默认聊天接管不能在缺少观察数据时直接一次性开启。

## 2. 当前 Runtime 与遥测基线

### 2.1 当前安装版开关

`0.2.1` 安装版当前启用：

- `PA_AGENT_RUNS_API_ENABLED=true`
- `PA_AGENT_RUN_READ_ONLY_TOOLS_ENABLED=true`
- `PA_AGENT_CONTEXT_BUILDER_ENABLED=true`
- `PA_AGENT_OUTPUT_VERIFICATION_ENABLED=true`
- `PA_AGENT_RAG_TOOLS_ENABLED=true`
- `PA_COMPATIBILITY_TELEMETRY_PERSIST_ENABLED=true`

仍关闭：

- `PA_CHAT_AGENT_RUNTIME_ENABLED`
- `PA_CONVERSATION_SUMMARY_WORKER_ENABLED`

因此桌面主聊天仍走 legacy ChatService，只有显式 Agent Runs API 使用 durable Runtime。

### 2.2 2026-08-07 遥测快照

- `window_count=18`
- `/tool-calls=5`
- `/tools=1`
- `/tools/plan=0`
- `legacy_zero=false`
- 当前18个窗口的 `ended_at` 均为空，主要来自安装、升级和 smoke 期间的强制停止；尚不能把它们当作稳定生产观察窗口。

这些数据说明遥测链路已经工作，但还没有形成足够长、正常结束、可用于默认切换决策的观察样本。

## 3. 0.3.0 产品目标

### 3.1 必须交付

1. 普通聊天默认进入 durable Agent Runtime。
2. 知识库聊天默认使用 Runtime RAG 工具和可信引用验证。
3. 桌面端根据 `/capabilities` 唯一决定执行模式，不再预调用旧 planner。
4. SSE 流式、取消、断线重连、审批恢复和唯一消息投影达到安装版稳定标准。
5. 自动摘要 worker 在聊天 Runtime 稳定后独立灰度，默认使用本地 Ollama。
6. Runtime、legacy、验证、摘要和故障指标可在诊断/报告中复核。
7. 关闭单个 feature flag 即可回退，不要求数据库 downgrade。
8. 完成 `0.2.1 → 0.3.0` 安装升级、数据保留和回滚验收。

### 3.2 明确不做

- 不在 `0.3.0` 删除 `/tools`、`/tools/plan` 或旧 `/tool-calls` 端点。
- 不开放任意 Shell、任意 API、任意数据库写入或无边界文件写入。
- 不新增 MCP OAuth、真实远程 Provider 上线或自动长期记忆写入。
- 不把代码、Shell、API、数据库验证器全部接入真实工作流；这些继续属于 `0.4.0`。
- 不把 macOS/Linux、Authenticode 和 Tauri 全窗口自动化混入 Runtime 主线。
- 不把摘要 worker 与 Chat Runtime 放在同一次开关变更中。

## 5. M0：`0.2.1` 批 A 观察与基线

### 5.1 观察窗口

满足以下任一较晚条件：

- 连续观察至少7天且积累不少于100个有效 Agent run；或
- 使用量不足100个 run 时延长至14天。

观察期至少包含：

- 三次正常启动和正常退出，telemetry 窗口必须写入 `ended_at`；
- 一次应用升级或重新安装后的首次启动；
- 一次 Ollama 临时不可用与恢复；
- 一次用户取消；
- 一次审批暂停与恢复；
- 普通 Agent run 和 RAG Agent run。

### 5.2 必须采集的基线

- run：created/running/completed/failed/cancelled/waiting_approval。
- run耗时、首个模型 delta、总完成时间和超时。
- owner lock竞争、丢失、reconcile和孤儿 run。
- 输出验证：started/passed/failed/retry/exhausted。
- RAG：拒答、引用验证失败、检索与总回答 P95。
- ContextBuilder：截断次数、估算 token、provider usage偏差。
- 工具：执行、取消、超时、失败和残留进程。
- compatibility：`/tools`、`/tools/plan`、`/tool-calls`、`/chat/stream` 的mode/outcome。
- sidecar：正常结束窗口、异常退出窗口和重启恢复。

### 5.3 进入 Chat Runtime 灰度的门槛

- 数据损坏、重复副作用、审批绕过和秘密泄漏均为0。
- 不存在无法取消、无法恢复或超过10分钟仍无状态推进的 run。
- 正常退出能写入 `ended_at`，异常退出能在下次启动被 reconcile。
- owner lock竞争和丢失行为符合文档，不出现双 coordinator。
- 输出验证和 RAG 引用失败均失败关闭，不向用户发布未验证答案。
- P0/P1问题全部关闭或有明确的发布阻断决定。
- 形成一份带时间范围、样本量和异常解释的基线报告。

注意：M0阶段 legacy 调用非零是预期现象，因为聊天尚未接管；此时不以 `legacy_zero=true` 作为进入条件。

## 6. M1：配置、能力协商与遥测增强

### 6.1 开关治理

1. 在 Tauri 配置结构中显式支持：
   - `PA_CHAT_AGENT_RUNTIME_ENABLED`
   - `PA_CONVERSATION_SUMMARY_WORKER_ENABLED`
2. 两个开关必须独立保存、加载和回退。
3. 开发/测试环境先显式开启，`0.2.1` 升级用户不应在未完成 canary 前被静默切换。
4. 最终 `0.3.0` 是否默认写入 Chat Runtime=true，由 M3 canary结果决定。
5. 摘要 worker 无论如何不得与 Chat Runtime 同时首次开启。

### 6.2 `/capabilities` 契约

必须保持互斥状态：

- `chat_execution_mode=legacy | agent_runtime`
- `legacy_tool_planner_enabled`
- `agent_read_only_tools_enabled`
- `rag_chat_runtime_enabled`

约束：

- 桌面端只根据 `chat_execution_mode` 决定是否调用旧 planner。
- 同一条消息禁止同时进入 legacy和Runtime。
- `/capabilities` 不可用时安全回退 legacy，并记录兼容遥测。
- 开关变化必须在 sidecar重启后生效，不能出现半进程状态。

### 6.3 遥测增强

- 区分 ordinary chat、RAG chat、旧 tool_result兼容和显式 Agent Runs API。
- 记录 route/mode/outcome，不保存聊天正文、模型提示或 secret。
- 增加正常 shutdown窗口验收，避免所有窗口 `ended_at=null`。
- 提供按版本、时间范围和模式输出的观察脚本。
- 报告区分真实用户流量、QA smoke和开发测试，避免将测试调用计入生产归零结论。

### 6.4 验收标准

- 配置 roundtrip和旧配置兼容测试通过。
- `/capabilities` 四种关键组合测试通过。
- 前端不存在双执行或旧 planner预调用。
- 遥测能区分 canary、legacy和Runtime，不含敏感正文。
- 关闭 Chat Runtime开关后无需数据库变化即可回退。

## 7. M2：普通聊天 Runtime 接管

### 7.1 主链路

普通消息应按以下路径执行：

```text
Desktop send
  → GET /capabilities
  → POST /chat/stream
  → durable AgentRun
  → ContextBuilder
  → ModelGateway/Ollama
  → OutputVerifier
  → run.completed
  → 唯一 assistant message 投影
  → SSE done
```

### 7.2 必须完成

- 单轮与多轮普通聊天。
- 原生 token流式，不把完整回答重复发送为第二份消息。
- 会话历史经过 ContextBuilder预算和最近消息保留策略。
- 断线后通过run_id和durable事实恢复。
- 用户取消能停止模型、工具和后续投影。
- continuation并发和重复重连返回同一消息。
- Provider在首个delta前可按策略重试；首个delta后失败不自动重放。
- Runtime失败时返回明确错误，不自动把同一消息再交给legacy执行。

### 7.3 测试

- 普通聊天Runtime路由四分支。
- 多delta、单done和无重复完整文本。
- SSE断线、取消和重连。
- 相同run的并发continuation。
- 应用重启前后唯一assistant message。
- Ollama超时、连接拒绝、缺终止帧和中途错误。
- ContextBuilder截断、预算和敏感摘要排除。
- 前端E2E确认Runtime模式不调用 `/tools/plan`。

### 7.4 验收标准

- 每个用户消息最多产生一个run和一个最终assistant message。
- 取消、断线或重连不会生成重复模型调用或重复消息。
- 未验证候选不会显示为最终答案。
- 普通聊天成功率不低于M0 legacy基线。
- 首token和总耗时P95相对M0基线回退不超过20%；超过时必须有批准的原因和优化计划。

## 8. M3：RAG、审批、恢复与可靠性

### 8.1 知识库聊天

只有以下条件同时成立时进入Runtime RAG：

- Chat Runtime开启；
- RAG工具开启；
- 输出验证开启；
- 请求明确使用知识库。

必须保证：

- collection/document过滤不被弱相关结果绕过。
- 证据不足时返回明确拒答，不伪造引用。
- citations来自同一run中成功的RAG工具事实。
- quote是模型实际看到文本的精确子串。
- 未知、冲突、超限或被篡改证据失败关闭。
- 旧SSE中的sources由durable证据投影，不采用模型自报元数据。

### 8.2 审批与恢复

- confirm工具暂停为waiting_approval。
- token轮换、过期、拒绝和一次消费。
- 应用退出或崩溃后checkpoint可恢复。
- 恢复时不重置验证重试预算。
- 已执行非幂等工具处于unknown时不自动重放。
- 历史 `tool_result` 请求继续使用兼容路径，并记录原因。

### 8.3 故障注入矩阵

- Ollama请求中途断开。
- MySQL短暂断连。
- owner lock verify失败。
- sidecar被强制结束后重启。
- SSE客户端在不同阶段断开。
- 审批前、审批后和工具执行后崩溃。
- RAG检索无结果、低分、rerank不可用和伪造引用。
- 工具超时、取消、输出截断和验证失败。

### 8.4 安装版 canary

1. 只在单一测试配置开启Chat Runtime。
2. 先执行20次普通聊天，不启用摘要worker。
3. 再执行10次RAG聊天，覆盖有答案和无答案。
4. 执行审批暂停/恢复、断线重连和应用重启。
5. 连续运行24–48小时，无P0/P1后扩大到日常配置。
6. 扩大后继续观察至少7天，再决定0.3.0默认值。

### 8.5 回退条件

出现以下任一情况立即关闭Chat Runtime：

- 数据丢失或重复消息。
- 审批绕过、重复副作用或秘密泄漏。
- 无法恢复的stuck run。
- 未验证RAG答案被发布。
- owner lock异常导致双协调器。
- 明显且无法解释的延迟/失败率回退。

回退只关闭 `PA_CHAT_AGENT_RUNTIME_ENABLED`，批 A和schema `0021`保持不变。

## 9. M4：摘要 worker 独立灰度

### 9.1 启动条件

- Chat Runtime canary稳定至少24–48小时。
- 普通聊天和RAG聊天没有未处置P0/P1。
- 摘要worker单测、故障注入和安装版配置roundtrip通过。

### 9.2 安全约束

- 默认只使用本地Ollama。
- 远程Provider必须额外开启 `PA_CONVERSATION_SUMMARY_ALLOW_REMOTE_PROVIDER=true`。
- 原始消息永不删除。
- 摘要保存来源范围、source hash和结构化字段。
- 模型输出不符合Schema时不写入数据库。
- 疑似含secret的来源标记sensitive，不进入默认上下文。
- 不对waiting approval和未完成工具上下文做破坏性压缩。

### 9.3 灰度顺序

1. 测试库运行确定性样本。
2. 安装版开启worker，但先只处理专用QA会话。
3. 人工核对目标、决定、待办、约束、错误和来源范围。
4. 验证重启幂等、重复调度和失败恢复。
5. 扩大到日常会话，持续观察至少7天。

### 9.4 验收指标

- 无效摘要写入数为0。
- 原始消息删除数为0。
- 相同来源/hash不产生重复有效摘要。
- 摘要不会覆盖当前请求、系统策略、审批或未完成工具上下文。
- 关闭worker后聊天继续正常工作。
- 没有显式授权时远程摘要调用数为0。

## 10. M5：legacy兼容与退役准备

### 10.1 0.3.0的处理原则

- 保留旧 `/tools`、`/tools/plan` 和 `/tool-calls` 端点。
- 保留带旧 `tool_result` 请求的兼容路径。
- 可以增加deprecated日志、诊断提示和版本说明，但不删除接口。
- Runtime默认启用与legacy删除必须是不同提交、不同发布决策。

### 10.2 归零观察

Chat Runtime默认启用后开始新的归零窗口：

- `/tools/plan` 的桌面Runtime调用为0。
- 新消息不产生legacy `/tool-calls`。
- pending/waiting_approval遗留已耗尽或有处置方案。
- 覆盖至少一个发布升级周期，并持续至少14天。
- 报告排除明确标记的QA调用。

### 10.3 后续决定

如果归零条件满足，只形成退役提案；实际删除安排在独立 `0.3.x` 或 `0.4.0` 变更中，并再次执行完整升级/回滚测试。

| Python unit | ContextBuilder、verifier、telemetry、summary | 有界、幂等、无敏感正文 |
| Python integration | Runtime/chat/RAG/approval/recovery | durable状态、唯一投影、失败关闭 |
| Frontend unit | capabilities、planner绕过、SSE状态 | 无双执行、回退明确 |
| Playwright | 普通聊天、RAG、审批、取消、断线 | UI契约不回退、无重复消息 |
| Rust | 配置roundtrip、sidecar树清理 | 开关独立、退出无残留 |
| Installer | clean install、upgrade、rollback | schema/数据/配置/进程一致 |
| Fault injection | Provider/DB/lock/SSE/crash | 可取消、可恢复、不重放副作用 |
| Security | token、审批、引用、诊断包 | 无绕过、无secret泄漏 |

## 13. 质量门槛

### 13.1 零容忍项

- 数据丢失。
- 重复assistant message或重复副作用。
- 审批绕过。
- 未验证RAG引用对用户可见。
- secret进入日志、遥测、诊断包或摘要。
- 多coordinator并发写入。
- 正常退出留下PrivateAgent sidecar子进程。

### 13.2 非回退项

- 普通聊天完成率不低于legacy基线。
- RAG已知答案Recall/MRR/引用正确率不低于批准阈值。
- 无答案拒答门禁继续通过。
- 首token和总耗时P95相对M0回退不超过20%，或有批准的硬件/功能解释。
- 取消和审批动作在UI中及时反馈，不出现无界等待。

## 14. 回滚设计

| 级别 | 回滚动作 | 数据库处理 |
|---|---|---|
| 摘要异常 | 关闭summary worker | 不downgrade，保留已生成摘要供审计 |
| Chat Runtime异常 | 关闭Chat Runtime | 不downgrade，保留run/event事实 |
| 批 A异常 | 逐个关闭对应批 A开关 | 不downgrade |
| 安装版异常 | updater回退0.2.1或重装0.2.1 | schema兼容时不downgrade |
| 新迁移异常 | 停写、使用升级前克隆或批准的迁移runbook | 禁止盲目downgrade |

回退前必须先处理running/waiting_approval和unknown非幂等执行，不能直接删除历史事实。

## 15. 分工建议

| 工作流 | 主要范围 | 主要文件/交付物 | 并行边界 |
|---|---|---|---|
| Runtime Backend | M2/M3，chat coordinator、projection、recovery | routes_chat、runtime、repository、测试 | 不同时重构summary和tool dispatcher |
| Desktop | M1/M2，配置、capabilities、SSE UX | Tauri lib、runtime API、chat store、E2E | 不自行改变后端执行语义 |
| RAG/Verification | M3，工具证据、拒答、引用验证 | rag adapter/verifier、评测报告 | 不放宽collection和引用边界 |
| Summary | M4，worker、Schema、来源hash | summary worker、context tests、QA报告 | Chat Runtime稳定前不进入默认配置 |
| Telemetry/QA | M0/M5，观察、故障注入、归零报告 | telemetry脚本、诊断、evidence | 不把QA流量算作生产归零 |
| Release | M6，版本、构建、安装升级、GitHub Release | dist资产、manifest、tag | 冻结后不接受非阻断功能 |

多人或多AI并行时，`routes_chat.py`、Tauri `lib.rs`、Runtime repository/coordinator和release事实源必须设单一负责人，避免相互覆盖。

## 16. 推荐执行顺序

1. 立即开始M0观察，建立 `0.2.1` 基线报告。
2. 并行完成M1配置/遥测准备，但保持Chat Runtime关闭。
3. M0达到进入门槛后，在测试配置开启普通聊天Runtime。
4. 完成M2普通聊天和故障回归。
5. 完成M3 RAG、审批、恢复和安装版canary。
6. Chat Runtime稳定24–48小时后开始M4摘要worker灰度。
7. Chat Runtime扩大使用后启动M5 legacy归零观察；本版本不删除端点。
8. 冻结0.3.0，统一版本号并运行完整门禁。
9. 执行0.2.1→0.3.0安装升级、数据保留、回滚和进程清理。
10. 生成tag、发布资产和GitHub Release，核对远程哈希。

## 17. 0.3.0 完成定义

只有同时满足以下条件，才能标记 `0.3.0` 完成：

- M0批 A观察达到时间/样本门槛，没有未处置P0/P1。
- 普通聊天和知识库聊天默认进入durable Runtime。
- 旧planner不再参与Runtime模式的新消息。
- SSE、取消、重连、审批、恢复和唯一消息投影通过安装版验收。
- RAG拒答和可信引用验证继续通过。
- 摘要worker完成独立灰度；最终默认状态和限制写入release notes。
- legacy端点保留可回退，删除不混入本版本。
- 完整工程门禁、干净安装、0.2.1升级、数据保留和应用回滚通过。
- 正常退出无sidecar残留。
- tag提交、报告、manifest、安装包和GitHub Release资产完全一致。
- Windows-only、外部Ollama和代码签名状态如实说明。

## 18. 0.3.0 之后

`0.3.0` 稳定运行并完成至少14天legacy归零观察后，再决定：

- 是否以独立 `0.3.x` 删除无调用的legacy端点；
- 是否进入 `0.4.0`，逐个开放代码、Shell、API、数据库和多步骤可信工作流；
- 是否启动MCP、远程Provider、自动记忆、正式签名或跨平台项目。

在此之前，不应让这些扩展分散Runtime默认接管的测试和发布资源。
