# PrivateAgent 0.3.0 Alpha 开发计划：Runtime能力冻结

> - 计划修订日期：2026-08-08
> - 稳定基线：`v0.2.1` / `a3ac17c`
> - 当前开发提交：`9797a4b`
> - 目标检查点：`0.3.0-alpha.2`
> - 版本性质：内部预发布检查点，不单独发布稳定版
> - 后续路线：[`integrated-0.5.0-development-plan-20260808.md`](./integrated-0.5.0-development-plan-20260808.md)
> - 核心目标：冻结聊天Runtime、RAG、审批恢复、摘要和遥测契约，为UI全面改造提供稳定接口

## 1. 修订结论

`0.3.0` 不再作为需要独立7–14天观察和正式发布的稳定版本，而是整个 `0.5.0` 集成开发列车中的Runtime检查点。

新版执行规则：

1. 原计划中的Runtime、RAG、审批、恢复、摘要和兼容遥测技术任务继续执行；
2. 原M0的7–14天观察不再阻塞开发，改为一次工程基线演练；
3. 每个里程碑通过自动化、故障注入和安装版smoke后立即进入下一项；
4. `0.3.0-alpha.2` 不进入稳定GitHub Release和正式updater通道；
5. Alpha通过后冻结公开前后端契约，直接进入 `0.4.0-alpha` UI/UX改造；
6. 正式使用观察统一放到全功能完成后的 `0.5.0-rc.1`，固定14天。

### 1.1 本版本解决什么

- 普通聊天和知识库聊天统一进入durable Agent Runtime；
- 桌面端通过 `/capabilities` 选择唯一执行路径；
- SSE、取消、断线、续传和消息投影稳定；
- RAG引用、输出验证和领域验证器失败关闭；
- 审批暂停、批准、拒绝、过期和重启恢复完整；
- ContextBuilder和摘要worker具备边界、幂等和遥测；
- sidecar优雅停机、遥测窗口和异常reconcile可信；
- legacy仍可一键回退，但新Runtime流量可以被准确区分。

### 1.2 本版本不解决什么

- 不全面重做UI、交互、动画和排版；
- 不开放通用Shell、任意API、任意数据库写入或任意文件写入；
- 不物理删除legacy端点和旧表；
- 不完成MCP OAuth、跨平台或正式代码签名；
- 不对外发布稳定 `0.3.0`；
- 不执行独立7–14天正式使用观察。

必要的桌面端改动只限于Runtime兼容、错误反馈、取消、审批和E2E钩子；全面UI工作由 `0.4.0-alpha` 承担。

## 3. 开发原则

1. **不等待日历，只等待证据。** 测试、构建、smoke通过即可继续。
2. **开关独立。** Runtime、RAG、摘要和兼容遥测不能由一个总开关同时改变。
3. **失败关闭。** 验证、RAG引用、审批和数据库异常不能降级为发布未经验证答案。
4. **单执行链。** 同一桌面请求只能进入Runtime或legacy之一。
5. **事件事实优先。** UI不根据文案猜状态，必须消费公开状态和事件。
6. **迁移保持additive。** Alpha阶段不删除旧列、旧表和旧事件。
7. **保留回退。** 关闭Chat Runtime即可回到legacy，不要求数据库downgrade。
8. **不扩大UI范围。** 只处理0.3功能正常运行必需的界面兼容。
9. **不展示隐藏推理。** UI只展示计划、动作、公开验证和结果。
10. **报告绑定commit。** Alpha证据必须绑定同一代码、二进制和配置快照。

## 4. 目标架构

### 4.1 聊天路由

```text
Desktop
  → GET /capabilities
  → chat_execution_mode == agent_runtime ?
       POST /chat/stream → AgentRunCoordinator → AgentRuntime
     : POST /tools/plan + legacy chat
```

Runtime模式必须满足：

- 桌面端不调用旧 `/tools/plan`；
- 一个用户消息只创建一个run；
- 同一run只由一个coordinator持有；
- SSE delta只投影一次；
- 完成、失败、取消和等待审批都来自持久化状态；
- 断线后可以继续读取run事实，不创建替代run。

### 4.2 RAG路由

```text
knowledge_base=true
  → ContextBuilder准备上下文
  → Runtime获得RAG工具
  → 检索/读取/引用
  → 输出验证
  → 仅发布已验证答案或明确拒答
```

当RAG工具或输出验证未开启时，Runtime不能伪装成完整RAG路径；必须明确走兼容路径或失败关闭，并记录原因。

### 4.3 审批恢复

```text
tool.approval_required
  → run = waiting_approval
  → 持久化checkpoint和参数哈希
  → approve/reject/expire
  → 一次性token消费
  → 原run恢复或收敛为终态
```

应用重启后必须从数据库恢复待审批事实，不依赖旧进程内存。

### 4.4 摘要worker

```text
周期tick
  → 找到满足阈值且未覆盖的会话
  → 读取有界消息窗口
  → 本地Provider默认生成摘要
  → 幂等保存summary
  → 原始消息保留
  → 下一次ContextBuilder复用
```

远程Provider只有在用户已经配置并显式允许摘要使用时才能调用。

## 7. A0：工程基线与M0工具链

### 7.1 目标

原M0由“长期观察门槛”改为“开发期基线演练”。它不决定稳定发布，只证明：

- runner连接的是明确的Alpha二进制和配置；
- run、RAG、取消、审批和故障样本能够采集；
- 正常退出窗口合法；
- 异常窗口能够reconcile；
- 聚合器不会把失败、取消和无效run计入completed样本；
- 报告绑定commit、版本、SHA-256和时间范围。

### 7.2 一次性演练

建议在独立QA配置执行：

- 3次启动/正常退出；
- 20个普通或RAG run；
- 1次取消；
- 1次审批暂停/恢复；
- 1次Ollama中断/恢复；
- 1次异常退出和下次启动reconcile。

这次演练可以在同一工作日完成，不要求跨7天。

### 7.3 退出条件

- runner和聚合器测试全绿；
- 不读取错误的项目 `.env` 或错误二进制；
- HTTP客户端、Ollama和sidecar进程全部清理；
- `ended_at >= started_at`；
- 无stale窗口和负时长窗口；
- 报告能够区分人工、QA、普通、RAG、取消和故障样本；
- 不把本次样本宣称为最终生产观察。

## 8. A1：配置、能力、遥测与优雅停机

### 8.1 配置治理

- 所有新增开关在开发、安装和测试环境行为一致；
- `/capabilities` 只返回非敏感、确定性的能力事实；
- 桌面端只根据 `chat_execution_mode` 决定执行路径；
- 不因Ollama/MySQL临时不可用改变静态能力声明；
- 未识别旧后端时保持legacy兼容。

### 8.2 遥测

必须区分：

- `/chat/stream`: `agent_runtime`、`agent_runtime_rag`及互斥legacy原因；
- `/agent-runs`: 显式Agent API；
- `/tools`、`/tools/plan`、`/tool-calls*`: legacy调用；
- `origin`: process与QA；
- `version`: 运行二进制版本；
- `outcome`: created、routed、failed、cancelled等低基数结果。

### 8.3 停机与reconcile

- 桌面退出先请求 `/internal/shutdown`；
- sidecar进入lifespan finally并flush `ended_at`；
- 超时才执行进程树强杀；
- 下次启动reconcile陈旧窗口；
- 并发flush不能产生负时长；
- Alpha验收后不存在无主sidecar进程。

### 8.4 退出条件

- feature flag组合测试通过；
- capability契约测试通过；
- telemetry并发、flush、reconcile、origin和version测试通过；
- 3次启动退出无负时长、无残留；
- `/internal/shutdown` 认证和loopback边界符合安全模型。

## 9. A2：普通聊天Runtime接管

### 9.1 主链任务

1. Chat请求创建唯一Agent run；
2. ContextBuilder读取有界历史、摘要和允许的记忆；
3. ModelGateway以流式方式执行；
4. delta映射为兼容SSE；
5. 完成后只持久化一次assistant消息；
6. 验证失败不发布候选答案；
7. 取消和断线收敛到持久化终态；
8. 重连读取同一run，不重放副作用。

### 9.2 必须覆盖

- 成功流式；
- 首delta前失败；
- 首delta后失败；
- 缺终止帧；
- 最终答案与delta不一致；
- 用户取消；
- SSE断开；
- MySQL轮询或续传失败；
- 页面刷新后恢复；
- 旧 `tool_result` 输入继续走兼容路径；
- Runtime开启时旧planner调用为0。

### 9.3 退出条件

- 一个请求、一个run、一个最终消息；
- 失败后不回放legacy生成第二份答案；
- 断线后无活跃run泄漏；
- 取消后无模型或工具残留；
- MySQL断连返回明确SSE错误，不伪造完成；
- Chat Runtime关闭后旧路径仍能使用；
- Python、组件和Playwright双模式测试通过。

## 10. A3：RAG、审批、恢复与可靠性

### 10.1 RAG

- `knowledge_base=true` 使用Runtime RAG工具；
- 检索、来源读取和引用验证均产生公开事件；
- 无证据时明确拒答；
- 引用不存在、越权、错位或验证失败时失败关闭；
- RAG工具关闭或输出验证关闭时不进入伪Runtime RAG路径；
- 来源元数据可以稳定投影给后续UI。

### 10.2 审批

- CONFIRM工具进入 `waiting_approval`；
- checkpoint、参数哈希、风险和能力持久化；
- 批准后一次性token只消费一次；
- 参数变化、过期token和跨run token全部拒绝；
- 拒绝和取消收敛为明确终态；
- 应用重启后可重新加载和继续处理。

### 10.3 恢复

- 启动时reconcile orphaned run；
- `waiting_approval` 保留可恢复checkpoint；
- running/queued孤儿按事实收敛；
- owner lock竞争时只有一个coordinator；
- 同一run不能被重复附着和重复执行副作用。

### 10.4 故障注入

必须覆盖：

- Ollama连接拒绝、超时和中途断开；
- MySQL轮询、事件读取和续传失败；
- Chroma/RAG检索失败；
- 输出验证失败、重试和耗尽；
- 工具超时、取消和迟到结果；
- 应用退出、sidecar强杀和重启；
- owner lock竞争。

### 10.5 退出条件

- 普通与RAG路径均有真实模型安装版smoke；
- 审批批准、拒绝、过期和重启恢复通过；
- verifier失败不向用户发布答案；
- 无重复副作用、审批绕过和秘密泄漏；
- 不存在超过10分钟无推进且无法取消/恢复的run；
- 故障注入测试能够稳定重复。

## 11. A4：摘要worker

### 11.1 边界

- 独立开关，不随Chat Runtime自动开启；
- 默认使用本地Ollama；
- 远程Provider必须已有配置并显式允许；
- 只处理达到消息阈值的会话；
- 输入窗口有消息数和字符数上限；
- 摘要不能删除、覆盖或修改原始消息；
- 同一源窗口重复调度不会产生重复摘要；
- 失败不会阻塞聊天主链。

### 11.2 生命周期

- lifespan启动worker；
- tick间隔和批量有界；
- shutdown取消worker并等待清理；
- Provider失败可重试但有上限；
- 成功摘要可被ContextBuilder复用；
- 遥测不记录聊天正文。

### 11.3 测试

- 阈值不足不生成；
- 达到阈值生成；
- 保留最近消息；
- 最大源窗口限制；
- 幂等重复tick；
- 本地Provider成功/失败；
- 远程Provider默认拒绝；
- 显式允许远程Provider；
- 原始消息完整；
- sidecar退出worker清理。

### 11.4 退出条件

- 测试和安装版本地模型smoke通过；
- 摘要质量不会引入明显事实反转；
- 原始消息数量和内容哈希不变；
- 重复调度不重复写入；
- 关闭摘要开关后Chat Runtime不受影响；
- UI所需summary元数据契约冻结。

## 12. A5：legacy兼容与契约冻结

### 12.1 兼容原则

- 本Alpha不删除 `/tools`、`/tools/plan` 和旧 `/tool-calls*`；
- Runtime关闭、旧后端和历史 `tool_result` 继续可用；
- Runtime开启时桌面新消息不调用旧planner；
- legacy调用非零不阻塞Alpha；
- legacy物理删除统一推迟到 `0.6.0+`。

### 12.2 需要冻结的公开契约

UI全面改造开始前必须冻结：

1. `/capabilities` 字段和默认语义；
2. `/chat/stream` SSE事件、顺序和错误格式；
3. Agent run状态集合；
4. Agent run公开事件类型和payload；
5. 审批列表、批准、拒绝和续传接口；
6. RAG来源和引用结构；
7. 摘要可见元数据；
8. compatibility mode/outcome枚举；
9. 取消、超时、失败和恢复的UI文案事实字段。

冻结后如需破坏性变化，必须更新UI计划和相关E2E，不允许由前端猜测兼容。

### 12.3 退出条件

- 生成API/SSE/事件契约清单；
- Runtime与legacy模式矩阵通过；
- telemetry报告能够解释每个兼容原因；
- 无低基数之外的用户正文标签；
- 新UI可以仅基于公开契约实现全部核心状态。

## 15. 零容忍问题

以下问题会阻断Alpha，但修复并重跑相关门禁后即可继续，不需要等待新的7天窗口：

- 数据损坏；
- 重复工具副作用；
- 审批绕过或token重放；
- 秘密进入日志、数据库、Vue或报告；
- 同一消息创建多个有效run；
- 已失败候选被投影为成功答案；
- verifier或RAG引用失败后仍发布答案；
- owner lock失效导致双coordinator；
- 取消/超时后残留模型或工具进程；
- 原始消息被摘要worker删除或改写；
- 正常退出产生负时长或永久open窗口；
- 关闭feature flag无法回退。

## 16. 回退设计

### 16.1 功能回退

- 关闭 `PA_CHAT_AGENT_RUNTIME_ENABLED`：普通聊天回到legacy；
- 关闭 `PA_AGENT_RAG_TOOLS_ENABLED`：RAG走明确兼容路径；
- 关闭 `PA_CONVERSATION_SUMMARY_WORKER_ENABLED`：停止摘要调度；
- 保留Agent run、事件、审批和摘要数据，不进行自动删除；
- 关闭遥测持久化不改变业务执行。

### 16.2 应用回退

- Alpha只安装到QA环境或独立数据目录；
- 不覆盖用户唯一可用的 `v0.2.1` 安装包和Release资产；
- 如需回退应用，优先安装 `v0.2.1` 并保留数据；
- Alpha新增schema保持旧应用可忽略；
- 禁止为了测试回退直接对主库运行破坏性downgrade。
